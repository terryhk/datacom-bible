# 第21章 IPv6过渡技术

> IPv4 与 IPv6 长期共存的过渡期需要三类技术：双栈（设备同时跑两套协议栈）、隧道（一种协议封装在另一种里穿越）、协议转换（NAT64 报文"整容"）。本章两讲覆盖隧道全家桶（手动隧道/GRE/6to4自动/ISATAP/6PE/6VPE）与 NAT64 动态+静态映射，核心思路："抓住了'隧道目的地如何被确定'这个关键点，隧道就学得很轻松。"

## 一、总起

IPv4→IPv6 不可能一刀切换——网络是基础设施，只能平滑演进。过渡技术三大类按部署场景选择：双栈适合设备能力充足的新建网络（最简单但要求设备支持两套协议栈）；隧道解决 IPv6 孤岛穿越 IPv4 公网（或反向）的连通问题；协议转换解决纯 IPv6 主机访问纯 IPv4 服务（或反向）。本章两讲以隧道为主线：第一讲从手动隧道到 GRE 到 6to4 自动隧道再到 6to4 中继，核心是"隧道目的地如何被确定"——手动=人工指定、自动=从目标地址提取；第二讲补全 ISATAP（主机-路由器隧道利用 SLAAC 获取前缀）、6PE（MPLS 承载 IPv6 无需 VPN 实例）、6VPE（IPv6 VPN 隔离）和 NAT64 协议转换（动态单向+静态双向）。过渡技术的选择不是技术问题而是场景问题——"谁的地盘谁做主"。

**适用人群**：
- **初学 / 转行人员（HCIP 进阶）**：理解 IPv4 与 IPv6 长期共存背景，掌握双栈（Dual Stack）、隧道（Tunnel）与协议转换（NAT64）三大过渡技术流派；
- **备考工程师（HCIP / HCIE 核心）**：攻克 IPv6 over IPv4 手动隧道、GRE 隧道封装、6to4 自动隧道前缀运算（2002:IPv4::/48）、ISATAP 园区过渡、以及 6PE/6VPE 运营商过渡机制；
- **一线工程实践者**：掌握企业跨公网打通 IPv6 孤岛隧道选型、出口防火墙 NAT64/DNS64 协议转换部署、以及隧道两端 MTU 与分片排错。

## 二、分述

### 2.1 过渡技术全景与隧道本质

**三大类**：
| 技术 | 原理 | 适用 |
|---|---|---|
| 双栈 | 设备同时跑 IPv4+IPv6，应用决定用哪套 | 新建网络，设备能力充足 |
| 隧道 | 报文重新封装穿越异种网络 | IPv6 孤岛穿越 IPv4 公网（或反向） |
| 转换 | IPv6↔IPv4 协议转换（"报文整容"） | 纯 IPv6 主机访问纯 IPv4 服务 |

**隧道命名规则**：被封装的在前，负责隧道的在后。如 IPv6 over IPv4 = IPv6 被 IPv4 封装。

**手动 vs 自动隧道（★核心区分）**：
- **手动**：源和目标均手动指定
- **自动**：源手动，目标**自动确定**——每种自动隧道有自身机制
- 【设计本源与技术哲学】："抓住了'隧道目的地如何被确定'这个关键点，隧道就学得很轻松。"

### 2.2 IPv6 over IPv4 手动隧道

**配置**：隧道口配 IPv6 地址（逻辑 IPv6 链路），`tunnel-protocol ipv6-ipv4`，指定 source 和 destination。
- 静态路由 `ipv6 route-static <目标> Tunnel口` 告诉设备进隧道封装
- **支持路由协议**：隧道口自身发 OSPFv3 组播→自动按 source/destination 封装到对端
- **点到点**：只能指定一个 destination，多站点需多个 Tunnel 口

**排错**：`destination` 易误敲为 `dseparation`（Tab 补全选错）→ 协议层 down。

### 2.3 GRE 隧道

与手动隧道区别：多一层 GRE 包头，切换仅需改 `tunnel-protocol gre`。GRE 可封装多种网络层协议（IPX/AppleTalk 等），包头标识协议类型（IPv6=0x86DD）。

**额外特性（手动隧道无）**：
- Keepalive 连通性检测
- 明文认证（`gre key 123`，仅比对一致，无哈希无防篡改）
- 校验和与序列号

【设计本源与技术哲学】："隧道不是做安全保护的东西，是为了连通性；安全是隧道的增值服务。不要指望一个技术能解决你所有的问题。"

### 2.4 6to4 自动隧道（★重点）

**目标地址自动确定**：从 IPv6 目标地址内嵌的 IPv4 地址提取。

**地址规划刚性要求**：站点内网 IPv6 必须用 `2002::/16` + 32 比特公网 IPv4（十六进制）构成 `/48` 前缀。如 1.1.1.1 → `2002:0101:0101::/48`。

**配置**：`tunnel-protocol ipv6-ipv4 6to4`，指定 source，**不指定 destination**。

**路由写法**：`ipv6 route-static 2002::/16 Tunnel0/0/0`（一条搞定所有 6to4 站点）。

**★不支持路由协议**：未指定 destination，组播包（FF02::5）不含内嵌 IPv4→无法确定隧道目的地→不支持组播→不支持路由协议。仅支持单播。

### 2.5 6to4 中继

**场景**：非 2002 前缀网段需与 6to4 站点互访——回程从 6to4 站发回时对端无该网段路由→丢包。

**解法**：在对端写静态路由，**下一跳填一个内嵌了目标站点公网 IPv4 的地址**（如 `2002:0101:0101:1::`），使其**路由迭代递归**到 Tunnel 口。下一跳是否真实存在不重要，能迭代到 Tunnel 口就行。

### 2.6 ISATAP 隧道（主机-路由器）

**场景**：IPv4 网络主机通过 ISATAP 路由器访问 IPv6。

**Interface ID**：主机=`0200:5EFE`+主机IPv4；路由器=`0000:5EFE`+路由器IPv4。

**★核心——利用 SLAAC 获取前缀**：
1. 双方隧道口自动生成 FE80 链路本地地址
2. 路由器隧道口配全局单播前缀（如 2001:1111::/64）
3. 主机按已知路由器 IPv4 **推理**其链路本地地址（FE80+0000:5EFE+路由器IPv4）
4. 主机向推理地址发 RS→经 IPv4 隧道→路由器回 RA 带前缀
5. 主机前缀+自身 Interface ID→全局单播地址，路由器隧道口即网关

【设计本源与技术哲学】："虚拟网卡就理解成隧道口，学会共鸣式的想象。"

### 2.7 6PE（MPLS 承载 IPv6，无需 VPN 实例）

- MPLS 骨干承载 IPv6，**不需要 VPN 实例**——IPv6 地址唯一不冲突
- PE 间 IPv4 iBGP 运载 IPv6 路由（非 BGP4+），私网标签+公网 LDP 标签两层封装
- ★**共享显式空标签 2**：所有 IPv6 路由统一标签 2（IPv6 显式空标签=2；IPv4=0），弹出后直查 IPv6 路由表，大幅省标签
- 需 NE40E（AR 不支持）

### 2.8 6VPE（IPv6 VPN 隔离）

6PE 把 IPv6 全放"一个 VPN"不隔离（类比 VLAN 1）。用户要隔离→6VPE。

★"除 PE-CE 间路由协议不同，其他原理跟 IPv4 VPN 相同。"

差异：VPN 实例 IPv6 地址族下 RD/RT 分开规划。6PE→6VPE 改造：IPv6 地址族配 RD/RT，BGP VPNv6 激活邻居。

### 2.9 NAT64 协议转换

**本质**：IPv6↔IPv4 直接协议转换。防火墙依目的地址是否含 NAT64 前缀判断转换。

**前缀**：知名前缀 `64:FF9B::/96`（内置）；自定义可选 32/40/48/56/64/96。

**动态映射**：IPv6→IPv4 单向。依赖 DNS64（AAAA→A 记录），源 IPv6→地址池 IPv4（PAT），目的提取前缀后 IPv4。★只单向。

**静态映射**：双向。绑定 IPv6 服务器↔公网 IPv4。IPv4 用户来访→源转 NAT64 前缀地址，目的转 IPv6 真实地址。★"适合少量服务器。"

★安全策略放行是常见漏配点。

### 2.10 配置命令速查

```bash
# IPv6 over IPv4 手动隧道
interface Tunnel0/0/0
 tunnel-protocol ipv6-ipv4
 source 1.1.1.1
 destination 3.3.3.3
 ipv6 enable

# GRE 隧道（仅改协议）
 tunnel-protocol gre

# 6to4 自动隧道
interface Tunnel0/0/0
 tunnel-protocol ipv6-ipv4 6to4
 source 1.1.1.1                # 不指定 destination

# 6to4 中继（非2002网段可达）
ipv6 route-static 2003:123:123:1:: 64 2002:0101:0101:1::

# ISATAP（路由器侧）
interface Tunnel0/0/0
 tunnel-protocol ipv6-ipv4 isatap
 source GigabitEthernet0/0/0
 ipv6 address 2001:1111::1/64

# 6PE（NE40E）
bgp 100
 ipv6-family unicast
  peer 3.3.3.3 enable
  peer 3.3.3.3 label-route-capability
  peer 3.3.3.3 advertise explicit-null   # IPv6显式空标签=2

# 6VPE
ip vpn-instance a
 ipv6-family
  route-distinguisher 1:1
  vpn-target 1:1 export-extcommunity
  vpn-target 1:1 import-extcommunity
bgp 100
 ipv6-family vpnv6
  peer 3.3.3.3 enable

```shell
# ═══ 1. IPv6 over IPv4 手动隧道标准配置 ═══
[R1] interface Tunnel 0/0/1
[R1-Tunnel0/0/1] tunnel-protocol ipv6-ipv4               # 隧道协议设为 IPv6-over-IPv4
[R1-Tunnel0/0/1] source 202.100.1.1                     # 隧道本地公网源 IPv4
[R1-Tunnel0/0/1] destination 202.100.2.2                # 隧道对端公网目的 IPv4（★误敲 dseparation 会导致 down）
[R1-Tunnel0/0/1] ipv6 enable
[R1-Tunnel0/0/1] ipv6 address 2001:DB8:12::1 64         # 隧道逻辑链路 IPv6 地址
[R1-Tunnel0/0/1] quit
# 引导流量进隧道
[R1] ipv6 route-static 2001:DB8:2:: 64 Tunnel 0/0/1

# ═══ 2. 6to4 自动隧道配置（目的地从目的 IPv6 前缀自动提取） ═══
# 假设 R1 本地公网 IPv4 为 202.100.1.1（16 进制为 CA64:0101）
# 规划 6to4 专用前缀：2002:CA64:0101::/48
[R1] interface Tunnel 0/0/2
[R1-Tunnel0/0/2] tunnel-protocol ipv6-ipv4 6to4         # 设为 6to4 自动隧道模式
[R1-Tunnel0/0/2] source GigabitEthernet 0/0/1           # 绑定出口物理源
[R1-Tunnel0/0/2] ipv6 enable
[R1-Tunnel0/0/2] ipv6 address 2002:CA64:101::1 64       # 属于 2002:CA64:0101::/48 空间
[R1-Tunnel0/0/2] quit
# 6to4 缺省或静态路由直接指向 Tunnel 口（根据目的 IP 前缀自动解析对端 IPv4）
[R1] ipv6 route-static 2002:: 16 Tunnel 0/0/2

# ═══ 3. NAT64 协议转换配置（防火墙环境） ═══
[FW] nat64 prefix 64:FF9B:: 96                          # 定义 NAT64 知名转换前缀
[FW] nat address-group NAT64_POOL mode pat
[FW-address-group-NAT64_POOL] section 0 202.100.1.50 202.100.1.60
[FW] nat-policy
[FW-policy-nat] rule name IPv6_TO_IPv4_TRANS
[FW-policy-nat-rule-IPv6_TO_IPv4_TRANS] source-zone trust
[FW-policy-nat-rule-IPv6_TO_IPv4_TRANS] destination-zone untrust
[FW-policy-nat-rule-IPv6_TO_IPv4_TRANS] action src-nat address-group NAT64_POOL
```

## 三、总结

**核心重点十带走**：
1. 过渡技术三式：双栈（应用决定用哪套）、隧道（封装穿越）、转换（NAT64 报文整容）。
2. 隧道命名：被封装的在前；手动 vs 自动的核心区分="隧道目的地如何被确定"。
3. 手动隧道：source+destination 人工指定，支持路由协议（隧道口发组播自动封装），点到点限制多站点需多 Tunnel 口。
4. GRE：多一层 GRE 包头，额外支持 Keepalive/明文认证/校验和——"隧道为连通性，安全是增值服务"。
5. 6to4 自动隧道：目标从 IPv6 地址内嵌 IPv4 提取；地址刚性要求 2002::/16+公网IPv4=/48；不支持路由协议（组播无法确定目的地）。
6. 6to4 中继：非 2002 网段写静态路由，下一跳填内嵌目标站点 IPv4 的地址→路由迭代到 Tunnel 口。
7. ISATAP：主机 0200:5EFE+IPv4 / 路由器 0000:5EFE+IPv4；利用 SLAAC（RS→RA 带前缀）获取全局地址。
8. 6PE：MPLS 承载 IPv6 无需 VPN 实例；IPv6 显式空标签=2（IPv4=0），共享标签弹出直查 IPv6 路由表。
9. 6VPE：6PE+VPN 实例隔离；IPv6 地址族 RD/RT 分开规划，原理同 IPv4 VPN。
10. NAT64：动态单向（IPv6→IPv4，依赖 DNS64+PAT）；静态双向（适合少量服务器）；安全策略放行是常见漏配点。

**落地注意事项**：`destination` 误敲 `dseparation` 是手动隧道排错第一步；6to4 地址规划必须严格遵循 2002+IPv4=/48 格式否则目标提取失败；6to4 中继下一跳不需要真实存在，能迭代到 Tunnel 口就行；6PE/6VPE 需 NE40E 设备（AR 模拟器不支持）；NAT64 前缀长度只能选 32/40/48/56/64/96；ISATAP 实验需虚拟机桥接（模拟器主机不支持 ISATAP）。

**学习建议**：隧道实验按"手动→GRE→6to4→6to4中继"顺序走一遍，体会"目的地确定机制"的演进——从人工指定到地址内嵌提取到路由迭代递归，每一步都问"目标怎么定的"。6to4 地址规划是练习重点：取一个公网 IPv4（如 10.1.2.3），手写 2002:0A01:0203::/48 的完整前缀，再划子网，确保换算无误。ISATAP 的核心在 SLAAC 流程——在纸上画出主机如何"推理"路由器的链路本地地址并发 RS，画通即理解。NAT64 部分重点区分动态（单向+DNS64+PAT）和静态（双向+绑定）的适用场景。学完本章，IPv6 全栈（基础+路由+过渡）地基完整，下一站可进第 22 章 MPLS 或第 25 章 QoS。

## 附：本章术语速查表

| 术语缩写 | 英文全称 | 中文含义 | 关键作用 |
|---|---|---|---|
| **GRE** | Generic Routing Encapsulation | 通用路由封装 | 在任意 IP 网络上封装任意三层协议的数据报文，支持 Keepalive 与多播穿透 |
| **6to4** | 6to4 Automatic Tunnel | 6to4 自动隧道 | 利用 2002:IPv4::/48 格式将对端公网 IPv4 内嵌于 IPv6 前缀中，实现自动点对多点隧道 |
| **ISATAP** | Intra-Site Automatic Tunnel Addressing Protocol | 站内自动隧道寻址协议 | 在 IPv4 局域网内为主机提供 IPv6 接入，将 IPv4 地址内嵌于接口 ID（0000:5EFE:IPv4） |
| **NAT64** | Network Address Translation 64 | 网络地址与协议转换 64 | 将 IPv6 数据包与 IPv4 数据包头进行结构化双向语义转换，配合 DNS64 实现异构互访 |
| **6PE** | IPv6 Provider Edge Router | IPv6 运营商边缘路由器 | 运营商骨干利用现有 MPLS IPv4 核心网承载并转发客户 IPv6 业务流量，无需建 VRF |
