# 第20章 IPv6路由协议

> IPv6 路由协议不是重新发明——OSPFv3、IS-IS for IPv6、BGP4+ 三大协议的核心算法（SPF/BGP 选路）完全复用 IPv4 版本，变化只在"地址承载方式"与"报文结构细节"。本章四讲把 IPv6 路由从静态到动态全覆盖：IPv6 静态路由的链路本地地址下一跳优势（割接不丢包）、OSPFv3 四大不同点（基于链路运行/多实例/骨肉分离/Router-ID 标识邻居）、LSA 类型体系（1-9 类完整 SPF 树绘制）、IS-IS IPv6 新增 TLV（232/236/129）、BGP4+ 配置要点与链路本地地址建邻连环坑。

## 一、总起

IPv6 路由协议的学习成本远低于预期——"你不用再那么辛苦地去学，你一看别人一说你就秒懂了"。OSPFv3 复用 OSPFv2 的区域划分/路由器角色/开销计算/DR 选举/LSA 泛洪/SPF 算法；IS-IS for IPv6 只需新增两个 TLV 和一个 NLPID，SPF 算法保持不变；BGP4+ 路由属性（选路/防环/反射器）直接套用 IPv4 BGP。变化集中在三个维度：**链路本地地址的协议级利用**（OSPFv3 用它建邻居、IS-IS Hello 包用它标识接口、BGP 用它建邻则有连环坑）、**报文结构重构**（OSPFv3 骨肉分离设计——拓扑与地址分离）、**多实例能力**（一条链路多实例隔离）。本章四讲递进：第一讲立静态路由基础与 OSPFv3 四大不同点，第二讲钻报文结构（Hello/Option/LSA 头部/8 类 9 类新增），第三讲完整 SPF 树绘制实战（一类→二类→八类→九类顺藤摸瓜），第四讲 IS-IS IPv6 TLV + BGP4+ 配置与坑。

**适用人群**：

## 二、分述

### 2.1 IPv6 静态路由：链路本地地址作下一跳

**基本配置**：`ipv6 route-static <目标网段> <下一跳>`，负载分担与浮动路由与 IPv4 一致。缺省路由写法 `:: 0`。

**链路本地地址作下一跳的规则**：必须先写出接口再写下一跳地址（`ipv6 route-static 2002::2:: 64 GigabitEthernet0/0/0 FE80::12::2`），因为所有接口都有相同 FE80 前缀，路由器无法区分去哪条链路。

**两大优势（实验验证）**：
1. **互联链路全局前缀不在同一网段也能通信**：R1 和 R2 互联接口全局前缀分别为 2003::/64 和 2002::/64，全局单播下一跳不可达，但用链路本地地址作下一跳即可通
2. **割接中业务不中断**：持续 ping 的同时将 R2 接口全局地址从 2003::12::2 变更为 2004::12::2，ping 全程不丢包

【设计本源与技术哲学】："链路本地地址对于我们 IPv6 的网络来说它是一个非常有用的地址，它能够保证网络割接过程中网络尽量的稳定。"

【类比】"铁打的银盘流水的兵"——链路是物理存在的"银盘"（铁打的），网段是可以任意变更的"兵"（流水的）。OSPFv2 运行在网段上（依赖"兵"），网段变了就受影响；OSPFv3 运行在链路上（在"银盘"上工作），靠链路本地地址工作，不依赖全局单播网段。

### 2.2 OSPFv3 概述：V2 与 V3 相同点

核心机制完全复用 V2：区域划分（骨干区/非骨干区）、路由器角色（IR/ABR/ASBR）、开销计算、路由优先级（内部 10/外部 150）、4 种网络类型、5 种报文类型、邻居建立与状态转换、DR/BDR 选举、LSA 泛洪、SPF 路由计算——全部一致。协议号仍为 89，组播地址 FF02::5（所有 OSPF 路由器）/ FF02::6（DR/BDR），对应 V2 的 224.0.0.5/6。

### 2.3 OSPFv3 四大核心不同点（★考试重点）

**不同点 1：基于链路运行，而非基于网段运行**
- 使用**链路本地地址**建立和维护邻居关系，不依赖接口上的全局单播地址
- 全局单播地址任意增删改（割接地址重编），OSPFv3 邻居不中断、路由不中断、业务不中断
- 实验验证：链路两端完全不配全局单播地址，仅配链路本地地址，OSPFv3 邻居正常建立，路由正常计算，通信正常

**不同点 2：单条链路支持多实例（Instance ID）**
- Instance ID 范围 0~255（默认 0），一个接口可加入不同进程的不同区域
- `ospfv3 1 area 0 instance 0` + `ospfv3 2 area 1 instance 1` 两个实例独立工作互不干扰
- Hello 报文携带实例 ID，相同才能建邻居
- V2 同一广播域隔离只能靠认证不同密码（产生大量认证失败日志），V3 多实例天然隔离

**不同点 3：LSA 去 IP 地址意义 + 报文/LSA 结构重构**
- 一类和二类 LSA **不再包含地址信息**，只描述拓扑——"更专一了"
- 新增专门承载地址/前缀信息的 LSA 类型（8 类、9 类）
- LSA 中新增**泛洪范围字段**（U/S2/S1），直接在报文里表达泛洪范围

**不同点 4：邻居由 Router-ID 标识，不再由 IP 地址标识**
- Router-ID **必配**（不配则进程无法启动，V2 有自动选举机制）
- 不再需要 `network` 命令：直接在接口下 `ospfv3 <进程> area <区域>`
- 其他配置（参考带宽/汇总/引入/特殊区域/静默接口）命令风格与 V2 一致

### 2.4 OSPFv3 报文头部与 Hello 包

**通用头部**：版本 V3、报文类型、报文长度、Router ID、Area ID、校验和、Instance ID。**与 V2 关键区别**：V2 携带认证类型和认证数据字段，V3 取消了——借助 IPv6 扩展包头（ESP/AH）实现认证加密。

**Hello 包携带**：接口 ID（设备自动分配）、优先级（默认 1）、Hello 间隔（10s）/邻居失效间隔（40s）、DR/BDR 的**Router ID**（★V2 用接口 IP）、已建立邻居的 Router ID 列表。

**邻居建立条件**：照搬 V2 + **额外多一个实例 ID 必须相同**。

**Option 关键比特位**：
| 位 | 含义 |
|---|---|
| AT | 是否支持 V3 认证（默认 0） |
| DC | 是否支持按需链路（抑制周期 Hello，"现在已经不会再去用它了"） |
| R | 始发路由器是否有效（类似 IS-IS 过载位） |
| NP | 是否 NSSA 区域（与 V2 的 N 比特一致） |
| E | 是否支持 5 类 LSA（置 1=常规区域） |
| **V6** | 是否参与 IPv6 路由计算（置 1=参与） |
| MC | 是否支持组播（现已不用） |

★NP 和 E 最重要——判断区域类型（常规/特殊/NSSA）。R 和 V6 类似 IS-IS 过载位的 interarea/external 两个参数。

### 2.5 LSA 头部、新旧判断与泛洪范围

**LSA 三参数唯一标识**：LS Type + Link State ID + Advertising Router（与 V2 一致）。

**新旧判断机制**（与 V2 完全一致）：序列号（大优）→ 校验和（大优）→ 老化时间=3600s（最优）→ 差值 >900s（Age 小者优）/ <900s（认为一样）。

**U/S2/S1 泛洪范围**：
- U=0 → 未知类型仅链路本地泛洪；U=1 → 按 S2/S1 确定范围
- S2/S1：00=链路本地、01=区域内、10=AS 内、11=保留

### 2.6 OSPFv3 LSA 类型体系（★核心）

| 类型 | V3 名称 | 泛洪范围 | 与 V2 对比 |
|---|---|---|---|
| 1类 | 路由器 LSA（Router） | 区域内 | 只描述拓扑（P2P/Transit/虚链路），**无 StubNet** |
| 2类 | 网络 LSA（Network） | 区域内 | DR 产生，描述尾节点连哪些实节点 |
| 3类 | 区域间前缀 LSA | AS 内 | ABR 产生，与 V2 三类用途一致 |
| 4类 | 区域间路由器 LSA | AS 内 | 描述 ASBR，与 V2 四类一致 |
| 5类 | AS 外部 LSA | AS 内 | 一条 LSA 可携带多个前缀（V2 一条一前缀） |
| 7类 | NSSA LSA | 区域内 | 与 V2 七类一致 |
| **8类** | **链路 LSA（Link-LSA）** | **链路本地** | V2 无对应，提供链路本地地址用于下一跳计算 |
| **9类** | **区域内前缀 LSA** | **区域内** | V2 无对应，描述区域内叶子（路由），依附于一类或二类 |

**"骨肉分离"设计（★精华）**：
- V2 一类 LSA 有四种 Link Type（P2P/Transit/Stub/虚链路）——拓扑和路由混在一起
- V3 一类只描述拓扑（骨头：P2P/Transit/虚链路），叶子信息用 9 类单独携带（肉）
- 【类比】"买菜——你给我来点净瘦肉不要骨头，你给我来点骨头不要肉回去炖排骨汤"

**8 类 LSA（链路本地泛洪）三个作用**：
1. 向该链路上的其他路由器通告本接口的链路本地地址
2. 通告本接口的 IPv6 前缀列表
3. 通告本链路始发的二类 LSA 中设置的可选项

【类比】"就像我跟德纲讲悄悄话，只有我和德纲互相讲，其他人都不知道。"——链路本地地址只需用于计算下一跳，其他链路的链路本地地址对计算无意义。这就是**功能拆分**思路——类比 Linux 哲学"所有一切都是文件"，每个零部件只负责自己的功能，好修好换。

⚠**易踩坑**：V3 的 8 类（Link-LSA）和 V2 的"芭蕾"（Graceful Restart）**不是同一个东西**。

**9 类 LSA（区域内泛洪）**：编号从 1 开始。通过三个参数声明依附对象：
- 依附于**实节点一类** → 叶子挂在路由器上（非广播型链路前缀 + 环回口）
- 依附于**尾节点二类** → 叶子挂在链路上（广播型链路前缀，由 DR 收集各路由器 8 类中的前缀汇总而成）

★**DR 的额外角色**：收集广播型链路上各路由器的 8 类 LSA 前缀→汇总为 9 类 LSA→统一以尾节点名义在区域内泛洪。

### 2.7 SPF 树完整绘制实战（顺藤摸瓜法）

**绘制顺序**（V3 比 V2 多两步）：
1. **一类 LSA** → 画实节点（路由器），描述 P2P 邻居关系和广播链路连接
2. **二类 LSA** → 画尾节点（广播链路抽象），尾节点到实节点开销=0
3. **八类 LSA** → 获取链路本地地址（计算下一跳）
4. **九类 LSA** → 挂叶子（IPv6 前缀 + 开销）

【类比】"丁真与理塘"——村子本无名气，因为出了丁真大家才知道理塘。广播型链路由 DR 的接口 ID 统一代表——DR 接口 ID 就是"形象代言人"。

**实验验证**：以 R1 为根计算到 R3 环回口路由：开销=1(R1→R2) + 1(R2→尾节点) + 0(尾节点→叶子) = 2，下一跳=FE80::12::2。与 `display ipv6 routing-table` 完全一致。

**V3 一类 LSA 的 Link State ID**：从 0 开始的点分十进制正整数（0.0.0.0），无实际逻辑含义，像编号。一台路由器如需多条一类则用 0.0.0.0、0.0.0.1 等。

### 2.8 三/四/五类 LSA、特殊区域与认证

**三类**（区域间前缀）：ABR 产生，默认路由前缀长度=0。
**前缀 Option 比特位**（3/5/7/8/9 类均有）：P（传播位，NSSA 前缀是否被 ABR 传播）、MC（组播）、LA（本地地址位=接口 IP）、NU（非单播，置 1 不纳入单播路由计算）。
**五类**：一条 LSA 可携带多个前缀（V2 一条一前缀）；E 比特=开销类型（1=类型 2 默认，0=类型 1）；F 比特=转发地址（可选，V2 必选）；T 比特=路由 Tag（可选）。
**特殊区域**：NSSA/完全 NSSA/Stub/完全 Stub，配置与 V2 一致。汇总（ABR 区域间/ASBR 外部/NSSA 七转五）与 V2 一致。

**认证三方式**：
| 方式 | 特点 |
|---|---|
| IPv6 AH 扩展包头 | 认证不加密 |
| IPv6 ESP 扩展包头 | 认证+加密，抓包看不到 OSPFv3 明文 |
| OSPFv3 自有认证 | 认证不加密，命令与 V2 类似（AR 模拟器可能不支持，NE40 支持） |

### 2.9 IS-IS for IPv6：新增 TLV

IS-IS 基于 TLV 结构，支持 IPv6 只需新增两个 TLV + 一个 NLPID，**SPF 算法不变**——比 OSPF 支持 IPv6 更简单。

| TLV | 名称 | 用途 |
|---|---|---|
| 232 | IPv6 接口地址 | Hello 包中=链路本地地址；LSP 中=全局单播地址 |
| 236 | IPv6 可达 | 描述 IPv6 前缀及开销（类比 OSPFv3 九类） |
| 129 | 协议支持 | NLPID: 0xCC=IPv4, 0x8E=IPv6 |

**236 号 TLV 比特位**：
- **U（Up/Down）**：Level-2 路由泄漏到 Level-1 时置 1（★SR-MPLS 中有理论价值）
- **X**：标识外部路由引入（类似 OSPF 5 类）（★SR-MPLS 中有理论价值）
- **S**：子 TLV 标示位
- **R**：保留

### 2.10 BGP4+：配置与链路本地地址建邻连环坑

**纯 IPv6 环境必须手动配 Router ID**——没有 IPv4 地址可自动作为 Router ID，不配则邻居起不来。

**链路本地地址建邻三步坑**：
| 步骤 | 问题 | 解决 |
|---|---|---|
| 第一坑 | 邻居起不来——路由器不知链路本地地址在哪个接口可达 | 指定出接口 `peer FE80::... connect-interface G0/0/0` |
| 第二坑 | 邻居建起来了但路由学不到——下一跳属性中的链路本地地址被强制变全零 `::`，对端认为无效丢弃 | 路由策略改下一跳为全局单播 `apply ipv6 next-hop 2001:...` |
| 结论 | — | ★推荐直接用**全局单播地址**建 BGP4+ 邻居 |

路由属性（选路/防环/反射器）与 IPv4 BGP 完全一致，直接套用。

### 2.11 配置命令速查

```bash
# IPv6 静态路由（链路本地地址作下一跳，必须指出接口）
ipv6 route-static 2002::2:: 64 GigabitEthernet0/0/0 FE80::12::2
ipv6 route-static :: 0 <下一跳>                          # 缺省路由

# OSPFv3 基础配置
ospfv3 1
 router-id 1.1.1.1                                        # 必配
interface GigabitEthernet0/0/0
 ospfv3 1 area 0                                          # 接口下直接启用（无 network）
 ospfv3 1 area 0 instance 1                               # 多实例

# OSPFv3 查看
display ospfv3 peer                                       # 邻居以 Router-ID 标识
display ospfv3 lsdb router 0.0.0.0 originate-router 1.1.1.1  # 一类
display ospfv3 lsdb network 0.0.0.4 origin-router 2.2.2.2    # 二类
display ospfv3 lsdb link 0.0.0.3 origin-router 1.1.1.1       # 八类
display ospfv3 lsdb intra-prefix 0.0.0.1 origin-router 1.1.1.1  # 九类（注意拼写）

```shell
# ═══ 1. OSPFv3 多区域与特殊区域完整配置模板 ═══
[R1] ospfv3 1
[R1-ospfv3-1] router-id 1.1.1.1                         # ★必须手工指定 32 位点分十进制 Router-ID（不配进程不工作）
[R1-ospfv3-1] quit
[R1] interface GigabitEthernet 0/0/1
[R1-GigabitEthernet0/0/1] ipv6 enable
[R1-GigabitEthernet0/0/1] ipv6 address 2001:DB8:12::1 64
[R1-GigabitEthernet0/0/1] ospfv3 1 area 0               # 接口下直接宣告进进程与区域（无 network 命令）
[R1-GigabitEthernet0/0/1] ospfv3 network-type p2p       # 链路类型设为 P2P 加速收敛

# ═══ 2. IS-IS for IPv6 (Multi-Topology) 配置模板 ═══
[R1] isis 1
[R1-isis-1] is-level level-2
[R1-isis-1] cost-style wide
[R1-isis-1] network-entity 49.0001.0000.0000.0001.00
[R1-isis-1] ipv6 enable topology standard               # 启用 IPv6 单/多拓扑计算
[R1-isis-1] quit
[R1] interface GigabitEthernet 0/0/1
[R1-GigabitEthernet0/0/1] isis ipv6 enable 1            # 接口宣告入 IS-IS IPv6

# ═══ 3. BGP4+ (MP-BGP IPv6 单播族) 经典配置模板 ═══
[R1] bgp 100
[R1-bgp] router-id 1.1.1.1
[R1-bgp] peer 2001:DB8:12::2 as-number 200             # 推荐使用对端 GUA 全球单播地址建邻（避免链路本地地址连环坑）
[R1-bgp] ipv6-family unicast                           # 进入 IPv6 单播地址族视图
[R1-bgp-af-ipv6] peer 2001:DB8:12::2 enable            # 激活该 IPv6 对等体
[R1-bgp-af-ipv6] network 2001:DB8:1:: 64               # 注入本地 IPv6 业务路由
[R1-bgp-af-ipv6] quit
```

## 三、总结

**核心重点十带走**：
1. IPv6 静态路由链路本地地址作下一跳必须先写出接口——优势：全局地址变更割接不丢包、不同网段互联也能通。
2. OSPFv3 基于链路运行（链路本地地址建邻居）而非基于网段——全局单播地址增删改不影响邻居和路由，"铁打的银盘流水的兵"。
3. OSPFv3 多实例（Instance ID 0-255）——一条链路多进程多区域隔离，V2 做不到。
4. OSPFv3 骨肉分离——一类二类只描述拓扑（骨头），8 类提供链路本地地址（下一跳），9 类挂叶子（路由），功能拆分类比 Linux 哲学。
5. 8 类 LSA 链路本地泛洪——"讲悄悄话"，只在该链路两台路由器间共享；9 类区域内泛洪——DR 收集广播链路各路由器 8 类前缀汇总为 9 类。
6. SPF 树绘制顺序：一类画实节点→二类画尾节点→八类取下一跳→九类挂叶子；尾节点到实节点开销=0。
7. OSPFv3 Router-ID 必配（不配进程不启动），无 network 命令（接口下直接 ospfv3 area）；DR/BDR 用 Router-ID 表达（V2 用接口 IP）。
8. IS-IS IPv6 新增 232（接口地址：Hello=链路本地/LSP=全局）、236（可达前缀，U/X 比特在 SR-MPLS 有理论价值）、129（NLPID: 0xCC=IPv4/0x8E=IPv6），SPF 算法不变。
9. BGP4+ 纯 IPv6 环境必须手动配 Router-ID；链路本地地址建邻连环坑（建不起→指定出接口→路由学不到→改下一跳）→推荐用全局单播地址建邻。
10. OSPFv3 认证三方式（AH 认证不加密/ESP 认证+加密/自有认证 AR 可能不支持）；特殊区域和汇总配置与 V2 完全一致。

**落地注意事项**：OSPFv3 改网络类型的命令 `ospfv3 network-type` 与 V2 的 `ospf network-type` 不是同一条（V3 进程未启动时命令被封锁）；`display ospfv3 lsdb intra-prefix` 注意单词拼写；五类 LSA 一条可携带多个前缀（V2 一条一前缀），`display ospfv3 lsdb` 直接看不出编号对应哪条外部路由需展开；IPv6 地址长度长考试中配错一个导致 SRv6 实验现象出不来——"排查困难"反复强调；BGP4+ 链路本地地址建邻的第二坑（下一跳变全零）最隐蔽，排错时先检查路由策略是否改了下一跳。

**学习建议**：OSPFv3 的核心在 SPF 树绘制——搭一个 4 台路由器拓扑（R1-R2 点到点 + R2/R3/R4 广播型），配好后从 R1 出发顺藤摸瓜：先 display 一类画出实节点和邻居关系，再查二类画出尾节点，再查八类获取链路本地地址，最后查九类把叶子挂上去——在纸上画出完整拓扑树后与路由表对比开销和下一跳，一致即毕业。8 类和 9 类是 V3 新增的精华，理解"为什么 8 类只在链路泛洪"（链路本地地址只需本地有效）和"为什么 9 类由 DR 汇总"（避免各搞各的）比背命令更重要。IS-IS IPv6 和 BGP4+ 部分考试要求不高，重点记住 U/X 比特位和 BGP4+ 链路本地地址建邻的三步坑即可。学完本章，IPv6 路由地基完整，下一站第 21 章（IPv6 过渡技术：双栈/隧道/NAT64）。
