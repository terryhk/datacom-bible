## 一、总起

IPv6 不是一个全新协议——它是 TCP/IP 体系的地址层升级。路由原理不变（OSPF/IS-IS/BGP 只需扩展支持 IPv6），转发逻辑不变（路由表查下一跳），变得是**地址长度与地址管理体系**：128 位带来无限地址空间、层次化汇总、即插即用（SLAAC）、简化包头（固定 40 字节去掉校验和与分片字段）。本章四讲层层递进：第一讲立基（IPv6 背景、地址格式与缩写、EUI-64 生成规范），第二讲展开类型体系（GUA/ULA/链路本地/组播/任播、报文头结构、OSPFv3 配置入门），第三讲钻协议（ICMPv6 差错/通知分类、PMTU 发现、NDP 五报文八功能、SLAAC 全流程、邻居状态机、重复地址检测、重定向五条件、M/O 标志位、前缀生命周期），第四讲收尾分配（DHCPv6 四步/两步交互、租约 T1/T2、中继、PD 前缀代理 60→62→64 层次化分配）。

## 二、分述

### 2.1 IPv6 诞生背景与六大优势

**IPv4 的四大缺陷**：地址耗尽（2011 年 IANA 把最后 468 万个地址分给 5 个 RIR 后无地址可分）、包头设计不合理消耗性能、路由表过大且查表效率低（地址分配凌乱无法精确汇总）、依赖 ARP 导致广播泛滥。

**IPv6 六大优势**：
1. **无限地址空间**：2¹²⁸ 个地址（340 万亿万亿万亿），"地球表面每平方米 67 万亿个"
2. **层次化地址分配**：运营商 /32 → 企业 /48，32 位前缀可汇总 65536 个 48 位网段——地址长→层次多→精确汇总→路由表小
3. **即插即用**：万物互联场景，插网线自动生成全球唯一 IP 直接上网（SLAAC）
4. **简化包头**：固定 40 字节（IPv4 变长 20~60），去掉包头长度/分片字段/校验和/总长度→转发性能提升
5. **原生 IPsec**：端到端加密认证（"量子计算机破解除外"）
6. **支持移动特性与 QoS**

【设计本源与技术哲学】："你要看 IPv6 的普及程度或未来发展趋势，你就看 DNS——没有 DNS 就没有现在的互联网。"（全球 1505/1527 个顶级域已支持 IPv6 解析，98.6%）

**过渡技术三式**：
| 技术 | 原理 | 比喻 |
|---|---|---|
| 双栈 | 同时跑 IPv4+IPv6 两套协议栈，应用决定用哪套 | 双系统 |
| 隧道 | IPv6 孤岛穿越 IPv4 网络封装转发 | IE 阶段学 |
| NAT64 | 协议转换（不是地址转换），IPv6 报文↔IPv4 报文 | — |

**IPv6 路由协议**：OSPFv3、IS-IS for IPv6、BGP4+、PIM——核心机制不变（OSPFv3=v2 学好即可；IS-IS 加 TLV；BGP4+ 换路由簇），只需掌握 IPv6 邻居配置。

### 2.2 地址格式、缩写规则与地址结构

**基本格式**：128 比特 → 16 进制书写，每 16 比特一组共 8 组，冒号分隔（7 个冒号），大小写不区分。**只有前缀表示法**（地址/前缀长度），没有子网掩码。

**两套缩写规则**（★高频考点）：
1. **段内省略前导零**：`0001`→`1`、`00FD`→`FD`、全零段→`0`；只能省前导零，后置零不能省（`1000` 不能缩）
2. **连续全零段缩写为 `::`**：一个或多个连续全零段统一用 `::`；**整个地址最多一个 `::`**（两个则无法唯一反推，地址非法）

**地址结构**：网络前缀（=网络号，同前缀=同网段）+ 接口标识（=主机号）。运营商分配前缀给企业（一般 /48），企业内部分子网，终端自己定接口标识。

### 2.3 Interface ID 三种生成方式与 EUI-64 规范

| 方式 | 原理 | 适用 |
|---|---|---|
| 手动配置 | 管理员指定 | 管理性要求强 |
| 系统自动生成 | OS 私有算法生成局域网唯一 ID | 终端即插即用（Windows 不用 EUI-64 防 MAC 泄露隐私） |
| **EUI-64** | MAC 48bit 中间插入 `FFFE`→64bit，第 7 比特取反 | 网络设备（交换机/路由器） |

**EUI-64 坑点（★高频易错）**：
- **前缀=64**：完美匹配
- **前缀<64**（如 /48）：华为用零填充空缺的 16bit（接口标识=128-48=80bit，EUI-64 只生成 64bit，剩 16bit 自动补零）
- **前缀>64**：华为**不允许**报错；思科允许（取 EUI-64 后段补上）
- 【设计本源与技术哲学】："就很多人在这里面会掉到自己的思维误区里面去。"

### 2.4 IPv6 地址三大类型与五类单播

**三大类型**：单播（Unicast）、组播（Multicast）、任播（Anycast）——**无广播地址**（用组播替代广播效果）。Interface ID 全 1 在 IPv6 是可用单播地址（可配在接口上），全 0 代表网络号不能配。

**五类单播地址**：

| 类型 | 前缀 | 核心特征 |
|---|---|---|
| **未指定地址** | `::` | 全零，不能配在接口上 |
| **环回地址** | `::1` | 本机测试 |
| **链路本地地址** | `FE80::/10`（★不是 /64！） | 自动生成、仅链路内通信、**不具备路由能力**；ping 必须指定出接口 |
| **全球单播 GUA** | `2000::/3` | 公网地址；运营商 /48 → 16bit 子网 ID → /64 接口 ID |
| **唯一本地 ULA** | `FC00::/7` | 40bit Global ID 随机哈希生成→理论上全球唯一；类似 IPv4 私网但避免冲突 |

**链路本地地址详解**：
- 前缀 `/10`（FE80~FEBF 均属此范围，系统默认用 FE80 生成）
- 任何启用 IPv6 的三层接口自动生成（华为需先配一个 GUA 或 ULA 才连带生成，或手动 `ipv6 address auto link-local`）
- ping 链路本地地址**必须指定出接口**（所有接口都可能有相同 FE80 前缀）
- 【类比】无人机小队内部协同，外面的人不知道——安全性高

**GUA 结构**：3bit 固定 + 45bit 全球路由前缀（/48）+ 16bit 子网 ID + 64bit 接口 ID。运营商给 /48 可划 65536 个 /64 子网。子网不够时以 4bit 为边界借位。

**ULA 结构**：8bit 固定 + 40bit Global ID（时间+系统标识 SHA-1 取低 40bit）+ 16bit 子网 ID + 64bit 接口 ID。两公司合并不冲突——"唯一性管理就简单"。NAT 在 IPv6 原则上不推荐（破坏端到端对等通信），但保留客户自选。

### 2.5 组播地址、组播 MAC 与被请求节点组播

**组播地址**：`FF00::/8`（前 8bit 全 1）。结构：8bit 固定 + 4bit FLAG + 4bit SCOPE + 80bit 预留 + 32bit Group ID。
- **FLAG**：0000=永久（如 FF02::5 给 OSPFv3）；0001=临时（可回收）
- **SCOPE**（传播范围）：1=接口本地（不出网卡）、2=链路本地、5=站点本地、8=组织本地、E=全局

**常见组播（★必记）**：
| 地址 | 含义 |
|---|---|
| `FF02::1` | 链路所有节点（替代广播） |
| `FF02::2` | 链路所有路由器 |
| `FF02::5` / `FF02::6` | OSPFv3 DR / BDR |
| `FF02::9` | RIPng |
| `FF02::D` | PIM |

**组播 MAC**：`33:33` + 组播 IPv6 低 32bit，直接映射无需 ARP。如 FF02::5 → `33:33:00:00:00:05`。

**被请求节点组播（★核心机制）**：`FF02::1:FF`（前 104bit 固定）+ 单播地址低 24bit。
- **两大用途**：①替代 ARP 完成 MAC 地址解析 ②地址冲突检测（DAD）
- **优势**：只有目标主机（监听该组播）才处理，其他主机网卡直接丢弃不送 CPU——"不浪费他人的生命"，增强安全性
- 【设计本源与技术哲学】："利用这个地址做解析，不监听这个组的主机在网卡就丢了，根本不需要送给 CPU。"

### 2.6 任播与 IPv6 报文头

**任播**：本质是单播地址——在不同位置多台服务器配相同单播地址，路由选最近路径到达。简化全球部署（DNS 只需解析一个地址）。现状：太依赖运营商，"谁的地盘谁做主"，未大面积部署。

**IPv6 报文头（★固定 40 字节）**：
- Version、Traffic Class（QoS）、Flow Label（流标签，新增字段，与源地址区分流——"为未来创新留下空间"，尚无具体应用）
- Payload Length（=扩展头+上层数据，不含基本头）、Next Header（下一个包头类型：扩展头或上层协议号 TCP=6/UDP=17）、Hop Limit（防环类似 TTL）
- Source/Destination Address 各 128bit

**相比 IPv4 优化**：去掉包头长度（固定无需声明）、分片字段（用扩展头，无需分片不携带→提高性能）、校验和（链路层/传输层已有，"网络层校验躺平了"）、总长度（只携载荷长度）。扩展包头 7 种通过 Next Header 链式串联。

### 2.7 ICMPv6：差错与通知

**协议号 58**。类型分两大类：**0-127 = 差错消息**（目标不可达/数据包过大/TTL 超时/包头错误）；**128-255 = 通知消息**（测试诊断等）。

**类型 1（目标不可达）代码**：0=无路由、1=管理策略禁止（ACL）、2=超出源地址范围、3=地址不可达（二层解析不出 MAC）、4=端口不可达。

**路径 MTU 发现（PMTU）**：IPv6 路由器**默认不分片**（分片由源主机负责）。机制：源主机按 1500 发→中途路由器发现超 MTU→回"数据包过大"ICMPv6 携带自身出口 MTU→源主机按新值重发→迭代找到路径最小 MTU。

### 2.8 NDP 协议：五报文八功能

**五类报文**：133=RS（路由器请求）、134=RA（路由器公告）、135=NS（邻居请求）、136=NA（邻居公告）、137=重定向。

**八大功能**：路由器发现、前缀发现/SLAAC、DAD、地址解析、邻居状态跟踪、前缀重编址、参数发现、重定向。

**RA 报文核心功能（三合一）**：路由器发现（定位网关）、前缀发现（SLAAC 获取地址）、参数发现（如缺省跳数 64）。
- RA 源地址=路由器**链路本地地址**，目的=`FF02::1`
- 华为默认关闭 NDP：`undo ipv6 nd ra halt` 开启（"不杀死 RA = 让 RA 活着"）
- 发送间隔：华为 200~600 秒随机值

**SLAAC 全流程**：链路本地地址生成→DAD→发 RS→路由器回 RA 带前缀→主机生成 GUA→DAD→正式使用。
- PC 端：`ipv6 address auto global default`（`global`=SLAAC 生成 GUA，`default`=同时获取网关）
- **多网关负载分担**（★IPv6 天生支持，IPv4 需 VRRP）：两网关同优先级发 RA→主机自动生成两条缺省路由；改高优先级→主机优选；失效自动切换
- SLAAC 限制：仅支持 64 位前缀发布

### 2.9 地址解析（NS/NA 替代 ARP）

PC1 发 NS：源=同前缀 GUA，目的=目标主机单播对应的**被请求节点组播地址**，携带自身 MAC 和目标 IP。只有目标主机处理，其他丢弃。PC2 回单播 NA 携带自身 MAC，完成解析。

【★HCIE 面试必死题】"接口有多个 IPv6 地址时，用与目标地址**同前缀**的地址作为 NS 的源地址；前缀不同则直接查路由表不需要解析。"报文携带核心地址说错="欢迎下次光临"。

### 2.10 邻居状态机

| 状态 | 含义 |
|---|---|
| INCOMPLETE | 解析未完成/邻居不可达 |
| REACHABLE | 解析成功且 30 秒内有交互 |
| STALE | 超过 30 秒无使用，陈旧但可用 |
| DELAY | STALE 下发数据后发 NS 探测，5 秒内有回应→REACHABLE |
| PROBE | DELAY 超时，每秒发 NS 连发 3 次，有回应→REACHABLE，无→INCOMPLETE |

IPv4 ARP 缓存只有老化无维护；IPv6 万物互联需要**缓存探测与跟踪机制**——"信息可靠真实"才用。

### 2.11 DAD、重定向、M/O 标志位与前缀生命周期

**DAD（重复地址检测）**：接口启用任何单播地址前做 DAD——用全零地址作源，向新地址的被请求节点组播发 NS。无 NA 回应=可用；有 NA=冲突弃用。临时地址概念：DAD 通过前不能通信，"产品没通过质检不能出厂"。

**重定向五条件（全满足才做）**：①目标非组播 ②源 IP 与网关接口 IP 同网段 ③路由下一跳出接口=接收接口 ④下一跳与源同网段 ⑤邻居缓存有源主条目。R1 发 137 重定向给 PC1，PC1 缓存去 PC2 下一跳=R2。链路本地地址在此体现优势：稳定不变，"优点都在细节里"。

**M/O 标志位**：
| M | O | 含义 |
|---|---|---|
| 0 | 0（默认） | 纯 SLAAC |
| 0 | 1 | SLAAC 获取地址 + DHCPv6 获取其他参数（如 DNS） |
| 1 | 1 | 完全由 DHCPv6 分配（有状态） |

**前缀生命周期**：优先存活时间（可发起新连接）和有效存活时间（可接受连接不能发新连接）。每收到 RA 时间复位——持续发前缀=地址一直可用，不发才会老化。类比停水通知——有缓冲期业务不中断。

### 2.12 DHCPv6：有状态分配与 PD 前缀代理

**DHCPv6 vs SLAAC**：SLAAC 只分前缀不分 DNS；DHCPv6 分地址+DNS+NIS+SNTP 等，功能更精细。

**时间参数**：有效时间（≥3h）、优选时间（≥2h）、T1=优选×0.5（发 Renew 续约）、T2=优选×0.8（发 Rebind 重绑定）。

**四步标准交互**：Solicit→Advertise→Request→Reply。端口：客户端 UDP 546、服务器 UDP 547。Solicit 目标=`FF02::1:2`（链路所有 DHCPv6 服务器/中继）。**两步快速交互**：Solicit 携带 Rapid Commit→直接 Reply（仅单服务器环境）。

**无状态 DHCPv6**：客户端已有地址，仅获取 DNS 等→发 Information-Request，服务器回 Reply，不记录状态。

**中继**：客户端与服务器跨网段时，网关设备充当中继封装 Relay-Forward 报文，与服务器间路由必须可达（单播通信）。

**PD 前缀代理（★核心难点）**：
- 层次化地址分配：下游向上游申请前缀，拿到后再细分 /64 给直连终端
- 服务器配 /60 基准前缀，assign /62→分 4 个 /62 子网给下游
- 客户端 `dhcpv6 pd myprefix` 申请→在终端接口 `ipv6 address myprefix ::1::/64` 细分
- 关键理解：前面固定比特不动，后面借位划分——"完全就是子网划分问题"
- 运营商用得多，企业网用得少

### 2.13 OSPFv3 基础配置

```bash
ospfv3 1
 router-id 1.1.1.1                      # 必须手动配（IPv4 点分十进制）
interface GigabitEthernet0/0/0
 ospfv3 1 area 0                        # 接口下直接启用（无 network 命令，类似 IS-IS）
```

### 2.14 华为设备 IPv6 基础使能与 SLAAC/DHCPv6 验证模板（VRP 实战）

#### 1. IPv6 基础全局与接口使能模板

```shell
# ═══ 1. 全局开启 IPv6 协议栈 ═══
[R1] ipv6                                               # 全局启用 IPv6 转发功能（必配）

# ═══ 2. 接口 IPv6 编址三方式 ═══
[R1] interface GigabitEthernet 0/0/1
[R1-GigabitEthernet0/0/1] ipv6 enable                   # 接口启用 IPv6 功能
# 方式 A: 手工配置全球单播地址 (GUA)
[R1-GigabitEthernet0/0/1] ipv6 address 2001:DB8:1::1 64 
# 方式 B: 基于 EUI-64 规范自动生成后缀（MAC 插 FFFE 且第 7 比特反转）
[R1-GigabitEthernet0/0/1] ipv6 address 2001:DB8:2:: 64 eui-64
# 方式 C: 自动生成链路本地地址 (Link-Local，前缀 FE80::/10)
[R1-GigabitEthernet0/0/1] ipv6 address auto link-local
[R1-GigabitEthernet0/0/1] quit

# ═══ 3. SLAAC 无状态自动配置通告 ═══
[R1] interface GigabitEthernet 0/0/2
[R1-GigabitEthernet0/0/2] ipv6 enable
[R1-GigabitEthernet0/0/2] ipv6 address 2001:DB8:10::1 64
[R1-GigabitEthernet0/0/2] undo ipv6 nd ra halt          # ★华为默认禁用发送 RA 报文，必须显式开启！
[R1-GigabitEthernet0/0/2] ipv6 nd autoconfig managed-address-flag   # M 位置 1：通知终端使用 DHCPv6 分配有状态 IP
[R1-GigabitEthernet0/0/2] ipv6 nd autoconfig other-flag             # O 位置 1：通知终端使用 DHCPv6 分配 DNS 等其他参数
[R1-GigabitEthernet0/0/2] quit
```

## 三、总结

**核心重点十带走**：
1. IPv6 = 128 位地址空间，固定 40 字节包头，无子网掩码只有前缀表示法，无广播只有单播/组播/任播三类。
2. 两套缩写规则：段内省略前导零 + 连续全零段缩写为 `::`（全地址最多一个 `::`，两个=非法）。
3. EUI-64：MAC 48bit 插 FFFE→64bit + 第 7 比特取反；前缀=64 完美匹配，<64 补零，>64 华为不支持。
4. 五类单播：链路本地（FE80::/10 不路由 ping 要指定出接口）、GUA（2000::/3）、ULA（FC00::/7 全球唯一随机 ID）、环回（::1）、未指定（::）。
5. 组播 FF00::/8（FLAG+SCOPE+GroupID），MAC=33:33+低 32bit；被请求节点组播 FF02::1:FF+低 24bit 替代 ARP 且增强安全。
6. NDP 五报文（RS/RA/NS/NA/重定向）八功能；SLAAC 全流程（RS→RA 带前缀→GUA 生成→DAD）；多网关负载分担 IPv6 天生支持。
7. NS/NA 地址解析：源=同前缀 GUA，目的=被请求节点组播，携带自身 MAC——HCIE 面试说错"欢迎下次光临"。
8. 邻居状态机五态（INCOMPLETE→REACHABLE→STALE→DELAY→PROBE）；DAD 用全零源地址发 NS 检测冲突。
9. M/O 标志位三组合（00=纯 SLAAC、01=SLAAC+DHCPv6 参数、11=完全 DHCPv6）；前缀生命周期双时间每收 RA 复位。
10. DHCPv6 四步交互（Solicit/Advertise/Request/Reply，端口 546/547）、两步 Rapid Commit（仅单服务器）、PD 前缀代理层次化分配（/60→/62→/64 借位划分）。

**落地注意事项**：华为设备必须先配一个 GUA/ULA 才会连带生成链路本地地址（或手动 `auto link-local`）；`undo ipv6 nd ra halt` 是 SLAAC 实验第一步，忘记则主机拿不到前缀；SLAAC 不加 `default` 参数主机只有 IP 没有网关；PD 前缀长度差值须 ≤16；华为要求接口有链路本地地址才能启用 DHCPv6 客户端；EUI-64 前缀 >64 华为报错，别拿思科的规则来配华为。

**学习建议**：IPv6 地址缩写规则务必手写练习——取一个 8 组全带零的地址，按两套规则逐步缩写直到完全压缩，再反向展开验证。EUI-64 实验必做：配一个 MAC 地址→手工推算 FFFE 插入+第 7 比特取反→与设备 `display ipv6 interface` 输出对比，一致才算掌握。SLAAC 双网关负载分担实验最能体现 IPv6 的"天生优势"——配两个 RA 源同优先级，在主机看两条缺省路由自动出现，改优先级观察主备切换，这比 VRRP 直观得多。PD 前缀代理是难点，在纸上画 /60 的二进制展开，标出借 2 位后 4 个 /62 子网的地址范围，再细分 /64 看每个子网的接口标识——画通即理解。学完本章，第 20 章（IPv6 路由协议）和第 21 章（IPv6 过渡技术）的地基就稳了。

## 附：本章术语速查表

| 术语缩写 | 英文全称 | 中文含义 | 关键作用 |
|---|---|---|---|
| **GUA** | Global Unicast Address | 全球单播地址 | 前缀 2000::/3，全球路由可达的公网 IPv6 地址，等价于 IPv4 公网 IP |
| **ULA** | Unique Local Address | 唯一本地地址 | 前缀 FC00::/7，私网使用的本地唯一 IPv6 地址，不向全球互联网通告 |
| **Link-Local** | Link-Local Address | 链路本地地址 | 前缀 FE80::/10，仅在单物理链路有效，用于邻居发现与动态路由下一跳 |
| **SLAAC** | Stateless Address Autoconfiguration | 无状态地址自动配置 | 终端通过监听路由器通告的 RA 报文前缀，自主生成全球单播地址实现即插即用 |
| **NDP** | Neighbor Discovery Protocol | 邻居发现协议 | 基于 ICMPv6 的控制协议族，替代 ARP 并提供路由通告、重定向与地址冲突检测 |
| **DAD** | Duplicate Address Detection | 重复地址检测 | 节点启用新 IPv6 地址前向被请求节点组播发送 NS 报文，探测是否存在冲突 |
| **PD** | Prefix Delegation | 前缀代理 | DHCPv6 客户端从上游服务器分级获取网络前缀并下发给本地下游接口的机制 |
