## 2. 背景与目标

### 2.1 业务背景与现状痛点

在大型智慧园区（如高校数字校园、三甲医院全互联院区、政企集团总部基地、高科技产业园）中，网络不仅要承载行政办公、科研开发、涉密财务，还需接入海量安防监控摄像头、IP 广播、医疗终端、智能电表等物联网（IoT）哑终端，并为外来访客提供可控的无线接入。传统基于“接入-汇聚-核心”的静态分层网络架构面临着四大结构性危机：

1. **“一网多用”与多业务硬隔离的天然冲突**：传统网络为了隔离办公、研发、安防与访客，通常依赖手工划分子网与堆砌 VLAN。不同业务在汇聚核心交织，二层广播域泛洪严重；若通过物理独立建网则硬件重复投资巨大、综合能耗极高，无法实现物理资产池化复用；
2. **“策略与 IP 强绑定”，移动办公权限管理崩溃**：传统安全控制依赖交换机或防火墙上的 IP ACL 规则。随着移动办公（BYOD）普及，员工在不同楼宇漫游或在 Wi-Fi 间切换时，IP 地址发生改变，原有的访问权限立刻失效；网络管理员被迫在全网数十台交换机上维护成千上万条冗余混乱的 ACL，“只敢加不敢删”，配置如同随时爆炸的屎山；
3. **现场设备开局人肉依赖重，纳管周期长**：园区包含数千台接入交换机与无线 AP，传统工程开局依赖技术人员手持 Console 线逐台刷命令，上线周期以周乃至月为单位，配置失误频发；
4. **海量 IoT 哑终端安全盲区与仿冒渗透**：监控摄像头、网络打印机、门禁刷卡机无法安装 802.1X 客户端，缺乏统一自动化的身份识别机制；黑客拔掉摄像头网线插上便携电脑即可非法接入内网，存在巨大的物理边界安全隐患。

### 2.2 建设目标

本设计旨在依托华为 **CloudCampus 大中型虚拟化园区网络解决方案**，采用先进的 **Fabric 架构** 与 **业务随行（Free Mobility）** 体系，打造一套池化、切片化、零信任自治的现代化云园区网络：

1. **物理资源池化与业务虚拟网络（一网多用，多 VN 硬隔离）**：统一构建高可靠、大带宽的 Underlay 物理承载矩阵，通过 VXLAN 技术切分出相互硬隔离的虚拟网络（VN_Office、VN_RD、VN_Security、VN_Guest），实现一套物理资产按需弹性切片承载全业务；
2. **Underlay 即插即用（PnP）全自动极简开局**：全网交换机与无线 AP 支持加电自愈开局，依靠 LLDP 协商 PnP VLAN、DHCP Option 148 引导 NETCONF/TLS 加密通道建立，实现全网分钟级图形化自动纳管；
3. **网关架构科学选型（集中式 vs 分布式）**：根据不同园区流量模型（南北向为主 vs 东西向密集），精准匹配集中式网关 Fabric 或分布式网关 Fabric，消除次优折返跑，保护核心交换机背板与 ARP 规格；
4. **业务随行与零信任权限治理（策略随人而动）**：用户网络权限与物理接入位置、VLAN、IP 彻底解耦；通过统一准入认证（802.1X/Portal/MAC）将用户划入安全组，通过全局二维策略矩阵进行可视化权限管控；在 VXLAN 报头直接注入源安全组 ID，实现目的端硬件级线速策略执行；
5. **IoT 哑终端智能指纹识别与策略联动**：通过 DHCP Option、HTTP UA 与 MAC OUI 自动比对指纹库，实现摄像头、打印机自动分类并动态下发接入策略，防止仿冒接入。

## 3. 用户与场景

### 3.1 涉及角色

| 角色代码 | 角色名称 | 核心关注点与职责 |
|:---|:---|:---|
| **ROLE-01** | **园区网络总架构师** | 负责 Fabric 拓扑选型、Underlay/Overlay 编址规范、多 VN 逻辑隔离与出口引流架构设计 |
| **ROLE-02** | **安全管理主管 / CISO** | 负责全网安全组划分、二维策略矩阵审批、准入异常逃生预案与跨 VN 访问合规审计 |
| **ROLE-03** | **工程实施与开局工程师** | 负责核心设备配置、DHCP Option 148 规划、批量导入设备 ESN/MAC 与现场 PnP 上线验收 |
| **ROLE-04** | **园区内部终端用户** | 包含内部行政、研发科研人员、后勤物联运维及外来访客，关注漫游体验与网络可达性 |

           |  Edge 节点 (汇聚)  |                                |  Edge 节点 (汇聚)  |

1. **科研人员跨楼栋无缝移动办公场景**：研发工程师张三在 A 楼通过 802.1X 认证接入，被赋予安全组 10；下午携带笔记本漫游到 B 楼接入 Wi-Fi，IP 地址自动变更为 B 楼网段，但系统依然判定其属于安全组 10，其访问研发代码服务器的权限毫秒级平滑跟随，无任何鉴权打断；
2. **海量安防摄像头即插即用场景**：保卫处新采购 200 台网络摄像头，安装工人物理插网线通电，交换机自动提取 DHCP Option 60 厂商指纹，控制器识别为“海康监控”，自动将端口加入安防监控 VN 并关联摄像头安全组，严禁其访问任何外网与办公网；
3. **多租户业务硬隔离与互联网共享直出场景**：财务 VN 与研发 VN 相互之间在二三层彻底物理级硬隔离；两者的公网出海流量统一汇总至 Border 核心，通过虚拟防火墙（VSystem）或独立安全区域执行 NAT 转换后受控直通互联网。

|:---|:---|:---|:---:|:---|:---:|

| **FR-02** | **多 VN（虚拟网络）硬切片隔离** | 统一物理 Fabric 必须切分为至少四大业务虚拟网络：`VN_Office`（办公）、`VN_RD`（研发）、`VN_Security`（监控）、`VN_Guest`（访客）。各 VN 分配独立的 VPN-Instance 与专属 VNI | **P0** | 1. 验证各 VN 之间路由默认彻底隔离，私网 Ping 不通；<br>2. 支持不同 VN 使用相同私网 IP 地址段而互不冲突。 | 第31章虚拟化园区规范 |
| **FR-03** | **Underlay PnP 自动化开局** | 全网交换机加电开箱即用：接入层利用 LLDP 协议自动协商 PnP VLAN（默认 3996 或 VLAN 1）；通过核心设备提供的 DHCP 获取管理 IP 与 Option 148 参数（提取控制器 IP/端口 18020），建立 NETCONF/TLS 加密通道自动纳管 | **P0** | 1. 模拟全新空配交换机上电，在 $<5\text{ min}$ 内自动被控制器发现并纳管；<br>2. 拓扑图自动还原物理连线。 | 第31章虚拟化园区规范 |
| **FR-04** | **网关架构按需灵活选型** | 系统必须支持根据园区流量特征选择网关模型：南北向外联流量占比 $>80\%$ 的中型园区采用**集中式网关 Fabric**（网关在 Border）；东西向互联密集的大型园区采用**分布式网关 Fabric**（网关下沉至 Edge，消除次优折返跑） | **P0** | 1. 集中式网关下，跨子网流量由 Border 集中路由；<br>2. 分布式网关下，同 Edge 跨子网流量在本地芯片内直接线速路由。 | 第31章虚拟化园区规范 |
| **FR-05** | **准入控制三剑客全场景覆盖** | 支持企业员工有线/无线采用 **802.1X 认证**；外来访客与临时人员采用 **Portal（Web 弹窗）认证**；海量无交互哑终端采用 **MAC 地址认证**；支持无线“MAC 优先的 Portal 认证”实现首次网页鉴权、二次无感秒连 | **P0** | 1. 员工 PC 通过 802.1X 输入域账号认证通过；<br>2. 手机连接 Wi-Fi 自动弹出 Portal 网页；<br>3. 打印机插线自动触发 MAC 认证放行。 | 第30章业务随行规范 |
| **FR-06** | **业务随行安全组体系设计** | 必须建立清晰的安全组模型：支持手工绑定的静态安全组（用于固定服务器）、认证通过后动态下发授权的动态安全组（用于员工/部门）、未认证阻断的未知组（Unknown）与服务器宕机时的逃生组（Bypass） | **P0** | 1. 登录控制器可配置不同安全组；<br>2. 用户认证通过后，`display access-user` 准确显示匹配的 Security Group ID。 | 第30章业务随行规范 |
| **FR-07** | **全局二维策略矩阵管控** | 全网安全策略必须从繁琐的 IP ACL 升级为“**源安全组 $\rightarrow$ 目的安全组**”的可视化二维策略矩阵；支持对单元格配置允许（Permit）、拒绝（Deny）及特定 QoS 限速动作 | **P0** | 1. 策略矩阵中配置“研发组 $\rightarrow$ 财务服务器 = 拒绝”；<br>2. 研发人员无论拿到何种 IP，均被交换机硬件线速阻断访问财务网段。 | 第30章业务随行规范 |
| **FR-08** | **VXLAN 原生携带安全组硬件执行** | 在 Fabric 网络中，源端 Edge 将认证用户安全组 ID（Group ID）直接注入 VXLAN 报头的保留字段；报文送达目的端 Edge 解封装时，目的设备直接读取源组 ID 并在芯片内匹配策略矩阵执行过滤，全网转发性能最优 | **P0** | 1. 抓包验证 VXLAN 报头保留字段携带了用户 Group ID；<br>2. 策略执行完全在目的端交换机硬件线速完成，无需向控制器频繁查询。 | 第30章业务随行规范 |
| **FR-09** | **IoT 哑终端指纹识别与策略联动** | 接入交换机必须能够抓取终端报文中的 DHCP Option 55/60、HTTP User-Agent、MAC OUI 指纹上报控制器；控制器比对内置指纹库识别设备类型后，协同交换机下发策略联动，自动划入隔离安全组 | **P1** | 1. 接入主流品牌摄像头，控制器指纹识别准确率达 100%；<br>2. 端口自动应用安全组受限访问策略，严禁其横向扫描内网。 | 第31章虚拟化园区规范 |
| **FR-10** | **准入高可用应急逃生设计** | 当发生骨干光缆中断导致认证服务器（RADIUS / iMaster NCE）全部失联宕机时，接入/汇聚设备必须能够感知异常并自动触发“逃生机制”，将新接入终端临时划入逃生组或逃生 VLAN，放行基础办公与 DNS 访问 | **P0** | 1. 人为阻断认证服务器 IP，验证交换机在超时后自动转入逃生状态；<br>2. 终端仍能正常获取 IP 并访问外网基础办公系统，严防全网断网。 | 第30章业务随行规范 |

### 4.2 非功能需求（Non-Functional Requirements）

| 需求编号 | 分类 | 指标与要求 | 验收方式 |
|:---|:---|:---|:---|
| **NFR-01** | **高可靠性** | 核心层（Border）与汇聚层（Edge）必须采用双节点集群（CSS/iStack/M-LAG）与多链路聚合冗余；单节点宕机收敛时延 **$<200\text{ ms}$** | 拔掉核心单台交换机电源，观察音视频会议与业务长连接不中断 |
| **NFR-02** | **表项规模** | 核心 Border 交换机必须支持至少 **50,000+ 主机 ARP 与 MAC 表项**；支持单 Fabric 纳管 1,000+ 台交换机与 3,000+ 台无线 AP | 导入仿真资产库进行满载规格压测 |
| **NFR-03** | **MTU 适配** | Underlay 全网物理交换机物理互联接口 MTU 必须强制调整为 **`9216`（Jumbo Frame）**，彻底消除 VXLAN 50 字节额外封装引发的分片与静默丢包 | 终端发送带 DF 置位的 1500 字节大包，全链路无分片平稳通过 |
| **NFR-04** | **漫游性能** | 无线终端在全园区同业务跨 AP 漫游时，漫游切换丢包率控制在 **0 丢包**，切换时延 **$<50\text{ ms}$**，语音通话无卡顿 | 工程师手持移动终端进行跨楼栋漫游通话压力测试 |

## 7. 风险与开放问题

### 7.1 现网潜在风险与规避策略
1. **老旧非智能交换机不支持 VXLAN 风险**：利旧改造项目中，部分老旧接入交换机不支持 VXLAN 封装或硬件 TCAM 不足。
   - **规避方案**：采用“Edge 网关上移至汇聚层 + 接入层纯做二层透传”的混合策略联动方案，老旧接入交换机仅透传 VLAN Tag，由汇聚交换机代为执行 VXLAN 封装与安全策略。
2. **移动终端 MAC 地址随机化导致准入失效风险**：现代智能手机（iOS/Android）默认启用随机 MAC 特性，导致 MAC 优先 Portal 无法识别老用户。
   - **规避方案**：通过 Portal 页面提示用户关闭“专用无线局域网地址（私有 MAC）”，或改用 802.1X 账号密码强认证。

### 7.2 开放问题与进阶工程探索
1. **超大规模园区跨多 Fabric 互联（Fabric-to-Fabric）**：本课主要围绕单 Fabric 矩阵展开，对于跨城多个超大型 Fabric 之间通过骨干网进行业务随行安全组端到端无损透传的高阶实现未深入展开；
2. **高校校园网 BNG/BRAS 设备与 VXLAN 的深度穿透**：课程提及方案 6 支持 PPPoE 穿透 VXLAN 完成认证，但针对运营商级大并发 BRAS 计费与策略矩阵深度协同的细节未深入展开。
