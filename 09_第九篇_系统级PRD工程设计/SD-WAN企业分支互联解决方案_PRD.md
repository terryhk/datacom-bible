## 2. 背景与目标

### 2.1 业务背景与现状痛点

在企业跨地域多分支互联与业务全面上云（SaaS、公有云、私有云数据中心）的数字化转型过程中，传统的专线网络架构面临着三大难以承受的商业与技术瓶颈：

1. **专线资费极其昂贵，带宽扩展成本畸高**：传统企业广域网高度依赖运营商 MPLS 专线或 MSTP 数字电路。MPLS 专线的单位带宽资费通常是普通商业宽带的 10 至 20 倍以上。随着高清视频会议、协作办公和大流量数据同步的普及，专线带宽捉襟见肘，企业每年需背负数百万乃至上千万元的专线租用开支；
2. **专线业务开通与扩容周期漫长**：国内跨省 MPLS 专线通常需要 30 天以上的商务流程与光纤施工周期，国际跨国专线开通周期更是高达 90 天。传统网络变更与新分支建设速度严重滞后于企业业务扩张步伐；
3. **多链路利用率严重失衡与云业务次优绕行**：传统分支多采用“主用专线 + 备用专线/宽带”模式，由于缺乏智能选路机制，备用链路常年处于闲置状态，造成近 50% 的网络带宽资产浪费；同时，所有分支流量均需强制绕行总部数据中心才能访问公网和 SaaS 云应用，引入大量次优时延与网络抖动；
4. **现场部署依赖高成本人肉运维**：新网点开局必须由专业网络工程师携带 Console 线出差到现场，满省或跨国奔波，差旅与人力成本高昂，且手工配置极其容易出现失误。

### 2.2 建设目标

本方案旨在利用软件定义广域网（SD-WAN）架构，构建一套软硬件解耦、云化集中管控、自动化开局与应用级智能调度的下一代广域承载网络：

1. **混合多链路聚合（Hybrid WAN 降本增效）**：将昂贵的 MPLS 专线、廉价的 Internet 宽带（光纤/PPPoE）以及 4G/5G 蜂窝网络统一池化，实现全链路双活与动态负载均衡，降低企业 50%~70% 的专线综合支出；
2. **全网极速零配置开局（ZTP）**：支持**邮件开局（URL 签名 Token）**、DHCP Option 148 开局与 U 盘开局，实现现场非技术人员“通电插线即上线”，分支开通时间从 30 天缩短至数分钟；
3. **基于应用与 SLA 的智能选路（体验保障）**：通过深度包检测（DPI/SAC）精确识别企业关键应用，结合底层链路的时延、抖动、丢包率等实时 SLA 质量，将关键业务（语音、视频会议、核心 ERP）智能引流至优质链路，链路劣化时毫秒级无感切换，恢复后平滑回切；
4. **全网端到端安全与多租户切片隔离**：Overlay 数据通道全量采用高强度 IPsec 加密传输，支持多部门/多业务（VN / VRF）二三层安全隔离。

## 3. 用户与场景

### 3.1 涉及角色

| 角色代码 | 角色名称 | 核心关注点与职责 |
|:---|:---|:---|
| **ROLE-01** | **企业网络架构师 / CIO** | 关注全网 TCO（总体拥有成本）降幅、跨国跨分支网络 SLA 保障率、核心业务容灾可用性 |
| **ROLE-02** | **NOC 监控中心运维主管** | 关注 iMaster NCE 全局大屏健康度、全网链路告警、各站点应用流量占比与吞吐报表 |
| **ROLE-03** | **分支机构现场行政人员** | 零 IT 背景，负责分支现场 CPE 设备的物理上架、插网线与点击开局邮件中的激活链接 |
| **ROLE-04** | **业务终端用户（内部员工）** | 关注音视频会议清晰流畅不卡顿、跨分支数据访问时延低、云端办公协同无感知切换 |

### 3.2 典型用例与部署场景

```
[场景 1: Hub-Spoke 集中式互联] ──> 分支 CPE ──(IPsec Overlay)──> 总部 Hub CPE ──> 总部数据中心 / 内网服务器
[场景 2: 分支直访云端 (Direct Internet Access)] ──> 分支 CPE ──(本地下沉)──> 本地 Internet 出口 ──> SaaS / 公有云
[场景 3: 分支间动态直连 (DSVPN / Mesh)] ──> 分支 A CPE ══(动态协商 IPsec)══> 分支 B CPE (大流量跨分支协同)
```

1. **总部与多分支企业专网（Hub-Spoke）**：大型连锁商业、金融网点、集团分支机构，所有分支通过双链路（MPLS+Internet）与总部 Hub 互联，由 RR 集中下发路由，数据通过 IPsec 加密隧道互访；
2. **本地 Internet 分流直出（DIA，Direct Internet Access）**：普通网页浏览、外部文件下载与公共 SaaS 流量直接在分支 CPE 本地解封装走 Internet 出口，避免绕行总部骨干；
3. **跨地域大流量分支点对点直连（Full-Mesh / 动态按需打洞）**：两个生产研发分支之间若发生频繁的高清协同设计或海量数据库同步，两端 CPE 动态按需建立 IPsec 隧道，直接端到端传输，流量不经过总部二次中继。

## 4. 需求清单

### 4.1 功能需求（Functional Requirements）

| 需求编号 | 需求名称 | 详细描述 | 优先级 | 验收要点 | 规范归属 |
|:---|:---|:---|:---:|:---|:---:|
| **FR-01** | **四大通信通道独立编排** | 系统必须严格分离四大逻辑通信平面：① 管理通道（NETCONF over TLS 18020）、② 控制通道（BGP EVPN TCP 179）、③ 数据通道（动态 IPsec/GRE）、④ SLA 遥测通道（NQA/BFD 探针） | **P0** | 1. 抓包确认管理通道采用 TLS 加密；<br>2. CPE 与 RR 正常建立 BGP EVPN 对等体；<br>3. 数据流抓包显示为 ESP 加密封装。 | 第32章 SD-WAN 架构规范 |
| **FR-02** | **ZTP 邮件开局 (URL/Token)** | 支持非专业人员通过电子邮件完成 CPE 开局：控制器生成携带私钥签名 Token 与有效期时间戳的专用 URL；现场终端连入 CPE 初始 Wi-Fi/LAN 后点击 URL，将信息推送给 CPE，CPE 自动发起注册并完成配置加载 | **P0** | 1. 邮件中提取的 Token 具有防篡改签名与失效时间；<br>2. 现场仅通过点击链接完成整机上线，耗时 $<5\text{ min}$；<br>3. 控制器显示站点自动转为“在线”状态。 | 第32章 SD-WAN 架构规范 |
| **FR-03** | **ZTP DHCP 与 U 盘开局** | 支持通过运营商 DHCP Option 148 自动获取控制器 IP 与端口上线；支持在无网络孤岛场景下，将加密开局配置拷入 U 盘插入设备 USB 口自动解析刷机开局 | **P1** | 1. DHCP Option 148 正确解析控制器 IP 与端口；<br>2. 插入 U 盘后设备自动加载并执行配置。 | 第32章 SD-WAN 架构规范 |
| **FR-04** | **BGP EVPN 与 RR 路由反射** | 控制平面必须部署路由反射器（RR），各 CPE 仅需与 RR 建立 BGP EVPN 邻居。由 RR 负责反射跨站点的私网路由、TLOC 传输位置与 IPsec 密钥参数，免去全网 $N(N-1)/2$ 邻居爆炸问题 | **P0** | 1. 验证 CPE 上只有与 RR 的 EVPN 邻居；<br>2. CPE 能够通过 RR 学习到远端站点的私网路由与 TLOC；<br>3. RR 支持主备高可用部署。 | 第32章 SD-WAN 架构规范 |
| **FR-05** | **SAC / DPI 深度应用识别** | CPE 转发平面必须集成深度报文检测引擎，能基于报文特征码、域名、TLS SNI 等信息识别数千种企业级应用（如区分腾讯会议视频流、语音流、Office 365 与网页下载） | **P0** | 1. 运行 `display application-statistic` 能够准确识别常见视频会议与企业软件流量；<br>2. 能够针对未知流量归入默认应用类别。 | 第32章 SD-WAN 架构规范 |
| **FR-06** | **多维度实时 SLA 质量探测** | CPE 设备之间必须通过轻量级 NQA/BFD 探针，对所有活动的物理链路持续进行实时质量探测，采集三大核心指标：往返时延（Delay）、抖动（Jitter）与丢包率（Packet Loss Ratio） | **P0** | 1. 探针采样周期支持毫秒级配置；<br>2. 控制台及 CLI 能实时刷新每条链路的 SLA 数据。 | 第32章 SD-WAN 架构规范 |
| **FR-07** | **基于应用与 SLA 的智能选路** | 系统必须支持管理员自定义智能选路策略：为特定应用配置 SLA 门限（如视频流要求：时延 $<50\text{ ms}$，丢包率 $<1\%$）；主用路径满足条件时优先走 MPLS 专线，劣化时**毫秒级无感切换至备用 Internet 链路** | **P0** | 1. 链路正常时，视频流量 100% 命中 MPLS；<br>2. 人为增加丢包率后，流量在 $<1\text{ s}$ 内自动切换至 Internet，视频通话不中断。 | 第32章 SD-WAN 架构规范 |
| **FR-08** | **防震荡回切机制 (WTR)** | 当主用链路故障恢复、SLA 重新达标时，系统严禁立即切回，必须启动“恢复等待时间（Wait to Restore, WTR）”定时器（如观察稳定 5 分钟），确认无抖动后再平滑切回主用专线 | **P1** | 1. 主链路恢复瞬间流量不发生抖动切换；<br>2. 达到设定的 WTR 观察时长后，流量平滑迁移回主用链路。 | 第32章 SD-WAN 架构规范 |
| **FR-09** | **多租户业务虚拟网络 (VN) 隔离** | 支持在单一物理 SD-WAN 基础设施上切分多个业务虚拟网络（VN）。每个 VN 绑定独立的 VPN-Instance（VRF），各部门（如研发、财务、访客）数据路由硬隔离 | **P1** | 1. 验证不同 VN 间私网 IP 冲突时路由互不干扰；<br>2. 跨 VN 通信必须经由总部防火墙安全策略受控放行。 | 第32章 SD-WAN 架构规范 |
| **FR-10** | **双 CPE 与双链路高可用冗余** | 总部与大型分支必须支持双 CPE 设备热备与双归属上行链路冗余。当单台 CPE 宕机或单条上行物理光缆中断时，设备依靠 VRRP/VGMP 协议在微秒级实现本端故障倒换 | **P1** | 1. 拔掉单台 CPE 电源，全网业务流量切换时延 $<200\text{ ms}$；<br>2. 备用 CPE 接管后控制通道与数据通道无缝重连。 | 第32章 SD-WAN 架构规范 |

## 5. 方案与架构概述

### 5.1 四层分层逻辑架构

```
                 +-------------------------------------------------+
                 |            1. 业务呈现层 (UI / Portal)           |
                 |  (可视化大屏 / 租户管理 / 业务模板 / 报表审计)     |
                 +------------------------+------------------------+
                                          │ RESTful API
                 +------------------------▼------------------------+
                 |       2. 网络控制层 (iMaster NCE 控制器)         |
                 | (设备 ZTP 纳管 / 拓扑编排 / 选路与安全策略集中计算) |
                 +------------+-----------------------+------------+
                              │ NETCONF/TLS           │ NETCONF/TLS
                              ▼                       ▼
    +------------------------------------+   +------------------------------------+
    |      3. 控制协同层: 路由反射器 RR   |   |      3. 控制协同层: 路由反射器 RR   |
    |      (云端/总部部署, BGP EVPN 路由)  |   |      (冗余热备, 跨站点私网路由分发)  |
    +-----------------+------------------+   +------------------+-----------------+
                      │                                         │
                      │ 控制通道 (BGP EVPN)                      │ 控制通道 (BGP EVPN)
    ══════════════════╪═════════════════════════════════════════╪══════════════════
                      │                                         │
        +-------------▼------------+               +------------▼-------------+
        |  4. 数据转发层: 总部 CPE  |<=== 数据通道 ===>|   4. 数据转发层: 分支 CPE   |
        |  (双网关, IPsec 硬件加解密)|  (动态 IPsec)  |   (SAC 应用识别/智能选路)   |
        +--------------------------+               +--------------------------+
```

### 5.2 核心机制与关键技术选型

1. **Overlay 控制平面选型（BGP EVPN）**：
   - 彻底取代传统繁琐的点对点静态配置与私有协商信令，采用工业级标准 **BGP EVPN（AFI 25 / SAFI 70）**；
   - 携带扩展的 TLOC 属性（包含站点 System-IP、Color 色彩标记与 Encapsulation 封装类型）；
   - 通过 RR 实现跨站点私网路由按需反射，兼顾超大规模网络的横向扩展能力；
2. **数据平面加密选型（动态 IPsec 隧道）**：
   - 转发面统一采用标准 IPsec 协议（ESP 封装 + SHA256/AES 算法）；
   - 支持 NAT 穿越（NAT-Traversal，UDP 4500 封装），确保分支即使位于运营商多层 CGNAT 内部，亦能自主与公网及总部建立加密通道；
3. **ZTP 邮件开局安全鉴权设计**：
   - 采用非对称加密签名机制，URL 包含控制器公钥签名的数字凭证；
   - 签名内联设备唯一 ESN、管理员授权时间窗口，防止凭据泄露引发的重放攻击与非法设备冒用；
4. **混合链路流量编排策略矩阵**：

```
+------------------+-----------------------+--------------------+-----------------------+
| 业务类型         | 应用示例              | SLA 保障要求       | 正常主用链路          | 劣化备用链路          |
+------------------+-----------------------+--------------------+-----------------------+
| **核心生产类**   | 财务系统、ERP、核心 DB | 极高 (时延<30ms)   | MPLS 优质专线         | 高品质 Internet 宽带  |
| **协作音视频**   | 视频会议、VoIP 电话   | 高 (抖动<10ms,丢包<1%)| MPLS 专线             | Internet 宽带         |
| **普通办公办公** | OA 审批、邮件交互     | 中 (丢包<3%)       | Internet 宽带 1       | Internet 宽带 2       |
| **大流量互联网** | 软件下载、视频娱乐    | 尽力而为 (Best-Effort)| 本地 DIA Internet 直出 | 链路拥塞时直接限速丢弃|
+------------------+-----------------------+--------------------+-----------------------+
```

## 7. 风险与开放问题

### 7.1 现网潜在风险与规避策略
1. **多分支运营商跨网互通抖动风险**：不同省份的分支可能分别采用移动、联通或电信宽带，公网跨运营商互访存在高时延与丢包抖动。
   - **规避方案**：在总部 Hub 侧同时接入三家运营商的多条 BGP 多线带宽，确保分支总能就近匹配相同运营商链路。
2. **非专业人员邮件开局误操作风险**：现场人员误连接其他网络或点击链接超时导致 Token 失效。
   - **规避方案**：开局邮件附带图文极简操作单，提供备用扫码开局模式，Token 有效期宽限设为 48 小时。

### 7.2 开放问题与进阶工程探索
1. **5G 网络切片与 SD-WAN 的端到端协同**：课程提及 5G 蜂窝可作为混合链路之一，但针对 5G 核心网切片（S-NSSAI）与 CPE 内部业务流映射的深度配置未深入展开；
2. **第三方异构 SD-WAN 设备跨厂商互通**：课程主要针对华为体系展开，关于与思科（Viptela）或 Fortinet 等异构厂商的 IPsec 动态路由互通细节未深入展开。
