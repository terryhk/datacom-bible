## 一、总起

企业园区网络承载着办公、研发、生产、安防监控及智能楼宇等核心业务。在过去，园区网通常采用基于物理端口和 IP/VLAN 划分的静态分层架构。然而，随着移动办公（BYOD）、无线全覆盖、万物互联（IoT 海量哑终端）以及跨楼宇/跨分支协同办公的爆发，传统园区网陷入了四大治理困境：
1. **策略与物理位置/IP 强绑定**：传统安全控制依赖防火墙或交换机上的 IP ACL。当员工从总部 3 楼出差到 8 楼，或通过 Wi-Fi 漫游时，获取的 IP 地址改变，导致原有的访问权限全部失效；
2. **ACL 规则爆炸与配置黑洞**：大中型企业拥有数千名员工与数十个部门，网络管理员必须在全网数十台汇聚和核心交换机上手工维护数万条错综复杂的 ACL。随着人员变动，老旧规则“只敢加不敢删”，配置如同随时爆炸的屎山代码；
3. **海量哑终端安全隐患**：网络打印机、监控摄像头、IP 电话、考勤门禁等哑终端无法安装 802.1X 客户端，传统网络缺乏统一防仿冒鉴权机制，极易成为黑客内网渗透的物理跳板；
4. **策略执行性能开销剧烈**：若每台接入或汇聚交换机都对复杂 IP ACL 进行逐包深度检索，容易击穿低端交换机的 TCAM 硬件表项，导致转发表溢出引发丢包。

华为 **业务随行（Free Mobility）** 方案应运而生。它引入了零信任安全设计思想，确立了**“用户权限与 IP 地址彻底解耦，策略随人而动”**的核心哲学：
- **统一身份认证**：员工通过 802.1X 或 Portal 认证，访客通过扫码/短信认证，哑终端通过 MAC 认证，统一由 iMaster NCE / RADIUS 服务器进行身份凭据检验；
- **抽象安全组（Security Group）**：无论用户分配到什么 VLAN、拿到什么 IP，认证成功后由控制器赋予其唯一的“安全组 ID（Group ID）”；
- **二维策略矩阵（Policy Matrix）**：全网安全控制从“源 IP 到目的 IP”升级为“**源安全组到目的安全组**”的业务语言矩阵（如：研发员工组 $\rightarrow$ 财务服务器组 = 拒绝；管理层组 $\rightarrow$ 互联网 = 允许且优先调度）；
- **VXLAN 原生携带**：在虚拟化网络中，VXLAN 报头的保留字段直接携带源安全组 ID，终点设备在解封装时直接在硬件芯片内匹配策略矩阵，**实现极速、无感的全网策略漫游**！

本章全面梳理园区网的全景图谱与业务随行落地：
1. **企业园区网全景架构**：标准三层（核心-汇聚-接入）vs 扁平化两层拓扑设计、双核心与链路冗余高可用、六大功能分区（办公区、服务器区、出口区、运维区、访客区、DMZ 区）；
2. **准入认证三剑客**：802.1X（高安全有客户端）、Portal（免客户端 Web 认证）、MAC 认证（哑终端自动放行）以及 MAC 优先 Portal 组合机制；
3. **安全组体系设计**：静态安全组（固定服务器/网段）、动态安全组（用户认证授权绑定）、未知组（Unknown Group，默认阻断）与逃生安全组（Bypass Group，服务器挂死时的容灾）；
4. **策略执行机制与 6 大组网方案**：深入剖析认证点与策略执行点分离/合一模型，以及在纯传统网络、第三方混搭网络与 VXLAN 虚拟化网络中的落地范式。

**适用人群**：
- **初学 / 转行人员**：系统掌握现代中大型园区网的物理与逻辑拓扑划分，理解企业员工上网如何完成认证与放行；
- **备考工程师（HCIE 核心攻坚）**：彻底拿下 HCIE 笔试与实验中的“安全组规划”、“认证点与策略执行点选型对比（方案 1~6）”、“VXLAN 报头 Option/Reserved 字段携带 Security Group ID 原理”；
- **一线工程实践者**：掌握大型高校、三甲医院、政企集团“有线无线一体化”与“权限随行”工程实操模板与排错避坑指南。

## 二、分述

### 2.1 企业园区网分层拓扑与功能分区设计

#### 标准三层分层模型

```
                     +-----------------------------------+
                     |           出口区 (Egress)          |
                     |  (路由器 / 防火墙 / 行为管理 / IPS) |
                     +-----------------+-----------------+
                                       |
                   ====================|====================
                                       |
                     +-----------------+-----------------+
                     |          核心层 (Core)            |
                     |     (双核心 CE/S12700 高速转发)     |
                     +--------+-----------------+--------+
                              |                 |
                +-------------+                 +-------------+
                |                                             |
     +----------+----------+                       +----------+----------+
     |     汇聚层 (Agg)    |                       |     汇聚层 (Agg)    |
     | (S6700, VLAN三层网关)|                       | (S6700, VLAN三层网关)|
     +----+-----------+----+                       +----+-----------+----+
          |           |                                 |           |
     +----+---+   +---+----+                       +----+---+   +---+----+
     | 接入层 |   | 接入层 |                       | 接入层 |   | 接入层 |
     | (S5700)|   | (S5700)|                       | (S5700)|   | (S5700)|
     +----+---+   +---+----+                       +----+---+   +---+----+
          |           |                                 |           |
       [PC/终端]   [无线 AP]                         [哑终端]     [监控摄像头]
```

1. **核心层（Core Layer）**：
   - **定位**：全网的交通枢纽与高速交换骨干，负责在各汇聚区域、出口区及服务器区之间提供超高带宽、微秒级超低时延的无阻塞包转发；
   - **设计原则**：**核心层必须保持极致纯粹！坚决不做任何复杂的 ACL 包过滤、NAT 转换或深层报文检查**；通常采用两台高端框式核心交换机通过集群（CSS / 链路聚合）实现双活；
2. **汇聚层（Aggregation Layer）**：
   - **定位**：连接接入与核心的桥梁，通常作为**传统园区网的二三层广播域边界与 VLAN 默认网关（VLANIF 所在地）**；
   - **功能**：汇聚接入层流量、终结二层广播域、执行策略路由（PBR）、QoS 复杂流标记、VRRP 网关冗余保护；
3. **接入层（Access Layer）**：
   - **定位**：终端（PC、笔记本、手机、无线 AP、哑终端）物理接入的第一个环节；
   - **功能**：二层 VLAN 划分、802.1p 报文优先级初标、PoE 远程供电、端口安全（Port Security / 限制 MAC 漂移）、DHCP Snooping 防私接、DAI 动态 ARP 检查。

#### 现代两层扁平化演进
在中小园区或现代化新建园区中，随着网络设备芯片性能的飞跃式提升，广泛采用**“核心 + 接入”两层扁平化架构**：
- 取消独立的汇聚层，将二三层网关与控制能力直接上移到核心交换机，或者通过 VXLAN 分布式网关下沉到接入交换机；
- 架构层级减少，链路故障跳数降低，端到端时延大幅减小，运维架构极度清爽。

### 2.2 准入控制三剑客：802.1X / Portal / MAC 认证

在零信任网络中，“任何终端未通过身份认证前，严禁访问内部任何网络资源”。企业主要依赖三类认证技术构筑防御屏障：

```
                              [准入控制三大模式]
           ┌──────────────────────────┼──────────────────────────┐
       802.1X 认证                Portal 认证                 MAC 认证
   (基于端口, 客户端交互)      (免客户端, 网页弹窗重定向)       (面向海量无交互哑终端)
     高安全、员工办公首选          访客、出差、外包首选           摄像头、打印机、IP电话首选
```

| 维度 | 802.1X 认证（IEEE 802.1X） | Portal 认证（Web 认证） | MAC 认证 |
|:---|:---|:---|:---|
| **客户端要求** | **必须安装**或启用操作系统内置的 802.1X 客户端软件 | **无需安装**，仅依赖通用浏览器访问 HTTP/HTTPS 页面 | **无需客户端**，终端完全无感知 |
| **交互协议** | **EAP 协议**（EAP-TLS / PEAP / EAP-MSCHAPv2） | HTTP/HTTPS 报文重定向 + Portal 协议与认证服务器交互 | RADIUS 协议以终端的 MAC 地址作为用户名和密码 |
| **安全性** | **极高**（支持数字证书、动态私钥协商、抗嗅探） | **中等**（易受中间人 ARP 欺骗与重定向篡改） | **较低**（存在 MAC 地址克隆伪造风险） |
| **典型应用场景** | 企业固定员工桌面 PC、研发保密笔记本、金融终端 | 访客 Wi-Fi、大型商业中心、酒店会议室移动终端 | 网络打印机、安防监控摄像头、考勤门禁、智能电表 |

#### 强强联合：MAC 优先的 Portal 认证（MAC-Prioritized Portal）
为了兼顾“访客首次认证的安全可信”与“后续无感快速接入”，企业 Wi-Fi 广泛部署 **MAC 优先 Portal 认证**：
1. **首次接入**：终端连接 Wi-Fi，触发 Portal 认证，用户在弹窗网页中输入手机验证码完成鉴权；
2. **凭据沉淀**：认证成功后，RADIUS/iMaster NCE 服务器在后台自动记录该终端的 MAC 地址，并设置有效期（如 30 天）；
3. **二次无感秒连**：用户几天后再次进入园区，设备检测到 MAC 地址，直接通过后台 MAC 认证通道自动鉴权通过，**免去反复输入密码的繁琐体验**！

### 2.3 业务随行（Free Mobility）架构体系

#### 痛点根源：传统网络“策略随 IP 走”的破产

```
传统架构: 员工张三在 3 楼 (IP: 10.1.3.10) ──> ACL 允许访问财务服务器 (192.168.100.1)
          员工张三移动至 5 楼 (IP: 10.1.5.20) ──> 命中缺省拒绝规则, 业务中断！
          若要放行: 管理员必须在全网各汇聚核心交换机上疯狂堆叠补齐 ACL！
```

【设计本源与技术哲学】：“业务随行解决的最核心问题，就是**把用户从 IP 地址的紧箍咒里彻底解救出来**！网络工程师不要再去管终端拿到的是 10.1 还是 10.2 网段，那些都是底层 Underlay 的事情。在业务层，我们只认‘你这个人是谁’和‘你属于哪个安全组’！”

#### 核心对象一：安全组（Security Group）分类

安全组是承载权限控制的最基本单元，分为四大类型：

```
                                  [安全组四大分类]
           ┌───────────────────────┬───────────────────────┬───────────────────────┐
       静态安全组               动态安全组               未知安全组 (Unknown)     逃生安全组 (Bypass)
  (手工绑定固定 IP/网段,    (用户认证通过后, 控制器    (未认证或无法识别的非法    (认证服务器彻底挂死时,
   面向服务器与打印机)       根据角色动态授权匹配)       终端, 默认执行全量隔离)    提供基础网络的应急通道)
```

1. **静态安全组（Static Group）**：
   - 适用于 IP 地址长期固定的资产（如生产数据库、ERP 服务器、DNS 服务器、静态网段）；
   - 在控制器或交换机上手工将特定 IP 地址或 CIDR 网段划入静态组；
2. **动态安全组（Dynamic Group）**：
   - 适用于移动人员与动态终端；
   - 用户接入网络完成 802.1X/Portal 认证后，RADIUS 服务器根据用户的账号身份、组织架构、接入时间、终端类型（PC/手机），**动态向接入/认证交换机下发 Authorization Group ID（如 Group-100: 研发员工组）**；
3. **未知安全组（Unknown Group）**：
   - 所有尚未认证、认证失败或未经登记的外来流量，统统归属 Unknown 组；在策略矩阵中对该组默认采取严格阻断；
4. **逃生安全组（Bypass Group）**：
   - **高可用容灾兜底**：当骨干网络震荡导致所有认证服务器（RADIUS / iMaster NCE）全部宕机失联时，交换机自动进入逃生模式，将新上线用户归入逃生组，放行基础办公网络与 DNS 访问，严防全员无法办公事故。

#### 核心对象二：二维策略矩阵（Policy Matrix）

安全管理人员不再需要写繁琐的 `rule permit ip source x.x.x.x destination y.y.y.y`，而是在 iMaster NCE 控制器上操作一张极简直观的二维矩阵：

```
              目的安全组: 财务服务器组    研发代码库组    互联网访问区
源安全组
──────────────────────────────────────────────────────────
财务人员组   │      PERMIT     │      DENY      │     PERMIT
研发人员组   │       DENY      │     PERMIT     │     PERMIT
外包访客组   │       DENY      │      DENY      │   PERMIT (限速2M)
未知组       │       DENY      │      DENY      │      DENY
```

### 2.4 认证点与策略执行点：六大组网模型推演

在全网工程设计中，**认证点（Authentication Point）** 与 **策略执行点（Enforcement Point）** 可以合一部署，也可以跨设备分离开局：

```
[核心模型概览]
方案 1: 传统园区网，集中式网关 ──> 认证点与策略执行点合一部署在【核心交换机】
方案 2: 传统园区网，分布式接入 ──> 接入交换机做认证点，【核心交换机】作为集中策略执行点
方案 3: VXLAN 虚拟化园区网    ──> 边界交换机做认证点，VXLAN 封装携带安全组，【目的边缘节点执行策略】
方案 4: 异构第三方交换机混合  ──> 第三方交换机透传，华为汇聚/核心做策略执行点，通过 IP-Group 订阅
方案 5: 独立旁挂无线 AC 场景  ──> AC 负责无线认证，核心交换机订阅 IP-Group 同步做有线无线统一策略
方案 6: 高校校园网 BNG 场景    ──> BNG/BRAS 设备做认证，核心交换机协同执行业务随行策略
```

#### 经典方案 3（VXLAN 虚拟化园区合一部署）机制深度揭秘：

```
       [源端 Leaf-1 (认证点)]                            [宿端 Leaf-2 (策略执行点)]
      ┌──────────────────────┐                          ┌──────────────────────┐
      │ PC-1 (属于安全组 10) │                          │ Server (属于安全组 50) │
      └──────────┬───────────┘                          └──────────▲───────────┘
                 │                                                 │
                 ▼                                                 │ (匹配策略矩阵: 10->50 允许)
      ┌──────────────────────┐   VXLAN 封装骨干网 (Underlay) ┌─────┴────────────────┐
      │ 压入 VXLAN 报文:     │══════════════════════════════>│ 解封装 VXLAN 报文:    │
      │ Group Policy ID = 10 │                               │ 读取源安全组 ID = 10  │
      └──────────────────────┘                               └──────────────────────┘
```

1. **源端打标**：PC-1 在 Leaf-1 认证成功，归入安全组 10；
2. **报文无损携带**：当 PC-1 发送数据包时，Leaf-1 将其封装为 VXLAN 报文。**VXLAN 报头规范中的保留字段（RFC 7348 预留位）被定义为 Group Policy ID，Leaf-1 将数字 `10` 直接写入报头**；
3. **宿端硬件极速匹配**：报文穿过 Underlay 骨干送达 Leaf-2。Leaf-2 解封装时，芯片直接读出“源安全组 = 10”，而目标服务器属于“目的安全组 = 50”；
4. **优势**：Leaf-1 在入方向完全不需要执行复杂的策略查询，**将策略执行动作完全推向目的宿端执行**，全网转发性能最优，无需任何中间控制信令同步！

### 2.5 生产级 VRP 配置实战（安全组与业务随行）

以下为华为交换机手工开局业务随行（基于安全组与策略矩阵）的核心配置模板：

```shell
# ==================== [核心交换机业务随行开局] ====================
sysname Core_Switch

# 1. 创建静态安全组与动态安全组
group-based-acl name Finance_Servers id 50
 group-based-acl name Dev_Servers id 60
#
# 为静态安全组绑定固定服务器 IP/网段
group-based-acl name Finance_Servers
 rule 5 permit ip source 192.168.100.0 0.0.0.255
#
group-based-acl name Dev_Servers
 rule 5 permit ip source 192.168.200.0 0.0.0.255

# 2. 定义基于安全组的访问控制规则 (Group-based ACL / UCL)
# 语法: 从源安全组到目的安全组的策略匹配
acl number 6001
 rule 10 permit ip source-group 10 destination-group 60  # 研发组(10) 访问 研发服务器(60) -> 允许
 rule 20 deny ip source-group 10 destination-group 50    # 研发组(10) 访问 财务服务器(50) -> 拒绝
 rule 30 permit ip source-group 20 destination-group 50  # 财务组(20) 访问 财务服务器(50) -> 允许

# 3. 在全局或接口应用安全组策略矩阵
traffic-policy Policy_FreeMobility global

# 4. 配置认证逃生模板 (防止 RADIUS 服务器挂死全网瘫痪)
authentication-profile name Dot1x_Profile
 dot1x-access-profile Dot1x_Access
 authentication event authen-server-down action authorize security-group Bypass_Group
```

## 三、总结十带走

1. **园区网设计分工**：核心层追求极致高速纯转发（不配复杂 ACL），汇聚层做三层网关与汇聚，接入层做安全接入；
2. **扁平化演进趋势**：中小园区大面积消灭独立汇聚层，转向“核心 + 接入”两层架构或全 VXLAN Fabric；
3. **准入三剑客选型**：802.1X 对应员工高安全；Portal 对应访客免客户端；MAC 认证对应打印机/摄像头等哑终端；
4. **无感体验最佳实践**：Wi-Fi 场景首推“MAC 优先的 Portal 认证”，首次网页鉴权，后续凭 MAC 秒连；
5. **业务随行本质**：权限与 IP 地址彻底解耦，无论员工在何处接入、IP 如何变化，访问控制策略随人而动；
6. **安全组体系**：静态组针对固定服务器，动态组由控制器根据认证身份下发，未知组默认拒绝，逃生组兜底容灾；
7. **策略矩阵革命**：彻底摒弃传统冗长易错的 IP ACL，升级为“源安全组 $\rightarrow$ 目的安全组”的直观二维授权格；
8. **VXLAN 原生赋能**：利用 VXLAN 报头保留位直接灌入源安全组 ID，报文在出端 Leaf 硬件芯片直接匹配，性能无损；
9. **IP-Group 订阅同步**：在非 VXLAN 或第三方混搭环境中，依赖控制器向策略执行点下发 IP-Group 映射表实现跨设备策略协同；
10. **一线工程铁律**：准入系统必须配置逃生组或逃生 VLAN，严防 RADIUS 服务器异常导致全企业断网瘫痪。
