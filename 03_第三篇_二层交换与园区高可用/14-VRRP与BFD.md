# 第14章 VRRP与BFD

## 一、总起

堆叠把双核心合成一台，但很多现网（利旧、跨机房、成本）仍是两台独立核心——网关谁当？VRRP 的答案：两台设备共同维护一个**虚拟 IP+虚拟 MAC**，用户网关永远指向虚拟 IP，挂了自动换人、用户全程无感。BFD 则补另一个短板：路由协议自带的死亡检测太慢（OSPF 40 秒、IS-IS 30 秒、BGP 180 秒，静态路由干脆没有），中间经过交换机的间接故障硬件信号根本感知不到——BFD 以毫秒级周期互发探测报文，任何介质、任何协议都能调用它做"快速故障雷达"。本章两讲各自成章又天然成对：VRRP 的 Track 可以直接联动 BFD（三种主流上行跟踪方式之一），BFD 的价值正是给 VRRP/OSPF/BGP 这些"慢性子"协议提速。全卷最重要的一句方法论：【设计本源与技术哲学】："底层转发极易被忽略的关键一环——网关切换不光是网关要切，流量是跟着 MAC 表项的更新被切过去的。"

**适用人群**：
- **初学 / 转行人员（HCIP 进阶）**：理解第一跳网关冗余协议（VRRP）工作机制，搞懂虚拟 IP、虚拟 MAC 及免费 ARP 切换流向；
- **备考工程师（HCIP / HCIE 核心）**：攻克 Master 选举与定时器、上行链路 Track 联动降优先级、抢占延时（Preempt Delay）、以及 BFD 毫秒级探测会话建立与状态机；
- **一线工程实践者**：掌握双核心园区网中“VRRP + MSTP 双主互备”、VRRP Track BFD 毫秒级联动、以及静态路由/动态路由联动 BFD 的加固模板。

## 二、分述

### 2.1 VRRP 要解决的三个层次问题

1. **单网关痛点**：网关一挂全 VLAN 断网
2. **手动双网关的局限**：配两个网关地址让用户自己挑——"就像公司两部电梯坏了换另一部"，可普通用户连网关是什么都不知道
3. **VRRP 的答案**：对用户完全透明——多台设备（最多 4 台，一般 2 台）在同一广播域组播协商，共守一个虚拟 IP；用户网关永远指虚拟 IP，谁当 Master 与用户无关

**概念基座**：VRID（虚拟路由器 ID）区分不同 VRRP 组；虚拟 MAC 固定格式 `0000-5E00-01{VRID 十六进制}`（VRID=10 → 0000-5E00-010A）；VRRP 基于接口运行，一台设备可同时跑多组。【设计本源与技术哲学】："虚拟路由器是面向小白用户的术语——本质只是维护一个虚拟 IP 充当网关，充其量叫接口级虚拟化，不是系统级虚拟化。"

### 2.2 角色分工与流量切换的底层逻辑（★核心）

**角色**：一组只有一台 **Master**（转发流量+响应 ARP），其余 Backup 只监听不转发虚拟 MAC 的报文。

**ARP 应答**：用户 ARP 解析网关 IP → **只有 Master 用虚拟 MAC 应答**（两台都答=PC ARP 缓存错乱）。下行交换机学到虚拟 MAC 在 Master 端口，数据帧全发向 Master。

**切换三部曲（★底层数据面转发关键细节）**：
1. Master 每 **1 秒**发组播通告；Backup 的 Master_Down 定时器（3×通告间隔+偏移）超时未收到 → 判死
2. 新 Master 上位第一件事：发**免费 ARP**（源 MAC=虚拟 MAC，目的=FF）——**目的是刷新下行交换机的 MAC 表**，把虚拟 MAC 挪到新端口
3. 用户 PC 的 ARP 缓存根本不用变——帧封装的还是那个虚拟 MAC，交换机查新表自然导流
【设计本源与技术哲学】："流量怎么切过去的？是根据 MAC 表项的更新被切过去的。"

**Backup 并非完全空闲**：目标 MAC 是用户真实 MAC 的**回程流量**途经 Backup 也正常转发——来回路径不对称不影响通信。

### 2.3 Master 选举与状态机

**优先级规则**：范围 0-255（可配 1-254，缺省 100），**越大越优**；同优先级比接口 IP 大者；**255**=虚拟 IP 与接口真实 IP 相同时自动获得（必然 Master）；**0**=Master 主动辞职的信使（接口删 VRRP 配置时发 priority=0 通告，对方免等 3 秒立即顶上）。

**偏移时间公式（★）**：`偏移 = (256-优先级)/256`（必小于 1 秒）；`Master_Down = 3×通告间隔 + 偏移`。作用：多台 Backup 错峰超时——优先级高的偏移短、先超时、先上位，避免同时造反打内战。

**状态机**：启用 VRRP（优先级<255）→ 先进 **Backup**，各自等超时 → 短者单方升 Master 发通告 → 对方收到更高优先级通告自动保持 Backup。Master 收到更高优先级通告 → 退位（**抢占默认开启、延时默认 0=立即抢**）。Backup 升 Master 的三条路：超时/收到 0 通告/收到更低优先级通告（抢夺）。

**报文**：只有通告（Advertisement）一种，目的组播 **224.0.0.18**、协议号 **112**、源 IP=Master 接口真实 IP；携带 VRID/优先级/虚拟 IP/认证。V2 只管 IPv4，V3 兼 IPv4/IPv6。

### 2.4 VRRP 三种用法（经典双核心实验）

**舞台**：两台核心（SW1/SW2）+ Eth-Trunk 互联 + MSTP（实例 10 绑 VLAN 10 以 SW1 为根、实例 20 绑 VLAN 20 以 SW2 为根）——注意 VRRP 通告走 Eth-Trunk，**STP 阻塞口传不了**。

| 用法 | 结构 | 评注 |
|---|---|---|
| **主备备份** | VLAN10：SW1 优先 120 当 Master，SW2 100 待命 | 最基础；全部流量走 SW1 |
| **基于 VLAN 的负载分担（★工作首选）** | VLAN10 主在 SW1；VLAN20 主在 SW2 | 每个 VLAN 内仍是主备，两 VLAN 互为主备=负载分担+互备份；**与 MSTP 根桥规划对齐**路径才最优 |
| **VLAN 内负载分担** | 同 VLAN 建两组（VRID10 虚拟 254 主在 SW1；VRID20 虚拟 253 主在 SW2），PC 网关手工分流 | 局限：终端网关要手动分配，DHCP 不好整合——实际一般不做 |

```
# SW1（VLAN10 Master + VLAN20 Backup）
interface Vlanif10
 vrrp vrid 10 virtual-ip 10.1.10.254
 vrrp vrid 10 priority 120
interface Vlanif20
 vrrp vrid 20 virtual-ip 10.1.20.254        # 默认100 即Backup
```

### 2.5 Track 上行跟踪与抢占延时（★工程必备）

**痛点**：上行链路断而 VRRP 不切（下行协商还在）→ 流量到 Master 无路由 → 业务断。

**解法**：Master 上配 Track 跟踪上行接口：
```
vrrp vrid 10 track interface GigabitEthernet0/0/4 reduced 30
```
上行口 Down → 优先级 120-30=90 → Backup(100) 收到低优先级通告立即抢主。**只配 Master 侧**（Backup 不用）。跟踪方式三种：物理口 / BFD / NQA。

**★现网典型翻车案例**：把 `reduced` 误敲成 `increase` → 上行口 Down 优先级反涨到 150 → 永远切不走。`reduce` 与 `increase` 语义相反，敲错即翻车。

**抢占延时（回切的学问）**：故障恢复后默认延时 0 立即抢回——但此时 OSPF/BGP 邻居还没建好、路由表是空的，流量抢回来也是黑洞。解法：`vrrp vrid 10 preempt-mode timer delay 60`——等路由收敛完再无缝回切。

**排错三板斧**：`display vrrp` 看 Master IP 字段（Backup 看到的对端真实 IP=通告交互正常的证据）；`display mac-address` 看虚拟 MAC 学在哪个口（验证流量走向）；结合 ARP 缓存+生成树状态做二三层综合分析。

### 2.6 BFD：为什么需要与是什么

**痛点场景**：R1-SW1-SW2-R2，中间链路断——两台路由器硬件信号全部无感，OSPF 还得等 40 秒死亡定时器，静态路由更是"没报文就当活着"，路由表健在业务已死。各家协议的老Hello太慢：OSPF 40s / IS-IS 30s / BGP 180s / RIP 180s。

**BFD 是什么**：**通用、标准化、介质无关、协议无关**的快速故障检测机制（毫秒级甚至微秒级）。★华为是 BFD 的主要技术贡献者。介质无关=IP 层协议，IP 通就能用；协议无关=独立模块，谁都能调用。【类比】"就像 Python 的模块——每个 .py 文件都能被别的模块 import，BFD 就是系统里的功能模块，被各种应用叠 Buff 调用。"

### 2.7 BFD 报文、会话与状态机

**关键字段**：本端状态；**检测倍数**（默认 3）；**本地/远端标识符**（Discriminator，设备生成唯一值——★一条链路上多个会话靠本地+远端标识符**共同**区分）；本地最小发送/接收间隔（默认 1000ms）；最小 Echo 接收间隔（**微秒级**）；认证可选。

**静态 vs 动态会话**：
- 静态=标识符管理员手工指定（仍要报文协商！【设计本源与技术哲学】："不是两个哑巴给个眼神就懂"），两端**交叉配**：R1 local 100/remote 200，R2 local 200/remote 100；配完 `commit` 提交
- 动态=标识符自动生成自动匹配

**状态机**（DOWN→INIT→UP + AdminDown）：双方**独立**完成三次握手——R1 发 DOWN → R2 收到转 INIT 回发 → R1 收 INIT 转 UP 回发 → R2 收 UP 转 UP。各自独立维护，双向对称。

### 2.8 两种检测模式与 Echo 单臂回声

| 模式 | 谁判断故障 | 机制 | 检测时间公式 |
|---|---|---|---|
| **异步模式** | **对端**判断本端 | 我只管发，对方收不到就认为我挂了 | 本地接收间隔 × 对端检测倍数 |
| **查询模式** | 自己判断链路 | 连发多个控制包，规定时间没回音就宣布 Down | 本地接收间隔 × 本端检测倍数 |

异步模式的比喻：【设计本源与技术哲学】："歌唱得好不好听不由唱歌的人决定，由听歌的人决定——服务质量好坏不由发送端单方面宣布，而由接收端真实体验决定。"

**间隔协商**：实际发送间隔=max(本地发送, 对端接收)——"你多少毫秒发，我就多少毫秒收"，协商后交叉一致。（公式"有点绕"，实操直接两端配一样即可。）

**Echo（单臂回声）**：对端设备**不支持 BFD** 时的补救——报文源目 IP 都填自己接口 IP，强制从指定接口"硬发"出去，靠对端直连路由把包弹回来。【类比】"打乒乓球找不到对手，自己往墙上打，墙帮你弹回来。"【设计本源与技术哲学】："霸王硬上弓——不查路由，直接从指定接口发出去。"只能直连检测、用查询模式。

### 2.9 BFD 联动实战：静态路由与 OSPF

**联动架构**：BFD 会话 → **跟踪模块** → 应用模块（VRRP/OSPF/BGP/静态路由/接口备份）。"BFD 就成了这些应用模块叠 Buff 的地方。"

**静态路由联动**：
```
bfd
bfd test bind peer-ip 10.1.12.2 source-ip 10.1.12.1
 discriminator local 100
 discriminator remote 200
 commit
ip route-static 2.2.2.2 24 10.1.12.2 track bfd-session test
```
★**易错**：会话还没协商 UP 就绑路由——"路本来是好的，由于绑了个失效状态的 BFD 会话，反而变 Inactive"。两端配齐、会话 UP 后路由才 Active。"BFD 好路由好，BFD 坏路由坏。"

**OSPF 联动（配置最简）**：
```
ospf 1
 bfd all-interfaces enable
 bfd all-interfaces min-tx-interval 100 min-rx-interval 100 detect-multiplier 3
```
Hello 仍管建邻居，BFD 只接管**故障检测**——BFD Down 即邻居 Down，不等 40 秒。【设计本源与技术哲学】："你请了个更牛的高手来守家，原来那些将领还留着。"

**两大纪律**：
1. ★BFD **只加速故障检测，不加速邻居建立**——DR/BDR 选举、TCP 三次握手该多慢还多慢
2. 实验要做出效果须用**两台交换机**串中间（双方都感知不到间接故障）；单台交换机场景故障点直连 R2，立即感知，效果不明显

**细节**：协商配对前发包慢（约 12 秒一个——"天天给女生写小作文，关系都没建立，写那么勤干嘛"），配对后才切到配置的毫秒级周期。BFD 报文由 ASIC 芯片处理不走 CPU（引述华为产品经理）。园区网用得少，主战场在广域网/数据中心/运营商骨干。

## 三、总结

**核心重点十带走**：
1. VRRP 本质=接口级虚拟化：一组一个虚拟 IP（`0000-5E00-01VRID` 虚拟 MAC），用户网关指虚拟 IP，切换全程无感。
2. 只有 Master 应答 ARP；切换靠免费 ARP 刷新**交换机 MAC 表**导流——"流量跟着 MAC 表项更新被切过去"。
3. 选举：优先级大者胜（1-254，默认 100）→ 同级比接口 IP 大 → 255=IP 拥有者专属；0=辞职信；Master_Down=3×间隔+偏移（(256-优先级)/256 错峰防内战）。
4. 三用法：主备备份 / 基于 VLAN 负载分担（★首选，与 MSTP 根桥对齐）/ VLAN 内双组（手动分流，不实用）。
5. Track 必配在 Master：上行口 Down 优先级 `reduced 30` 才能切（误敲 increase 翻车）；回切配 `preempt-mode timer delay 60` 等路由收敛。
6. VRRP 通告走组播 224.0.0.18 协议号 112；通告不能穿 STP 阻塞口——双核心必须 Eth-Trunk 互联。
7. BFD=介质无关+协议无关的通用毫秒级检测模块（"Python 模块，谁都能 import"）：静态会话标识符交叉配+commit，动态自动协商。
8. 状态机 DOWN→INIT→UP 双方独立三次握手；标识符二元组（本地+远端）唯一区分同链路多会话。
9. 异步模式对方评判（"唱歌好不好听听众说了算"）、查询模式自查；Echo=对端不支持时的墙上乒乓球（源目 IP 同为自身，硬发出弹回）。
10. 联动：静态路由 track bfd-session（会话未 UP 别绑，防好路变 Inactive）；OSPF 一条 `bfd all-interfaces enable` 全接口生效——BFD 只提速检测不提速建邻。

**落地注意事项**：双核心上线前把 MSTP 根桥、VRRP Master、上行口位置三者的对应关系画成表逐一核对——不一致=一半流量绕远；Track 的 reduce/increase 再三确认（方向反了永切不动）；抢占延时按路由协议收敛时间留足（OSPF 小区域 30-60 秒）；BFD 间隔别一味调小——毫秒级 probing 打的是对端 CPU/ASIC，老旧设备慎用；两台直连设备跑 BFD 没意义（物理 down 立即可见），BFD 的价值在"隔了交换机的间接故障"。

**学习建议**：VRRP 实验务必做完整版：MSTP+Eth-Trunk+VRRP 三件套（正是本章蒸馏稿里的双核心拓扑），重点观察两个瞬态——切换时免费 ARP 报文与交换机 MAC 表变化、Track 触发时 display vrrp 里优先级的即时衰减。BFD 两个实验各做一遍：静态路由联动体验"会话未 UP 绑路由=好路变坏"的坑；OSPF 联动用两台交换机拓扑抓包看协商前 12 秒慢速发包与协商后毫秒级的切换。学完本章，二层三件套（12/13 卷）+网关冗余集齐，下一第 15 章《DHCP 与无线接入》补完园区网接入侧最后两块。
