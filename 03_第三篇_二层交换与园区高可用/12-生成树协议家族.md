## 一、总起

交换机用 MAC 表转发、遇未知就泛洪——一旦成环，广播风暴分分钟打瘫痪网络。生成树家族三代协议都在干一件事：**在物理有环的拓扑上算出一个逻辑无环的转发拓扑，阻塞冗余端口，链路断了再快速把备用端口顶上来**。STP（802.1D）立规矩：全网选根桥、每台选根端口、每段选指定端口、剩下的阻塞——但收敛以 30/50 秒计。RSTP（802.1w）三板斧提速：预先规划好阻塞端口的"接班"角色（AP/BP）、收到次优 BPDU 立即反杀不等老化、PA 握手让指定端口秒级进入转发。MSTP（802.1s）解决单生成树"所有 VLAN 共用一棵树、负载不均路径次优"的先天缺陷：多实例各算各的树、VLAN 映射上车。本章同时讲透一个工程冷知识：**华为的 STP 不是标准 802.1D**（偷偷借了 RSTP 一堆特性，唯独借不了 PA），考试按标准答、实验按华为看。

**适用人群**：
- **初学 / 转行人员（HCIA 入门）**：理解广播风暴与二层物理环路的危害，掌握根桥、根端口、指定端口与阻塞端口的选举逻辑与 30/50 秒收敛过渡；
- **备考工程师（HCIP / HCIE 核心）**：攻克 RSTP P/A 快速协商机制、次优 BPDU 反杀、五大改进、以及 MSTP 多实例（MSTI/CIST/ERPC/IRPC）的映射计算与面试真题；
- **一线工程实践者**：掌握现网边缘端口防下挂（Edge-Port + BPDU Protection）、下级接入防抢根（Root Protection）、以及 MSTP 双核心双向负载分担的标准工程模板。

## 二、分述

### 2.1 STP 骨架：四大角色与选举材料

**为什么需要生成树**：交换机泛洪机制 × 物理环路 = 广播风暴 + MAC 表震荡。解法：阻塞冗余端口，把环裁成树。

**四大角色（★）**：
| 角色 | 定义 | 要点 |
|---|---|---|
| 根桥 Root | 全网 BID 最小的交换机 | 有抢夺性——优先级更小的新设备接入可直接抢位 |
| 根端口 RP | 非根桥上**有且仅有一个**，接收最优 BPDU | 到根桥的最优出口 |
| 指定端口 DP | 每个**冲突域/网段**上一个，发送最优 BPDU | ★抓住"冲突域"而非接口上连什么；**根桥全端口都是 DP**；DP 一定发 BPDU |
| 替代端口 AP | 既非 RP 又非 DP → 阻塞（display 显示 discarding） | 待命备份 |

**选举材料三件套**：
1. **BID** = 16bit 桥优先级 + 桥 MAC。优先级 0~61440、**必须是 4096 的倍数**（默认 32768，违者报错）；先比优先级小、再比 MAC 小
2. **开销 Cost**：接口维护的路径代价，带宽越大开销越小。华为三标准：802.1D / 802.1T（**默认**，千兆=20000）/ 华为私有（千兆=20）。★**全网标准必须一致**，违者计算错乱。手动 `stp cost` 优先于自动计算
3. **PID** = 4bit 端口优先级（0~240，**步长 16**，默认 128）+ 12bit 接口编号；编号不可改，优先级可改

⚠核心架构警告：**别拿 STP 开销与 OSPF 开销硬对比**——"一个二层一个三层你们硬扯什么呢"，面试乱扯暴露的是分层概念不清。

### 2.2 BPDU：结构与传递规律

**BPDU（桥协议数据单元）**：STP 的协议帧，802.3 封装。两种：**配置 BPDU**（类型 0）与 **TCN BPDU**（拓扑改变通知）。

**★四个核心参数（选举的命根子）**：
| 参数 | 含义 |
|---|---|
| RID | 根桥的 BID |
| RPC | 发送者根端口到根桥的累计开销（根桥发出时=0） |
| BID | 发送者的桥 ID |
| PID | 发送端口的 ID |

其他字段：协议版本（0=STP/1=RSTP/3=MSTP）、Flag（TC/TCA）、Message Age（≥20 跳丢弃）、Max Age 20s、Hello 2s、转发延时 15s。

**传递规律（★稳定网络）**：根桥每 2 秒从所有 DP 发 BPDU；非根桥**RP 收、DP 转发**。转发时：RID 不变、RPC=收到的 RPC+收口自身开销、BID 换成自己的、PID 换成出端口的。

### 2.3 角色选举：根端口五步法与指定端口判定

**根端口五步比较法（★逐条比，小者胜）**——比的是各端口**收到的 BPDU**：
1. RID（最小）——根桥定了可跳过
2. RPC 累计 = 收到的 RPC + **本端口自身开销**（★根端口要做累加）
3. 上行 BID（发送者桥 ID，小者优）
4. **收到的 BPDU 里的 PID**（上行端口的 PID，小者优）——★不是比自己端口的 PID！
5. 自身端口 PID（全部相同如有 Hub 中继时才用到）

**指定端口判定（IA 快速法 vs 根本原因法）**：网段上"发得最好"的端口是 DP。根桥全 DP（没人能比根桥发得更好）；连终端/路由器的口无竞争即 DP。**IP 阶段的根本原因法（★）**：非根桥先定 RP，然后**根据 RP 那份 BPDU 为其余每个端口"计算"一份 DP BPDU**（RID 沿用、RPC=RP 的 RPC+RP 口开销、BID 换自己、PID 换出端口），与该端口实际收到的 BPDU PK——计算的更好 → 该口是 DP；算的更差（别人发的更好）→ 该口是 AP 阻塞。★DP 判断**直接比 RPC 不做累加**（累加已在计算时做完了）。【设计本源与技术哲学】："IA 教的是根据结果反推，今天讲的是它成为指定端口的根本原因。"

**AP 被阻塞的根因**：根据根端口算出来的 BPDU，没有该端口从别处收到的 BPDU 好。

**调树三法（控制角色=控制树形）**：改 cost（最常用，影响最小）、改上行 BID（影响面大慎用）、改上行端口 PID。心法：先分析各口收到的 BPDU 找到"比输的原因"，再选影响最小的参数改。实验实证：改 SW4 端口 cost 10000 → RPC 反超翻转 RP；改上行 PID 优先级为 0 → 对端口胜选 RP。

### 2.4 端口五状态与 30 秒等待

| 状态 | 收发 BPDU | 转发数据 | 学 MAC |
|---|---|---|---|
| Disable | ✗ | ✗ | ✗ |
| Blocking(Discarding) | **收不发** | ✗ | ✗ |
| Listening | 收发 | ✗ | ✗ |
| Learning | 收发 | ✗ | ✓ |
| Forwarding | 收发 | ✓ | ✓ |

迁移时序：激活→Blocking；判定 RP/DP→Listening（15s）→Learning（15s）→Forwarding。**AP 端口顶替亦需 30 秒**（15+15）——工程现象"插上网线 30 秒才通"的根源。转发延时在根桥上调（`stp timer forward-delay`，单位 1/100 秒，默认 1500）。

**两个 15 秒的设计原因（★）**：
- Listening 15s：让新根桥 BPDU 传遍全网再放行转发——否则全网暂无阻塞口，**临时环路**。（即先等全网状态就绪再放行转发，避免盲目切换引发震荡）
- Learning 15s：先学 MAC 再转发，减少收敛期**未知单播泛洪**

### 2.5 三种故障场景逐拍分析（换位思考法）

【方法论】分析 STP 故障必须**站在交换机视角**，不能用人的上帝视角——"你人是有眼睛的，那当然是作弊嘛"。SW2（无 AP）：RP=唯一去路；SW3（有 AP）：RP 是正路 AP 是备路。

| 场景 | 时序 | 合计 |
|---|---|---|
| **根桥故障** | SW2 立即"造反"以自己为根发 BPDU；SW3 的 AP 还留着老根 BPDU"我对他还有敬畏之心"，**等 20s Max Age 老化**后才理 SW2 → 重新选举 → AP 变 RP → 15+15 | **50s**（20+30） |
| **直连故障**（AP 所在交换机物理直感 RP 失效） | BPDU 立即老化无需等 20s → AP 立即顶替为 RP → 15+15 | **30s** |
| **非直连故障**（AP 所在交换机**无法**直感的链路故障） | SW3 的 RP 还能收到根桥 BPDU；AP 收到 SW2 次优 BPDU 仍要等 20s → AP 这次变的是 **DP**（不是 RP！） → 15+15 | **50s**（20+30） |

三个坑：
1. **DP 故障不影响通信**——对面本来就是 AP 阻塞，此路本就不通。【设计本源与技术哲学】："自古套路得天下，我就看你们往里面跳。"
2. 链路中间有**光电转换器**时物理层感知不到断 → 按**非直连**算 50s
3. ★直连/非直连的定义锚点是"**AP 端口所在的交换机**"能否直接感知——不是故障链路本身连着谁

### 2.6 TCN 机制与华为 STP 的真相

**拓扑变更的善后（STP 版）**：收敛后 MAC 表还残留旧表象（默认 300s 老化）→ 修正流程：
1. 感知故障的交换机从 DP 发 **TCN BPDU** 逐跳上传
2. 上游回 **TCA**（ACK 置 1）确认
3. 根桥收到后下发 **TC 置 1** 的配置 BPDU，**持续 35 秒**（=MaxAge 20+FD 15）
4. 全网交换机把 MAC 老化时间临时改为 **15 秒**——15 秒内更新到的（正确表象）保留，更新不到的（错误表象）清除
（模拟器抓得到 TCN/TCA 但 MAC 老化改 15 秒的效果不实现，真机才有。）

**★华为 STP 不是标准 802.1D**：借用了 RSTP 一揽子特性——次优 BPDU 立即处理（省 20s）、三状态、AP/BP 角色、边缘端口、非根桥自主发 BPDU——**唯独借不了 PA 协商**（STP 报文 Flag 比特位不够用）。结果：华为设备上根桥故障/非直连故障实测 **30 秒**而非 50 秒。考试理论按 802.1D 答 50s；实验抓包看到 30s 是华为私有优化所致，非笔误。

### 2.7 RSTP 五大改进（★经典面试题）

1. **端口角色**：新增 **AP**（根端口备份——因收到别人更好的 BPDU 被阻塞，保留着那份更好的 BPDU）与 **BP**（指定端口备份——因收到**自己发的** BPDU 被阻塞，只在 Hub 冲突域/自环场景出现）。RSTP **预先规划**阻塞端口的接班角色，STP 只有一锅煮的 blocking
2. **端口状态 5→3**：Discarding（合并 Disable/Blocking/Listening，不学 MAC 不转发）/ Learning / Forwarding
3. **BPDU Flag**：8 个比特全部用起来——P/A 比特（协商）、Learning/Forwarding 描述位、**角色比特**（01=AP/BP、10=RP、11=DP）、TC/TCA 不变。RSTP **只有一种 RST BPDU**——没有 TCN，拓扑变化用 TC 比特直说（送命题：RSTP/MSTP 里看不到 TCN 计数）
4. **BPDU 处理**：非根桥**自主**按 Hello 发 BPDU 不依赖根桥驱动；老化 18s（2s×3×3）可调到 6s；**次优 BPDU 立即处理**（"反杀"，省 20s）
5. **快速收敛机制**：根端口秒切、边缘端口、PA 协商

### 2.8 RSTP 快速收敛三引擎

**引擎一：根端口快速切换（AP→RP 秒级）**——RP 失效后 AP 立即顶替进转发。为什么敢不等 30 秒？稳定时本就无环，RP 失效相当于"环上先剪断一处"，AP 补上不构成临时环路。【设计本源与技术哲学】："判断拓扑变化时，如果没有临时环路风险，可以立即进入转发状态。"

**引擎二：边缘端口（★项目必开）**——接 PC/打印机/三层设备的口：
1. 立即进入 Forwarding（免 30 秒）
2. Up/Down **不触发**拓扑变化、不发 TC
3. 学到的 MAC 不被 TC 删除
4. 依然发 BPDU（特殊指定端口）
5. **一旦收到 BPDU 自动失去边缘属性**，重新参与计算（防环能力保留）

**银行办公网案例**：某银行每天早上网络慢一会儿自愈——员工陆续开机端口 Up/Down 触发 TC 清空 MAC 表 → 未知单播泛洪拖垮网络。开边缘端口后根治。

**引擎三：PA 协商（DP 秒级转发的钥匙）**——触发三条件（缺一不可）：①点到点**全双工**链路；②DP 处于 **discarding** 主动发 P=1；③**对端是 RP** 才配合（对端是 AP 就不理你——"我就是阻塞的，管你转不转发"）。

**场景一：间接故障逐包复盘（★抓包实证）**——SW2 的 RP 失效：
1. SW2 无 AP，以自己为根发次级 BPDU（P=1）"造反"
2. SW3 的 AP 用"次优立即处理"老化旧 BPDU，为自己一算——发现自己发的更好 →**反杀**："我才是 DP"（男追女变女追男）
3. SW2 收到更好的 BPDU → 自己的口变 RP
4. SW2 **同步置位 Sync**：把所有非边缘指定端口暂时阻塞，营造无环环境 → RP 立即 Forwarding，回 A=1
5. SW3 收到 A=1，DP 也立即 Forwarding——**P/A 两包一秒内握手完毕**
6. TC BPDU 通知全网刷 MAC 表

**场景二：新增链路成环**——新链路两端都以为自己是 DP 互发 P=1 → 下游发现根桥更好选 RP → 同步置位回 A=1 → 为下一个口重算 DP 再触发 PA → **逐跳推进**，该阻塞的口被算成 AP，约 2 秒收敛（STP 要 30 秒）。【设计本源与技术哲学】："万变不离其宗：DP 处于 discarding 就引发 PA，对端 RP 配合、AP 不配合。"

** BP→DP 不能秒切（★常见理论误区，实机抓包纠正）**：BP 顶替成 DP 仍需 30~50 秒——BP 场景对端是 AP，不配合 PA 协商，只能老实等老化+过渡。真机实测为 50 秒（20s 老化 + 30s 过渡）。

### 2.9 RSTP 的 TC 机制与四大防护

**TC 机制（比 STP 简化）**：
- **唯一触发条件：非边缘端口迁移到 Forwarding**（边缘口 Up/Down 不算拓扑变化）
- 流程：TC While 计时器（Hello×2）→ **立即删除**状态变化端口学到的 MAC（不是 15 秒老化）→ 从非边缘 DP 和 RP 发 TC BPDU（4 秒发 2 次）→ 收到者清空**除收包口和边缘口之外**的 MAC → 继续扩散

**四大防护（★配置位置是考点）**：
| 防护 | 生效端口 | 行为 |
|---|---|---|
| BPDU 防护 | **边缘端口**（全局命令 `stp bpdu-protection`） | 边缘口收到 BPDU → **error-down**（防有人私接交换机抢根桥） |
| 根防护 | **指定端口**（`stp root-protection`） | 该口只能当 DP，收到更优 BPDU → discarding；30 秒无更优 BPDU 自动恢复 |
| 环路防护 | **根端口和 AP**（`stp loop-protection`） | 单向链路（收不到 BPDU）→ 口进 discarding 角色转 DP 不转发，防单向环 |
| TC-BPDU 防护 | 全局 | `tc-protection interval 10` + `threshold 5`：10 秒内只处理 5 次 TC，超出的一次性合并处理——防伪造 TC 攻击 CPU（100 次攻击最多执行 6 次删表） |

### 2.10 MSTP：多实例负载分担

**单生成树三大缺陷（★）**：
1. 所有 VLAN 共用一棵树 → 冗余链路闲置，**无法负载分担**
2. **二层路径次优**——VLAN3 的网关在 SW2，但树是按 VLAN2 网关（根桥）长出来的，VLAN3 用户去网关要绕行阻塞路径
3. Trunk 放行不一致+阻塞位置叠加 → 部分 VLAN 可能不通（该类故障过半源于 Trunk 放行列表配置失误）

**MSTP 设计思想**：**实例=车，VLAN=乘客**——先造几棵树（Instance），再把 VLAN 映射上去；不同实例可设不同根桥 → 不同 VLAN 组走不同路径 → 负载分担。收敛机制全部继承 RSTP（PA 同款）。历史上 PVST（每 VLAN 一棵树）因 100 VLAN=100 棵树负担太大且是思科私有未标准化；华为 BVSTP 仅用于对接思科。MSTP 是折中：几棵树就够。

**单域配置五步（★）**：
```
stp region-configuration
 region-name HCIE            # 域名（区分大小写，域内必须一致）
 revision-level 10           # 修订级别
 instance 1 vlan 10 20       # VLAN 10/20 → 实例1
 instance 2 vlan 30 40       # VLAN 30/40 → 实例2
 active region-configuration # ★必敲！不激活前面的全部白配
```
根桥指定：`stp instance 1 root primary`（优先级直接归 0，**之后禁止再改优先级**）/ `stp instance 2 root secondary`（4096）。SW1 做实例1主根+实例2备根，SW2 反着来 → VLAN 10/20 走 SW1 方向、30/40 走 SW2 方向，负载分担达成。

**实例 0（★最容易忘）**：任何域默认存在实例 0，**VLAN 1 和所有未映射 VLAN 归它管**——单域配了 2 个实例实际有 **3 棵树**。生产配置建议：给实例 0 也人为指定根桥，别放任自生自灭；新建 VLAN 忘映射就会"混进实例 0"。

**多域术语体系（★）**：
| 术语 | 含义 |
|---|---|
| MSTI | 每个生成树实例（0~4094） |
| IST | 域内实例 0 的树（保域内无环） |
| CST | 把每个域抽象成一台"虚拟交换机"，域间链路组成的树 |
| CIST | IST+CST 全局树——全局 VLAN 的跨域无环路径 |
| 总根 | CIST（全网实例 0）优先级最小的交换机 |
| 根域/非根域 | 总根所在域 / 其他域 |
| Master 端口 | 非根域到总根最短域间路径上的端口（=该域 CIST 根端口） |

**多域两大机制**：
1. **非根域重新选举**：总根定后，非根域的实例 0 根桥**重新洗牌**——Master 端口所在交换机自动成为本域实例 0 新根桥，单域时代的旧根桥"自动下台"（类比：新皇帝登基换内阁）
2. **CIST 选举 6+1 参数**（逐次比小）：总根 ID → ERPC（域间开销，**只在域间累加**）→ 域根 ID → IRPC（域内开销，**只在域内算**）→ 指定交换机 ID → 指定端口 ID → 接收端口 ID

**BPDU 双层结构**：外层带 CIST 参数（只有实例 0 信息，跨域传递）；MSTP 扩展部分带域内各实例信息（不出域）。域间 BPDU 的发送者 BID 用**域内实例 0 根桥**的 BID 代表整个域。**修订级别的真实用途**：BPDU 不传完整映射表（太大）而传哈希——修订级别防 MD5 哈希碰撞误判"同域"。现网运维中不同 MST 域直接配置不同整数即可，无需过度纠结哈希碰撞理论。

**MSTP 局限（★）**：负载分担只在**域内实例**层面实现；域间的 CIST 仍是单生成树——全局 VLAN 共用一棵树。

### 2.11 生成树标准配置与工程加固模板（VRP 实战）

#### 1. RSTP 与四重防护工程配置模板

```shell
# ═══ 1. 全局启用 RSTP 与主备根桥指定 ═══
[SW1] stp mode rstp                                     # 华为默认是 MSTP，需显式切为 RSTP（全网模式须一致）
[SW1] stp root primary                                  # 指定为首选根桥（将桥优先级锁死为 0）
[SW2] stp mode rstp
[SW2] stp root secondary                                # 指定为备用根桥（将桥优先级锁死为 4096）

# ═══ 2. 接入接口：边缘端口 + BPDU 防护（生产标配黄金组合） ═══
[SW1] interface GigabitEthernet 0/0/24                  # 面向终端 PC 的接入端口
[SW1-GigabitEthernet0/0/24] stp edged-port enable       # 设为边缘端口，跳过 Listening/Learning 立即进入转发
[SW1-GigabitEthernet0/0/24] quit
[SW1] stp bpdu-protection                               # 全局开启 BPDU 保护（边缘口若收到 BPDU 则直接 error-down 关闭接口）

# ═══ 3. 下联指定端口：根保护（防下级单位私接更优交换机抢根） ═══
[SW1] interface GigabitEthernet 0/0/1                   # 连接下级汇聚交换机的指定端口 (DP)
[SW1-GigabitEthernet0/0/1] stp root-protection          # 收到更优 BPDU 时自动将端口置为 Discarding，报文消失后自动恢复

# ═══ 4. 根端口与阻塞端口：环路保护（防单向链路导致阻塞口冒充 DP） ═══
[SW3] interface GigabitEthernet 0/0/2                   # SW3 上的 AP 阻塞端口或 RP 根端口
[SW3-GigabitEthernet0/0/2] stp loop-protection          # 长期收不到对端 BPDU 时保持阻塞状态，防止错误转变为 DP 导致成环

# ═══ 5. 全局 TC-BPDU 泛洪攻击防护 ═══
[SW1] stp tc-protection                                 # 开启 TC 保护（默认在 2 秒周期内最多处理 1 次 TC 清表操作）
```

#### 2. MSTP 多实例双核心负载分担配置模板

```shell
# ═══ SW1 与 SW2 必须配置完全相同的 MST 域参数 ═══
[SW1] stp mode mstp
[SW1] stp region-configuration
[SW1-mst-region] region-name HUAWEI_CAMPUS              # 域名（大小写敏感，全网一致）
[SW1-mst-region] revision-level 1                       # 修订级别（全网一致）
[SW1-mst-region] instance 1 vlan 10 to 19               # 实例 1 承载 VLAN 10~19
[SW1-mst-region] instance 2 vlan 20 to 29               # 实例 2 承载 VLAN 20~29
[SW1-mst-region] active region-configuration            # ★必须激活配置，否则域配置不生效！
[SW1-mst-region] quit

# ═══ 实例根桥分配：实现双核心流量双向负载均衡 ═══
# SW1 充当 Instance 1 的主根、Instance 2 的备根
[SW1] stp instance 1 root primary
[SW1] stp instance 2 root secondary

# SW2 充当 Instance 2 的主根、Instance 1 的备根
[SW2] stp instance 2 root primary
[SW2] stp instance 1 root secondary

# ═══ 状态检查与验证 ═══
<SW1> display stp brief                                 # 检查各端口在各实例下的角色 (RP/DP/AP) 与状态 (FORWARDING/DISCARDING)
```

## 三、总结

**核心重点十带走**：
1. 选举材料：BID（优先级 4096 倍数+MAC，比小）、开销（三标准全网一致、1T 默认千兆 20000）、PID（优先级 16 倍数+编号）；BPDU 四参数 RID/RPC/BID/PID。
2. 角色：根桥全 DP；每台非根桥一个 RP（五步法：RID→RPC**累加**→BID→**收到的** PID→自身 PID）；DP 判定用"根据 RP 算出的 BPDU"与收到的直接比（**不累加**）；剩下是 AP。
3. 状态机：Blocking（收不发）→Listening 15s→Learning 15s→Forwarding；AP 顶替 30 秒，新插网线 30 秒--两个 15 秒=防临时环+先学 MAC 防泛洪。
4. 三故障：根桥 50s（造反+敬畏 20s+30s）、直连 30s（物理直感立即老化）、非直连 50s（等 20s，AP 变 **DP**）；锚点在"AP 所在交换机"；DP 故障不影响通信；光电转换器=非直连。
5. TCN 链：TCN 逐跳上传→TCA 确认→根桥 TC 发 35 秒→全网 MAC 临时 15 秒老化自清洗；华为 STP 借 RSTP 特性（除 PA）实测 30s，理论答 50s。
6. RSTP 五改进：AP/BP 预定角色、三状态、Flag 8 比特（P/A+角色码）、BPDU 自主发+次优立即反杀+18s 可调 6s、快速收敛三引擎。
7. AP=RP 备份秒级顶替（无临时环风险）；BP→DP **不能秒切**（对端 AP 不配合 PA 握手，实测 50s，部分早期文档描述有误）。
8. PA 三条件：全双工点到点、DP discarding、对端 RP；过程=次级 BPDU→反杀→Sync 阻塞非边缘 DP→RP forwarding 回 A=1→双方秒通；新增链路逐跳 PA 约 2 秒。
9. 边缘端口五特性（立即转发/Up-Down 不触发 TC/MAC 不被删/仍发 BPDU/收 BPDU 失效）+银行案例；TC 唯一触发=非边缘口进转发、MAC 立即删。
10. MSTP：实例=车 VLAN=乘客；域配置三要素（域名/修订/映射）+active 必敲；实例 0 兜底所有未映射 VLAN（三棵树别忘了）；多域 CIST 6+1 参数（ERPC 域间累加、IRPC 域内算）；防护四件套按端口位置配（BPDU 防护=边缘、根防护=DP、环路防护=RP/AP、TC 防护=全局）。

**落地注意事项**：`active region-configuration` 不敲域配置=白配（最常见事故）；域内三要素必须逐台核对一致（域名大小写都敏感）；`stp root primary` 敲完后优先级就锁死了，别再想手调；所有接终端的口必开边缘端口+BPDU 防护（两者是生产标配组合）；根防护放在"不该出现更优 BPDU"的指定端口上（下级单位上联口）；模式切换全网统一（stp mode）；负载分担规划时实例 0 的根桥也要规划——它管着所有没上车的 VLAN。

**学习建议**：本章的练习主线是"预判→验证"：拿任何拓扑先在纸上写出每台设备的 RP/DP/AP 与收到的 BPDU 四参数，再上模拟器 `display stp brief` 对答案——全对才算"心中有树"。故障场景建议用秒表实测三类恢复时间，并特意体验"华为 STP 30s vs 理论 50s"的差异；PA 协商务必抓包一次（P=1/A=1 两包一秒握手），看懂 Sync 阻塞过程比背文字强十倍。MSTP 先做单域负载分担（双实例双根桥），再做双域观察 Master 端口与实例 0 换主现象。RSTP 保护四件套各做一次攻击实验（私接交换机/抢根桥/拔单向纤/伪造 TC）。学完本章接第 13 章《链路聚合与设备堆叠》——STP 解决环，堆叠从根源上消灭环。

## 附：本章术语速查表

| 术语缩写 | 英文全称 | 中文含义 | 关键作用 |
|---|---|---|---|
| **STP** | Spanning Tree Protocol | 生成树协议 | IEEE 802.1D 标准协议，在二层网络中通过阻塞冗余链路消除环路 |
| **RSTP** | Rapid Spanning Tree Protocol | 快速生成树协议 | IEEE 802.1w 标准协议，引入 P/A 握手与 AP/BP 角色将收敛压至秒级 |

| **DP** | Designated Port | 指定端口 | 每个冲突域/物理链路上发送最优 BPDU 的接口，负责向该网段转发流量 |
| **AP** | Alternate Port | 替代端口 | 根端口的备份接口，长期处于阻塞状态，在主根链路断开时秒级接替 RP |

| **TC** | Topology Change | 拓扑改变 | 触发全网交换机刷新 MAC 地址表以加速拓扑收敛的通知机制 |
