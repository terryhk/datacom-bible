## 一、总起

以太网天生一个广播域，主机一多，广播、未知单播、病毒蠕虫全网乱窜。本章三章走一条主线：**先隔**——VLAN 给 MAC 地址表加一维 VLAN 属性，广播域从"物理一台交换机"解耦为"逻辑多个广播域"；**再通**——隔离之后 VLAN 间要通信，路由器子接口（单臂路由）或三层交换机 VLANIF 接口充当网关，其中"逻辑拓扑抽象"（把三层交换机看成路由器、VLANIF 看成路由器接口）是全卷最值钱的思维方式；**后管**——通了之后要管控流量，ACL 按五元组精细放行/拒绝，通配符掩码与默认规则是两大坑位。三个实验体系（跨交换机 VLAN 互通、三层交换机 OSPF 互联+出口设计、ACL 精细化过滤）构成园区网的配置骨架。

**适用人群**：
- **初学 / 转行人员（HCIA 入门）**：理解广播域隔离的物理与逻辑解耦，搞懂 Access/Trunk/Hybrid 端口收发规则与 PVID 打剥 Tag 机制；
- **备考工程师（HCIA / HCIP 核心）**：攻克单臂路由子接口三件套、三层交换机 VLANIF 网关逻辑抽象、高级 ACL 五元组匹配与默认规则陷阱；
- **一线工程实践者**：掌握跨交换机 Trunk 放行白名单规划、业务网段与互联网段隔离、以及出口精细化访问控制的安全加固策略。

## 二、分述

### 2.1 VLAN 的动机与本质

**没有 VLAN 的世界**：一台交换机=一个广播域；多台交换机组网后，广播/未知单播泛洪波及全网所有主机——安全问题（蠕虫病毒借广播传播）+ 带宽浪费。用路由器隔离？不灵活——路由器一个接口一个广播域，员工换个工位就得换个网段地址。【设计本源与技术哲学】：路由器隔离"不灵活"，要在交换机上隔离。

**VLAN 本质（★）**：给交换机 MAC 地址表**添加 VLAN 属性**——"MAC 地址-端口-VLAN"三元组对应关系；查表转发与泛洪都只在本 VLAN 内发生，跨 VLAN 二层隔离。
- ★VLAN **没有消除泛洪**：广播依然要泛洪（干道上该发还得发），但**受影响的主机数量减少了**——广播域数量变多、范围变小。【设计本源与技术哲学】："隔离的是不同 VLAN 的广播，但广播依然是要泛洪的。"
- 附加价值：蠕虫病毒被限制在 VLAN 内、VLAN 可跨交换机部署（组网灵活）、安全与规划解耦于物理位置。

### 2.2 802.1Q 帧结构

电脑网卡发出的以太网帧**没有 VLAN 信息**（PC 不知道自己属于哪个 VLAN）——Tag 由交换机负责打。

```
| 目的MAC | 源MAC | [TPID | Priority | CFI | VLAN ID] | 类型/长度 | 数据 | FCS |
                     └────────── 4字节 802.1Q Tag，插在源MAC与类型字段之间 ──────────┘
```

| 字段 | 宽度 | 内容 |
|---|---|---|
| TPID | 16bit | **0x8100** 固定值，标识这是个 802.1Q Tag 帧（★必背） |
| Priority | 3bit | 优先级 0-7，QoS 用 |
| CFI | 1bit | 以太网环境固定 0 |
| VLAN ID | 12bit | VLAN 号（0~4095，可用范围 1~4094） |

帧分两类：**Untag 帧**（原始以太帧）与 **Tag 帧**（带 802.1Q）。★核心规则（华为产品手册原话）：**交换机内部所有帧都以 Tag 形式存在**——Access 发出去的 Untag 只是出端口时剥掉了，进交换机就打上了。

### 2.3 三种端口类型：Access / Trunk / Hybrid

**Access（接主机的基本款）**：
- 收 Untag → 打上 PVID 的 Tag；收 Tag → 只有 Tag==PVID 才收，否则丢
- 发 → 仅发 Tag==PVID 的帧，且**剥离 Tag**（出去的一定是 Untag）
- PVID 默认 1；配置 `port link-type access` + `port default vlan <ID>`

**Trunk（交换机之间的干道）**：
- 收 Untag → 按 PVID 打 Tag 后判断放行；收 Tag → 判断该 VLAN 是否放行
- 发 → Tag==PVID 且放行 → 剥 Tag 发；Tag≠PVID 但放行 → **保留 Tag** 发
- ★默认只放行 VLAN 1（`port trunk allow-pass vlan 1` 是缺省命令不显示在配置里），其他 VLAN 必须手动放行
- 四核心命令：`port link-type trunk`、`port trunk pvid vlan <ID>`、`port trunk allow-pass vlan <列表>`、`undo port trunk allow-pass vlan <ID>`

**Hybrid（华为特色，"特殊的 Trunk"）**：
- 收：与 Trunk **完全相同**
- 发：**管理员决定 Tag 剥不剥**（放行的前提下）——与 Trunk 的唯一区别
- `port hybrid pvid vlan <ID>` + `port hybrid untagged vlan <列表>`（剥 Tag 发）+ `port hybrid tagged vlan <列表>`（带 Tag 发）
- ★**华为交换机默认接口类型就是 Hybrid**（默认 PVID=1）
- 查看端口能力：`display port vlan`——U=Untag 放行、T=Tag 放行

**方法论（★阮工业级工程规范反复强调）**：不要背"Access 接 PC、Trunk 接交换机"的死板结论——掌握三种端口**收发行为**后按需求分析。【设计本源与技术哲学】："以不变应万变的方法，未来你想怎么接就怎么接。"推论：Trunk 可等价实现 Access 效果（PVID+只放行一个 VLAN），反之 Access 做不了 Trunk 的事。跨交换机链路用 Trunk 的原因：要保留 Tag 传递，保证同一 VLAN 的广播只在该 VLAN 内泛洪。

### 2.4 VLAN 划分五方式

| 方式 | 依据 | 适用/特点 |
|---|---|---|
| 基于接口 | 接口-PVID 绑定 | **最常用**，灵活性与管理性平衡 |
| 基于 MAC | MAC-VLAN 映射（接口需 Hybrid） | 适合下联不支持 VLAN 的交换机场合；但每台交换机要配全量映射，管理量大 |
| 基于 IP | IP 所属 VLAN | 需要"IP 换 VLAN"的场景 |
| 基于协议 | IPv4/IPv6 分流 | 运营商 IPTV 场景 |
| 基于策略 | MAC+IP+接口三要素 | 安全性最高（防 MAC/IP 欺骗） |

### 2.5 VLAN 间通信其一：单臂路由

每个 VLAN 一个路由器物理口做网关 → VLAN 多了接口不够。**单臂路由**：交换机上行 Trunk 放行多 VLAN，路由器物理口下建子接口。

子接口三要素（★）：
```
interface GigabitEthernet0/0/0.10
 dot1q termination vid 10        # 绑定VLAN10：收Tag10由此处理，发出打Tag10
 ip address 10.1.1.254 24
 arp broadcast enable            # 允许子接口向下发ARP（模拟器必配，真机默认开）
```
- 子接口=逻辑上的独立物理口；物理口本身无法绑定 VLAN，天然处理 Untag 帧——子接口处理 Tag 帧
- 抓包实证：同一个 ICMP 包上去 VLAN10（TTL=128）下来 VLAN20（TTL=127），**ID 相同**证明是同一个包被路由
- 局限（引出下一节）：路由器转发性能低于交换机 + 单点故障（交换机-路由器链路断则全断）；优点是省接口省链路

### 2.6 VLAN 间通信其二：三层交换与 VLANIF

**三层交换本质（★）**：让交换机自己具备路由功能——具备路由功能且支持路由协议的交换机叫三层交换机。企业部署套路：**接入层二层交换机**做用户 VLAN 接入，**汇聚层三层交换机**做 VLAN 网关。

**VLANIF 接口**：
- 每个 VLAN 一个 VLANIF（VLAN 10→VLANIF 10），逻辑虚拟接口，类比单臂路由的子接口
- ★理解钥匙：**把 VLANIF 想象成该 VLAN 里的一台主机/路由器**——它和该 VLAN 内所有主机同处一个广播域
- 创建后自动产生直连路由，维护自己的 ARP 缓存；网关交换机手握三张表：MAC 地址表（二层）+ 路由表 + ARP 缓存（三层）

**二层 vs 三层转发判断（★考点）**：
- 目标 MAC ≠ 交换机自身 VLANIF 的 MAC → **二层转发**（查 MAC 表；同网段互访经过网关设备也是二层转发，不做路由）
- 目标 MAC = 自身 VLANIF 的 MAC → 解封装查路由表 → **三层转发** → 重新封装（打出接口 VLAN 的 Tag）查 MAC 表发出

**逻辑拓扑抽象（★全卷最值钱的思维）**：物理上 VLAN 跨交换机存在，但"同一 VLAN=同一广播域"。把三层交换机抽象成路由器、VLANIF 抽象成路由器接口、下挂二层交换机抽象成普通交换机——物理图与逻辑图**等价**，这就是网络虚拟化。此后一切通信分析按路由器组网理解。【设计本源与技术哲学】："物理图和逻辑图结合思考去进行网络问题分析。"

### 2.7 三层交换机组网：互联、OSPF 与出口设计

**两台三层交换机互联**：新建互联 VLAN（如 VLAN 100），两端各配 `interface Vlanif 100` + 同网段 IP，互联口 Trunk 放行。本质=两台"VLAN 里的主机"互通——与两台 PC 同 VLAN 能通一个道理。跑 OSPF：把 VLANIF 当路由器接口 network 宣告即可。

**干道思维**：交换机间用 Trunk 而非 Access——同时支持三层互联（VLANIF）和普通二层同 VLAN 互访（放行业务 VLAN），未来扩展免改造。

**出口路由器扩展**：加互联网 VLAN（如 VLAN 1000）+ VLANIF 互联 → 三层交换机写默认路由指向出口路由器 → 出口路由器写回程静态路由。OSPF 与静态混用，因地制宜。

**路径分析的现实课**：网关部署不当时流量会绕路（本地 VLAN 的网关在远端交换机上，流量先到本地网关再折返远端）。【设计本源与技术哲学】："你没有办法让每台主机的流量路径是最优的，因为你的网络拓扑设计就这么一回事了。"——垃圾规划也要能分析出流量路径，有权衡才谈优化。

**排错方法论**：逐跳查——主机 ping 网关通不通 → 网关有没有去目标的路由 → 下一跳可达吗 → 对端有没有回程路由。模拟器里不通九成是配错配漏；思路一致适用于现网。

### 2.8 ACL：原理、通配符与默认规则

**ACL 是什么**：访问控制列表=流量过滤规则表（放行/拒绝），同时也被 NAT、策略路由、防火墙、QoS、IPsec 广泛调用。结构：一个 ACL（编号）= 一张表；多个 rule = 多行；每行 = 动作（permit/deny）+ 报文特征 + 规则号。

- 规则号默认 5 起步、**步长 5** 递增——留间隔方便日后插入规则；`step` 命令可整体重排
- 匹配顺序：**规则号从小到大，一旦命中立即执行动作**，不再往下看

**★默认规则（华为特性，易错重灾区）**：
| 使用场景 | 末尾隐藏规则 |
|---|---|
| 直接用于流量过滤（traffic-filter） | **permit（允许所有）** |
| 被其他工具调用（Route-Policy/NAT 等） | **deny（拒绝所有）** |

（与思科不同——思科默认全 deny。部分早期教材曾对此有误印，需注意以设备真实行为为准。）

**通配符掩码（核心难点）**：
- **0 = 匹配（该比特必须一致），1 = 忽略（不关心）**——与子网掩码语义相反
- 与反掩码的区别：反掩码 0/1 必须连续，通配符掩码**可以不连续**，更灵活
- 常用写法：
  - 网段 `192.168.1.0 0.0.0.255`；主机 `1.1.1.1 0.0.0.0`（或 `host 1.1.1.1`）；所有 `any`（= `0.0.0.0 255.255.255.255`）
  - **奇偶地址匹配**：偶数主机掩码 `0.0.0.254`（最后一比特强制 0）、奇数同理——不连续掩码的典型用法

**匹配位置**：`inbound`（入口先过滤再路由）/ `outbound`（先路由再过滤）——类比保安管进不管出。★**outbound 对路由器自身产生的报文无效**（路由器自己 ping 出去不受控，inbound 无此限制）。引用不存在的 ACL 或空 ACL = 视为不匹配，等于没配，不影响转发。

### 2.9 基本 ACL、高级 ACL 与书写策略

| 类型 | 编号 | 能定义的特征 |
|---|---|---|
| 基本 ACL | 2000~2999 | 只有**源 IP**（分片信息、生效时间段可选） |
| 高级 ACL | 3000~3999 | 源 IP + 目的 IP + 协议 + ICMP 类型 + TCP/UDP 源目端口 + 时间段 |
| 二层 ACL | 4000~4999 | 以太帧头（源/目 MAC、协议类型 0x0800/0x0806）——IA 不深入 |
| 命名 ACL | 名字+`base`/`adv` | 同对应编号类型，默认高级 |

**书写策略（★）**：**精细的写前面（小规则号），宽松的写后面**——顺序写反，漏网之鱼先被宽规则放走。

**精细化过滤实验（1.1.1.1 能 ping 不能 Telnet / 1.1.1.2 能 Telnet 不能 ping）**：
```
acl 3001
 rule 5 permit tcp source 1.1.1.2 0 destination 3.3.3.3 0 destination-port eq 23
 rule 10 permit icmp source 1.1.1.1 0 destination 3.3.3.3 0
 rule 15 deny tcp source 1.1.1.1 0 destination 3.3.3.3 0 destination-port eq 23
 rule 20 deny icmp source 1.1.1.2 0 destination 3.3.3.3 0
interface GigabitEthernet0/0/0
 traffic-filter inbound acl 3001
```
两大陷阱实测：
1. 全写 permit = 没配（默认也 permit）
2. 图省事补一条 `deny ip any` → **把 OSPF（协议号 89）报文也干掉，邻居断、全网瘫**——要默认拒绝必须显式 `permit ospf`，或者干脆用"精细化拒绝 + 默认放行"策略

策略不唯一：精细化拒绝+默认放行 vs 精细化允许+默认拒绝，按运维需要因地制宜。

## 三、总结

**核心重点十带走**：
1. VLAN 本质=MAC 地址表加 VLAN 维度（三元组），隔离的是**不同 VLAN 的广播**；广播依然泛洪，只是受影响主机变少。
2. 802.1Q Tag 4 字节插在源 MAC 与类型字段之间：TPID 0x8100 / Priority 3bit / CFI / VLAN ID 12bit；**交换机内部所有帧都带 Tag**。
3. 三端口核心差异：Access 剥 Tag 收发本 VLAN；Trunk 保留 Tag 传多 VLAN（默认只放行 VLAN 1，缺省命令不显示）；Hybrid 收同 Trunk、发由管理员定剥不剥（**华为默认类型**）。
4. PVID 是"打 Tag 用的默认值"，不是"端口所属 VLAN"的口语标签；判断端口行为只看收发规则，不死记"Access 接 PC"。
5. 单臂路由=子接口三件套（dot1q termination vid + ip address + arp broadcast enable），抓包同 ID 上下行换 VLAN、TTL 减一。
6. 三层交换=VLANIF 当网关；判断二三层的标准是**目标 MAC 是否为自身 VLANIF 的 MAC**；同网段流量过网关设备仍是二层转发。
7. 逻辑拓扑抽象：三层交换机=路由器、VLANIF=路由器接口——园区网一切分析的地基；交换机互联用 Trunk 一次到位。
8. 出口设计：VLANIF 互联出口路由器 + 默认路由去 + 回程静态路由回；排错永远逐跳查（网关→路由→下一跳→回程）。
9. ACL：规则号小者先匹配即停；**直接过滤默认 permit、被调用默认 deny**（华为）；通配符 0 匹配 1 忽略、可不连续（奇偶匹配 0.0.0.254）。
10. outbound ACL 管不了路由器自己发的包；空 ACL/不存在 ACL 等于没配；`deny ip any` 会误杀 OSPF（协议 89）——默认拒绝必须先 permit 路由协议。

**落地注意事项**：Trunk 两端放行清单必须对称（单边放行=单边不通的经典故障）；发往普通 PC 网卡的口，出去的帧必须 Untag（Hybrid 配置时 untagged 列表别漏）；互联 VLAN 只起三层作用，别混入业务广播；ACL 上线前先在测试口验证规则顺序，尤其检查有没有宽规则排在细规则前面；改步长会重排规则号，批量插规则前先规划号段。

**学习建议**：本章三个实验体系建议全部亲手复刻：①跨交换机 VLAN 互通用 Access+Trunk 验证"同 VLAN 通、跨 VLAN 隔"；②Hybrid 共享网关主机隔离实验（IDC 托管场景）最能锻炼端口行为推演能力——先在纸上写出每个口的 U/T 放行表再敲命令；③ACL 四规则实验务必亲手触发"deny ip any 杀死 OSPF"现象，看一眼终身免疫。逻辑拓扑抽象的功夫要在每个实验里练：先画物理图再画逻辑图，两张图对得上才算真懂。学完本章即可进第 12 章《生成树协议家族》——冗余链路与 VLAN 碰撞出的问题在那里解决。

| **802.1Q** | IEEE 802.1Q Standard | 虚拟局域网帧标记协议 | 在以太网帧头插入 4 字节 Tag（TPID=0x8100 + VLAN ID）的标准协议 |
| **PVID** | Port Default VLAN ID | 端口默认虚拟局域网标识 | 交换机接口接收到不带标签的 Untag 帧时，为其打上的默认 VLAN 标记 |
| **VLANIF** | VLAN Interface | 虚拟局域网逻辑三层接口 | 三层交换机为各 VLAN 创建的虚拟路由接口，充当终端的默认网关 |
| **ACL** | Access Control List | 访问控制列表 | 基于五元组等报文特征进行顺序匹配过滤的访问控制技术 |
