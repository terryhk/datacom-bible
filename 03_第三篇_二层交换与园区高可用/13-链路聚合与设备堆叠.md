## 一、总起

冗余是网络高可用的命根子，但冗余带来自己的麻烦：多根线=环路（第 12 章 用生成树阻塞，代价是带宽闲置+收敛慢）；双核心=双份配置（MSTP+VRRP+Trunk 每台都要配）。本章两级跳解决：**第一级 Eth-Trunk**——多根物理线捆成一根逻辑链路，带宽叠加、互为备份，生成树把它当一条链路看待，环路问题从"链路层"消失；**第二级堆叠/集群**——多台物理交换机虚拟成一台逻辑设备（盒式叫 iStack、框式叫 CSS），双核心在逻辑上坍缩成单核心，MSTP/VRRP 直接退场。全章贯穿着一条核心底层心法：【设计本源与技术哲学】："把堆叠线想象成交换机内部的线路裸露在外面"——虚拟化的本质是"物理归物理、逻辑归逻辑"。附赠生产网两大硬核话题：堆叠分裂的 MAD 检测与 CSS1/CSS2 的架构差异。

## 二、分述

### 2.1 高可用设计三层与框式架构

**可靠性设计**：设备/链路故障时业务不中断。类比：人的眼耳手脚全是冗余设计——坏一个还能生活。三个层面：单板冗余（主控/电源/风扇双配）、设备冗余（双机）、**链路冗余**（多根线）。预算有限做不了设备冗余，链路冗余成本最低："多根线总比少根线要好"。

**框式交换机架构**（大型项目）：机框+电源+风扇+**MPU 主控板**（大脑：协议处理、生成路由表/MAC 表）+**SFU 交换网板**（内部高速公路：线卡间高速转发）+**LPU 线路板**（业务接入）。50 台接入交换机双上连要 100 个口——"买框式花十几万接一台电脑，一般公司没这么奢侈"。

### 2.2 Eth-Trunk：概念与手动模式

**链路聚合**：多个物理接口绑定为一个逻辑接口（Eth-Trunk），不升级硬件就增加带宽，同时成员口互为冗余。术语四件：聚合组（LAG）/成员接口/活动接口（转发数据）/非活动接口（备份）。Eth-Trunk 在交换机上就是一个普通接口——照样配 Trunk/Access/Hybrid。

**手动模式（Manual）**：管理员强制捆绑，两端**不跑协议**。★所有成员口都是活动口，没有活动/非活动之分。类比静态路由："管理员让我们在一起，捆了就完事了。"
```
interface Eth-Trunk 1                # 编号0-63，本地有效（两端可不同号）
 mode manual load-balance            # 默认即手动，可不显式配
 trunkport GigabitEthernet 0/0/1    # 逐个加入成员口
 trunkport GigabitEthernet 0/0/2
```
- 三层互联：交换机侧 Eth-Trunk 二层口不能直接配 IP → 配合 VLANIF；路由器侧 `undo portswitch` 切三层口直接配 IP
- **缺陷（★考点）**：只能靠物理层状态判断对端——中间有光电转换器时本端口 down 对端感知不到，数据照发全丢
- 成员口退出：物理口下 `undo eth-trunk`；删组：`undo interface Eth-Trunk 1`

### 2.3 LACP 模式：协商、选举与抢占

两端跑 LACP 协议，成员口互发 **LACPDU**（携带：设备优先级、设备 MAC、接口优先级、接口号）。

```shell
# ═══ 1. LACP 静态协商模式标准配置（SW1 主动端，SW2 配合端） ═══
# SW1 上配置：调整系统优先级争夺主动端
[SW1] lacp priority 100                                 # 系统 LACP 优先级（默认 32768，数值越小越优，成为主动端）
[SW1] interface Eth-Trunk 1
[SW1-Eth-Trunk1] mode lacp-static                       # 配置为静态 LACP 模式
[SW1-Eth-Trunk1] max active-linknumber 2                # 限制最大活动链路为 2 条（其余接口进入非活动备份状态）
[SW1-Eth-Trunk1] lacp preempt enable                    # ★必须开启抢占功能（默认关闭，不开则故障恢复后不会切回主链路）
[SW1-Eth-Trunk1] lacp preempt delay 10                  # 抢占延时 10 秒（防链路频繁翻滚闪断）
[SW1-Eth-Trunk1] trunkport GigabitEthernet 0/0/1 to 0/0/3 # 将 3 个物理口加入聚合组（2 主 1 备）
[SW1-Eth-Trunk1] quit

# 针对成员接口微调优先级决定谁当活动口（在主动端配置生效）
[SW1] interface GigabitEthernet 0/0/1
[SW1-GigabitEthernet0/0/1] lacp priority 10             # 接口优先级越小越优，确保 G0/0/1 成为活动端口

# ═══ 2. 跨设备聚合与堆叠 MAD 代理检测配置 ═══
# 在堆叠系统与下游交换机互联的跨设备 Eth-Trunk 上开启 MAD 代理
[Stack-Switch] interface Eth-Trunk 10
[Stack-Switch-Eth-Trunk10] mad detect mode relay        # 启用 MAD 中继代理检测（利用下游交换机检测堆叠是否分裂）

# ═══ 3. 查看与验证 ═══
<SW1> display eth-trunk 1                               # 检查 Local/Partner 状态、活动链路数及 Selected 状态
```

**主动端选举**：先比**设备 LACP 优先级**（`lacp priority 0-65535`，默认 32768，小者优）→ 相同比 MAC 小者。主动端说了算——活动接口以它为基准选。

**活动接口选择**：主动端按**接口 LACP 优先级**（接口下 `lacp priority`，默认 32768，小者优）选前 N 个（N=`max active-linknumber 3`，**只在主动端配**）；优先级同则接口号小的优先；被动端对端对应口同步成为活动口。

**抢占（★默认关闭）**：不开=先到先得——规划为备份的口可能因早协商一步占坑（实验翻车现场：24 号口该活动却没选上，20 号口白占名额）。两解法：shutdown 再 undo shutdown 顶包（但原口回来抢不回）；正解 `lacp preempt enable` + `lacp preempt delay 10`（默认 30s、最低 10s）——确保**优先级优的口永远是活动口**。类比 DR/BDR：先到先得。

**M:N 冗余规划**：4 口 3 活动 1 备份（3:1）。生产中罕见 1:3 冗余（极度浪费端口带宽），★工作实际"四根就四根都用"很少搞精细节——但要**知道能力**："深藏不露的高手，不用可以，但要知道。"

### 2.4 负载分担：流的哈希

- **基于包**：逐包轮转，会乱序，★不推荐且华为不支持
- **基于流（默认）**：同一流走同一链路，不乱序。机制：成员口分 HASH-KEY+端口索引，默认**源 IP ⊕ 目的 IP 异或**取后几位（4 口取 2bit、8 口取 3bit）映射端口
- ★"这个平均不是真的平均"——哈希分布不均，某链路可能背 80% 流量："你们不至于长这么大还相信平均主义吧？"
- 算法 6 种可选（`load-balance`：源/目 MAC、源/目 IP 及组合）；默认源目 IP 的原因：多数场景差异性最大
- **成员口数量 2 的幂次方**（2/4/8/16）——"搞三个口五个口效果就不好"；**两端算法可不同**，按流量特征选（PC→服务器方向源 MAC 差异大适合源 MAC，回程相反）
- 【设计本源与技术哲学】："你不懂理论就根本不知道在什么情况下去用什么东西……做多容易啊，很多男人就跟牛一样，没有耕坏的地只有累死的牛。"——理论是活用的前提

### 2.5 堆叠与集群：概念、角色与选举

**为什么**：传统双核心=MSTP 防环+VRRP 网关冗余+Eth-Trunk+Trunk，百台 VLAN 时代配置量爆炸。堆叠后**物理保持冗余、逻辑变成一台**——拓扑回归两层直连，MSTP/VRRP 全部退场。【设计本源与技术哲学】："左边的图和右边的图不是对立的，而是统一的——物理上这样布线，逻辑上这样理解网络。"

**命名**：iStack=盒式堆叠（理论可 9 台+，**实际部署建议两台**）；CSS=框式集群（**只支持两台**）。本质："堆叠和集群只是叫法和实现有差异，组网场景和用途一样。"

**三大优势**：①简化逻辑拓扑（无环，MSTP 退场——但生成树**不能关**，防施工误接线）；②故障收敛快到"几乎感知不到"（★"感知不到不代表不丢包——蚊子叮你你感知不到，不代表它吸不到你的血"，TCP 靠重传兜底，视频语音可能受影响）；③简化管理（一个 IP、一个 Console 管全部）。

**三种角色**：
| 角色 | 职责 |
|---|---|
| 主 Master | 管理平面+控制平面全包（Telnet/OSPF/STP 协议处理） |
| 备 Standby | 待命接替，只有一台 |
| 从 Slave | 纯转发，≥3 台才有，可多台 |

**堆叠 ID**：成员编号，决定端口呈现（堆叠后 G0/0/2 显示为 `堆叠ID/0/0/2`）；缺省 0，冲突时主交换机自动遍历分配空闲 ID。

**主选举三规则（★）**：先比**启动完成时间**（先完成者优先）→ 差小于 20 秒比**堆叠优先级**（默认 100，`stack port priority` 越大越优——注意与 LACP 相反）→ 仍同比 MAC 小者。★【设计本源与技术哲学】："管理重在理，不在管——主交换机是事先规划确定的，不是让它自己选。"调好优先级+控制上电次序，确保规划的那台当选。

### 2.6 堆叠连线：逻辑口交叉与环形容错

每台两个堆叠逻辑口 `StackPortN/1`、`StackPortN/2`（N=堆叠 ID）；一个逻辑口可绑多个物理成员口（带宽+可靠双保险）。

**★连线铁律：逻辑口 1 连对端逻辑口 2（交叉）**——不是物理口 1 连物理口 2。物理成员口之间怎么接都行（这边的 1/2/3 接那边的 4/5/6 也对），逻辑绑定关系说了算。

**两种拓扑**：链形（首尾不闭环——断一根堆叠线即分裂，可靠性低）；**环形（首尾相连，断一条不分裂，★推荐）**。

### 2.7 成员退出/加入/合并与 MAD 多活检测

**三场景**：
- **退出**：主退→备升主重选备；环形退一台，把断开的两端口**直连**保环形；链形拆中间=分裂
- **加入**：新机先关机接线再上电→直接成为从；ID 冲突或版本不同→自动同步+重启
- **合并**：两套运行中堆叠相遇→两主竞争，**输的一方全部重启**从角色加入，业务全断。【设计本源与技术哲学】："碰到合并我八辈子都不干，合个屁啊，没事合并有病了。"

**分裂灾难**：两套系统同 IP 同 MAC 同配置——OSPF/IS-IS 的 LSA/LSP 互相震荡，路由崩坏。

**MAD（多活检测）**：分裂后两套系统竞争，**失败方关闭所有物理口**（保留端口除外）=隔离下线。竞争规则同主选举：启动完成时间→主优先级→MAC。两种部署（同一系统二选一）：
- **直连检测**：成员间直连 MAD 链路（推荐经一台普通交换机中转，不必全互联）；平时不发包，分裂后每秒发检测包
- **代理检测**：借用上下行华为交换机（须支持 MAD 代理）在链路聚合中兼职检测；前提是上下行本来就是聚合组网

### 2.8 升级三方式与跨设备聚合

| 方式 | 场景 | 中断 |
|---|---|---|
| 智能升级 | 新建堆叠/新成员加入，自动同步主机版本 | 仅新成员重启，原有不受影响 |
| 传统升级 | 无业务窗口：拷贝新软件+startup 指定+整堆叠重启 | 较长中断 |
| 平滑升级 | 上下行均为链路聚合，逐台拆出 active/backup 区轮流升级 | 有风险，条件苛刻 |

类比：手术前先治别的病，创造适合手术的身体条件——"没有这种环境你就得想别的方法。"

**跨设备链路聚合+本地优先转发**：堆叠=一台设备，成员分别接上下行做聚合天然成立。但哈希可能把备机上来的流量甩到主的成员口出（穿越堆叠线）——**流量本地优先转发**（默认开启）：备收到的尽量从备的口出，减轻堆叠链路负担；可关。

### 2.9 CSS 集群：概念、CSS1 与 CSS2

**四概念**：主/备（无"从"角色，主备**同时转发**）；集群 ID（=堆叠 ID）；CSS 集群链路；集群优先级（越大越优）。★【设计本源与技术哲学】："你只要知道他妈的就是一台设备就行了——控制平面还是转发平面，就当一台设备去理解。"路由表/ARP/MAC 表双机实时同步。

**控制平面**：连好线→配好→重启→集群自动建立（先 save！）。框式通常双主控板（一主一备），两台共 4 块；集群建立后**主交换机的主用主控板成为全系统唯一控制平面**。单主控也能做但可靠性差——主控一挂就分裂。

**CSS1 vs CSS2（★架构分水岭）**：
| | CSS1（传统） | CSS2（第二代） |
|---|---|---|
| 集群卡位置 | 主控板（SIP 口）或业务口 | **交换网板** |
| 跨框流量路径 | 接口板→**主控板**→集群卡→对端 | 接口板→**交换网板**→集群卡→对端（不经主控） |
| 致命弱点 | 单框两块主控板全坏→该框瘫痪、集群分裂 | **4 块主控板只要 1 块活着就不分裂** |
| 定位 | 老平台 | 园区网 S 系列框式首选（更贵） |

【设计本源与技术哲学】："主控板坏了，他娘的四块只有一块还在，老子还是堆叠。"（具体框式机型是否支持 CSS2 需查阅对应硬件版本规格书。）

### 2.10 堆叠/集群配置实操与两大黑洞

**iStack 新建（三台环形，堆叠卡方式）**：
```
# A 机（规划为主）
stack slot 0 priority 200          # 优先级200（越大越优）
save                               # ★下电前必须 save
# B 机
stack slot 0 renumber 1            # 堆叠ID改为1
save
# C 机
stack slot 0 renumber 2
save
# 全部关机 → 按图接线（交叉+闭环）→ A 先上电等十几秒 → B 上电 → C 接线后上电自动加入
```
业务口方式多一步逻辑口绑定：`interface stack-port 1` → `port member gigabitethernet 0/0/27`（27 进逻辑口 1、28 进逻辑口 2，两端交叉接）。

**S 系列 CSS（集群卡，★无需下电）**：
```
# A
css port interface-type qsfp+
set css mode css-card              # 集群卡模式
set css id 1
set css priority 100
save
css enable                         # A 重启，等约30秒
# B（随后）
set css id 2 / set css priority 10 / save / css enable   # 大概率自动加入
```
业务口方式：`set css mode lpu` + `css port 1 add ...` 添加成员口。

**两大黑洞（★运维必知）**：
1. **堆叠配置 display cu 看不见**——直接写入 Flash 独立存储；`reset save configuration` 删配置重启，堆叠照样活着；拆除必须用**专门的拆除堆叠命令**
2. **改配置前必做备份**；拆除、改造都按产品手册"听话照做"，不自创

**华为智能堆叠**（插线自动协商，免手配）——补充工程实践："被客户卷出来的。"

**H3C IRF 对照**：华为堆叠的等价技术，支持 4 台。流程：关物理口→配 IRF 逻辑口绑成员→undo shutdown→save→`irf-port-configuration active`→B 改 `irf member 1 renumber 2` 重启。[HCL 与 eNSP 共存安装术：先改注册表 VirtualBox 版本键值 6.0.14 装好后改回——两模拟器互不打架。]

## 三、总结

**核心重点十带走**：
1. Eth-Trunk 手动模式：无协议全活动口，简单但只认物理层状态（光电转换器场景双端感知不同步=丢包黑洞）。
2. LACP：主动端（设备优先级小→MAC 小）说了算；活动口按接口 LACP 优先级选前 N；**抢占默认关**——不开就是先到先得，规划会翻车。
3. 负载分担基于流（哈希源目 IP 异或），"平均不是真的平均"；成员口 2 的幂次方；两端算法可不同，按流量特征选。
4. 堆叠本质：物理冗余+逻辑单机——MSTP/VRRP 退场、收敛无感（但感知不到≠不丢包）、一个 IP 管全部；生成树留着防施工误接线。
5. 主选举三规则：启动完成时间→堆叠优先级（**越大越优**，与 LACP 相反）→MAC 小；★事先规划确保当选，不放任自选。
6. 连线铁律：逻辑口 1 交叉对逻辑口 2，物理口随意；**环形拓扑**断一线不分裂，链形必分裂。
7. 合并=业务全断的高危操作（"八辈子不干"）；分裂靠 MAD 兜底：竞争失败方全端口关闭，直连（中转交换机）或代理（上下行聚合兼职）二选一。
8. CSS1 致命伤=集群卡在主控板（双主控全坏即分裂）；CSS2 移到交换网板——4 块主控活着 1 块就不倒；S 系列首选 CSS2。
9. 堆叠配置在 Flash 里 display cu 看不见、reset 配置也删不掉——拆除必须专用命令；变更前必备份。
10. 新建节奏：单机配 ID/优先级→save→关机→交叉环形接线→按优先级次序上电；S 系列 CSS 用 css enable 免下电；跨设备聚合默认本地优先转发。

**落地注意事项**：LACP 精细规划（M:N 备份）必须开抢占，否则故障恢复后活动口与规划不符；哈希不均是常态，做容量规划时按"单链路可能背全部流量"留余量；两台堆叠是黄金配置，多台堆叠的合并/分裂风险陡增；堆叠线带宽要扛得住"本地优先被打破时"的跨框流量；升级优先智能/平滑，传统重启放在维护窗口；H3C 对接场景记得 IRF 与堆叠命令体系不同。

**学习建议**：Eth-Trunk 两模式各做一遍实验，重点复现"不开抢占 24 号口没选上"的规划翻车和"shutdown 中转链路直连模式感知不到"的丢包——这两个坑见识过就免疫。堆叠在 eNSP 里模拟不了（盒式），建议使用 HCL 华三模拟器练 IRF，配置思路完全同构（关口→绑逻辑口→save→激活→改 ID 重启）；IE 备考者按"三套堆叠两套自配"的考试要求练到手熟——"总共不到 10 条命令，比配 OSPF 单区域还简单"。学完本章，二层高可用三件套（生成树+聚合+堆叠）集齐，接下来第 14 章《VRRP 与 BFD》讲网关层的高可用，正好补齐最后一块拼图。
