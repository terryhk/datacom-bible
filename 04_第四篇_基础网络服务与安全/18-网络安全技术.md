## 二、分述

### 2.1 端口隔离：不动 VLAN 的"同网不同通"

**场景**：IDC 机房两家公司服务器同 VLAN 但要求互相隔离——再切 VLAN 浪费地址、还要动网关。端口隔离：同交换机同 VLAN 内把端口拉进隔离组，**组内二层不通**。

**机制本质**：隔离组成员口的帧不从其他成员口转出——**ARP 广播被拦**，ARP 解析不完，二层通信自然断。"本地有效，不能跨交换机。"

**类型与模式两组概念（★易混）**：
| 维度 | 选项 | 含义 |
|---|---|---|
| 类型 | 双向隔离（默认） | **组内隔离、组间互通**（说的是组关系不是通信方向！） |
| | 单向隔离 | `am isolate interface` 跨组也能隔离 |
| 模式 | L2（默认） | 只断二层（ARP 不通）；网关开**VLAN 内 ARP 代理**可三层通 |
| | ALL | 二层三层全断，开了代理也没用 |

★L2 模式"三层通"的真相：网关用自己的 MAC 代替目标主机回应 ARP（ARP 代理），流量先到网关三层转发——两台主机 ARP 缓存里对方的 MAC 全是网关 MAC。类比：看病先退烧再消炎——隔离是先控住症状（防横向渗透），根因另治。

**实验矩阵**：1/2 口入组1、3/4 口入组2 → PC1↔PC2 不通、PC3↔PC4 不通、跨组（1↔3、1↔4、2↔3、2↔4）全通、未入组主机照常出外网。

### 2.2 MAC 地址表安全：三类表项各司其职

| 类型 | 特性 | 用途 |
|---|---|---|
| 动态 MAC | 报文学习、老化 300 秒、重启丢 | 日常 |
| **静态 MAC** | 手工绑定、不老化、重启保留 | ★其他口收到"源 MAC=绑定值"的帧**直接丢弃**——防 MAC 欺骗 |
| **黑洞 MAC** | 源或目标是它，所有接口直接丢 | 压制已知恶意 MAC |

【设计本源与技术哲学】："黑洞 MAC 治标不治本——但有攻击行为时先压制住，再想办法杀毒。就像发烧先退烧保大脑，再开消炎药。"

**辅助能力**（知道有即可）：禁 MAC 学习（`mac-address learning disable action discard/forward`，discard 模式配静态 MAC=精准白名单）、接口/VLAN 学习数量限制、老化时间微调。★**安全必须有告警**：接口连一台 PC 却学到俩 MAC——"人手五个指头，案发现场出现六指掌纹那必须警惕"。数量超限可配丢包+告警，发现异常才能及时响应。

### 2.3 端口安全：动态/静态/Sticky 三态五组合

**比 MAC 表安全更进一步**：不光限"学几个"，还能指定"只能是谁"。

**安全 MAC 三态**：
| 态 | 来源 | 老化 | 重启后 |
|---|---|---|---|
| 安全动态 | 启用后学到的自动转安全 | 默认不老化（可配） | **丢失重学** |
| 安全静态 | 手工绑定 | 不老化 | 保留 |
| **Sticky（沾黏）** | 学到自动"粘住"转静态 | 不老化 | **save 后保留**（免手工） |

**三种惩罚动作**（超限触发）：
| 动作 | 行为 | 适应 |
|---|---|---|
| Restrict（默认） | 丢违规+**告警上报** | 日常首选 |
| Protect | 只丢不报 | 免日志噪音 |
| **Shutdown** | 接口 Error-Down，**合法用户也断网** | 最严：一端口一 MAC 责任到人 |

Error-Down 恢复：手动 shutdown/undo shutdown；真机可 `error-down auto-recovery cause port-security interval <秒>` 自动恢复（模拟器不支持）。

**五组合全覆盖（工程实践组合总结）**：纯动态先到先得（重启丢）→ 手工绑 1+动态补余 → 手工粘 1+自动粘余 → 纯 Sticky 万事大吉 → 全静态零灵活最森严。管理最严做法：**绑一个静态 MAC+动作 shutdown**——"MAC 不匹配直接关接口，责任到人可溯源"。类比：进严格机房的防静电服流程——公司不是 APP 用户，领导必然安全优先而非员工方便优先。

**老化两种**：绝对（到点就删不管流量）/相对（每分钟检查，连续 N 分钟无流量才删）。

### 2.4 MAC 漂移：先问因，再开方

**现象**：同一 VLAN 不同端口反复学到同一 MAC，表项来回覆盖震荡。**两大成因**：环路（根治靠生成树）/伪造攻击（治理靠本节特性）。

【铁律】**漂移是结果不是原因**——找到根因（环 or 攻）再对症下药，不要倒果为因。

**防漂移两招**：
| 招 | 命令 | 原理 |
|---|---|---|
| 学习优先级 | `mac-learning priority 3`（0-3，大者稳） | 信任口高优：高优学的不被低优覆盖 |
| 禁同优先级覆盖 | 全局命令 | 先学为王，后来无效——"立嫡长子为太子，后来的不算" |

**检测后处理四挡**（真机 V200R024 支持，模拟器部分不支持）：
| 动作 | 场景 |
|---|---|
| 告警 | 网管人工介入 |
| 接口 Error-Down | 能定位攻击主机时（接入口） |
| 仅阻该 MAC | 干道口不能关接口——只封这一个人 |
| **退出 VLAN** | 干道口上单个 VLAN 出事，其他 VLAN 不陪葬 |

类比：打仗能精确定位就精确打击，不能就范围压制。

### 2.5 流量抑制 vs 风暴控制：限速与惩罚

**流量抑制**：对**五种**报文（广播/未知组播/未知单播/已知组播/已知单播）做限速。三个维度：pps、bps、带宽百分比。方向差异（★）：
- **入方向=限速**：超出速率的丢弃
- **出方向=阻塞**：广播/未知组播/未知单播三种**直接不转发**（无速率概念）
- VLAN 视图下：只对广播做 bps 限速
```
interface GigabitEthernet 0/0/1
 broadcast-suppression cir <值>          # CR 约定速率，CBS 设备自选
 broadcast-suppression block outbound    # 出向阻塞
```

**风暴控制**：只管**三种泛洪报文**，但多了**惩罚动作**：
```
storm-control broadcast min-rate <min> max-rate <max>
storm-control action { block | error-down }
storm-control enable auto-recovery
storm-control whitelist protocol { arp | dhcp | ... }   # 白名单豁免
```
按检测间隔算平均速率比阈值；block 只堵该类型（接口还活着），error-down 直接关接口。

**两者区别一句话（★考点）**：流量抑制=限速丢包不伤接口，管正常业务大流量；风暴控制=可惩罚接口（block/error-down），管环路产生的有害流量。"网络没有环路时做流量抑制就行；风暴控制是环路真发生了，扛住危害默默排障——用户体验不受影响。"类比：生成树防环=河道拓宽（花钱）；风暴控制=三峡大坝（雨再大也扛得住）——治标不治本但保命。

### 2.6 MACSec（了解级）

802.1AE 交换机间**逐跳**二层加密（完整性/加密/源校验/防重放），部署在接聚之间；与 IPSec 互补（IPSec 管广域网）。用得很少、不是所有交换机都支持——知道定位即可，机制查产品手册。

### 2.7 DHCP Snooping（一）：信任接口防伪服务器

**三保护目标**：防伪造服务器、防合法服务器被 DDoS、保客户端拿到合法地址。

**接口三角色（★区分）**：
| 角色 | 行为 |
|---|---|
| **信任接口**（`dhcp snooping trust`，连合法服务器） | 服务器报文正常收发 |
| 非信任（未启监听） | 服务器报文（Offer/ACK/NAK）直接丢 |
| 非信任（已启监听） | 服务器报文照样丢；但客户端请求放行 |

工作逻辑：客户端请求只从**信任口**送向合法服务器——伪造服务器根本收不到请求；非信任口收到服务器报文一律丢（冒充无门）。类比：宾馆前台——"只有信任口能收服务员的回复，非信任口谁敢冒充直接丢。"
```
dhcp snooping enable                    # 全局
interface GigabitEthernet0/0/1
 dhcp snooping enable                   # 启监听（非信任）
interface GigabitEthernet0/0/3
 dhcp snooping trust                    # 连服务器设信任
```

### 2.8 DHCP Snooping（二）：绑定表——接入侧的事实数据库

**生成**：剥 DHCP 报文提取 **MAC+IP+VLAN+接口** 四元组入表。租约到期或客户端 Release 自动删。★**前情不记**：只记录启用监听**之后**的交互——"监控装之前房间发生的事没录像"。静态 IP 主机可手工补静态绑定表。

**无条件信任原则（★精彩讨论）**：交换机以监听到的组合为唯一真相——即使客户端当初用假 MAC 拿到真 IP 表也照录："真的假不了，假的真不了——我就以这个表为准，以后不按表来的都是假的。"（"一个谎言要用一千个谎言去补"）

**两大用途**：
1. **防 ARP 欺骗**：检查 ARP 报文的发送者 IP+MAC 是否与表匹配——不匹配即丢（请求应答都查）
2. **防 IP 源欺骗（IPSG）**：检查 IP 报文**源 IP** 是否对得上表

```
display dhcp snooping user-bind                              # 查绑定表
user-bind static ip-address 10.1.1.1 mac-address xxxx interface G0/0/1 vlan 10   # 静态绑定
interface GigabitEthernet0/0/1
 ip source check user-bind enable                            # IPSG 启用
 ip source check user-bind check-item ip-address mac-address # 检查粒度可选（IP／+MAC／+VLAN／全项）
```
⚠**IPSG 大坑**：没有绑定表就启用——**除 DHCP 请求外全拒，业务全断**。启用前必须保证表已生成或静态绑定到位。"安全就是哪个点都不能漏，漏一个点总有人钻空子。"

### 2.9 攻防三案例：饿死、中间人、与防御矩阵

**① DHCP 饿死攻击（DoS）**：伪造海量不同源 MAC 的 Discover 耗干地址池。类比：小混混占座位——七八个人一人一桌点杯水，不打不闹，饭店全占满正常客人进不来。
- 手段一：**变帧源 MAC** → 端口安全限 MAC 数（一个口学一个，变了就丢）
- 手段二：**不变帧 MAC 只变 CHADDR 字段**（帧头 MAC 恒定骗过端口安全）→ `dhcp snooping check dhcp-chaddr enable` 核验 CHADDR 与帧头源 MAC 一致性
- ★中继场景检查失效：中继会重写源 MAC 而 CHADDR 不变——**该检查只能部署在接入层**，中继之后必误杀

**② ARP 中间人攻击**（挂靠在 DHCP 生态讲）：攻击者两头骗——对客户端冒充网关（1.2→自己 MAC）、对网关冒充客户端（1.1→自己 MAC）→ 双向流量全过攻击者中转，交换机 MAC 表完全正常（PC3 的 MAC 就在 3 号口，没毛病）。类比：中间商对客户说我是厂家、对厂家说我是客户。
**防御**：Snooping 绑定表核对 ARP 应答——攻击者声称 IP=1.2 但绑定表里 1.2 的 MAC 不是他 → 丢。

**③ 防御矩阵总览**：
| 攻击 | 防御 |
|---|---|
| 伪造 DHCP 服务器 | Snooping 信任接口 |
| DHCP 饿死（变源 MAC） | 端口安全限 MAC |
| DHCP 饿死（变 CHADDR） | chaddr 一致性检查（仅接入层） |
| ARP 欺骗/中间人 | Snooping 绑定表对 ARP 检查 |
| IP 源伪造 | IPSG 对源 IP 检查 |
| MAC 伪造 | 静态 MAC/端口安全 |
| 环路风暴 | 生成树（治本）+风暴控制（保命） |


### 2.6 现代安全演进：零信任（Zero Trust）与 SASE 云安全架构

传统网络依赖“边界防火墙城墙模式”，内网横向移动缺乏防御。现代化安全全面向零信任转型：
1. **零信任（Zero Trust / ZTNA）**：核心理念为“持续验证，永不信任”。无论在企业内网还是外部 Wi-Fi，所有访问必须先经过强身份鉴权与设备态势感知评估，仅授予单次最小权限；
2. **SASE（安全访问服务边缘）**：Gartner 提出的融合架构，将 SD-WAN 广域智能选路与云原生安全栈（SWG、CASB、FWaaS、ZTNA）在分布式边缘 POP 点深度合体，实现“全球极速直连、网络安全随行”。

## 三、总结

**核心重点十带走**：
1. 端口隔离本地有效：组内二层不通（拦 ARP）、组间互通=“双向隔离”（说的是组关系）；L2 模式+VLAN 内 ARP 代理可三层通，ALL 全断。
2. MAC 表三类：动态（学/老化/丢）、静态（绑定防欺骗——别口冒充源直接丢）、黑洞（源目皆杀，退烧式压制）。
3. 端口安全三态：动态（重启丢）、静态（手工保）、Sticky（自动粘住+save 保留）；五组合从全动态到全静态由松到严。
4. 惩罚三挡：restrict 丢+报（默认）、protect 丢不报、shutdown 关接口连坐断网——“一 MAC 一接口+shutdown”是责任到人的最严准入。
5. MAC 漂移是果不是因：环路→生成树根治；攻击→优先级（高优压低优）+禁同优覆盖；干道口用退 VLAN/单阻 MAC 精准处理。
6. 流量抑制：五种报文入向限速/出向阻塞/VLAN 只广播 bps——只丢包不伤接口；风暴控制：三种泛洪报文+block/error-down 惩罚+白名单——环路保命罩。
7. Snooping 信任接口：请求只从信任口出、非信任口的服务器报文一律丢——伪造服务器无米下锅。
8. 绑定表四元组（MAC/IP/VLAN/接口）是接入侧事实库：只记监听后的交互；无条件信任原则——不按表来全是假的。
9. 三大攻防：饿死攻击→限 MAC+CHADDR 核验（仅接入层，中继必误杀）；ARP 中间人→绑定表对 ARP 检查；IP 伪造→IPSG 四级粒度检查（⚠无表启用=除 DHCP 全断）。
10. MACSec=逐跳二层加密（IPSec 管广域网，它管交换机间），了解定位即可；全局心法：“不要指望一种技术解决所有安全问题——标本兼治多管齐下综合治理”。

**落地注意事项**：端口隔离上线前先确认是否需要三层通，需要则提前在网关开 ARP 代理（L2 模式）；Sticky 记得 save 否则白粘；shutdown 动作的端口提前配好 auto-recovery 或明确人工处置预案；风暴控制阈值参考业务高峰广播量再定，别拍脑袋；Snooping 部署顺序——先开监听等绑定表积累，最后才启用 IPSG（顺序反了业务全断）；信任接口只给连 DHCP 服务器的口，接 AP/交换机的口都别手滑；CHADDR 检查绝不部署在中继之后。

**学习建议**：本章特性多而碎，建议按“攻击—防御”配对记忆而非死背命令清单：每学一个防御先想“它防的是哪一招”。实验优先级：端口隔离四 PC 矩阵（半天搞懂组关系语义）、端口安全五组合各跑一遍观察重启行为（Sticky 的价值一目了然）、Snooping+IPSG 联动（先故意在无表时开 IPSG 打断全网，体会“事实库先行”的铁律）。MAC 漂移实验用两 PC 改同 MAC 人为制造，配合优先级调整观察“先学为王”。饿死攻击可用脚本灌 CHADDR 伪造报本，再上 chaddr 检查看攻击哑火——防御技术“看得见效果”才算真掌握。学完本章，第 11 章→18 的交换与接入体系全部闭环，下一站：第 19 章 IPv6 系列或第 22 章 MPLS。
