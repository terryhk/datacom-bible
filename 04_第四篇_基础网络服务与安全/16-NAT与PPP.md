## 一、总起

IPv4 地址不够用，私网地址在公网没有路由——包出去了回不来。NAT 在出口处改写地址让"多个人共享少数公网地址"；PPP 则是老牌广域网点到点链路协议，凭借"自带认证+自带地址分配"两板斧存活至今，还被以太网借去搞出了 PPPoE 宽带拨号。本章两讲各成体系：NAPT 讲透"地址+端口复用"的映射表机制与五种形态的适用场景（从领导专车到全员拼车）；PPP 讲透"三阶段协商"的骨架与 PAP/CHAP 的安全差异，压轴两个冷知识——**PPP 两端不同网段也能通**（NCP 协商生成对端 /32 主机路由）、**认证是单向的**（双向认证=两次独立的单向）。两讲共同的灵魂拷问都指向"路由是前提"：NAT 只做地址转换不做路由，PPP 只管链路协商不管全局路由。

**适用人群**：
- **初学 / 转行人员（HCIA 入门）**：理解公网与私网 IP 划分、NAT 地址转换基本机制，掌握点到点链路协议（PPP）连接与上网方式；
- **备考工程师（HCIA / HCIP 核心）**：攻克 NAPT 端口复用与 Easy IP 转换差异、NAT Server 端口映射、PPP 三阶段协商（LCP/认证/NCP）、PAP 明文与 CHAP 挑战握手认证、以及 IPCP 动态分配 IP；
- **一线工程实践者**：掌握企业出口多公网 IP 池规划、内网服务器对外安全发布、PPPoE 宽带接入拨号、以及跨网段 /32 主机路由自动生成的工程排错。

## 二、分述

### 2.1 私网为什么出不了公网

私网地址全网重复、不具备唯一性——**公网路由器不维护私网路由，回包无处投递**。不是路由协议不支持私网，是根本没有路由可查。所以 NAT 的本质是在出口改写地址，让回包有处可寻。

【设计本源与技术哲学】："做 NAT 的前提是路由还是要先做通——路由如果本身不通，你做什么 NAT 都通不了。"这条铁律贯穿全部五种 NAT：出口路由器要能回私网（回程路由），运营商要把企业公网地址段路由指到企业出口——**缺一条路由都不通**。

### 2.2 静态 NAT：一对一的专车

内网私网 IP ↔ 外网公网 IP **固定一对一映射**。出站改源 IP、回包改目的 IP。
- **优点**：真正的双向互通——外网可**主动**访问内网主机
- **缺点**：一个私网吃掉一个公网，地址成本最高
- **场景**：对外服务器、需要双向互访的少量主机（类比：领导配专车，一人一车）
```
interface GigabitEthernet0/0/1            # ★外网口（不是内网口！新手最常见配错）
 nat static global 203.1.1.1 inside 10.1.1.1
```
（系统视图配 `nat static global ...` + 外网口 `nat static enable` 是等价写法。）

### 2.3 动态 NAT：换着穿的鞋

从**地址池**随机取公网地址做一对一转换，每次不同（类比：多双鞋换着穿）。
```
nat address-group 2 203.1.1.2 203.1.1.3   # 起止必须连续
acl 2000
 rule permit source 10.1.2.0 0.0.0.255     # ★NAT 调 ACL 默认拒绝，必须显式 permit
interface GigabitEthernet0/0/1
 nat outbound 2000 address-group 2 no-pat  # ★no-pat = 不转端口 = 纯动态 NAT
```
**致命局限**：池里有几个地址就只允许几个人**同时**在线（第四人无地址可用）；外网主动访问理论可行实际没法用。现已很少单独使用。（模拟器上时通时断是已知 bug，防火墙上正常。）

### 2.4 NAPT：端口复用的拼车（企业上网主力）

**IP+端口一起转**，映射表用"公网 IP:不同端口"区分各内网主机的会话。一个公网地址理论支撑 65535 个会话；地址池 N 个地址 → N×65535。

```
interface GigabitEthernet0/0/1
 nat outbound 2000 address-group 2         # ★去掉 no-pat 即 NAPT（与动态 NAT 仅此一词之差）
```
- 实验实证：PC2/PC3 出网后 `display nat session` 显示同转 203.1.1.5 不同端口
- **局限**：外网**不能主动**访问内网——没有事前映射，路由器不知道该还原来给谁
- 【设计本源与技术哲学】："端口号提高了 IP 地址提供服务的能力——一个地址用不同端口提供不同服务、访问不同服务。"

### 2.5 Easy IP：不建池的 NAPT

本质=NAPT，但不建地址池，**直接借外网接口的 IP** 做转换：
```
interface GigabitEthernet0/0/1
 nat outbound 2004 interface               # 用出接口 IP，无池
```
场景：家庭宽带/小办公室——外网地址 PPPoE 拨号动态获取，根本没法预建池。

### 2.6 NAT Server：有限服务的定向发布

只把**指定协议+指定端口**映射出去（对比静态 NAT 的全端口全协议裸奔）：
```
interface GigabitEthernet0/0/1
 nat server protocol tcp global 203.1.1.10 www inside 10.1.5.1 www
 nat server protocol tcp global 203.1.1.10 ftp inside 10.1.5.1 ftp
 nat server protocol icmp global 203.1.1.11 inside 10.1.5.1
```
- 只映射 HTTP 时，FTP 登录失败、Ping 失败——**没映射的服务就是不通**（实验逐项验证）
- 灵活玩法：同一服务器 Web 用 .10、Ping 用 .11（迷惑外网侦察）；多台服务器不同服务共用同一公网地址不同端口
- ★**单向性**：NAT Server 只有外→内静态映射，服务器**不能主动出网**——要上网须叠加 NAPT（组合拳：NAPT 管出、NAT Server 管入，出向 203.1.1.5 入向 203.1.1.10 互不干扰）。"不要胡子眉毛一把抓。"
- NAT 破坏 IPv4 端到端对等模型：安全上有利（隐藏内网），管理上添乱（溯源难）

### 2.7 PPP 骨架：三阶段协商

点到点链路协议，协商全自动：**LCP（链路层）→【认证（可选）】→ NCP（网络层）**。
- LCP 报文协议号 **C021**；NCP/IPCP **8021**；普通 IP 数据 **0021**；PAP **C023**；CHAP **C223**（★五个协议号必背）
- LCP/NCP 报文体四件套：**Code（01=Request / 02=ACK / 03=NAK / 04=Reject）+ ID（请求响应配对）+ Length + Data**
- 帧结构：Flag(7E) → Address(**FF 全 1**，点到点无需寻址，全 1 应付了事) → Control(03 无编号) → Protocol → 信息 → FCS

【节奏铁律】协商是阶段性的——LCP 过了认证才登场，**链路建立后再补配认证不会触发**，必须 `shutdown`/`undo shutdown` 重建（类比叫号过号重来）。工程定位：重点把握状态机流转框架，不必死记字段十六进制取值。

### 2.8 LCP 协商三参数与三种应答

默认协商：**MRU**（最大接收单元，默认 1500）、**认证类型**（配了认证才有；★认证方的 Request 才携带）、**魔术字**（随机数防环，不用管）。

| 情形 | 应答 | 处理 |
|---|---|---|
| 参数可接受 | ACK | 四包完成 |
| 参数不匹配（MRU 2000 vs 1500） | **NAK（带自己能接受的值）** | ★自动按**小的**兼容，无需人为 |
| 参数不认识 | **Reject** | 去掉该参数重发 |

重传：3 秒一次，连续 10 次无回应判死。

### 2.9 PAP vs CHAP：明文与挑战

**★认证是单向的**——所谓双向认证=两个独立单向过程，方向间的用户名密码互不相干、认证方式也可各选各的（实验：R1 对 R2 跑 PAP、同时 R2 对 R1 跑 CHAP，互不干扰）。类比：考 HCIE 是华为认证你，不是你质疑华为。

**PAP（C023)**：被认证方**主动**发用户名+密码——**明文**，两次握手（Request→ACK/NAK）。快但不安全。
```
# 认证方 R1
aaa
 local-user R2 password Huawei@123
 local-user R2 service-type ppp
interface Serial1/0/0
 ppp authentication-mode pap
# 被认证方 R2
interface Serial1/0/1
 ppp pap local-user R2 password Huawei@123
```

**CHAP（C223）**：认证方**主动**发挑战——三步握手：
1. Challenge：随机 ID + 空用户名 + 随机数
2. Response：被认证方用**本地存的密码**+ID+随机数算 MD5，回用户名+MD5 值（**密码本身不上链路**）
3. Success/Failure：认证方用同样原料本地算 MD5 比对
```
# 认证方 R2
aaa
 local-user R1 password Cisco@123
interface Serial1/0/1
 ppp authentication-mode chap
# 被认证方 R1
interface Serial1/0/0
 ppp chap user R1
 ppp chap password Cisco@123
```
★MD5 一致≠密码曾明文传输——两边各用**自己存储的**密码独立计算，间接证明密码相同。安全但不传密码。

**认证类型一边 PAP 一边 CHAP**=管理员配置错误，协商必败。

### 2.10 NCP 地址协商：PPP 的独门绝技

**静态协商**：双方 NCP Request 各携本端 IP，对方验合法+不冲突即 ACK。协商成功后路由表**自动生成对端 IP 的 /32 直连主机路由**（出接口=本 PPP 口）。
- ★**由此 PPP 两端 IP 不同网段照样通**——以太网做不到（无 ARP 可用，点到点链路根本不需要二层寻址）。经典考点。

**动态协商**（PPP 自带 mini-DHCP）：
```
# 分配方 R1
ip pool ppp
 network 3.3.0.0 255.255.0.0
interface Serial1/0/0
 remote address pool ppp
 ppp ipcp remote-address forced
# 被分配方 R2
interface Serial1/0/1
 ip address ppp-negotiate
```
流程：被分配方带 0.0.0.0 请求 → 分配方 NAK 给地址 → 再 Request → ACK。R2 得 3.3.0.x，R1 自动生成 `/32` 主机路由。**不需要 DHCP 服务器**。

**PPPoE 本质**：以太网自己没有认证和动态地址分配——**借 PPP 的这两板斧**封装在以太网上跑，成就家庭宽带拨号。【设计本源与技术哲学】："以太网就捡了一个大便宜，把 PPP 的这两个功能用到 PPPoE 业务里，然后大发其财。"会话建立后靠周期 Echo Request/Reply 保活。三层交换机能否做 PPPoE 服务器——看软件功能，与硬件类型无关："所有网络技术都是软件功能。"

## 三、总结

**核心重点十带走**：
1. 私网出不去的根因=公网无私网路由回不了包；NAT 前提是路由先通（出口回私网 + 运营商回公网段，缺一不可）。
2. 静态 NAT 一对一双向通（专车）；动态 NAT 池里随机一对一（换鞋穿），N 人在线需 N 地址——已淘汰边缘。
3. NAPT 地址+端口一起转（去掉 no-pat 一词之差），一个公网 65535 会话；外网不能主动进。
4. Easy IP=不建池的 NAPT，借外网口 IP——拨号动态地址场景唯一解。
5. NAT Server 只放指定协议端口：全端口裸奔→定向发布；单向性要叠加 NAPT 才能出网；同服务器多公网地址/多服务共一个地址皆可玩。
6. NAT 调用 ACL 默认拒绝（与 traffic-filter 默认放行相反）——必须显式 permit。
7. PPP 三阶段 LCP→认证→NCP；五协议号 C021/8021/0021/C023/C223；Code 四值 Request/ACK/NAK/Reject；Address=FF 无意义的仪式字段。
8. LCP 三参数 MRU/认证类型/魔术字；不匹配回 NAK 自动取小兼容，不认识回 Reject 删参数重发；链路建立后补配认证无效须重启接口。
9. 认证单向：PAP 明文两次握手（被认证方主动），CHAP 挑战三次握手（认证方主动、密码不上链路、MD5 间接验证）；双向认证=两次独立单向可混搭。
10. NCP 静态协商生成对端 /32 主机路由→**跨网段直连成立**；动态协商自带 mini-DHCP（0.0.0.0→NAK 分配→ACK）；PPPoE=以太网借 PPP 认证+分配两板斧。

**落地注意事项**：静态 NAT/NAT Server 一律配在**外网口**；上线清单必含两向路由核对；FTP 测试用主动（Port）模式，被动模式模拟器测不通；地址池必须连续、同一地址不得进多个池；服务器完整方案=NAPT+NAT Server 组合拳；PPP 排错先抓包定位卡在哪个阶段（LCP 卡参数、认证卡用户名密码、NCP 卡 IP），改完认证记得重启接口重协商；命令记不全查产品手册——"资料都给你了你就不看，那你怎么学得好？"

**学习建议**：NAT 部分按"五种形态逐个实验"推进，每种都做两件事：`display nat session` 看映射表实况、故意删一条路由验证"路由不通 NAT 白搭"。PPP 部分核心实验就一个：单向 PAP+单向 CHAP 同链路共存的抓包全景（LCP 四包→PAP 两包→CHAP 三包→NCP 四包），配合动态地址分配实验看 /32 主机路由自动出现——两实验做完，PPP 知识点全部落地。PPPoE 建议回家看看自己路由器的 WAN 口配置，对号入座。学完本章，IA 阶段出口技术收官，接下来第 17 章《防火墙与VRF》进入安全域模型与虚拟化路由的世界。

## 附：本章术语速查表

| 术语缩写 | 英文全称 | 中文含义 | 关键作用 |
|---|---|---|---|
| **NAT** | Network Address Translation | 网络地址转换 | 在网络边界路由器改写 IP 报文头部的源/目的 IP，解决私网访问公网问题 |
| **NAPT** | Network Address Port Translation | 网络地址与端口转换 | 同时转换 IP 地址与传输层端口号，实现成百上千内网主机共享单个公网 IP |
| **Easy IP** | Easy IP (Interface-based NAT) | 基于接口的简易 NAT | 借用路由器出口公网接口的现有 IP 地址进行 NAPT，常用于拨号动态获取 IP 场景 |
| **PPP** | Point-to-Point Protocol | 点到点协议 | 专用于串行点到点链路的数据链路层协议，内置 LCP 链路协商、认证与 NCP 网络协商 |
| **PAP** | Password Authentication Protocol | 密码认证协议 | 基于明文传输的简单两次握手链路认证协议，安全性较弱 |
| **CHAP** | Challenge Handshake Authentication Protocol | 挑战握手认证协议 | 引入随机挑战字与 MD5 哈希的三次握手认证协议，密码不上链路，安全性高 |
| **PPPoE** | PPP over Ethernet | 以太网承载点到点协议 | 将 PPP 帧封装在以太网帧中传输的技术，实现以太网环境下的用户接入控制与计费 |
