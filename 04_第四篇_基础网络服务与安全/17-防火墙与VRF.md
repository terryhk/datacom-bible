## 一、总起

路由器按"有没有路由"转发，防火墙按"该不该转发"裁决——这是个哲学层面不同的设备。本章三讲把华为防火墙从零拆到深：第一讲立地基（安全区域模型：域内默认通、域间默认拒、Local 是防火墙自己；安全策略三要素、匹配次序、**管理型流量必须 service-manage 而不是安全策略**的翻车现场）；第二讲钻内核（状态检测会话表、首包机制、**Server-Map→目标NAT→路由→源NAT→安全策略**的包处理次序、FTP 主动/被动模式抓包实据、ASPF 一条命令驯服多通道协议），随后 VRF 登场——"把每个 VPN 实例当成一台独立的路由器"，一部设备多张路由表的魔法；第三讲收尾 VRF 实战（实例间直接互通的两条路、带实例的 ping 测试、下一代 VXLAN 的伏笔）。防火墙与 VRF 看似两个主题，内核却是同一件事：**用逻辑边界替代物理边界**——安全区域是流量的逻辑边界，VRF 是路由的逻辑边界。

**适用人群**：
- **初学 / 转行人员（HCIP 进阶）**：理解状态检测防火墙与传统路由器 ACL 的本质区别，掌握安全区域（Trust/DMZ/Untrust/Local）划分与安全策略编写；

## 二、分述

### 2.1 防火墙定位与形态部署

**是什么**：安全隔离设备，**双向默认隔离**——"就像生活中的墙：你出不去，别人也进不来"。功能全家桶：内外网隔离、上网行为管理、内容过滤、入侵防御（IPS 特征库匹配漏洞）、网络级防病毒（类比新生儿疫苗——公共卫生而非个体医护）。

**三形态**：框式（9 开头，运营商/数据中心出口）、盒式（中小企业）、软件墙（USG6000V 虚拟机，模拟器同款，功能真实）。

**两部署模式**：三层（路由）模式接口配 IP 功能完整但要动现网地址；**二层（透明墙）** 配 Trunk 不配 IP（"就像交换机的两个口多了安全检测"），对现网零改造，但**不支持 IPSec/SSL VPN/NAT**（模拟器有 bug 只能配不能生效）。发展史：包过滤（ACL 时代）→ 1994 状态检测 → 1998 ASIC 芯片 → UTM 多合一 → 2008 多核 → 下一代（用户/应用/内容维度）→ AI 防火墙（华为 CIS 态势感知+沙箱+大数据整体方案，"单用玩不了 APT"）。

### 2.2 包过滤 vs 状态检测（★防火墙的分水岭）

**包过滤**：逐包查 ACL——100 条规则可能查到第 89 条才命中，性能差；**双向隔离要求每个业务双向放行**（出一条回一条还得精确到端口），配置量爆炸。实验实证：只放出向 Telnet 仍不通，回包被反向 ACL deny——补一条精确到端口的反向 permit 才通。

**状态检测（★现代防火墙标配）**：
- **只检查会话首包**，通过即建会话表（源目 IP/端口、序列号、标记位）；后续包与回包查表即过——**反向不用写策略**
- 检查 TCP 序列号与标记位合法性——比包过滤**更安全**（不是只快）
- ASIC 专用芯片（类比 GPU 专算图形）+ 多核分布式架构，性能无虞

【设计本源与技术哲学】："所以现在我们的防火墙基本上都是属于状态检测的类型。"

### 2.3 安全区域模型（★一切策略的地基）

**四默认区域**（不可删、优先级不可改）：**Trust**（内网）、**Untrust**（外网）、**DMZ**（服务器区）、**Local**（防火墙自身）。优先级 1~100 表达信任程度——★**没有实际用途**，只是认知标签；自定义区域优先级必须唯一。

**三条铁律（实验逐条验证"密不透风"）**：
1. **域内默认放行**（同区域接口间流量自由）
2. **域间默认拒绝**（Trust↔Untrust、Trust→Local、Untrust→Local……全不通，只有 Local→Local 通）
3. **接口加入区域=接口下挂的网络加入该区域；接口本身永远属于 Local**

**流量方向判断法**：看源/目标地址落在哪个区域；源或目标是**防火墙自身接口 IP → 必然涉 Local**（10.1.1.1 防火墙口→10.1.2.2 即 Local→Trust）。

### 2.4 安全策略与 service-manage（★本章最大翻车现场）

**策略三要素**：①条件（源/目区域、源/目 IP、服务、用户、应用、URL、时间段）②动作 permit/deny ③安全配置文件（可选，对放行流量再做反病毒等内容检查——"什么协议配什么档案，对号入座：坐车戴头盔可以，打伞没必要"）。

**条件匹配**：定义的条件**同时满足**（与）；同类多值是**或**（目标区域写 DMZ 和 Untrust 任一命中）；没定义=不关心。按配置次序从上到下，**精确在前宽泛在后**（ACL 同款经验）。

**★管理型流量专题（实验翻车后总结）**：
| 谁访问谁 | 用什么 |
|---|---|
| 其他设备**访问防火墙**（Ping/HTTP/Telnet/SSH/SNMP 管理型协议） | **`service-manage permit` 接口开洞**——安全策略写了白写！ |
| 其他设备访问防火墙（OSPF/ESP 等非管理型） | 正常写安全策略（→Local） |
| **防火墙主动访问**其他设备（任何协议） | **必须写安全策略**（Local→目标区域），无 service-manage 的事 |

service-manage 的语义：在哪个接口开的洞，从该接口进来的指定协议就被允许访问**防火墙所有接口地址**。实战：内网口开 Telnet+Ping+HTTP、外网口只开 Ping——内网可管，外网只能测通。

**全局开关**：`default action permit` 域间全通当路由器（临时排障用）；域内包过滤开启后域内也默认拒。

### 2.5 会话表、包处理次序与长连接

**会话表机制**：首包（TCP SYN=1/ACK=0 规范性检查）过策略 → 建表 → 后续与回包查表放行。不同协议不同老化时间（TCP/HTTP/DNS/ICMP 各异）。

**包处理次序（★必须牢记的硬核结论）**：
```
查会话表（命中=非首包直接转发）
  ↓ 未命中 → 状态检测
Server-Map → 目标NAT → 查路由表 → 源NAT → 安全策略 → 建会话 → 转发
```
（流程图是模块次序示意不是铁板钉钉，以产品手册 USG6000 为准。）

**长连接**：会话老化时间 < 业务空闲时长 → 表被提前删 → 后续包匹配不到会话被丢。真实案例：医生问诊时系统空闲，开药单时被迫重新登录。解法：为指定流量配超长老化时间的长连接。

### 2.6 多通道协议与 ASPF/Server-Map（★防火墙精华）

**单通道**：一个端口一条连接（Telnet/SSH/HTTP/SMTP/POP3）——一条策略搞定。**多通道**：控制通道+数据通道各自建连（FTP/SIP/H.323）。

**FTP 两模式抓包实据**：
| 模式 | 数据通道谁发起 | 目标端口 |
|---|---|---|
| 被动模式 | 客户端→服务器（P1×256+P2） | **伪随机**（实测 144×256+92=36956） |
| 主动模式 | 服务器(:20)→客户端 N+1 | 伪随机 |

（"FTP 用 20 端口"说法不精确——20 只是主动模式的**源**端口。）

**防火墙痛点**：数据通道端口随机没法写精确策略；主动模式方向还相反。

**ASPF（应用层包过滤）**：读应用层载荷、预判协议未来行为。工作流（主动模式为例）：
1. 管理员只写**控制通道**一条策略
2. ASPF 从控制通道嗅出数据通道三元组（源/目 IP+端口）→ 动态生成 **Server-Map 表项**（临时，实测约 9 秒老化）
3. 数据通道首包到达 → **先查 Server-Map（在安全策略之前！）** → 命中放行 → 生成正式会话表
4. `firewall detect ftp` 一条命令（默认已开）；会话表中可见 FTP 与 FTPData 两个会话

【价值】"把多通道协议当成单通道协议用——把复杂的交给了产品，把简单留给了管理员。"关掉 ASPF 的实验现象：登录成功但 dir 无数据（控制通道活在，数据通道死透）；补救只能按地址粗放——不安全。附赠细节：防火墙会做**端口扰乱**（华为思科皆有），实验端口与理论值不一致属正常。

### 2.7 防火墙 NAT 三式

| 式 | 命令骨架 | 说明 |
|---|---|---|
| 地址池 | `nat address-group pool` → `nat-policy rule` → `action source-nat address-group` | 默认 PAT；`no-pat` 只换地址不换端口 |
| Easy IP | `action source-nat easy-ip interface G1/0/1` | 借出接口地址，免 destination-zone |
| NAT Server | `nat server protocol tcp global 8.8.8.8 53 inside 192.168.1.10 53` | 可加区域限定（如只对 Untrust 开放） |

★**黄金规则**：无论什么 NAT，**安全策略只放两端主机的真实 IP**（网卡上配的地址）——"日常工作中就只放真实 IP，不用管 NAT 之后的地址"（安全策略在 NAT 之前处理）。NAT 对多通道协议还会转换应用层内嵌地址（NAT ALG），否则 FTP 服务器回连私网地址必死——"NAT 把网络搞得很复杂，所以 IPv6 的观念是能不用就不用"。

### 2.8 VRF：一台设备、多张路由表

**定义**：VPN 实例（ip vpn-instance），路由隔离、一网多用。**三核心特点（逐一实验验证）**：
1. **一组绑定的路由接口**：物理口/子接口/VLANIF/VBDIF/隧道口均可绑定
2. **独立地址空间**：不同实例 IP 可重叠（类比：一台物理机装两台虚拟机各装一套 Office）
3. **独立路由协议**：各实例各跑各的 OSPF/静态，各自一张表

**Public 实例**：华为三层设备默认自带（类似生成树实例 0），未绑定的接口全在 Public。
```
ip vpn-instance A
 route-distinguisher 1:100     # X:Y 格式，本地唯一
interface Vlanif10
 ip binding vpn-instance A     # ⚠绑定瞬间原 IP 被清空，必须重配
```
【设计本源与技术哲学】："VRF 就是把每个 VPN 实例当成一台独立的路由器在看待——直接配就行了。"

**园区网隔离实验全景**（办公 A 网 VLAN10/20 + 监控 B 网 VLAN30/40 同一核心）：
- 无 VRF：四网段同表全网通
- 建实例绑接口：`display ip routing-table vpn-instance A` 只剩 10/20，B 只剩 30/40——设备共 **Public+A+B 三张表**，隔离生效，跨实例 ping 不通
- 实例内运行 OSPF：`ospf 1 router-id X vpn-instance A`——如同独立虚拟路由器
- **跨实例上网双路由**（★写法必背）：
```
ip route-static vpn-instance A 0.0.0.0 0.0.0.0 20.1.1.1 public   # 实例A缺省，下一跳去Public找
ip route-static 10.1.10.0 24 vpn-instance A 10.1.100.1           # Public回程，进实例A找
```
- OSPF 跨实例收五类 LSA 计算默认路由需补 `vpn-instance capability simple`

【设计本源与技术哲学】："什么叫网络虚拟化？这就是网络虚拟化！"

### 2.9 VRF 实例间直接互通（不走 Public 绕行）

**痛点**：两实例互通若绕 Public，前提是公网设备有回程路由——"实际上公网设备不可能有你内网两个网的路由"。

**正解（核心交换机上写）**——★架构设计中必须强调此实验"实验手册里肯定没有、市面上找不到，必须自己做"：
```
ip route-static vpn-instance A 10.1.30.0 24 vpn-instance B 10.1.200.1
                       # 实例A中加去往实例B 30网段的路由，下一跳=实例B接口地址
ip route-static vpn-instance B 10.1.20.0 24 vpn-instance A 10.1.100.1
```
**两方案对比**：
| 方案 | 下一跳写法 | 工作量 |
|---|---|---|
| **核心交换机上做（经典款）** | 网段路由，第三方设备同时挂两实例接口，下一跳好写 | 小（几条网段路由） |
| 网关上直接做 | 只能写 **/32 主机路由**（下一跳不能是自己接口） | 巨大（逐主机） |

类比：核心做=十字路口交警统一指挥；网关做=给每辆车单独指路——车多指不过来。

**测试必带实例名**：三张表并存时路由器不知用哪张查——`ping -vpn-instance A -a 10.1.100.2 10.1.10.254`。类比：找"三年级八班姓阮的学生"得先说哪个学校。**伏笔**：VXLAN 集中式网关跨 VPN 访问与此逻辑同源，第 26 章 再会。

### 2.10 防火墙双击热备（防火墙1讲重头戏）

**痛点**：两台墙各跑各的 VRRP——上行组.active 在墙一、下行组.active 在墙二 → 去程建会话在墙一、回程到墙二无会话 → 丢包。

**解药双协议**：**HRP**（华为冗余协议，私有）：心跳线（可 Eth-Trunk 多条）同步配置与会话表；**VGMP**（VRRP 组管理协议）：把防火墙所有 VRRP 组绑一起——一组切换全体切换，保证来回同墙。【类比】"杰克和露西——你跳我也跳，最后死的是那个男的。"部署硬要求：**两台设备型号/版本/接口卡数量位置必须相同**（"一份菜炒两份一样的"）。

**同步范围（★）**：自动同步=安全策略/NAT/区域/用户/IPSec/SSL VPN 等；状态同步=会话表/ServerMap/黑白名单/AAA；**不同步=OSPF 等路由协议配置、接口 IP、静态路由**（要单独配）。

**四种组网形态**：
| 组网 | 主备备份 | 负载分担 |
|---|---|---|
| 上下行均 VRRP | 一台 active 一台 standby；`link-group` 接口联动加速收敛 | 两组 VRRP 交叉主备 |
| 上下行均 OSPF | **备墙 `hrp standby force`**：自动通告开销 **65500**（"这不就是 OSPF 末节路由器吗"），主墙正常 1；切换时开销自动翻转 | 双机均 Active 名义上按主机名 ASCII 定名主；`hrp mirror session enable` 会话实时镜像——来回不同墙也不丢包 |

**负载分担不推荐（★原厂立场）**：来回路径不一致使 IPS/防病毒/垃圾邮件过滤**误判漏判**、IPSec 排障困难——"性能问题用钱可以解决，出了问题钱解决不了"。"首选项就是主备备份：数据中心、IDC、互联网出口都很少用负载分担。"切换机制：主墙接口故障 → VGMP 优先级每口降 2 → 心跳通告 → 备墙抢主发免费 ARP 引流；回切默认延迟 60 秒。`hrp standby config enable` 开启后备墙也能配（自动同步到主墙）。

### 2.11 虚拟系统（VSYS）：防火墙里的防火墙

**概念**：一台物理墙切成多个虚拟防火墙——独立账号/权限/路由表/接口，"你就当成一个一个的防火墙去理解"。类比：物理机装虚拟机，根系统=物理防火墙本身（仍可过滤流量）。

**两种分流**：**接口分流**（物理口直接指派）；**VLAN 分流**（接口变 Trunk 按 Tag 分流）。
```
vsys enable
vsys name A
 assign interface GigabitEthernet1/0/0      # 接口分流
 assign vlan 10                             # VLAN分流
switch vsys A                               # 进虚墙配置视图
```
**内部逻辑**：每虚墙自动创建 Virtual-if（编号=虚墙 ID，根墙永远 0），相互全互联如同一个广播域。**路由规则（★）**：
- 虚墙→根墙：写缺省路由指向 `public`
- 根墙→虚墙：静态路由指向对应 `vpn-instance`
- **虚墙间互访必须根墙配静态路由**（`ip route-static vpn-instance A 20.1.1.0 24 vpn-instance C`）——安全考虑，根管理员管控
- 过根墙的流量**两层都要放行**（虚墙+根墙）；虚墙直连流量根墙虚拟接口同区域默认放行

实验实证单向性："虚墙 A 放行 Trust→Untrust、虚墙 C 放行 Untrust→Trust → A 主动访 C 通，反过来不通——单向放行，外网主动访问你不行。"

## 三、总结

**核心重点十带走**：
1. 防火墙=双向默认隔离的墙；三形态（框/盒/软件）两部署（三层全功能/透明墙零改造但不支持 IPSec/NAT）。
2. 状态检测=只查首包建会话、回包查表即过、反向免策略、查序列号标记位比包过滤更安全；包过滤双向精确放行配置爆炸。
3. 区域模型：域内默认通、域间默认拒、Local=防火墙自身；接口入区=下挂网络入区，接口本身永远 Local；优先级只是标签无实际用途。
4. 管理型流量（Ping/Telnet/HTTP/SSH）访问防火墙**只能 service-manage 接口开洞**，安全策略写了白写；防火墙主动出访**必须**安全策略（Local→区域）；非管理型（OSPF）正常走策略。
5. 策略三要素（条件与或规则：定义条件同时满足、同类多值或、未定义不关心），精确在前宽泛在后；包处理次序 **Server-Map→目标NAT→路由→源NAT→安全策略**。
6. ASPF 读应用层预判未来：控制通道一条策略+`firewall detect`，数据通道 Server-Map 自动放行（首包先查 Server-Map 再查策略，临时表约 9 秒老化）；FTP 目标端口是 P1×256+P2 伪随机，20 只是主动模式源端口。
7. 防火墙 NAT 三式同路由器，但**安全策略永远只放真实 IP**（策略在 NAT 前处理）；NAT 对多通道协议需 ALG 转换内嵌地址。
8. VRF 三特点=绑定接口+独立地址空间+独立路由协议；绑定瞬间清 IP 要重配；设备默认 Public 表；跨实例上网双路由写法（实例缺省指 public + Public 回程指 instance）。
9. 实例间直接互通在核心做网段路由（下一跳=对方实例接口地址）；网关上做只能 /32 主机路由工作量爆炸；测试必带 `ping -vpn-instance`。
10. 双击热备：HRP 同步配置+状态、VGMP 统一切换（"你跳我也跳"）；路由协议配置不同步要单独配；VRRP 组主备 active/standby、OSPF 主备备墙自动通告 65500（末节路由器同款思想）；负载分担原厂不推荐（误判漏判+排障难）。虚拟系统接口/VLAN 两分流，虚墙间互访根墙说了算，过根墙两层放行。

**落地注意事项**：排错第一步先查接口有没有加进安全区域（IP/路由/策略全对还不通的头号原因）；service-manage 只在指定接口开洞——外网口管好 Telnet/SSH 只留 ping 是基本素养；双机部署前核对型号/版本/板卡完全一致；心跳线只跑同步不走业务（华为方案）；OSPF 主备的 65500 开销是**默认隐藏机制**——display 配置看不见但在生效（"最坑的就是默认配置"）；IPSG 在没有绑定表时启用=除 DHCP 外全拒（全网断）；虚墙间互通改路由必须找根墙管理员。

**学习建议**：防火墙部分把"五个实验"都走一遍：包过滤双向放行对比（体会状态检测的价值）、区域密不透风验证、service-manage 翻车重演（安全策略写了不通→接口开洞立通，一遍终身免疫）、FTP ASPF 开关对比看 Server-Map 生灭、双机热备主备切换看会话同步（remote 标记）。VRF 部分核心就在两张图：三张路由表的隔离验证、跨实例上网的双路由流向——在纸上画出报文从实例 A 到公网再回来的完整路径（每跳标注查哪张表），画通即毕业。虚拟系统建议做一个虚墙 A/B/C 互通矩阵实验，把"两层放行"的手感练出来。学完本章即可进第 18 章《网络安全技术》（接入层攻击面防护）或直接跳第 22 章 MPLS（VRF 就是 L3VPN 的地基）。
