## 二、分述

### 2.1 路由控制四件套与"拒绝优先"

**四条命令（★核心必掌握命令）**——按工具能力从弱到强：
| 工具 | 命令 | 能力 |
|---|---|---|
| ACL | `peer <邻居> filter-policy <acl> import/export` | 只能过滤（ACL 默认语义 permit=允许收发） |
| 前缀列表 | `peer <邻居> ip-prefix <名> import/export` | 只能过滤 |
| AS-Path-Filter | `peer <邻居> as-path-filter <编号> import/export` | 只能过滤（按 AS_Path 匹配） |
| Route-Policy | `peer <邻居> route-policy <名> import/export` | 过滤 + 改属性一把抓 |

**★多条策略"拒绝优先"规则**：同一邻居同一方向挂多个过滤策略（如 ACL 允许而 Route-Policy 拒绝同一条路由）时——**拒绝优先生效**。本质：所有工具做的都是"允许/拒绝"二元判断，工具之间没有优先级，只看动作。【设计本源与技术哲学】：逻辑上不要把它想复杂——过滤器的世界只有"放行"与"拦截"。

**ACL/前缀列表实验**（方框形四 AS 拓扑，R1 引入静态 1.0/2.0/3.0）：
```
acl 2000
 rule permit source 192.168.1.0 0.0.0.255
bgp 1
 peer 10.1.12.2 filter-policy 2000 export        # R1 对 R2 只放行 1.0
```
现象：R2 只有 1.0 走 R1；2.0/3.0 绕道 R4→R3→R1。前缀列表版本等效（`index 10 deny 192.168.2.0 24` + `index 20 permit 0.0.0.0 0 less-equal 32`）。

**思考题的完整因果链**（经典排错逻辑推演）：R2 上为何没有 R4 转传过来的 1.0？——R4 从 R2/R3 都收到 1.0 → R4 优选 R1 方向（Best）→ 从 R3 学到的 1.0 不是最优 → 不再传给 R2。**BGP 只通告最优路由**。【设计本源与技术哲学】："你要说清楚是谁由于什么原因所以导致了什么结果。"面试表达按这个三段式说。

### 2.2 AS_Path 正则表达式与 as-path-filter

**为什么需要**：过滤"经过某个 AS 的所有路由"，前缀列表要写一千条，AS-Path-Filter 一句正则搞定。形象工程类比：正则表达式像日料——工作里偶尔用，不必焦虑其复杂性。

**正则 = 直接量 + 元字符**（元字符类比数学里的"+ - × ÷"，表逻辑不当数值）：

| 元字符 | 含义 | 例子 |
|---|---|---|
| `.` | 任意一个字符 | — |
| `*` | 前面字符 0 次或多次 | `123*` 匹配 12、123、1233… |
| `+` | 前面字符 1 次或多次 | `123+` 匹配 123、1233…不匹配 12 |
| `?` | 前面字符 0 或 1 次 | `123?` 匹配 12、123 |
| `^` | 字符串开始 | `^123` 以 123 打头 |
| `$` | 字符串结束 | `123$` 以 123 结尾 |
| `_` | 分隔符号（逗号/括号/空格） | `^123_`=123 作独立整体开头；`_123$`=独立结尾 |
| `([])` | 整体匹配 / 单字符或 | `_(123|456|68)_` 出现任一即匹配；`[567]`=5或6或7 |
| `[^]` | 反向选择 | `[^123]` 除 1/2/3 |
| `-` | 连续范围 | `[0-5]`=0~5 |
| `\` | 转义还原为直接量 | 匹配 AS_Path 里的真实括号 |

**必会案例（★）**：
- `^$` —— AS_Path 为空 = **本 AS 始发**的所有路由
- `.*` —— 匹配所有（放行兜底用）
- `_100$` —— **起源于** AS100 的路由
- `^100_` —— AS_Path 第一跳是 100
- `_100_` —— **经过** AS100 的路由
- `_1$` 起源于 AS1（注意 `_1$` ≠ `1$`：后者只要结尾是"1"字符就算，会误伤 AS11/21）

**两步用法**：
```
ip as-path-filter 1 deny _3_                # 拒绝经过 AS3 的路由
ip as-path-filter 1 permit .*               # 默认全拒，兜底必须加
bgp 2
 peer 10.1.24.4 as-path-filter 1 import     # 对 R4 入方向过滤
```
第二用途——**做匹配条件配合 Route-Policy 改属性**：
```
ip as-path-filter 2 permit _1$
route-policy MED permit node 10
 if-match as-path-filter 2
 apply cost 80                              # 起源于AS1的路由 MED改为80
route-policy MED permit node 20
bgp 2
 peer 10.1.12.1 route-policy MED import
```
**验证命令**：`display bgp routing-table regular-expression <正则>`——先在 BGP 表里筛出匹配路由，确认正则写得对不对再上策略。核心难点：**匹配多了**（误杀/误改）与**匹配少了**（漏杀/漏改）都要防；AS_Path 可能被人为修改，改完正则可能失效。

### 2.3 团体属性：打标两法与挤牙膏传递

**公认四件套（限制传递范围，范围从大到小）**：
| 团体 | 范围 | 类比 |
|---|---|---|
| Internet (0) | 不限，**所有 BGP 路由天生属于它** | 人生下来就是人 |
| No-Export | 只在 AS（联盟）内传 | 别出小区 |
| No-Export-Subconfed | 只在成员 AS 内传（仅 IBGP，连成员 EBGP 都不传） | 别出学校 |
| No-Advertise | 不传任何邻居（EBGP+IBGP 都不传） | 只在家玩 |

**自定义团体** `AA:NN`：AA 通常用自己的 AS 号，NN 表业务/客户维度；一条路由可带多个团体（"讲师/父亲/武汉人"多重身份多重管理维度）。定位区分：**AS-Path Filter 管 AS 之间的路由管理，团体属性管 AS 内部的业务路由管理**——前提是先做好团体规划、打好标签。

**★添加的两处位置（效果不同）**：
| 位置 | 命令 | 生效位置 |
|---|---|---|
| 产生路由时 | `import-route static route-policy COMM`（apply community 1:100 …） | **本地 BGP 表**：若加 No-Advertise，本地就不往外传 |
| 发给特定邻居时 | `peer x.x.x.x route-policy COMM export` | **邻居 BGP 表**：本地照传，限制在下一台执行 |

**★挤牙膏传递规则（核心实验链 R1→R2→R4）**：团体属性默认**不随路由传递**——想让谁看到就对谁配 `peer x.x.x.x advertise-community`。
- 现象①：R1 export 加了团体但不配 advertise-community → R2 有路由无团体；
- 现象②：R1 配了 → R2 收到团体；
- 现象③：加的是 No-Advertise → R2 收到后**不再传 R4**；
- 现象④：去掉 No-Advertise 且 R2 配 `peer 10.1.24.4 advertise-community` → R4 才收到带团体的路由。
类比：挤牙膏——不挤不出；击鼓传花——收到的人必须主动向下传。**单向配置**（我传给你取决于我），不影响邻居关系。考试按标准解法两端都敲（多敲不扣分）。

### 2.4 团体属性运营：增删改三操作与精确匹配

**三种修改（类比数据库三种基本操作）**：
| 操作 | 命令 | 效果 |
|---|---|---|
| 追加 | `apply community 2:100 2:200 additive` | 原有属性保留，追加新值 |
| 替换 | `apply community 2:100 2:200`（无 additive） | 全部覆盖，按我的来 |
| 清空 | `apply community none` | 删除所有团体 |

**community-filter 匹配**：
- 基本（1-99）：`ip community-filter 1 permit 1:100`——**模糊匹配**（路由团体里**包含** 1:100 即命中，不要求只有它）
- 高级（100-199）：支持正则表达式
- **精确匹配**：`if-match community-list 1 whole-match`——团体集合必须与列表**一模一样**，多一个少一个都不行。⚠加上 whole-match 后通常全不匹配（实际路由往往带多个团体）

**多列表组合是"或"关系**：`if-match community-list 1 2` = 模糊匹配1 或 模糊匹配2；`1 whole-match 2` = 精确1 或 模糊2。多条语句之间"或"，子集包含写法逻辑上没错。【设计本源与技术哲学】："本身这样写没错，逻辑上虽然有包含的关系，但写在用上面没有错。"

**精细删除指定团体（deny 专用参数）**：`apply community-list 2 deny`——只删列表 2 里定义的那几个团体。★要删的团体**必须一条一个分开写**（`permit 1:200` 单独一条、`permit 1:300` 单独一条），写成一行设备理解不了。实验结论：**先执行删除、再执行添加**。适用场景：【设计本源与技术哲学】："一条路由的团体属性很多，你要删掉其中一两个，你用删的方法比较方便——免去敲那么多团体属性替换。"

**综合实验**：R4 用团体列表匹配 R2 传来的路由（1:100/1:200/1:300）→ 替换团体为 2:100 + 拉长 AS_Path → R4 改选 R3 路径——团体+属性组合拳直接改变优选结果。

### 2.5 ORF 按需发送与对等体组模板

**ORF（出口路由过滤器）**：场景——R1 发 100 条给 R2，R2 过滤掉 99 条 → R1 白发浪费带宽。ORF 让**R2 告诉 R1**"我只要 1.0/24"，R1 只发这条。
```
# R2（需求发起方）
ip ip-prefix ORF-PREFIX permit 192.168.1.0 24
peer x.x.x.x capability-advertise orf prefix-list send
# R1（配合方）
peer x.x.x.x capability-advertise orf prefix-list receive
# 双向：both
```
- 邻居重建后 R2 的 Route-Refresh 报文携带 ORF 条目（抓包可见，对思科设备需加 compatible 参数才解析）
- **动态协商**：以后 R2 只改自己的前缀列表，R1 自动配合——新增 6.0 自动按需发送。【设计本源与技术哲学】："未来你只要改自己的前缀列表，R1 就能配合你做工作……不用打电话了。"
- 核心优势不是过滤本身，是**免协调的按需发送**。

**对等体组（模板化）**：多个邻居策略相同时（同 connect-interface、同 route-policy、同 next-hop-local），组模板一处配置全组继承：
```
group IBGP internal                       # IBGP 组
peer x.x.x.x group IBGP                   # 邻居入组
peer IBGP connect-interface LoopBack0     # 全组生效
```
- EBGP 组（`group EBGP external`）：AS 号不同的邻居仍需逐个指 as-number
- **单独配置覆盖组策略**：某邻居同方向挂了不同 policy → 组策略对该邻居该方向失效。一对一原则：**一个邻居一个方向只能有一个 Route-Policy**。

### 2.6 BGP 安全三讲：认证、GTSM、4 字节 AS 号

**MD5 认证**：`peer x.x.x.x password simple/cipher <密码>`。★HCIE 面试题：**BGP 报文本身没有认证字段**——认证信息放在 **TCP Option**（MD5 签名哈希）里。

**GTSM 通用 TTL 安全机制**：
- 威胁：攻击者伪造邻居 IP 发 TCP SYN（DDoS）或伪造报文，耗 CPU
- 原理：合法邻居 TTL 消耗固定（直连 255→254）；伪造报文来自更远处，TTL 不对
- 命令：`peer x.x.x.x valid-ttl-hops N`——双动作：**发送时 TTL 强制 255**；**接收时校验 TTL ≥ 255-N+1**，不达标在网络层直接丢弃（不进 CPU）
- ★N 取值=邻居间**跳数**；**多路可达取最大值**（两条路径跳数 2 和 4 → 配 4），否则链路切换后邻居断
- 直连 EBGP 取 1；IBGP 环回建邻取实际跳数

**4 字节 AS 号**：
- 背景：2 字节（1-65535）枯竭 → 4 字节（1-4294967295）；表示可用点分形式 X.Y，换算 **X×65536+Y**，内部按整数存储
- 兼容机制：Open 报文 MyAS 字段仍是 2 字节不动——AS 号超 65535 时该字段填**预留填充符 23456**，真实 4 字节号放可选参数 TLV；路由更新里新增 **AS4_PATH** 属性携带真实 4 字节号
- 防环不变：AS_PATH 或 AS4_PATH 里出现自己的号都算环
- 还原：按序用 AS4_PATH 的 4 字节号替换 AS_PATH 中的 23456（对号入座）
- 类比：100 斤的秤称不了 200 斤——再加一把 1000 斤的秤（AS4_PATH）
- 现网华为 AR 默认都支持 4 字节（New Session），兼容问题仅存理论；模拟器难以演示 Old Session（受限于虚拟化实验平台支持度，现网验证以真实设备为准）

### 2.7 联盟：大 AS 的"省界"治理

**动机**：100 台路由器的大 AS，RR 方案仍会产生大量邻居关系 → 联盟把大 AS 切成多个**成员 AS**。类比：大 AS=中国，成员 AS=省份——**对外只认联盟 AS 号，对内才关心成员 AS 号**。成员 AS 用私有号（65001/65005/65006）；联盟与 RR 可结合。

**配置两件套（★）**：
```
bgp 65001                                  # 成员AS号
 confederation id 200                      # 声明联盟AS
 confederation peer-as 65005               # 声明成员EBGP邻居有哪些
 peer 10.1.12.1 as-number 100              # 联盟外邻居：只认联盟AS号
 peer 10.1.25.5 as-number 65005            # 成员EBGP邻居
```
外部设备（R1）与联盟内路由器建邻时**只用联盟 AS 号 200**——你出国别人只认你是中国人，不问你是哪个省。

**下一跳三情形（华为 vs 思科差异，★）**：
| 路由来向 → 传给 | 默认下一跳 | next-hop-local |
|---|---|---|
| 联盟 EBGP 学来 → 成员 EBGP/IBGP | 不变 | 可改 |
| 成员 EBGP 学来 → 成员 EBGP/IBGP | 不变 | **改不了（华为）** |
| IBGP 学来 → 成员 EBGP | 不变 | **改不了（华为）**；思科可改 |

华为解法（工业级标准解法）：**整个联盟内 IGP 打通**（或环回建邻）——下一跳天然可达，问题消失；辅以静态/路由策略改下一跳。

**属性传递**：Local_Prefer 与 MED 在**整个联盟内透传不丢**（成员 EBGP 间也传，突破常规限制）；AS_Path 经过成员 AS 时记入**小括号**（如 `100 (65001) (65005)`）——**选路时小括号不计长度**；传出联盟时小括号整体剥离、替换为联盟 AS 号（`200 100`）。联盟内做 AS_Path 策略修改时**只能操作小括号部分**。

**防环规则（三行表）**：
| 从谁收 | 检查什么 |
|---|---|
| 联盟 EBGP 邻居 | AS_Path 里不能有**联盟 AS 号**（有成员号可以） |
| 成员 EBGP 邻居 | AS_Path 里不能有**自己的成员 AS 号**（有联盟号可以） |
| 成员 IBGP 邻居 | 不做 AS_Path 防环检测（同普通 IBGP） |

**选路**：成员 EBGP 学来的路由在选路时**当 IBGP 对待**（表里显示 I）——不存在"EBGP 优于 IBGP"的比较；AS_Path 长度只比括号外。考试导向：联盟考察少，运营商现网在用；命令和两个括号的语义要会。

### 2.8 BGP 路由汇总五参数

**核心思想**：IPv4 公网地址分配零碎，盲目汇总可能黑洞——所以华为默认汇总后**明细照发**，观察一段时间无问题再抑制明细。基础命令 `aggregate 172.16.0.0 255.255.0.0` 层层加参数：

| 参数 | 作用 | 关键细节 |
|---|---|---|
| （无） | 生成汇总路由，明细照发 | 汇总属性取默认值 |
| `as-set` | 汇总路由继承明细的 AS_Path | 用**大括号** `{1,2,3}` 无序汇集（AS-Set），**选路时整包算 1 个长度**；同时继承明细中**最低优先级**的起源属性（有 ? 和 i 时取 ?）与团体属性；**不继承** Local_Preference（华为保持默认 100） |
| `detail-suppressed` | 抑制**所有**明细 | 明细仍进本地路由表指导转发；副作用：**不再继承团体属性**（加 as-set 也不行） |
| `attribute-policy ATT` | 给汇总路由改属性 | 典型用途：detail-suppressed 丢团体后手动补；**不能改 AS_Path** |
| `suppress-policy SUP` | **选择性**抑制明细 | ⚠反直觉：**匹配的被抑制、不匹配的照发**；用于"无黑洞风险的明细压掉、有风险的保留"；与 detail-suppressed 同配时仅 suppress-policy 生效 |
| `origin-policy ORG` | 指定**条件路由** | 只有条件路由存在汇总才产生（条件消失→汇总立即消失）；范围外明细"脱离父子关系"——抑制策略管不到、属性也不继承 |

**不精确汇总黑洞案例（★）**：Cloud1 有 172.16.1.0/24、2.0/24 → 汇总成 /20 通告；Cloud3 有 3.0/24、4.0/24 → 也汇总成 172.16.0.0/21 通告（两个汇总重叠）→ Cloud2 访问 2.1 按最长匹配或开销选路，可能被引去 Cloud3 → 黑洞甚至环路。**解法**：对有黑洞风险的 2.0 明细用 suppress-policy 保留通告。

### 2.9 Fake AS：AS 号平滑迁移

**动机**：全 AS 从 100 换到 200，100 台路由器 `undo bgp 100` 重配不现实。**思路**：不是真改自己——**只让邻居觉得你变了**（类比：渣男行骗，自己还是自己）。配置只对 **EBGP 邻居**：
```
bgp 3
 peer 10.1.13.1 fake-as 100    # 骗R1：我在AS100
```
IBGP 邻居不用骗——AS 内部传递不加 AS 号。Open 报文与路由通告中用 fake-as 替换真实号；邻居侧把 peer 的 AS 号改成新号重建邻居即可。

### 2.10 收尾三法一表：缺省路由与 EBGP 建邻

**BGP 下发缺省路由三法**：

| 方法 | 命令 | 前提 | 特点 |
|---|---|---|---|
| ① Network | 表里先有缺省（如静态指向出口），再 `network 0.0.0.0 0.0.0.0` | 路由表存在缺省 | 向**所有**邻居发布；出口自己也要用它上外网时选这个 |
| ② 指定邻居无中生有 | `peer 10.1.13.1 default-route-advertise` | **无前提**（自己路由表/BGP 表可以都没有缺省） | 只对指定邻居下发；自己明细学全、不需要缺省，但下游需要；⚠**生效有延迟**不是立即出现；可挂 route-policy 改属性（MED/Local_Pref/AS_Path） |
| ③ 条件触发 | `peer x.x.x.x default-route-advertise conditional-route-match {match-all\|match-any} <网段1> <网段2>` | 条件路由存在于 **IP 路由表**（★不是 BGP 表） | match-all=条件全在才发，match-any=任一在即发；条件消失→缺省立即撤回（接口 shutdown 验证过，日志提示"缺省路由被改变"） |

【设计本源与技术哲学】：为什么允许"无中生有"？——R3 跑 BGP 明细学得全，自己根本不需要缺省；它只是**生产一条缺省告知 R1**："未知流量都发给我，我有明细帮你转发。"形式在变、本质不变：缺省路由就是指导未知报文转发的保底。

**四种 EBGP 邻居建立方法（曾为 HCIE 面试题，★）**：
1. 物理口直连建邻（基本款）
2. 环回口建邻 + `ebgp-max-hop`（TTL 放行）
3. 环回口建邻 + **GTSM**（`valid-ttl-hops`，发 255 收包校验，一举两得）
4. 单跳环回建邻 + **忽略 TTL 检查**（两端配置后 TTL=1 也能收，不放大域）
方法 3/4 场景特殊，但厂家不会多此一举设计命令——特定场景必有用武之地。

【设计本源与技术哲学】：（收尾寄语）"这种特性类的东西，大家就慢慢地去看一下产品手册，慢慢逐渐地掌握一些东西，增加自己的知识宽度。"——当前深度对考试够用。

## 三、总结

**核心重点十带走**：
1. 过滤四件套：filter-policy(ACL)/ip-prefix/as-path-filter 只能过滤，route-policy 过滤+改属性；**同一邻居同一方向多策略冲突 → 拒绝优先**。
2. 正则必会五式：`^$` 本AS始发、`.*` 全部、`_100$` 起源于100、`^100_` 首跳100、`_100_` 经过100；先 `display bgp routing-table regular-expression` 验证再上策略。
3. 团体打标两位置：import-route 时加=本地 BGP 表生效；peer export 时加=邻居生效。公认四件套范围 Internet > No-Export > No-Export-Subconfed > No-Advertise。
4. 团体传递挤牙膏：默认不传，逐跳 `advertise-community`，单向配置；增删改三操作 additive 追加/无参替换/none 清空；删除用 `apply community-list deny` 且一条一个分开写，先删后加。
5. community-filter：基本模糊匹配（包含即命中），whole-match 精确匹配（一多不少都算不匹配）；多列表间"或"关系。
6. ORF 发起方 send + 配合方 receive：把"你想收什么"推给上游，改自家前缀列表即自动生效——不用打电话。
7. 安全三件：认证在 **TCP Option**（HCIE 面试）；GTSM 发 255 收验 ≥255-N+1、**多路取最大跳数**；4 字节 AS 用 **23456 填充 + AS4_PATH** 防环不变。
8. 联盟：外部只认联盟号，内部 `confederation id/peer-as`；成员 EBGP 路由选路当 IBGP；AS_Path 小括号不计长、出联盟剥离换联盟号；华为 next-hop-local 对成员 EBGP 无效 → **全联盟 IGP 打通**是正解。
9. 汇总五参数递进：as-set 大括号继承防环（算 1）→ detail-suppressed 全抑制（丢团体）→ attribute-policy 补属性（改不了 AS_Path）→ suppress-policy 选择性抑制（**匹配即抑制**，保黑洞风险明细）→ origin-policy 条件触发（条件没了汇总消失）。
10. 缺省三法按前提选：自己也要用→network；自己不需要→peer default-route-advertise（无中生有、有延迟）；跟着出口健康走→conditional-route-match（查 IP 路由表，条件消失即撤回）。

**落地注意事项**：改团体策略前先想清楚生效位置（本地表还是邻居表）——加 No-Advertise 在本地表生效会直接断传；suppress-policy 的"匹配即抑制"方向最容易配反，上线前用display 逐条核对抑制清单；联盟改造优先 IGP 打通再动 BGP；GTSM 的 N 别忘多路径取最大；正则上线前必须 regular-expression 预检；对等体组里给个别邻居开小灶后，记得组策略对其已失效。

**学习建议**：本章四个主题各自独立、可拆开学。过滤与团体（2.1-2.4）建议在第 08 章 综合实验的六路由器拓扑上继续加做——过滤做在哪个邻居哪个方向、团体打在哪一跳，肉眼验证一遍终身不忘。联盟实验重点抓"配置三行 + 小括号的三个行为"（不计长、出联盟剥离、只能改括号内）。汇总五参数按表格从上到下逐个加参数观察 BGP 表变化，尤其是 detail-suppressed 丢团体再补的完整链路。收尾的三法缺省路由建议结合双出口场景做条件触发的完整实验。学完本章，BGP 知识体系（第 08 章+09）告一段落，可回归 IGP 高级特性（第 10 章）或进入 MPLS 体系（第 22 章-24）。
