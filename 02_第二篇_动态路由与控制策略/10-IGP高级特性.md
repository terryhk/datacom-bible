## 二、分述

### 2.1 OSPF 快收敛三件套

**PRC（部分路由计算）**：SPF 两步走——先算树（拓扑）再算叶子（路由）。当**只有路由信息变化**（网段增删）、拓扑不变时，PRC 跳过第一步只重算叶子。类比：冬天叶子掉了，树的真实面貌才露出来——树没变，只是叶子变了。什么算"叶子"：一二类 LSA 里的 Stubnet 与二类里的 DR 接口掩码、三类、五类 LSA。★**路由器默认具备此能力，无需配置**，理解即可。

**智能定时器**：对付"突发变化要快、频繁震荡要稳"这对矛盾。
- `timers lsa-generation <初始> <保持> <最大>`：默认 **500ms / 1000ms / 5000ms**；第 N 次间隔=保持间隔×2^(N-2)，封顶最大间隔
- LSA 接收间隔、SPF 计算间隔同机制各自独立调节
- 类比：一次地震震完该睡睡；频繁地震 CPU 就得报警——震荡越频繁，产生间隔指数拉长。类比：你把接口插了拔拔了插，路由器不陪你玩了
- ★实际工作极少调（毫秒级人感知不到），但高频震荡场景有真实保护价值

**IP FRR（快速重路由）**：目标——收敛从秒级压到 **50ms 内**。思路：**不故障再算，而是事先算好备份路径写进 FIB**，主路径一断立即切换。类比：每个房间放灭火器——着火就地拿，不等跑厕所取。
- 算法 LFA（无环备份）：链路保护条件 `N→D < N→S + S→D`（备份下一跳到目标必须比本机更近，否则有环回风险）；节点+链路双保护再加 `N→D < N→E + E→D`
- 类比：备胎——你要当我的下一跳，你到目标必须比我近，不然我怀疑你得从我这里绕
- 配置：OSPF 进程下 `frr` → `loop-free-alternate`；接口可 `ospf frr block` 排除某接口当备份路
- 验证：`display ospf routing <网段>` 看主/备下一跳与备份类型
- 局限：**拓扑相关**——有些结构算不出备份路径，还可能出微环；SR/SRv6 才是终极解法
- ★考试是送分题：配上去就行；实际效果人测不出（ping 掉包看不出差别），**要结合 BFD 才真正有意义**（中间隔交换机时链路 Down 检测要等 40 秒，FRR 根本不触发）

### 2.2 等价负载分担微调

`maximum load-balancing <N>` 限等价路径数。实际路径数 > N 时设备按手册优先级选：**路由优先级小 → 接口索引大 → 下一跳 IP 大**。人为干预：`nexthop <IP> weight <权重>`（默认 1，越高越优先）。不同型号最大条数不同——原理相通，不必纠结型号。IS-IS 对照：优先级小 → **下一跳 System ID 小** → 接口索引小（与 OSPF 的"接口索引大"不同，注意区分）。

### 2.3 OSPF 普通区域缺省路由五式（★核心工程题）

| 命令 | 强制性 | 前提条件 |
|---|---|---|
| `default-route-advertise` | 非强制 | 本路由表存在**活跃的非本进程缺省** |
| `default-route-advertise always` | 强制 | 无前提，死活下发 |
| `default-route-advertise route-policy RP` | 非强制+改属性 | 同第一式；RP 只改开销/Tag/开销类型 |
| `default-route-advertise always route-policy RP` | 强制+改属性 | 缺省存在时策略生效，不存在按默认属性发 |
| 特殊区域自动下发 | 自动 | STUB/TOTALLY STUB/NSSA 由 ABR/ASBR 自动产生（第 05 章 已讲） |

- 开销/类型也可直接敲参数改（`cost 10000 type 1`），但 **Tag 必须用 route-policy 改**；三类缺省的默认开销用 `default-route-advertise summary cost` 设
- **route-policy 两大坑（★）**：①不要加 `if-match`——实验证明加了 if-match 后无论匹配与否都可能**不产生缺省**（匹配上反而黄了）；②条件逻辑：同名 if-match 内多目标是**或**，不同 if-match 之间是**与**——全满足才下发，而 `always` 时 if-match 只决定 apply 生不生效
- **always 场景判断**：出口自己也要靠缺省上外网 → 不加 always（自己都没有就别坑别人）；出口从 BGP 学全明细、自己不需要缺省 → 加 always
- 类比（追女）：这辈子认定一个人就够——不需要全网路由，明细到位即可

**实验细节**：`match-all`/`match-any` 条件检查的是 **IP 路由表**（非 BGP 表）；条件路由消失（接口 shutdown）→ 缺省立即撤回，日志提示"缺省路由被改变"。

### 2.4 双出口缺省路由的优先级博弈（★工程实战精华）

**标准方案**：两个出口各配**静态缺省（优先级 60）+ OSPF 下发缺省（150）**。
- 正常：各出口走自己的 60 静态，内部路由器收到两条五类缺省 → 负载分担
- 单出口故障：故障方静态失效 → 改用对端 OSPF 缺省 → 全网流量走好出口
- 恢复：静态 60 优于 150 → 自动切回

**BGP 缺省 255 的"先入为主"陷阱（★）**：
- BGP 缺省（255）先进路由表后，OSPF 后来学的 150 **不参与计算**（同前缀高优先级已占位——先入为主，不抢占）
- BGP 失效 → 才用 OSPF 的 150；BGP 恢复（仍 255）→ **继续用 OSPF 不切回**
- 类比：先占了茅坑先拉屎
- ★结论：BGP 缺省建议把优先级**改成 60**；千万别用 `default-route-advertise permit-calculate-other` 让 OSPF 去比优先级——出口会不稳定

### 2.5 OSPF 过滤两面：LSA 发送过滤与 ABR 区域间过滤

**`ospf filter-lsa-out`（接口方向，老特性）**：两台路由器间有千兆+2M 串行双链路时，LSA 在低速链路上重复泛洪浪费带宽。接口配 `ospf filter-lsa-out all` → 该口**只发 Hello 不发 LSU**。
- ★关键认知：**过滤的是报文，不是链路状态信息**——邻居关系正常、SPF 树不变、路由照算（改开销还能让路由继续走低速链路）
- **必须两端都配**，否则一端过滤了，LSA 又从另一端泛洪回来
- 现代网络带宽充裕，基本已弃用

**`area <X> filter`（ABR 区域间三类 LSA 过滤）**：
- `import`：过滤**进入**该区域的三类；`export`：过滤**从**该区域**发出**的三类
- 只能在 **ABR** 上做（非 ABR 配了无效）
- 实验矩阵：区域3不学1.0 → `area 3 filter import`；区域2/3 都不学1.0 → `area 0 export`（源头拦截）；同一目标多种实现路径，灵活选择
- prefix-list 比Route-policy 更可靠：route-policy 能匹配开销，但开销一变就失配

**LSDB 过载保护（`lsdb-overflow-limit <N>`）**：限量**非缺省外部 LSA**（5+7类）。
1. 自产+他人产生达上限 → **先删自己产生的非缺省五类**（"我就先吃点亏"），保留缺省五类和别人的
2. 别人产生的也到限 → 进入 overflow 状态：不收也不产生新的，定时器（默认 5 秒）周期检查
- ★设计理念：**缺省五类永远保留**——明细删了还有缺省垫底，网络依然通。【设计本源与技术哲学】："网络工程师就是把网络做通。"
- 适用：核心/汇聚强、接入层弱的分层网络；现代硬件性能下少用

### 2.6 末节路由器（Stub Router）——割接流量调度神器

**问题场景**：AS 内 OSPF、上层 IBGP，R2 故障恢复后 **OSPF 收敛快于 BGP** → 流量立即切回经 R2 的路径，而 R2 的 BGP 还没学到外部路由 → 丢包。【设计本源与技术哲学】："OSPF 收敛快了，我们把路径更快地迁移到恢复后的路径上，而这条路径的中间路由器由于缺乏 BGP 路由信息而导致业务中断。"

**解法**：把自己产生的 LSA 开销全部改为 **65535**（链路度量最大值），让全网 SPF 计算时绕开自己。类比：开车发现路太烂开不过去，赶紧掉头。

| 用法 | 命令 | 场景 |
|---|---|---|
| 立即生效 | `stub-router` | 割接/升级/板卡更换前把流量调空，完事恢复 |
| 重启后生效 | `stub-router on-startup <秒数>` | 重启完成后的指定秒数内保持末节，等 BGP 收敛完再恢复正常开销 |

★**末节路由器与末节区域（Stub Area）毫无关系**——纯名字撞车，考试必坑。

### 2.7 转发地址 FA：外部路由的路径优化

**用途**：外部路由路径优化——仅 **5 类与 7 类 LSA** 有 FA 字段。【设计本源与技术哲学】："有转发地址就跟着转发地址混，没有转发地址就跟着 ASBR 混。"

**5 类 LSA 携带 FA 的三条件（★全部满足）**：
1. ASBR 连外部网络的接口**加入 OSPF 进程**
2. 该接口网络类型为**广播/NBMA**
3. 该接口**不是静默接口**

为什么是这三条：加入进程才算得出 FA 的路由；P2P 没有额外出口无优化空间；静默接口感知不到邻居无法判断。**三条件同时满足=存在优化可能性**。任一不满足 → FA=0.0.0.0 → 按老规矩"经 ASBR"计算。

实验对照：R2 引入 4.4.4.0/24（FA=10.1.123.4）→ R1 负载分担、开销 3；接口改 P2P 或静默 → FA 归 0 → R1 只走 R2、开销 2。

**7 类 LSA 的 FA（★不同规则）**：**无条件必带 FA**。因为 7 转 5 时Adv-Router 变化（真 ASBR 被隐藏，R4 会误把 ABR 当 ASBR），不带 FA 必出次优路径。华为选 FA 的优先级：
1. NSSA 区域内的环回口地址（华为环回口开销 **0**，不干扰计算；思科为 1）
2. 无环回口 → NSSA 区域内第一个 UP 的接口地址
3. 都不满足 → 0.0.0.0

7 转 5 时 FA 原样继承；`suppress-forwarding-address` 可在 7 转 5 时抑制 FA。

### 2.8 IS-IS 缺省路由与双出口防环（★对照记忆）

三种发布方式：ATT 比特自动产生（L1-2 路由器）、L1 侧配禁止 ATT 产生、`default-route-advertise` 系列正经发布。核心命令三档：

| 命令 | 行为 | 风险 |
|---|---|---|
| `always` | 无条件下发；**会学习**其他 IS-IS 路由器下发的缺省 | 两出口互学 → **环路** |
| `match default` | 路由表有其他协议活跃缺省才下发；仍会学别人的 | **优先级震荡**：IS-IS 缺省 15 盖掉静态 60 → 静态失效 → 命令失效 → 自己的缺省消失 |
| `always avoid-learning` | 下发且**不学习**别人的 | 防环终极方案；代价：对端真挂了也学不到它的缺省兜底 |

- ★**双出口防环总原则**：只要出口之间**不互相学对方的缺省**，就不可能有环路。"不要互相学缺省路由，不要搞出环路就行了，其他的你们随便搞。"
- `match default` 的正确姿势：把静态缺省优先级压到 **≤14**（如 5），静态够"硬"不被 15 盖掉
- root-policy 版本（`default-route-advertise route-policy RP`）：按条件产生缺省——if-match 内是或、之间是与（同 OSPF 逻辑）；加 `avoid-learning` 同样防环
- ⚠级别：缺省默认 **Level-2**；L1 区域必须加 `level-1` 参数否则无效
- avoid-learning 要不要加**必须结合拓扑分析**：R2 不学 R1 的缺省，R1-R2 间有链路且 R2 出口也断时业务会断——两种拓扑场景均需权衡，"总而言之就是为了防止两个 ASBR 互相学而导致的环路"

### 2.9 IS-IS 工程杂项：快收敛、分片扩展、开销风格、tag、泄漏过滤

**快收敛对齐**：iSPF（增量 SPF，拓扑变化只算受影响节点，**默认开启**）、PRC（叶子变化不重建树）、LSP 快速扩散（路由计算前先把小批量 LSP 立刻扩散，避免逐跳定时器累计延迟）。

**LSP 分片扩展**：一条 LSP 超 MTU 需分片，分片号 1 字节最多 **256 个**。不够 → 配**虚拟系统 ID**：一个虚拟系统再给 256 分片，最多 50 个虚拟系统——51×256=**13056 分片**。类比：身份证上叫阮为，亲戚叫维维/阿维/小软——都是同一个人。24 号 TLV（别名 TLV）声明虚拟系统与初始系统的归属关系。
- **模式2**（全网支持）：虚拟系统不入 SPF 树（归到初始系统），零计算负担——首选
- **模式1**（有老设备不懂 24号TLV）：虚拟系统当独立路由器入树；初始系统到虚拟系统开销 0、回来开销 16777214（最大-1）抵消影响，但增加计算负担
- 配置后需**重启 IS-IS 进程**生效

**外部路由引入开销（★窄风格大坑）**：
- 窄/窄兼容风格下默认类型 external：实际开销 = 设置值 **+64**（固定附加）。【设计本源与技术哲学】："我配的是 10 但是他这里会变成 74，我就想不通为啥是这样"——这是现网迁移时极易忽视的经典陷阱
- internal 类型不加 64；窄风格下 **internal 优于 external**（类比 OSPF type-1 优于 type-2）
- **宽度量风格**：引入多少算多少，不分 internal/external，直接比总开销。★项目一律用宽风格——"没有理由不用宽"，高级特性多依赖它

**tag 四法**（前提：宽度量风格，窄风格不支持）：
1. 引入外部时 `import-route static tag 100`
2. 接口下 `isis tag 80`（内部路由）
3. 渗漏时 `import-route isis level-2 into level-1 tag 200`——还能**按原 tag 匹配筛选泄漏**+改新 tag（进阶玩法："没有任何理论，就是做实验多去练习"）
4. 汇总命令直接加 `tag` 参数

**区域间泄漏与过滤**：本质就是 `import-route isis level-2 into level-1`（L2→L1 默认不渗，需显式泄漏）与 `import-route isis level-1 into level-2`（L1→L2 默认全渗）。过滤照常写前缀列表（permit 放行/deny 拒绝，别想默认行为）；**只能在 L1-2 路由器上做**。

### 2.10 IS-IS 汇总防环两参数与过载设计

**汇总位置**：内部路由——各级路由器可对自己直连路由汇总（**L1/L2 路由器必须加对应 level 参数**，默认按 L2 汇总，不加看不到效果）；L1-2 上做区域间汇总（对标 OSPF ABR 汇总）。外部路由——ASBR 上做（L1/L2/L1-2 的 ASBR 都行）。汇总开销**继承明细中最小值**。

**防环两参数（★大胆加，没有坏处）**：
| 参数 | 防的环 | 机制 |
|---|---|---|
| `avoid-feedback` | 两台 ABR 把对方传回的汇总又学回来（明细消失汇总还在 → 环） | 自己发的汇总，别人传回来的**不计算不落表**（对标 OSPF 自带机制：本 ABR 不算其他 ABR 的相同三类） |
| `generate_null0-route` | 汇总+缺省路由同在时，不存在的地址在两设备间弹跳 | 路由表生成指向 null0 的汇总路由，命中即丢 |

【设计本源与技术哲学】："防环的关键就是不要算就好了——你发布你的，我发布我的。"

**过载（OL 比特位）**：LSP OL 位置 1 → 告知全网"我资源不足，SPF 树算到我就截止，别顺着我往下算"。对标 OSPF 末节路由器（OSPF 用 65535 开销表达"走我最烂"，IS-IS 直接说"我病了"）。
- ★**OL 与 ATT 不能同时置 1**（逻辑矛盾：都病了还引流？）——set-overload 后 ATT 自动清零
- `set-overload` 默认行为（L1-2 路由器）：两侧互不泄漏、不引入外部路由、ATT 清零、**只留自身直连网段**（类比：人病了不能干活，但去医院看他还是可以的）
- 精细化参数：`allow route-interleave`（保留内部路由泄漏、砍掉外部引入）；`allow route-external`（保留外部、不泄漏骨干路由）
- ★不管加什么参数，**SPF 树都不顺着这台设备往下算**——这是过载的底线语义
- 【设计本源与技术哲学】："ABR 天然就是本区域的末节——SPF 树是以区域为单位的一棵树。"

**主机名映射**：动态 `isis-name <名>`（hostname TLV 随 LSP 扩散，**全网每台都要开**才全网生效）；静态 `isis-name map <SystemID> <名>`（本地生效）。两者并存**动态优先**。纯运维体验优化。

### 2.11 IGP 高级特性核心配置与割接模板（VRP 实战）

#### 1. OSPF 快速收敛与 IP FRR 配置模板

```shell
# ═══ 智能定时器调优与无环快速重路由 (LFA FRR) ═══
[R1] ospf 1
# 智能定时器：初始 500ms，保持 1000ms，最大 5000ms（指数级退避防震荡）
[R1-ospf-1] timers lsa-generation 500 1000 5000
[R1-ospf-1] timers lsa-arrival 1000
[R1-ospf-1] timers spf 500 1000 5000

# 开启 IP FRR（LFA 算法事先计算无环备份路径写入 FIB）
[R1-ospf-1] frr
[R1-ospf-1-frr] loop-free-alternate                     # 计算 LFA 备份下一跳，实现 50ms 级快速故障切换
[R1-ospf-1-frr] quit

# 若某低速互联接口不希望充当备份路径，可在接口下显式屏蔽：
[R1] interface GigabitEthernet 0/0/2
[R1-GigabitEthernet0/0/2] ospf frr block
[R1-GigabitEthernet0/0/2] quit

# 验证 OSPF FRR 路由与备份下一跳
<R1> display ospf routing 192.168.2.0
```

#### 2. OSPF 普通区域缺省五式与 Route-Policy 避坑模板

```shell
# ═══ 场景 A: 强制下发缺省（出口网关常用，无论本地是否有缺省均通告） ═══
[R1-ospf-1] default-route-advertise always

# ═══ 场景 B: 挂接 Route-Policy 改开销与打 Tag（★切忌在策略中配置 if-match 匹配自身） ═══
[R1-route-policy] route-policy OSPF_DEF_POL permit node 10
[R1-route-policy-node10] apply cost 20                  # 修改缺省路由开销为 20
[R1-route-policy-node10] apply cost-type type-1         # 改为 Type-1 外部开销
[R1-route-policy-node10] apply tag 666                  # 打上专属 Tag 便于下游识别
[R1-ospf-1] default-route-advertise always route-policy OSPF_DEF_POL

# ═══ 场景 C: 双出口防环与静态路由优先级 60 博弈 ═══
# 本地配置默认静态指向运营商出口（优先级 60）
[R1] ip route-static 0.0.0.0 0.0.0.0 202.100.1.254 preference 60
# 内部运行 OSPF 下发缺省（优先级 150，天然劣于 60，出口正常时各走本地，出口故障切到对端）
[R1-ospf-1] default-route-advertise
```

#### 3. 现网维护与割接神器：Stub Router 与 Overload 配置

```shell
# ═══ OSPF 末节路由器割接配置（自产 LSA 开销置 65535，将经过本机的穿越流量全部调空） ═══
[R1] ospf 1
[R1-ospf-1] stub-router                                 # 立即变为末节路由器，排空流量即可安全割接
# 设备重启时等待 BGP 收敛完成后再接管流量（维持 300 秒末节状态）：
[R1-ospf-1] stub-router on-startup 300

# ═══ IS-IS 过载位（Overload）配置（LSP OL 位置 1，全网 SPF 树不穿过本设备） ═══
[R2] isis 1
[R2-isis-1] set-overload                                # 立即过载（ATT 自动清零，不穿过流量）
# 重启等 BGP 收敛保护：
[R2-isis-1] set-overload on-startup 300
```

#### 4. IS-IS 汇总防环两参数工业级配置

```shell
# ═══ IS-IS 汇总防环两参数（avoid-feedback 与 generate_null0-route） ═══
[R2] isis 1
# 在 Level-2 骨干上做路由汇总，同时加入防回馈与黑洞防环：
[R2-isis-1] summary 192.168.0.0 255.255.0.0 level-2 avoid-feedback generate_null0-route
# 作用：自己发出的汇总从别处传回来时不计算落表；本地自动生成指向 NULL0 的黑洞路由兜底防环
```

## 三、总结

**核心重点十带走**：
1. 快收敛三级：PRC 只算叶子（默认有）→ 智能定时器震荡指数退避（500/1000/5000）→ IP FRR 预装备份路径 50ms 切换（LFA 条件 N→D < N→S+S→D，拓扑相关，配 BFD 才完整）。
2. 负载分担：路径数超出 maximum load-balancing 时按优先级小→接口索引大（OSPF）/System ID 小（IS-IS）→下一跳 IP 大选；`nexthop weight` 人为干预。
3. 缺省五式按前提选：非强制（表里要有）/always（无中生有）/带 route-policy 只改属性**别加 if-match**；always 与否看出口自己缺不缺省。
4. 双出口标准答案：静态 60 + OSPF 150 各用各的；BGP 缺省 255 有**先入为主不抢占**坑——BGP 缺省一律改 60；禁止 permit-calculate-other。
5. 过滤双层：接口 `filter-lsa-out`（滤报文不滤状态，两端都配）；ABR `area filter import/export`（源头 import 拦窄，export 拦宽）。
6. LSDB 过载：先删自产非缺省五类、缺省永远垫底、5 秒定时器——"网络工程师就是把网络做通"。
7. 末节路由器：开销 65535 调空流量，割接 `stub-router`、重启等 BGP 用 `on-startup 秒数`；与 Stub Area 毫无关系。FA 三条件（进进程/广播NBMA/非静默）全满足才带，7 类无条件必带（防 7转5 次优）。
8. IS-IS 缺省防环就一句：**出口之间别互学缺省**——avoid-learning 终极方案；match default 需把静态优先级压到 ≤14 防震荡；L1 区域别忘 `level-1` 参数。
9. IS-IS 工程：分片扩展 51×256（虚拟系统+24号TLV，模式2零负担）；窄风格 external 偷偷 +64（用宽度量风格一了百了）；tag 四位置（引入/接口/渗透/汇总）。
10. 汇总防环两参数（avoid-feedback 不学回声 / generate_null0-route 黑洞兜底）都是"大胆加"；过载=OL 置 1 SPF 树不穿过，与 ATT 互斥，参数只再细筛砍哪类路由。

**落地注意事项**：所有缺省路由方案上线前先画双出口故障矩阵（单边断/双边断/恢复）逐格推演；route-policy 改缺省属性前全文检查有没有手滑加 if-match；FRR 部署后必须验证备份下一跳真的存在（LFA 算不出就白配）；IS-IS 改宽风格、虚拟系统、主机名映射都要**重启进程**才生效——变更窗口安排好；汇总上线前用 avoid-feedback + null0 两参数武装到位再动手；过滤类命令先在低峰验证 `display` 确认匹配范围，防"匹配多了"误杀。

**学习建议**：本章最值得反复练的是三张实验：①缺省路由五式+双出口优先级博弈（把 60/150/255 三种优先级的抢占关系全部实测一遍，"先入为主"看一次终身不忘）；②FA 三条件对照实验（接口类型一改 FA 立刻变 0.0.0.0，路由随之收窄）；③IS-IS 双出口防环三档命令对比（always 环路复现→match default 震荡复现→avoid-learning 一劳永逸）。IS-IS 的高级特性建议与 OSPF 逐条对照列表复习（stub-router↔set-overload、PRC↔PRC、filter-lsa-out↔泄漏过滤），两协议联记效率翻倍。学完本章，IGP 体系完整闭环，可进入交换高阶（第 12 章-14）或 IPv6 系列（第 19 章-21）。

## 附：本章术语速查表

| 术语缩写 | 英文全称 | 中文含义 | 关键作用 |
|---|---|---|---|
| **PRC** | Partial Route Calculation | 部分路由计算 | 仅当叶子网络发生变化而拓扑树结构不变时，只重新计算受影响路由，大幅减轻 CPU 开销 |
| **IP FRR** | IP Fast Reroute | IP 快速重路由 | 采用 LFA 无环备份算法预先计算备份下一跳写入 FIB，实现链路/节点故障 50ms 级硬切换 |
| **LFA** | Loop-Free Alternate | 无环备份候选 | IP FRR 核心算法，要求备份节点到目的距离必须小于该节点到本机的距离与本机到目的距离之和 |
| **Stub Router** | Stub Router | 末节路由器 | OSPF 特性，向外通告的一类 LSA 开销设为 65535，主动排空本设备的穿越流量以平滑割接 |
| **Overload** | Overload Bit | 过载位 | IS-IS LSP 头部标志位，置 1 表示设备资源耗尽，全网 SPF 树不再穿越此节点转发报文 |
| **FA** | Forwarding Address | 转发地址 | OSPF 5/7 类 LSA 中指示的实际转发下一跳，用于多路访问网络中消除次优绕路 |
