## 一、总起

前两卷学会了两种 IGP 各自怎么跑，本章学的是"路由的管理艺术"：两个路由域默认像国界一样隔离，route import 是唯一的通关文牒；import 什么、不 import 什么、import 进来改成什么样，就是路由策略。本章的工具链层层递进——ACL（只能匹配网络号的粗筛）→ 前缀列表（网络号+掩码的精筛）→ Filter-Policy（纯过滤阀门）→ Route-Policy（过滤+改属性的全能选手），最后用双点双向引入把工具串成完整攻防战，再用 PBR/MQC 把控制对象从"路由表"直接换成"报文本身"。

**适用人群**：
- **初学 / 转行人员（HCIP 进阶）**：建立路由与转发解耦观念，分清 ACL、前缀列表、Filter-Policy 与 Route-Policy 的职责边界；
- **备考工程师（HCIP / HCIE 级）**：彻底攻克双点双向引入的次优路径与环路攻防（Tag 打标过滤、OSPF 外部 150 设计机制、次优优先级改写），掌握 PBR 与 MQC 流策略体系；
- **一线工程实践者**：掌握多业务割接引流、策略路由选路、流量精确过滤（Traffic Policy）的现网工业级配置模板。

## 二、分述

### 2.1 路由引入：前提、行为与多进程

- **默认隔离**：ASBR 同时运行 OSPF 与 IS-IS 时能各自算路，但**不会自动**把一边的路由传给另一边——互通唯一的办法是引入。
- **单点双向引入**：`import-route` 互敲。命令语义（★逐字理解）："将路由表中**由某进程计算得到且活跃**的路由引入到另一进程"。
- **【工程类比】换手机**："我自己不用的旧手机给媳妇用，媳妇都鄙视我——你自己都不用来转发报文的路由，凭什么引入给别人？不用的东西给别人用就是不负责任。"
- **活跃判定实验**：R2 配静态 3.0→NULL0 + preference 5 压制 OSPF 的 3.0（能算出但不活跃）→ 引入悄然失效；删静态恢复。**不活跃的路由引不进去**——这是很多"特殊现象对不上理论"的根源。
- 引入后的形态：外部路由进 OSPF 变五类 LSA；进 IS-IS 后**路由表上长得像 L2 路由**（看不出外部身份），只有 LSDB 的**分片 LSP** 里能看到 external 标记（第 06 章 TLV130 的呼应）。
- 直连特例：接口已加入协议进程的直连网段随进程路由一起被引入；不生效时补 `import-route direct`。
- **多进程举一反三**：引入按进程号两两进行——"三个进程本质还是两两之间的事"。

### 2.2 匹配与过滤工具一：ACL（能力与缺陷）

- 被 filter-policy 等工具**调用做路由匹配**时，ACL **只能匹配网络号、不能匹配掩码长度**：permit 1.1.1.0 0.0.0.255 代表"前 24 比特是 1.1.1 的任何路由"——同网络号的 /24、/27、/28 **三条全部放行**，"只引入 /24"的需求无法表达。
- ★**默认语义翻转**（易错）：ACL 做**报文过滤**时默认允许所有；做**路由匹配**时**默认拒绝所有**——未 permit 的路由全部进不来（实验反证：rule deny 1.1.1.0 后连其他没提到的路由也全消失）。
- 结论：能用但残废——网络号一致掩码混杂的场景必须换前缀列表。

### 2.3 匹配与过滤工具二：前缀列表（IP Prefix-List）

- **定位**：匹配路由的**专用工具**（不能做报文过滤），网络号+掩码长度+掩码范围全都能管；大型网络几百上千条路由时"用 ACL 会疯"。
- **五种写法**（以 1.1.1.0 为例，★必须练到条件反射）：

| 写法 | 含义 |
|---|---|
| `permit 1.1.1.0/24` | 精确匹配：前 24 比特=1.1.1 **且**掩码恰为 /24 |
| `1.1.1.0/24 ge 24 le 27` | 斜杠值只锁网络号前 24 比特；掩码范围 24~27 |
| `ge 27 le 27` | 恰为 /27 |
| `ge 26`（无 le） | 26~32（上限 32 可省） |
| `le 30`（无 ge） | 24~30（下限从斜杠值起） |

- ★记忆要点：**斜杠后的参数一旦出现 ge/le，掩码就交给范围定义，斜杠值退化为纯网络号约束**。
- 默认语句同样**拒绝所有**；index 默认 10，多条从小到大依次匹配（与 ACL 套路一致：不匹配 index 10 就去试 20）。
- **特殊用法（工作必会）**：`0.0.0.0/0 le 32`=匹配**所有路由**（deny 后兜底放行其余时用）；`0.0.0.0/0`=匹配**缺省路由**。
- 思维体操（理解加深）：A 类所有子网=`0.0.0.0/1 ge 9 le 32`（首比特 0）；B 类所有子网=`128.0.0.0/2 ge 17 le 32`；主类网=首比特匹配+掩码恰 /8、/16、/24。

### 2.4 过滤阀门：Filter-Policy 与协议行为差异

**引入时过滤的唯一姿势**（第 1 讲）：`filter-policy {acl|prefix-list|route-policy} export [协议]`，必须与 import-route 搭配：
- 不带协议参数：对引入的**所有来源**统一过滤；
- 带协议（如 export isis）：只过滤 IS-IS 来源（静态等其他来源全放行）；
- ★两者**可并存**：带协议的先过、不带协议的殿后再过一遍——**双重过滤、拒绝优先**，任一环节拒绝即出局（工作中不常遇，但"命令存在集合里就要懂逻辑"）。

**按协议类型的行为差异**（第 2 讲核心）：

| 协议 | export 方向 | import 方向 |
|---|---|---|
| RIP（距离矢量） | 传的是路由本身，export 有效 | import 有效，可按接口细化 |
| OSPF/IS-IS（链路状态） | **完全无效**——传的是 LSA/LSP 拓扑信息，过滤会导致 SPF 树破裂 | 有效但**本质变味**：不拦 LSA 接收，而是**把 SPF 算出的路由拦在路由表外**——仅本地生效，邻居照常计算 |

- 实验验证：R2 export 过滤 1.1.1.1 → R3 照样学到；R3 import 过滤 → R3 路由表消失但 LSDB 还在、R2 不受任何影响。【核心结论】"链路状态是无法进行过滤的。"
- 工程含义：想"不给某邻居路由"在链路状态协议里没法 export 做，只能靠第 2.5 的引入源头控制或后续卷的 ACL/GTSM 等手段。

### 2.5 全能选手：Route-Policy

**结构**：多个 Node（节点）组成，节点按编号**从小到大、或关系**匹配，命中即执行并停止；每个 Node：
- **if-match**（条件）：可调 ACL/前缀列表/tag/开销/开销类型/下一跳等；同一 Node 内多个 if-match 为**与**关系；
- **apply**（动作）：改开销/开销类型/tag/preference/下一跳/AS-Path/团体属性等（BGP 卷大量复用）；
- 只 if-match 不 apply（纯过滤）、只 apply 不 if-match（全匹配）、两者皆空——全部合法；
- ★**隐藏默认 deny**：末尾隐含无条件拒绝所有节（与 ACL 同款）——忘了写放行节点，所有路由全灭。

**★被 if-match 调用时的语义翻转（本章最细考点）**：前缀列表/ACL 的 permit/deny 此时只决定"**是否匹配本 Node**"——
- permit → 匹配本 Node → 执行本 Node 动作；
- **deny → 跳过本 Node，继续向下找**（不是拒绝！）；
- 路由最终能不能过，由**Node 自身的 permit/deny** 说了算。
- 实验实锤：前缀列表 deny 4.0/24 + 无条件 permit Node 40（apply tag）→ 4.0 跳过 Node 10 落到 Node 40，照样被引入还打了 tag。
- 实践口径：被匹配对象统统 permit 写，"要不要"交给 Node 的 permit/deny 表达——直觉且命令最少。

**与 Filter-Policy 的关系**：Filter-Policy 纯过滤阀门（放行/拒绝二选一）；Route-Policy 是"**过滤+增值服务**"——【工程类比】普通火锅店 vs 海底捞（拉面表演、生日歌）。华为 Filter-Policy 还能反过来调用 Route-Policy（比思科灵活）。

### 2.6 双点双向引入：次优路径与环路的攻防（★每版必考）

**场景**：两台 ASBR（R2/R3）同时对接 OSPF 域与 IS-IS 域、互相引入做冗余。风险来自**路由回馈**——【工程定义】"你曾经引出去的路由又被引回来了。"

**风险的两段论**：
1. **环路风险**：A 协议路由经对端引回 B 协议再传回来，形成循环；
2. **次优路径**：引回来的路由若被优选（优先级/开销占优），流量绕远路。

**华为的安全垫——OSPF 外部路由优先级 150 的设计（★面试题）**：
- IGP 优先级版图：直连 0 / OSPF 内部 10 / IS-IS 15 / 静态 60 / RIP 100 / **OSPF 外部 150**；
- 150 把所有常见 IGP 的优先级**"包在里面"**（10~150）——无论 OSPF 和哪种 IGP 对接，引回的外部路由 150 总是劣于原协议，原协议继续优先 → InActive 的路由**不会再被引出去**，天然防次优防环；
- 思科同款逻辑：EIGRP 内 90/外 170 包住 OSPF 110、RIP 120（厂家商业竞争的延伸——"用我的协议，天然防环"）；BGP 255 则因为"BGP 用户是专业工程师，自己处理"。
- ★边界条件：150 防的是**稳定态**；路由失效/切换瞬间（Active/InActive 翻转）仍可能出现回馈。

**水平分割式防环（万能方法）**——从一个方向传出去的路由，不允许从另一个方向传回来：

```shell
# ═══ R2 (ASBR 1) 配置 ═══
# 1. ISIS 引入 OSPF：打 Tag 10，并拒绝携带对端 R3 引入的 Tag 20
route-policy ISIS_TO_OSPF deny node 10
 if-match tag 20                                        # 拒绝由 R3 引入的路由（防环）
route-policy ISIS_TO_OSPF permit node 20
 apply tag 10                                           # 本端引入时打上 Tag 10
#
ospf 1
 import-route isis 1 route-policy ISIS_TO_OSPF

# 2. OSPF 引入 ISIS：打 Tag 30，并拒绝由 R3 引入的 Tag 40
route-policy OSPF_TO_ISIS deny node 10
 if-match tag 40                                        # 拒绝对端 R3 引入的 Tag 40
route-policy OSPF_TO_ISIS permit node 20
 apply tag 30                                           # 打上本端 Tag 30
#
isis 1
 cost-style wide                                        # ★必须配置 Wide 宽开销，否则 IS-IS 无法传递 Tag！
 import-route ospf 1 route-policy OSPF_TO_ISIS

# ═══ R3 (ASBR 2) 镜像对称配置 ═══
route-policy ISIS_TO_OSPF deny node 10
 if-match tag 10                                        # 拒绝 R2 打的 Tag 10
route-policy ISIS_TO_OSPF permit node 20
 apply tag 20
#
route-policy OSPF_TO_ISIS deny node 10
 if-match tag 30                                        # 拒绝 R2 打的 Tag 30
route-policy OSPF_TO_ISIS permit node 20
 apply tag 40
```

判定做成功的标准：**"通了而且路由表不变"**（与做双点双向前每台设备的最优路由完全一致）。
预警：**双点双向本身不是防环手段，是互通手段**——面试嘴瓢说"双点双向防环"直接挂。

**次优路径两解法**（水平分割后仍可能存在的残留问题）：
- 解法一（依赖源端）：R5 引入时对目标路由打 Tag 1000，R2/R3 上 `preference ase route-policy PRE 150`——匹配 Tag 的外部路由优先级改 10，与内部路由同级比较 → 次优消除。局限：要求 R5 的管理权限。
- 解法二（独立自主，考试实际方案）：**全部 OSPF 外部路由改优先级 10，唯独排除对端从 IS-IS 引入的那些**——R2 匹配"R3 打的 Tag 20"保持 150、其余全 10；R3 对称。零外部依赖。
- ★配套踩坑实录（教学价值拉满）：IS-IS 默认**窄开销风格无法携带 Tag**——Tag 不生效 → 水平分割形同虚设 → 路由震荡。必须 `cost-style wide`。工程现场从"怀疑设备异常"排查到"定位宽度量值"的全过程已入正文：**排错直觉比结论值钱**。

### 2.7 策略路由 PBR：直接指挥报文

**定位分野**：路由策略控制的是**路由表条目**（间接影响转发）；PBR 直接控制**业务报文**——"我让你往东你就往东，别管路表怎么写"。【设计本源与技术哲学】：**策略路由的优先级高于路由表**。

- **接口 PBR**：管穿越流量，`ip policy-based-route PBR` 挂**入接口**（无方向参数、只在入方向生效——出接口时转发决策已完成）；
- **本地 PBR**：管设备自身产生 的报文，`ip local policy-based-route PBR` 系统视图全局调用；
- 结构与 route-policy 同构：node + if-match（ACL 等）+ `apply ip-address next-hop`；ACL 用高级 ACL 精确匹配五元组（如 ping 一条路、telnet 一条路）。
- ★**default 关键字行为反转**：`apply ip-address next-hop X` 不加 default=**优先走策略**（没路由也走）；加 default=**优先查路由表，查不到才走策略**——"有路由走路由，路由没了走 PBR，反着来的"。
- deny 的流量=不执行 PBR，回落路由表（与 route-policy deny 语义一脉相承）。
- 实验坑：eNSP 不自动对策略下一跳做 ARP 解析——先手动 ping 直连下一跳刷 ARP 缓存。

### 2.8 MQC：模块化的 PBR 与流量过滤

**三组件**（与 route-policy 概念对仗）：流分类 traffic classifier（=if-match）→ 流行为 traffic behavior（=apply，改向用 **redirect ip-nexthop**）→ 流策略 traffic policy（=node，绑定分类与行为），入接口 `traffic-policy PBR inbound` 调用。

**与传统方式的两点差异**：
- 流分类多条件默认**"或"**关系（可 operator and 改）；route-policy 同一 node 内多 if-match 是**与**关系；
- MQC 可匹配的报文特征更丰富（VLAN、MPLS 标签、DSCP 等），且模块化易迁移——分类不变、只改下一跳即可跨设备复用。

**MQC 做流量过滤**：流行为里 `deny` 即丢弃；★ACL 在 MQC 里的 permit/deny 只表示"是否命中该分类"（deny=跳过继续往下），而 Traffic-filter 调 ACL 的 deny 是直接丢包——**同一张 ACL 在不同工具里语义不同**。

【总结】万变不离其宗：**匹配上了按动作处理；没匹配上要么继续向下、要么回落路由表**——就这几种可能性，抓住主干工具随便变形。

### 2.9 PBR 与 MQC 核心配置模板（VRP 实战）

```shell
# ═══ 1. 传统接口策略路由 PBR 模板（入接口调用） ═══
# 定义 ACL 匹配源 IP 或五元组流量
acl number 3000
 rule 5 permit ip source 192.168.10.0 0.0.0.255 destination 10.1.1.0 0.0.0.255
# 定义策略路由节点
policy-based-route PBR_TEST permit node 10
 if-match acl 3000
 apply ip-address next-hop 10.1.12.2                     # 强制直接转发至下一跳（优先于全局路由表）
# 在数据流量的入接口上应用（注意：PBR 只能应用在入方向）
interface GigabitEthernet 0/0/1
 ip policy-based-route PBR_TEST

# ═══ 2. MQC 模块化 QoS 与流策略配置模板 ═══
# Step 1: 定义流分类（Traffic Classifier）
traffic classifier C_HTTP operator or
 if-match acl 3001                                      # 匹配特定 ACL 或 TCP 端口

# Step 2: 定义流行为（Traffic Behavior）
traffic behavior B_REDIRECT
 redirect ip-nexthop 10.1.23.3                          # 重定向到指定下一跳
 statistic enable                                       # 开启流量统计（便于排错与抓包核对）

# Step 3: 绑定流策略（Traffic Policy）
traffic policy P_REDIRECT
 classifier C_HTTP behavior B_REDIRECT

# Step 4: 接口或全局应用
interface GigabitEthernet 0/0/2
 traffic-policy P_REDIRECT inbound                      # 在入方向生效
```

## 三、总结

**核心重点**：
1. 引入铁律：**由该进程计算得到 + 路由表中活跃**，两条缺一不可（不活跃引不进去，静态压制的实验必复盘）。
2. ACL 调用做路由匹配：只能匹配网络号、默认拒绝所有；掩码要精控→ 前缀列表（五种写法 + 匹配所有 `0/0 le 32` + 匹配缺省 `0/0`）。
3. Filter-Policy 分协议行为：距离矢量双向有效；链路状态 export 完全无效、import 只挡路由表不挡 LSA（本地生效）。
4. 前缀列表 ge/le 出现时斜杠值退化为网络号约束；掩码交给范围定义。
5. Route-Policy：node 从小到大或关系、node 内 if-match 与关系、隐藏默认 deny；**被 if-match 调用的 permit/deny 只管"匹配与否"（deny=跳过 node），生死由 node 自身决定**。
6. 引入时过滤只有 `filter-policy … export`（可与 import-route 的协议参数组合成双重过滤、拒绝优先）。
7. 双点双向=互通手段而非防环；环路/次优来自路由回馈；三道防线：OSPF 外部 150 天然垫底（稳定态）→ Tag+deny node 四方向水平分割（消除回馈可能）→ 两种优先级解法（消除次优残留）。
8. IS-IS 窄开销风格不带 Tag——**做 Tag 策略前必查 `cost-style wide`**。
9. PBR 优先于路由表；接口 PBR 只在入方向；default 关键字反转优先次序；本地 PBR 管自身流量。
10. MQC 三组件模块化（分类或关系、redirect 改向、deny 过滤）；ACL 语义随调用工具而变。

**落地注意事项**：双点双向的验收标准是"通了而且路由表不变"——逐台比对引入前快照；改属性类操作先想"这个属性会不会影响之前的策略"（叠加效应）；前缀列表/策略全局命名要有体系，重名冲突现场很难查；路由策略类变更都在边界设备上做，改前 display 快照、改后逐台验证；PBR 上线前先确认下一跳可达（ARP 缓存）。

**学习建议**：本章工具全是为第 08 章《BGP 基础与路径优选》服务的（知识体系进阶逻辑），BGP 的 route-policy/if-match/apply 语法一模一样。检验标准：① 一张双协议双 ASBR 拓扑，能独立完成"引入→过滤→防环→消除次优"全流程并讲清每步为什么；② 前缀列表五种写法看到就出答案；③ 能说清"ACL 的 deny 在 Traffic-filter、filter-policy、route-policy if-match 三种语境下分别是丢弃、不进、跳过"——分得清这个，工具就算过关了。
