## 二、分述

### 2.1 动态路由与链路状态思想（IA）

**为什么需要动态路由**：大型/复杂拓扑中静态路由配置量巨大，且无法自动故障切换（浮动路由要逐条配）——动态路由协议让路由器自动学习路径、自动收敛。

**协议分类**：按工作范围 IGP（RIP/OSPF/IS-IS，自治系统内部）与 EGP（BGP，目前唯一）；按算法距离矢量（RIP，以讹传讹式"问路"）与链路状态（OSPF/IS-IS，"拿到全城地图自己算路"）。距离矢量已被现网淘汰，仅作概念了解。

**链路状态（LSA）四要素**：①路由器标识（所以需要 Router-ID，RIP 不需要）②谁连谁、什么类型链路 ③各自直连的网络号（树上的"叶子"）④链路开销。【设计本源与技术哲学】："从树根到达树上每片叶子的路径是唯一的——这就是链路状态路由协议最牛的地方：算出到达每个网络的最短路径，而且无环。"拓扑会变（增删设备/链路/网段、开销调整），故传的是"状态"——【设计本源与技术哲学】："状态往往代表随着时间变化而产生变化的东西。"

**OSPF 工作四阶段**：建邻居 → 邻居间交换 LSA（LSA 只在邻居间传递）→ 各自构建 LSDB（全网一致）→ 各以**自己为根**跑 SPF 算法，最优路由入 RIB。

**基本特性**：V2 仅 IPv4 / V3 仅 IPv6（V2 学好 V3 就简单）；支持 VLSM（对比 RIPv1/IGRP 只支持等长掩码——被淘汰的原因之一）；**无自动汇总**（汇总全靠手工，★强调）；多区域设计。

### 2.2 区域设计、Router-ID 与开销（IA→IP）

**区域规则**：Area 0 骨干区有且仅有一个、必须连续；非骨干区必须与骨干区**直接相连**；区域边界在路由器上（接口划入区域，V2 一个接口只属一个区域）。没有 Area 0 时非骨干区之间不通。划区域三大收益：SPF 树变小→CPU 省力；拓扑变化只影响本区域→收敛快；故障域缩小→更稳定。几十台规模的小网单区域即可。

**Router-ID**：全网唯一标识路由器（点分十进制，但**不是 IP 地址**）。
- ★IP 级纠正：【设计本源与技术哲学】：部分通用资料称"未手动配则用最大环回口 IP"——**那是思科做法，华为不是**。默认取第一个配置的接口 IP；工作中必须人为规划手动配置。
- 修改 Router-ID 必须重启进程生效：`reset ospf 1 process`——会断邻居，现网慎操作，规划期定死。
- 实践惯例：Loopback 接口 IP 作 Router-ID + 手动 `ospf 1 router-id x.x.x.x`，全网唯一。
- Router-ID 冲突的深层后果：主从选举靠它比大小——冲突则 DD 选举失败，邻居反复震荡。

**开销**：接口开销 = 参考带宽(默认 100M) ÷ 接口带宽（取整，<1 取 1）；路由开销 = 出接口开销累加（目标网段所在链路的出接口也算）。手动配置 > 自动计算；两端开销不一致会导致来回路径不同（允许但不便排错）。★参考带宽问题：千兆链路算出来开销也是 1 会与百兆等价——全网统一调大 `bandwidth-reference`（想让千兆=5 就设 5000，单位 Mbps）。

### 2.3 五种报文、邻居七条件与状态机（IP 核心）

**报文封装**：OSPF 直接被 IPv4 封装，**协议号 89**，组播 224.0.0.5（所有 OSPF 设备）/ 224.0.0.6（仅 DR/BDR）——ACL 拒了 89 或组播地址 OSPF 就瘫。类比：OSPF 与 IP 是鱼和水——为 IP 算路又靠 IP 封装。

**五报文**（IA 记名称用途，IP 拆字段）：

| 报文 | 用途 |
|---|---|
| Hello | 发现/建立/维护邻居（广播/P2P 每 10s，NBMA/P2MP 每 30s；Dead 默认 4 倍） |
| DD | 只携带 LSDB 中 LSA 的**头部摘要**，比对差异用 |
| LSR | 向邻居请求自己缺的 LSA |
| LSU | 承载具体 LSA 传递（LSA 是内容，LSU 是载体——类比 DNA 与细胞） |
| LSACK | 确认收到 LSA（★LSACK 确认的是 **LSA** 而非 LSU 报文） |

**★DD 按需同步设计思想**（面试重点）： тысяча条 LSA 可能 999 条相同，直接互发 LSA 浪费资源——DD 只带摘要，先"对目录"，再按需 LSR 请求。类比：对比两本书先对目录，不逐页翻。【设计本源与技术哲学】："从设计思想反推行为，比硬记流程容易理解。"

**邻居建立七条件**（缺一不可，`display ospf error` 逐项排错）：Router-ID 不冲突 → 区域 ID 一致 → 认证类型一致 → 认证数据正确 → Hello/Dead 间隔一致 → **N/E 选项比特一致**（N=0,E=1 普通；N=1,E=0 NSSA；N=0,E=0 末节——区域类型不匹配建不起邻居）。

**状态机**：
```
DOWN(没收到报文) → INIT(收到Hello但对方列表里没我) → 2-Way(对方列表里有我,双向通)
→ ExStart(空DD主从选举) → Exchange(带摘要DD) → Loading(LSR/LSU/LSACK)
→ Full(LSDB完全同步 = 邻接关系)
```
- 三次握手：R1 发 Hello（空邻居表）→ R2 收到进 INIT、回 Hello 带上 R1 的 ID → R1 收到直接进 2-Way。
- **主从选举**（ExStart）：双方互发空 DD（I=1,M=1,MS=1，随机序列号），**Router-ID 大者为 Master**；Exchange 阶段 Slave 必须用 Master 的序列号回 DD，Master 每轮序列号+1 作为**隐式确认**——IP 无可靠性，OSPF 用序列号自造可靠性。★Master/Slave 与 DR/BDR 是**两套无关机制**（常见混淆）。
- 2-Way 之后：双方都不是 DR/BDR → 停在 2-Way（DRother 间）；需要同步的（与 DR/BDR、P2P 链路）继续 ExStart。
- **LSA 摘要六参数**：标识三要素（类型 + 链路状态 ID + AdvRouter）+ 新旧三参数（序列号越大越新 → 同序列号比校验和（大者新）→ 再比老化时间：3600s 最新、差>900s 小者新、差<900s 视为相同）。

### 2.4 网络类型与 DR/BDR（IA→IP）

**四种网络类型**（由接口链路层决定，可 `ospf network-type` 修改）：

| 链路层 | 默认类型 | Hello | DR/BDR 选举 |
|---|---|---|---|
| 以太网/FDDI | 广播 Broadcast | 10s | 选 |
| PPP/HDLC | 点到点 P2P | 10s | 不选 |
| 帧中继/ATM | NBMA | 30s | 选 |
| 无默认（手动） | 点到多点 P2MP | 30s | 不选 |

**发包特征四句结论**（对照使用不问为什么）：P2P 五种全组播 224.0.0.5；P2MP 仅 Hello 组播、其余单播；NBMA 五种全单播；广播型 Hello/LSU/LSAck 组播、DD 和 LSR 单播。

**DR/BDR 存在的意义**：广播/NBMA 链路 n 台路由器全互联 Full 邻接会产生大量重复 LSU 泛洪——选出 DR 统一泛洪、所有路由器以 DR 的 LSDB 为基准同步（类比：军训"向左看齐"以排头为基准）。DRother 之间只到 2-Way，邻接只与 DR/BDR 建立。

**选举规则**：①接口 DR 优先级（0~255，默认 1）**大者胜** ②平手比 Router-ID 大者胜 ③★★**无抢夺性**——一经选出保持稳定，后来者优先级再高也只能先当 DRother/BDR（防邻居关系震荡）；④优先级=0 直接丧失被选举资格；⑤全部=0 则全员 Two-Way、LSDB 永远无法同步（★经典故障/面试题）；⑥ DR 挂了 BDR 顶上、再选新 BDR。★DR/BDR 是**接口在链路上的角色**不是路由器的角色——同一台路由器在不同链路可以是不同角色（类比：公司当老板、回家跪搓板）。

**路由器角色**：IR（接口全在同一区域）/ ABR（连多区且**至少一接口在 Area 0**）/ BBR（Area 0 里的路由器）/ ASBR（**执行了引入动作就算**，不要求真引入到路由——"拿了警证就是警察，有没有坏人另说"）。

### 2.5 一类/二类 LSA 与区域内路由计算（IP 核心）

**一类 LSA（Router-LSA）**：每台路由器描述自己直连链路，链路状态 ID = 自身 Router-ID。只有接口加入 OSPF 进程才会被描述——没加入的链路其他路由器算不出路由。

**四种链路类型**（每条由 Link ID + Data + Metric 组成）：

| 类型 | Link ID | Data | 性质 |
|---|---|---|---|
| StubNet（直连网段） | 网络号 | 掩码 | **路由信息**（树叶） |
| P2P（邻居） | 邻居 Router-ID | 本端接口 IP | **拓扑信息**（树干） |
| TransNet（伪节点） | DR 接口 IP（伪节点 Router-ID） | 本端接口 IP | **拓扑信息** |
| VLink（虚链路） | 对端 Router-ID | 本端接口 IP | **拓扑信息** |

- ★Loopback 特例：华为默认无论配什么掩码，一律按 **/32 主机路由**描述（建议直接配 /32 免生歧义）；改 `ospf network-type broadcast` 才按实际掩码。
- ★三个 ID 可能碰巧数值相同但含义完全不同——不要看到一样就当一样。

**二类 LSA（Network-LSA）**：**仅 DR 产生**，描述伪节点连接了哪些实节点（Attached Router 列表）。**伪节点思想**（类比：街坊邻居）——广播链路上若人人互相描述则信息爆炸，OSPF 把整条链路抽象成一台虚拟路由器，各家只需说"我连着这个伪节点"。**算法规定：伪节点到实节点开销恒为 0**（避免重复计费引入人为误差）。

**广播型链路网段路由怎么算**：二类 LSA 的 Link ID（DR 接口 IP）AND Net Mask —— 得出网段路由。★一类 LSA 不负责广播型链路网段路由（HCIE 面试常考）。

**顺藤摸瓜画 SPF 树**：一类 LSA 的 P2P/TransNet 引出别的 LSA（P2P→邻居的一类，TransNet→二类），二类的 Attached Router 又引出各路由器一类——从根出发整棵树必然连续；**路由就是树上的叶子（StubNet），开销沿路径累加**。LSA 数量可预测：一类数=区域内路由器数，二类数=区域内广播型链路数。

**LSA 更新与删除**：周期更新 1800s（30 分钟刷序列号+1、Age 重置——例行巡检，确保每条 LSA 反映半小时内状态）；触发更新（除优先级外任何参数变化）；最大寿命 3600s 到期从 LSDB 删除。**主动删除**：序列号不变、Age 直接置 3600 泛洪出去（典型：取消外部引入立即删五类）。★**路由删除 ≠ LSA 删除**：链路断了路由立刻消失，但残留 LSA 要等老化——孤立 LSA 不在树上，无效但占库。

### 2.6 三类 LSA 与区域间路由、防环（IP 核心）

**三类 LSA（Summary-LSA）**：ABR 产生，仅在产生区域泛洪；链路状态 ID = 目标网络号。每条区域间路由独立一条三类。

**ABR 两个核心行为**：①把直连区域由一类/二类算出的区域内路由，**转换**为其他区域的三类（Metric = ABR 自己到目标的开销）；②把骨干区的三类在直连非骨干区**新生**（不是转发！AdvRouter 改成自己、开销重算）为该区域的三类。三类不能跨区域传递——ABR 是"新生"不是"转发"。

**区域间路由计算**：`开销 = 到 ABR 开销（本区域 SPF 树）+ ABR 到目的开销（三类 Metric）`——到 ABR 段是 SPF（无环），ABR 之后是距离矢量（直接信结果）。必须先知道谁是 ABR。

**ABR 身份识别**：由**一类 LSA 的 flag 比特自我声明**（V/E/B：B=1 即 ABR，E=1 即 ASBR，V=1 有虚链路且 B 必=1）——不能靠三类 LSA 的 AdvRouter 反推（类比：穿警服不等于警察，得出示证件）。`display ospf abr-asbr` 查看到 ABR/ASBR 的路由。

**三类产生条件**：目标路由在 **OSPF 协议路由表**中存在即产生——活跃与否都可以；只有 OSPF 层面被过滤才不产生。

**区域间选路三规则（本质 = 防环）**：
1. 区域内路由（1/2 类）恒优于区域间路由（3 类）；
2. 区域 0 的三类恒优于非骨干区域的三类；
3. 最严格：ABR 在区域 0 **有 Full 邻居时，绝不使用**非骨干区域的三类。

**区域间水平分割**（★防环核心逻辑）：三类能再生三类的前提是这条路由被选中进入 OSPF 路由表；选路规则让"传回来的三类"永远竞争不过本区域一类/骨干三类 → 不进表 → 失去再生资格 → 不能传回原区域。OSPF 双层防环总结：**区域内靠 SPF 算法防环，区域间靠"星型架构 + 水平分割选路"防环**。

**骨干区不连续**：ABR 在区域 0 算不出某路由、只能从非骨干三类学到 → 判定骨干不连续 → 规则③生效，不通。（非骨干区不连无影响。）

### 2.7 五类/四类 LSA 与外部路由选路（IP→IE）

**五类 LSA（AS External）**：ASBR `import-route` 引入外部路由产生；**不按区域存放**（独立外部数据库）、泛洪全 AS、**AdvRouter 全程不变**。引入三参数：开销（默认 1）/ 开销类型（默认 Type2）/ Tag（默认 1）。

**四类 LSA（Summary ASBR）**：与 ASBR 不同区域的 ABR 产生，描述"到 ASBR 的开销"——算法与三类完全同构（到 ABR 开销 + ABR 到 ASBR 开销），链路状态 ID = **ASBR 的 Router-ID**（关键）。同区域的设备直接用 ASBR 一类 LSA 算，无需四类。

**外部路由开销 = 引入开销 + 到 ASBR 开销**。

**开销类型 1 vs 2（★强调）**：
- Type1：显示"引入开销 + 内部路径开销"之和，按和比较——精打细算型；
- Type2（默认）：只显示引入开销，先比引入开销（相同再比到 ASBR 开销）——【工程类比】"领导不惜代价，让你从这个出口出去"，**管理员可控性强**；
- 类型 1 恒优先于类型 2（类比 1 类优于 3 类）。

**存在性金句**：有 5 类不一定有 4 类（单区域无 ABR）；有 4 类不一定有 5 类（执行了引入命令就是 ASBR——"拿了警证就是警察，有没有坏人另说"）。

**网段冲突标识**：两条外部路由网络号相同掩码不同时（如 1.0/27 与 1.0/28），其中一条五类的链路状态 ID 改用**广播地址**表示以保唯一。三类同理。

**四类选路五场景（IE 专题，到同一 ASBR 的多路径）**：★多区域一类都能算到 ASBR 开销时，**优先选区域 ID 大的非骨干区域一类**（开销不同的选小的）；区域 0 引入时 ABR 一类/骨干四类优先，区域 0 无活动邻居才用非骨干四类；**非骨干引入时一类 vs 四类比开销小的**（四类可能赢一类——与三类规则的关键区别）。

### 2.8 虚链路 Vlink（IP→IE）

**三大场景**：①修复非骨干区未连骨干（最常用）②修复被分割的区域 0 ③无中生有造区域 0。

**限制**：只能穿越**一个**非骨干区域；两端路由器必须在该区域中；特殊区域不能建；★★**虚链路永远属于区域 0**（【工程类比】"就像台湾永远是中国的"）——证据：虚链路在一类 LSA 中于区域 0 描述（V 比特）；通过**单播** OSPF 报文维护。开销 = 穿越区域内的最短路径开销（自动计算）。

**两大隐藏规则（★IE 面试）**：
1. **防环**：通过虚链路学到的 1/2/3 类 LSA，**不会**再转换成穿越区域的三类——防止"虚实相间"环路；
2. **可达性校验**：ABR 通过虚链路算出的路由，必须**同时能从穿越区域算出**，才进路由表并对其他区域产生三类——防止"空中楼阁"（黑客帝国类比：虚拟世界要有真实链路对应）。

**坑点**：虚链路所在区域做不了区域 0 汇总（命令能敲不生效——在 R4 上对区域 2 做才行）；多条虚链路交叉的奇葩拓扑可能成环。实验现象：R2、R4 在穿越区域的一类 LSA 中互相标记 Vlink；R4 因虚链路成为 ABR。

```
vlink-peer 4.4.4.4        # 在穿越区域视图下配置对端 Router-ID
display ospf vlink        # 查看：邻居状态 Full、开销、Hello 10s/Dead 40s
```

### 2.9 特殊区域三大件（IP→IE 高频）

**动机**：五类外部路由全网泛洪 → 接入/汇聚弱鸡设备 LSDB 爆炸、外部路由震荡影响全网。特殊区域=在区域边界控制进来的 LSA，省资源提稳定。特殊区域不能是骨干区。

**STUB 末节区域**（区域内所有路由器敲 `stub`）七特点：
1. ABR 不向该区域**泛洪**五类（自己有，只是不给）；
2. ABR 不在该区域**产生**四类（★"不产生"≠"不泛洪"，面试官爱扣字眼）；
3. ABR 产生一条缺省三类（0.0.0.0 四个 0），区域 0 有邻居才产生；
4. 缺省开销默认 1，ABR 上 `default-cost` 可改——**多 ABR 时才有选路意义**；单 ABR 垄断场景改了白改；
5. 失去外部路由精确性 → 可能次优路径；
6. **末节区域不允许引入外部路由**（执行了也无效，不能有 ASBR——★考试重点）；
7. 多 ABR 彼此不计算对方产生的缺省三类——防环。

**完全末节 Totally STUB**：ABR 上加 `no-summary`，连三类明细也不给——LSDB 只剩本区域路由 + 缺省。"解决不了问题就解决制造问题的人。"历史背景：2002 年 64MB 内存都算高配，而今硬件过剩绝大多数场景不再必需。注意 `no-summary` **只在 ABR 敲**（三类本来就只有 ABR 产生）。

**NSSA（Not-So-Stubby Area）**："既要引入外部路由、又要 LSDB 精简"的既要又要方案：
- 区域外五类**不进** NSSA（`nssa` 区域内所有路由器敲）；
- 区域内引入的外部路由用**七类 LSA**（信息字段与五类完全相同，仅类型号不同），只在 NSSA 内泛洪；
- ABR 做 **7 转 5**：默认 **Router-ID 大的 ABR** 做；转换后 AdvRouter 改成自己并声明 ASBR——其他区域只见普通五类，按标准四五类流程计算（★方法论：【设计本源与技术哲学】："站在设备的角度换位思考：路由器只知道收到了什么信息，就按信息做该做的事——分布协同系统，各司其职"）；
- ABR 产生**七类缺省**供区域内部访问外部；完全 NSSA（`nssa no-summary`）同时有 3 类缺省和 7 类缺省时，**优先用 3 类缺省**。

**FA 转发地址（★★IE 核心）**：七类携带 FA；**FA≠0 时开销 = 引入开销 + 到 FA 的 OSPF 开销，下一跳 = 到 FA 的下一跳**（有 FA 就跟着 FA 混，不走 ASBR！）；FA=0 时传统算法。作用：7 转 5 后隐藏真实 ASBR 也算得出最优路径。反证实验：过滤到 FA 的路由 → 所有靠 FA 的外部路由全灭、7 转 5 停摆。

**7 转 5 控制命令**：`translator-always`（谁敲谁转换，双敲双转）；`suppress-forwarding-address`（FA 置 0 回传统算法）；两命令组合可实现双 ABR 负载分担。【设计本源与技术哲学】："每条命令一定有它适合的业务场景，它存在一定是有需要的。" ABR 自己引入外部路由到 NSSA 时产生 七类(NP=0，不会被再转) + 五类；优化命令 `no-import-route` 让 ABR 只产五类。七类与五类选路：**没有谁优先**——同开销类型比开销，相同则负载分担。

### 2.10 静默接口、认证与路由汇总防环（IE 收尾）

**静默接口（Silent Interface）**：终端网段接口只被 LSA 描述、不收发任何 OSPF 报文。防两大私接风险：学到全网路由的**路由泄漏**、发布低开销假路由的**路由欺骗**。只用于终端网段；互联接口用了邻居就没了。惯用法：`silent-interface all` 全静默再 `undo` 恢复互联口。

**报文认证**（只认证 OSPF 报文，业务流量不管）三作用：设备合法性、防篡改、防重放。三种方式：
- 空认证（默认）；明文（密码裸奔，"再穷的家也要有扇门"）；**MD5**（传 128 比特哈希不传密码；三特性：不可逆（指纹类比）、定长输出、**雪崩效应**；Key ID+密钥参与运算，序列号递增防重放）。
- ★区域认证 vs 接口认证（HCIE 面试）：**本质没区别**——都是在接口上对报文做认证，区别只是批量 vs 定制；**接口认证优先**、`authentication-mode null` 可剥离；邻居能否建立只看双方报文里的**认证类型+密码一致**，不关心对面配的哪种。【设计本源与技术哲学】："一切安全机制都是在信任的基础上运转的——没有绝对的安全，只有相对的。"

**邻居建立硬性补充**：广播型链路必须**同网段**（ARP 只解同网段，下一跳必须直连）且**掩码一致**（二类 LSA 由 DR 描述，DR 必须能代表链路上所有地址——"你要是代表不了我，别人访问我的时候就访问不到"）；网络类型不一致：P2P vs 广播**邻居能建但路由算不出**（链路描述冲突）；NBMA 与其他 Hello 间隔/单播组播不匹配直接建不了。**邻居能建立 ≠ 路由能计算**——万变不离其宗：只要链路描述不一致，路由就算不出。MTU 检测：DD 携带接口 MTU（华为默认 0 = 不检测），`ospf mtu-enable` 开检测。

**路由汇总**——区域间汇总 `abr-summary` 只能在 **ABR** 上对直连区域路由做（★面试：汇总是对**路由结果**的操作，区域内路由器改不了 1/2 类 LSA 的描述，只有 ABR 转三类时能汇总）；外部汇总 `asbr-summary` 在 ASBR/7 转 5 ABR 上做。参数：默认开销取明细中最大值、`cost` 指定控制选路、`not-advertise` 汇总不通告（可临时迁流量：一条链路 90% 拥塞时把汇总收掉逼流量走 50% 那条）。明细全挂则汇总自动失效。

**多 ABR 汇总一致性（★必守）**：两台 ABR 对同一区域必须汇总成**相同网络号/掩码**——否则彼此计算对方汇总 → 最长匹配 → 环路。多 ABR 彼此不计算对方产生的相同汇总（防环机制）。

**黑洞路由人为防环（万能方法）**：汇总与缺省共存的场景，在"既不需要该汇总又可能被指为下一跳"的路由器上敲：
```shell
ip route-static <汇总网段> <掩码> NULL0
```
静态优先级 60 < OSPF 150，丢包在本地而不是转发成环。【设计本源与技术哲学】："人为静态黑洞路由防环是万能方法，就像感冒喝板蓝根，板蓝根就可以了。"（同类场景 OSPF 无自动防环——IS-IS 天然动态防环，无需此操作。）

### 2.11 OSPF 核心配置模板与排错命令集（VRP 实战）

#### 经典拓扑配置模板

```shell
# 1. 基础多区域与接口宣告配置
[R1] ospf 1 router-id 1.1.1.1                           # 手工指定 Router-ID（必配，禁止使用默认自动选取）
[R1-ospf-1] area 0                                      # 骨干区域 Area 0
[R1-ospf-1-area-0.0.0.0] network 1.1.1.1 0.0.0.0        # 精确宣告环回口（反掩码全 0）
[R1-ospf-1-area-0.0.0.0] network 10.1.12.0 0.0.0.255    # 宣告与 R2 的互联链路
[R1-ospf-1-area-0.0.0.0] quit
[R1-ospf-1] quit

# 2. 接口参数调优（加速收敛与角色选举）
[R1] interface GigabitEthernet 0/0/1
[R1-GigabitEthernet0/0/1] ospf network-type p2p         # 两个路由器点到点互联改 P2P，免除 DR/BDR 选举（省 40s 等待）
[R1-GigabitEthernet0/0/1] ospf cost 10                  # 手工指定链路开销（默认根据参考带宽 100Mbps 自动计算）
[R1-GigabitEthernet0/0/1] ospf timer hello 5            # 调紧 Hello 间隔（默认 10s，Dead 默认 4 倍自动联动为 20s）
[R1-GigabitEthernet0/0/1] quit

# 3. 终端网段静默与接口认证
[R1-ospf-1] silent-interface GigabitEthernet 0/0/2      # 静默面向 PC 的接入接口（防私接伪造 LSA 与路由泄漏）
[R1] interface GigabitEthernet 0/0/1
[R1-GigabitEthernet0/0/1] ospf authentication-mode md5 1 cipher Huawei@123 # 接口启用 MD5 密文认证

# 4. ABR 区域间汇总与特殊区域配置（在 R2 上配置）
[R2-ospf-1] area 1
[R2-ospf-1-area-0.0.0.1] network 10.1.23.0 0.0.0.255
[R2-ospf-1-area-0.0.0.1] abr-summary 10.1.0.0 255.255.0.0  # 在 ABR 上向 Area 0 汇总 Area 1 的明细路由
[R2-ospf-1-area-0.0.0.1] stub                           # 末节区域（该区域所有路由器均需配置 stub）
# 若配置 Totally Stub 仅需在 ABR 上增加：stub no-summary
```

#### 核心排错命令与状态判定

```shell
# 1. 检查邻居简要状态（排错第一步，确认是否达到 Full）
<R1> display ospf peer brief
 OSPF Process 1 with Router ID 1.1.1.1
  Area 0.0.0.0 interface 10.1.12.1(GigabitEthernet0/0/1)'s neighbors
 Router ID: 2.2.2.2          Address: 10.1.12.2       State: Full  Mode: Nbr is Master  Priority: 1

# 2. 邻居卡滞状态与故障判定表：
# - 卡在 Down：物理不通、ACL 拦截协议号 89、或静默了互联接口；
# - 卡在 Init：本端收到对端 Hello，但对端发来的 Hello 邻居列表中没有本端 Router-ID（单向连通或单向防火墙阻断）；
# - 卡在 2-Way：双方广播链路上 DR 优先级均为 0（DROther 之间保持 2-Way 属于正常现象）；
# - 卡在 ExStart/Exchange：MTU 检测开启且两端 MTU 不一致，导致空 DD/带摘要 DD 报文被丢弃；
# - 卡在 Loading：LSU 报文过大超过 MTU 被静默丢弃，或者 LSDB 校验和错误；
# - display ospf error：查看具体的错误计数（如认证失败、区域 ID 不匹配、Hello 定时器不一致等）。

# 3. 链路状态数据库与路由查看
<R1> display ospf lsdb                                   # 查看全部 LSA 摘要（按 Type、LinkState ID、AdvRouter 分类）
<R1> display ospf lsdb router 1.1.1.1                    # 精确查看某台路由器产生的一类 LSA 拓扑与路由信息
<R1> display ospf routing                                # 查看由 OSPF SPF 算法算出的候选路由表
```

## 三、总结

**核心重点**（十带走）：
1. 链路状态四要素 + 工作四阶段（建邻居→传 LSA→建 LSDB→各跑 SPF）；LSDB 全网一致，SPF 各自为根。
2. Router-ID 华为必须手动规划，改了要重启进程；协议号 89，组播 224.0.0.5/6。
3. 五报文分工与 DD 按需同步设计；LSACK 确认 LSA 不是 LSU；主从选举（Router-ID 大者为 Master、序列号+1 隐式确认）与 DR/BDR 是两套无关机制。
4. 邻居七条件（Router-ID/区域/认证×2/N·E 比特/Hello/Dead）；状态机 DOWN→INIT→2-Way→ExStart→Exchange→Loading→Full。
5. DR/BDR：优先级大者胜、平手比 Router-ID、**无抢夺**、全 0 则永远 2-Way；是链路上的角色不是设备的角色。
6. 一类 LSA 四种链路类型（StubNet=路由信息，P2P/TransNet/VLink=拓扑信息）；二类 LSA 伪节点开销恒 0；广播网段路由由二类算（Link ID AND Mask）；顺藤摸瓜画树、叶子即路由。
7. 三类=ABR 对路由结果的新生转换；区域间"到 ABR SPF + ABR 之后距离矢量"；选路三规则 + 水平分割防环；ABR 身份看一类 V/E/B 比特自声明。
8. 五类=外部路由（AdvRouter 全程不变）；四类=到 ASBR 的路标（链路状态 ID=ASBR Router-ID）；开销 Type2 只看引入开销、Type1 看总和、Type1 恒优先。
9. 特殊区域：STUB 七特点（不产四类、缺省三类、禁引入）；NSSA 7 转 5 + FA 跟 FA 走 + 多 ABR `translator-always`/`suppress-fa` 组合。
10. 汇总只能在 ABR（区域间）/ASBR（外部）做；多 ABR 必须汇总一致；黑洞路由是万能防环补丁。

**落地注意事项**：Router-ID 与参考带宽在规划期一次定死全网统一（改一次断一次网）；以太网两台直连建议改 P2P 类型省掉 DR 选举；终端网段一律静默接口防私接；骨干区不能是特殊区域；虚链路只做过渡手段不进长期设计；现网排错顺序：`display ospf error` 看计数器 → 邻居七条件逐项过 → 状态机卡在哪一步 → LSDB 比对 → 选路规则核对。

**学习建议**：本章是三认证一体的核心卷，建议三层循环学：IA 层先把四阶段/五报文/区域规则说得出；IP 层在 eNSP 把状态机抓包逐包验证（每个状态对应什么报文、DD 序列号怎么跳）；IE 层专攻"选路规则类"面试题（区域间三规则、四五类五场景、FA、多 ABR 汇总一致性）——能给别人白板讲清"为什么这么设计"才算过关。实验检验：五台路由器三区域 + STUB/NSSA + 引入 + 汇总的综合拓扑，能独立完成并预测每台设备的 LSDB 内容。
