## 一、总起

OSPF 学的是"链路状态协议的标准形态"，IS-IS 学的是"同一思想的另一种实现"。它诞生于 ISO 的 CLNP 世界（不是为 IP 设计），因此从报文封装到认证机制都独树一帜：直接跑在链路层之上、TLV 模块化可扩展、区域边界在链路上而不是路由器上。课程一贯采用"对比 OSPF"的讲法——**每个机制都问一句：OSPF 怎么做的、IS-IS 为什么不同**。

**适用人群**：
- **初学 / 转行人员（HCIP 进阶）**：理解独立于 IP 的底层网络协议设计哲学，掌握 NET 地址编址规则与 L1/L2 邻接关系判定；
- **备考工程师（HCIP / HCIE 级）**：攻克 DIS 选举（与 DR 对比）、CSNP/PSNP 同步机制、ATT 缺省与路由泄漏（Route Leaking）、宽开销（Wide Cost）与防环机制；
- **一线工程实践者**：掌握运营商/城域网单区域扁平化部署最佳实践、平滑割接平滑迁移 NET、以及 `send-only` 无损更换认证密码。

## 二、分述

### 2.1 协议定位与 NET 地址

**IS-IS（中间系统到中间系统）**：链路状态路由协议，SPF 算路，主要活跃在运营商广域网/城域网；企业网以 OSPF 为主几乎见不到。【架构师观点】IS-IS 比 OSPF 更简单。

**与 OSPF 的本质区别——协议独立性**（★）：
- OSPF 是"工作在网络层**之上**的路由协议"——必须被 IP 封装（协议号 89），离开 IP 无法工作；
- IS-IS 是"工作在数据链路层**之上**的独立网络层协议"——直接跑在以太网（802.3）帧里，无 IP 包头，不依赖 IPv4/IPv6/CLNP 任何网络层协议。
- 扩展性红利：可以为多种网络层协议（CLNP/IPv4/IPv6）同时提供路由服务；【设计本源与技术哲学】："独成一派的网络层协议，可以独立在链路上工作。"
- 出生背景：为 OSI 的 CLNP 研发，CLNP 未流行导致其一度没落，后扩展支持 IP 成为"集成 IS-IS"复活。

**NET 地址**（SEL=0 的 NSAP，标识一台路由器）——三结构**从末尾往前数**：
```
49.0001.0000.0000.0001.00
└区域ID┘└─ System ID ─┘└SEL┘
 1~13B      固定6B       固定1B=00
```
- 区域 ID 变长自行规划（如 49.0001）；System ID 固定 6 字节、**全网唯一**；SEL 恒 00。
- 实践惯例：System ID 由 Loopback IP 改造（172.16.1.100 → 1720.1600.1100），非强制。
- 一台路由器最多配 **3 个 NET**（区域 ID 可不同、System ID 必须相同）——用于**不中断业务的区域迁移**（OSPF 做不到）。
- NSAP（IDP+DSP 的完整结构）只需了解背景，实际配置只用三结构。

**区域边界在链路上**（★与 OSPF 核心差异）：OSPF 区域边界在路由器上（一台路由器不同接口可属不同区域）；IS-IS 一台路由器完整地属于一个区域，**边界在链路上**。骨干/非骨干在物理拓扑图上**看不出来**，要按邻居级别逻辑分析。

### 2.2 区域模型、路由器级别与邻居规则

**骨干区域 = 连续的 L2 邻居**：IS-IS 区域 ID 没有任何内建含义（不像 OSPF 的 Area 0 语义内建）——骨干由**连续 L2 邻居关系**构成，有且只有一个、必须连续；非骨干区域由同区域 L1 邻居组成（非骨干区本身可以不连续）。★IS-IS **不支持虚链路**——骨干断了无法修复，规划期必须保证 L2 连续。（类比：北京也叫北平、燕京——区域 ID 只是叫法，改号不改位置。）

**三种路由器级别与 OSPF 对照**：

| IS-IS | 对应 OSPF | LSDB 维护 |
|---|---|---|
| L1 | 非骨干区 IR | 仅 L1 LSDB |
| L2 | 骨干区 IR | 仅 L2 LSDB |
| L1-2 | ABR | L1 + L2 两套 LSDB |

**邻居规则（★）**：L1 邻居要求**区域 ID 一致**；L2 邻居区域 ID **不要求**一致。全部组合：L1↔L1（同区）成 L1；L2↔L2（可跨区）成 L2；L1↔L1-2（同区）成 L1；L2↔L1-2（可跨区）成 L2；同区 L1-2↔L1-2 **既建 L1 又建 L2**。【方法论】遇双级别并存**单独拆解分析**，L1 的问题按 L1 查、L2 的问题按 L2 查。

**工程实践（★）**：【设计本源与技术哲学】："实际工作中 IS-IS 很简单——单区域、所有路由器打成 L2，放到一个区就搞定了。运营商城域网基本就是全 L2 单区域完事。"单区域优先 L2（以 L1 打底后续扩展受限），真要多区域再按 OSPF 逻辑换算。

**接口电路级别（Circuit Level）**：接口默认 L1-2 可收发两种 Hello；`isis circuit-level` 可改 L1/L2 只发单一级别 Hello——L1-2 路由器可通过电路级别控制与谁建哪种邻居。

### 2.3 报文体系：九种 PDU 与 TLV 架构

**报文结构** = 通用头部（域内路由协议鉴别器 0x83 等固定字段）+ 指定头部（PDU 特有）+ **可变长字段（TLV）**。

**TLV（Type-Length-Value）核心优势（★）**：按需携带网络属性，新增功能只需定义新 TLV 不改报文结构（类比模块化编程）；厂家可做私有扩展（别人不认识就忽略，不影响兼容）。OSPF 字段固定改结构难——正因 TLV，IS-IS 才能同时服务 CLNP/IPv4/IPv6。

**九种 PDU = 四大类**（按 L1/L2 细分）：

| 大类 | 细分 | 对应 OSPF |
|---|---|---|
| Hello | P2P Hello / L1 LAN Hello / L2 LAN Hello | Hello |
| LSP | L1 LSP / L2 LSP | LSU（承载链路状态） |
| CSNP | L1 / L2 | DD（LSDB 全量摘要） |
| PSNP | L1 / L2 | LSR + LSACK（请求+确认） |

广播链路分 L1/L2 两种 Hello 是因为链路上可能同时存在两级邻居要分开维护。"省长在省里还是农村老家，生活习惯一样"——L1 LSP 与 L2 LSP 内容无本质区别，级别只影响谁跟谁交换。

**常见 TLV**：1=区域地址（Hello）；2=IS 邻居（LSP，拓扑）；128=IP 内部可达（直连网段+开销，路由叶子）；130=IP 外部可达（引入的外部路由）；132=接口 IP。

**开销三种方式**（优先级从高到低）：接口开销 `isis cost` > 全局开销 `circuit-cost` > 自动计算 `auto-cost enable`（参考带宽÷接口带宽×10）。默认：物理口 10、Loopback 0；L1/L2 可分设。
**开销风格五种**（narrow/wide/兼容三种）：默认 **窄模式**——按固定表格查（≥2.5G→10、600M~2.5G→20…），**改参考带宽无效**；宽模式才用公式计算。两种调优组合：带宽不一致用"自动计算+接口微调"；带宽一致用"全局开销+接口微调"。

### 2.4 邻居建立、PPP 协商与 DIS 选举

**邻居建立七条件**：级别一致 → L1 另要求区域一致（L2 不要求）→ 网络类型一致（**与 OSPF 不同：OSPF 类型不一致能建邻居但路由算不出，IS-IS 连邻居都建不起来**）→ 接口地址同网段（**掩码可不一致**，判据是互在对方网段范围内；配了从 IP 也能过）→ System ID 唯一 → Hello 类型一致。HDLC/PPP 链路可 `peer-ip-ignore` 豁免网段检查（广播链路不适用）。【设计本源与技术哲学】："IS-IS 是直接运行在链路层之上、最早为 CLNP 设计的，邻居关系的形成跟 IP 地址无关——但现在 IP 网里部署就要检查 IP 了。"

**三次握手（仅三个状态 Down→Init→Up，LSDB 同步无状态机——"粗线条直男"）**：
- 广播链路（iSNeighbor TLV 携带**对方接口 MAC**）：R1 发 Hello（空邻居）→ R2 回 Hello（带 R1 的 MAC，Init）→ R1 回 Hello（带 R2 的 MAC）双方 Up。组播 MAC：0180-C200-0014（L1）/ 0015（L2）；P2P 化后 0900-2B00-0005。实测三次握手同 1 秒内完成，不按 Hello 周期。
- P2P 链路（P2P Adjacency State TLV 携带**对方 System ID + 状态**）：Down → Init → Up。

**PPP 协商模式与单向邻居（★HCIE 历史考点）**：`isis ppp-negotiation` 三档——3-way-only（发 TLV、收也要求）/ 3-way（默认，发 TLV、收不要求，向下兼容）/ 2-way（发不带 TLV，收到即 Up）。**唯一建不成正常邻居的组合**：一边 2-way、一边 3-way-only → 2-way 端已 Up 而 3-way-only 端永远停在 Init——**单向邻居**，路由算不对。

**DIS 选举六原则（★与 OSPF DR 对照记忆）**：
1. 只有广播型链路选 DIS（P2P 无）；
2. **没有 BDIS**（OSPF 有 BDR）；
3. **DIS 可被抢夺**（OSPF DR 不可抢夺）；
4. 比接口 DIS 优先级，**默认 64、范围 0~127**（字段仅 7 比特，与 OSPF 0~255 不同），0 **也参与**选举（OSPF 0 丧失资格）；
5. 平手比接口 **MAC 大者胜**（OSPF 比 Router-ID 小者胜）；
6. **L1 DIS 与 L2 DIS 分开选举**。

**Hello 定时器非对称（★）**：P2P：Hello 10s / 失效 30s。广播链路：**DIS 每 3s 发 Hello、9s 失效；非 DIS 每 10s 发、30s 失效**——两端参数不一致不影响邻居！【设计本源与技术哲学】："我告诉你我在多少秒后失效，你来按这个时间判断我——I can influence you. OSPF can't"（OSPF 双方必须参数一致，否则邻居起不来）。Hello 报文带 Holdtime 不带 Hello 周期，修改命令 `isis timer hello` / `isis timer holding-multiplier`。

### 2.5 LSP 标识、新旧判断与 LSDB 同步

**LSP ID 三要素** = System ID（6B）+ 伪节点标识符（1B：00=实节点 LSP↔OSPF 一类；非 00=伪节点 LSP↔OSPF 二类，DIS 产生）+ 分片标识符（1B：链路状态太多时分片成 00-00/00-01/…）。类比 OSPF 用"类型+LSA ID+AdvRouter"标识 LSA，IS-IS 用 LSP ID——"在家用真名、公司喊你 Tony，都是你"。

**LSP 新旧判断四步**：序列号（初始 1，越大越新，启动后产生新 LSP +1；收到的比本地小就把本地发回去"反杀"式反向同步）→ 剩余存活时间（**倒计时 1200s**，为 0 者最新=待删除；OSPF 是正计时 0→3600）→ 校验和（越大越新）→ 全同则不再转发。

**LSP 更新**：周期 **900s**（15 分钟，比 OSPF 30 分钟快一倍）序列号+1 刷新；触发更新（地址/掩码/开销/邻居/网段任何变化——实验加环回口序列号 17→18 即时可见）。

**P2P 链路 LSDB 同步**：互发 CSNP（LSDB 全量摘要：LSP ID+序列号+剩余时间+校验和）→ 差缺方发 PSNP（**序列号=0 表示请求**）→ 对方回 LSP → 收方回 PSNP（序列号≠0，携带 LSP 摘要=**确认**）→ 重传 5s。★模拟器（老 VRP）实际顺序常是"先 LSP → PSNP 确认 → CSNP 检查"，新真机按文档顺序——两者都保证最终一致，面试作答需按标准协议流程描述，同时掌握实机差异。

**广播链路 LSDB 同步——DIS 巡检制（★核心）**：
- 新路由器加入：与 DIS 互相直发所有 LSP 完成同步；与非 DIS 到 UP 即停（不重复传）；
- 非 DIS 收到新 LSP **默默加入 LSDB 不确认**（OSPF 有 LSACK）；
- **DIS 每 10s 周期发 CSNP** 巡检——缺谁谁发 PSNP 请求，DIS 回 LSP，**仍不确认**（有能力"从传"：本轮没同步完下轮再来）。【工程类比】"巡检——有事你就说，没事你就不要烦我。"

**为何 IS-IS 敢直接发 LSP 不怕浪费**（★运营商偏爱原因之一）：OSPF 每条外部路由一条五类 LSA 逐条比对；IS-IS 外部路由经**分片 LSP 批量携带**——14 条外部路由一条分片就装下，比对一次搞定。100 台路由器+50 条广播链路 = 仅 150 条 LSP，规模可控。

### 2.6 路由计算与区域间互访：循藤摸瓜、ATT 与路由泄漏

**单区域计算（循藤摸瓜）**：实节点 LSP 的 NBR ID 引出邻居 LSP（一类带出一类）→ 伪节点 LSP（尾节点带 01）引出链路上全部实节点 → 画出完整拓扑树 → 各节点 IP Internal TLV（128）挂叶子 → 开销沿树累加，下一跳查邻居表。【核心强调】"用协议的想法想问题，不要用自己的眼睛看拓扑。"

**★二类伪节点 LSP 纯拓扑**：只描述"连着哪些实节点、开销 0"，**不含任何 IPv4 地址/掩码**（OSPF 二类带 DR 地址+掩码可算网段路由）——广播网段的叶子由**每台路由器在一类（实节点）LSP 里自己描述**。

**L1-2 路由器直连路由描述规则（★标准教材较少提及、现网实测极易踩坑）**：L1 链路/L1-2 链路的直连路由 → L1 和 L2 LSP **都描述**；**L2 链路的直连路由 → 仅 L2 LSP 描述**——L1 区域设备因此**算不出**该网段。这是做电路级别优化后 L1 路由器路由表差异的根本原因。

**骨干区怎么拿到非骨干区路由**：L1-2 路由器把 L1 路由作为**自己 L2 LSP 的直连叶子**泛洪——对骨干路由器而言非骨干网段"看起来直连在 L1-2 路由器上"，纯 SPF 一把算到（OSPF 三类是"到 ABR 开销+LSA 开销"两段式距离矢量；IS-IS 更纯粹）。反向命令 `import-route isis level-1 into level-2` 是**默认行为**（配置不显示）。

**非骨干区怎么出去：ATT 比特 + 缺省路由**。默认 L2 路由**不进** L1 区域（L1 区域默认≈OSPF **完全末节区域**——只有缺省出路）；L1-2 路由器在 **L1 LSP 中 ATT 置 1**（Attachment，"我与骨干相连"），L1 路由器据此算缺省路由（开销=到该 L1-2 的 SPF 开销）；多台 L1-2 都置位则负载分担或按开销优选。
- ATT 置 1 条件：L2 LSDB 中存在**有效的、不同区域的** L2 LSP；
- 人为控制：`attached-bit advertise always`（强制置 1）/ 强制置零 / L1 侧 `attached-bit ignore`（本地忽略不算缺省，不影响同区其他 L1——链路状态泛洪特性）；
- 【方法论】【设计本源与技术哲学】："以终为始——ATT 置 1 还是 0，结果是缺省路由算不算得出来。我需要它指导未知报文转发就有存在的意义。"
- 华为 VRP 模拟器 Bug：自身 ATT 不置 1 时也不计算**别人** ATT=1 的缺省路由（思科会算）——不背死答案，按现场结果分析。

**路由泄漏（Route Leaking，L2→L1）**：解决"缺省路由次优路径"——
```
import-route isis level-2 into level-1 [filter-policy prefix-list 1]
```
泄漏路由在 L1 LSP 中**打星号（\*）**且 **DU 比特置 1**，被当作 L1-2 路由器的直连叶子（开销 = 其路由表中已有开销）。★**直连路由例外**：L1-2 自己的 L2 链路直连网段（如 23.0）泄漏时**不打星号**、过滤策略**管不住**——它被直接当 L1 LSP 直连网段处理，所以过滤只放行 3.0/4.0 时 23.0 照样出现，**正常现象不是配错**（新手高频困惑点）。

**防环三规则（★贯穿全卷）**：
1. **L1 路由恒优于 L2 路由**（实验：去同一目标 L1 开销 50、L2 开销 20，仍走 L1）；
2. **默认 L2→L1 不泄漏**——水平分割，出去的方向回不来；
3. **L2 路由恒优于泄漏进来的路由**（DU 比特标记泄漏身份，不会再被泄回骨干）。
类比 OSPF：一类>三类、骨干三类>非骨干三类。底层防环思维相同：**水平分割**。

### 2.7 认证体系：三类型本质与 SEND-ONLY 神技

**三类型按本质记，别按名字记（★）**：

| 类型 | 实际保护对象 |
|---|---|
| 接口认证 | 仅 Hello 包 |
| 区认证（Area） | L1 的 LSP/CSNP/PSNP |
| 路由域认证（Domain） | L2 的 LSP/CSNP/PSNP |

L2 路由器之间要认证 LSP 就配**路由域**认证（区认证只管 L1）——名字会骗人，本质不会。【设计本源与技术哲学】："按照本质来进行理解，不要直接按照认证类型的名称去理解。"

**四种方式**：明文 simple（裸奔）/ **MD5**（工作主流）/ 密钥链（分时段多密钥，客户嫌麻烦用得少）/ HMAC-SHA256（比 MD5 更强，新设备支持）。

**SEND-ONLY 换密码五步套路（★比 OSPF 高级的无中断换密钥）**：
```
① A: isis authentication-mode md5 plain huawei send-only   # 发旧密码、收不检查
② B: isis authentication-mode md5 plain cisco  send-only   # B 换新密码、收不检查
③ （此时互通）
④ A: isis authentication-mode md5 plain cisco              # A 去掉 send-only
⑤ B: isis authentication-mode md5 plain cisco              # 完成，全程邻居不掉
```
【设计本源与技术哲学】："自古套路得天下。" 套路对域/区认证同样适用。

**路由域认证 vs OSPF 认证的本质区别（★★面试级）**：
- OSPF：认证信息在**包头**——LSA 本体不带认证；R4 收 LSU 认证通过存 LSDB 后**重新生成新 LSU** 泛洪（新包头无认证）。所以 OSPF "区域认证"只在本机接口生效，**不同链路可用不同密码**。
- IS-IS：认证 TLV 是 **LSP 本体的一部分**——【设计本源与技术哲学】："一旦拥有，终身携带"，泛洪到哪帶到哪。因此路由域认证**区域内每台 L2 路由器都必须配且密码相同**，少一台都不行（实验：R5 单独配域认证 → R5 的 LSDB 只剩自己的 LSP，别人的 LSP 全因无认证 TLV 被拒收）。
- 默认行为差异：IS-IS 未启用认证时**忽略**收到的认证 TLV（单边配+SEND-ONLY 邻居照样建立）；OSPF 认证类型不匹配直接起不来。

**精细化参数**：`all-send-only`（三种包发带收不查，换密钥用）；`snp-packet authentication-avoided`（CSNP/PSNP 免认证只认证 LSP——广播网 DIS 每 10s 发 CSNP，避免频繁认证负担）；`snp-packet send-only`（收 SNP 忽略）。排错：`display isis error`。

**配置策略速查**：L2 邻居间 → 域认证；L1 邻居间 → 区认证；邻居 Hello 保护 → 接口认证；L1-2 路由器两种都配；纯 L1 不需要域认证、纯 L2 不需要区认证。

### 2.8 IS-IS vs OSPF 全景对比（贯穿六讲汇总）

| 维度 | OSPF | IS-IS |
|---|---|---|
| 协议位置 | IP 之上（协议号 89） | 链路层之上的独立网络层协议 |
| 报文扩展 | 固定字段 | TLV 模块化（可私有扩展） |
| 区域边界 | 路由器上（接口划区） | 链路上（整机属区） |
| 骨干定义 | Area 0 语义内建 | 连续 L2 邻居（逻辑分析得出） |
| 虚链路 | 支持（修复骨干断连） | **不支持** |
| 路由器角色 | IR/ABR/ASBR | L1/L2/L1-2 |
| 区域间路由 | 三类 LSA（两段式开销） | L1 路由作 L2 LSP 直连叶子（纯 SPF） |
| 非骨干出骨干 | ABR 产三类缺省 | ATT 置 1 诱导缺省（默认≈完全末节） |
| LSP/LSA 类型 | 七类 | 实节点/伪节点两类（外部路由走 TLV130 分片） |
| 广播网指定设备 | DR/BDR（不可抢夺，0 退出选举） | DIS（**可抢夺**，无备份，0 参选，默认 64/0-127） |
| Hello 参数 | 双方必须一致 | 单方声明 Holdtime、不一致也能建 |
| LSDB 确认 | LSACK | PSNP（广播链路部分场景免确认） |
| 区域间防环 | 一类>三类 + 水平分割选路 | L1>L2 + 默认不泄漏 + DU 比特 |
| 认证 | 包头认证（逐跳独立） | LSP 携带 TLV 终身携带（全区一致） |

### 2.9 IS-IS 核心配置模板与排错命令集（VRP 实战）

#### 经典组网配置模板

```shell
# 1. 基础进程、角色与宽开销配置
[R1] isis 1                                             # 启用 IS-IS 进程 1
[R1-isis-1] is-level level-2                            # 角色设置为纯 Level-2（运营商常用单区域扁平组网）
[R1-isis-1] cost-style wide                             # 强制使用 Wide 宽开销（支持 24 位 Metric，支持 MPLS-TE 与 SR 基础）
[R1-isis-1] network-entity 49.0001.0000.0000.0001.00    # NET 地址：区域 49.0001，System-ID 0000.0000.0001，SEL 00
[R1-isis-1] quit

# 2. 接口使能与参数微调
[R1] interface GigabitEthernet 0/0/1
[R1-GigabitEthernet0/0/1] isis enable 1                 # 接口宣告进进程 1
[R1-GigabitEthernet0/0/1] isis circuit-type p2p         # 链路类型设为 P2P（免除 DIS 选举，省去 CSNP 周期轮询，加速收敛）
[R1-GigabitEthernet0/0/1] isis dis-priority 120 level-2 # 若在广播网，调整 DIS 优先级争取当选（默认 64）
[R1-GigabitEthernet0/0/1] isis cost 20 level-2          # 手动指定该接口在 Level-2 下的开销值
[R1-GigabitEthernet0/0/1] quit

# 3. 路由渗透（Route Leaking）配置（在 L1-2 边界路由器上执行）
[R2] isis 1
[R2-isis-1] import-route isis level-2 into level-1      # 将 Level-2 骨干明细路由渗透入 Level-1，解决非骨干次优路径
# 可挂接路由策略只放行特定明细：import-route isis level-2 into level-1 filter-policy ip-prefix P1
```

## 三、总结

**核心重点**：
1. IS-IS 独立于 IP 直接跑在链路层上（802.3），TLV 结构带来超强扩展性——这是它跟到 SRv6 时代的根本原因。
2. NET 三结构从末尾倒着数：SEL(1B=00)+System ID(6B 唯一)+区域 ID(变长)；3 个 NET 用于无中断区域迁移。
3. 骨干=连续 L2 邻居；不支持虚链路；L1 邻居要求同区域、L2 不要求；同区 L1-2 之间双级别邻居并存——分开拆解分析。
4. 邻居七条件里 IS-IS 连网络类型不一致都建不起邻居（OSPF 能建但路由算不出）；地址同网段即可、**掩码可不一致**。
5. 三次握手：广播 iSNeighbor TLV 带 MAC / P2P Adjacency State TLV 带 System ID；PPP 协商唯一坑组合=一侧 2-way 一侧 3-way-only（单向邻居）。
6. DIS 与 DR 五点不同：无备份、可抢夺、优先级 0-127 默认 64、0 也参选、平手比 MAC 大；Hello 定时器非对称且不一致不碍邻居。
7. LSP ID=SystemID+伪节点ID+分片ID；新旧判断序列号>剩余时间（倒计时 1200s）>校验和；周期刷新 900s。
8. LSDB 同步：P2P 走 CSNP 摘要→PSNP 请求→LSP→PSNP 确认；广播走 DIS 10s 巡检 CSNP + 按需 PSNP，免确认靠"从传"兜底。
9. 二类伪节点 LSP 纯拓扑无路由信息——广播网段叶子各家自己描述；L2 链路直连路由只在 L2 LSP 描述（电路级别优化的隐性影响）。
10. 区域间互访三板斧：L1→L2 默认叶子化、ATT 缺省、路由泄漏（L2→L1 打星 DU=1，直连例外不过滤）；防环三规则收口。

**落地注意事项**：工程默认姿势=单区域全 L2 起步；规划期必须保证 L2 连续（没有虚链路后悔药）；窄模式开销风格下改参考带宽无效（先查风格再调优）；泄漏后看到"过滤没拦住的直联网段"别当故障；认证部署域认证要全区全网 L2 同密码，别漏一台；换密钥用 SEND-ONLY 五步法避免夜里断邻居。

**学习建议**：全部实验在 eNSP 完成：先把单区域全 L2 玩熟（邻居/LSDB/路由全流程），再做 L1/L2 双层区域（重点观察 ATT 与缺省生成），最后做路由泄漏+防环验证（改开销看选路翻转）。检验标准：能对照 2.8 的差异表逐条讲出"为什么这么设计"，并独立完成 PPP 单向邻居故障复现与排查。进入第 07 章《路由策略与路由控制》前，确保能白板画出 L1 区域访问骨干区的完整路径决策过程（缺省 vs 泄漏路由 PK）。

|---|---|---|---|
| **IS** | Intermediate System | 中间系统 | OSI 体系中的路由器实体 |
| **ES** | End System | 终端系统 | OSI 体系中的主机或终端设备 |

| 路由泄漏 | import-route level-2 into level-1，明细下放 L1（打星 DU=1） |
| DU 比特 | 泄漏路由的"身份标记"，防二次泄漏回骨干 |
| 电路开销 circuit-cost | 全局统一开销（优先级介于接口开销与自动计算之间） |
