## 一、总起

## 二、分述

### 2.1 网络设备与分层判定（承接认知）

- **分层判定（★）**：看"对数据做的转发动作"，不看物理形态——物理层设备（Hub）基于比特流 0/1 转发；二层设备（交换机）以帧为单位转发；三层设备（路由器）以包为单位转发。【设计本源与技术哲学】："没有绝对的二层设备或三层设备，具体要看针对数据做的转发动作。"
- **Hub**：一接口收到数据就向其他所有接口复制，不识别结构——单播/广播/组播一视同仁。
- **交换机**：先解析组装帧再转发；广播帧/组播帧从其他接口各复制一份，单播帧查表转发（比 Hub 安全）。
- **路由器**：接口收到广播默认不向其他接口转发→天然隔离广播域，又以单播连通不同广播域。广播域变小→安全性提升、省带宽省性能。
- **防火墙**：可理解为带安全功能的路由器，默认拒绝任意方向流量（双向隔离），通过有限授权实现受控访问——核心功能是流量访问控制。
- **无线设备**：FIT AP 无法独立管理（配置在 AC 无线控制器上，大型网络用 AP+AC）；FAT AP 可独立管理（家用无线路由器即属此类）。
- **三种通信**：单播=一对一（私聊）；广播=一对所有（校园广播）；组播=一对多只发所需组（收音机调频、分班上课）。
- **网络分类与拓扑**：局域网（园区/校园，方圆几千米）/城域网（城市）/广域网（跨城市国家）；星型、总线型、环型、树型（汇聚-接入分层）、全网状（可靠性最高、造价贵）、部分网状（关键节点全互联+分支星型）。
- **网络工程**：在信息系统工程方法和组织机构指导下，按标准规划设计，将软硬件集成为满足需求的高性价比网络。技术模块：机房/介质（物理层）→ 路由交换无线（连通层，网工重点）→ 存储计算安全（平台层）→ 应用。工程师能力=专业知识+基本素质+职业技能（沟通★）。

### 2.2 VRP 系统与文件架构

- **VRP（通用路由平台）**：华为数通产品线的操作系统，命令行风格统一——【架构师设计心法】思科靠收购起家各产品命令行不一，华为自研统一。主流 **VRP5**（AR 路由器、S 交换机系列）与 **VRP8**（NE/CE 系列），配置命令相同；`display version` 查看（模拟器 AR 显示 VRP5.130）。
- **文件类型（★忠告：非必要不删除任何文件）**：

| 类型 | 扩展名 | 说明 |
|---|---|---|
| 系统软件 | .cc | 出厂预置、开机自动加载，删除=设备无法启动 |
| 补丁文件 | .pat | 修复缺陷 |
| 配置文件 | .cfg / .zip | 如 vrpcfg.zip，删除=还原出厂配置（密码也存这里） |
| PAK | .bin | 行业客户定制裁剪，一般用不上 |

- **存储设备**：SDRAM=内存（断电丢，启动时加载系统软件与配置到这里运行）；Flash=闪存（非易失，存系统软件/配置，类比内置硬盘）；NVRAM=小容量非易失缓存（存日志，满了写 Flash）；SD 卡（断电不丢，可当 Flash 扩展，类比 U 盘）；USB 口用于升级/传大文件。
- **启动过程**：BootROM 初始化硬件并显示参数（CPU/内存/Flash 大小）→ 加载系统软件进内存 → 读配置进内存 → 设备可用。
- **版本升级流程**：FTP 上传新版 .cc → 命令指定新版本启动 → 重启 → 稳定运行数周后再删旧版（保留回退能力；升级后配置不丢）。

### 2.3 设备管理方式与级别体系

**三种登录入口**：
- **Web（MGMT 网管口）**：网管口出厂 IP 192.168.1.1，电脑设同网段（如 192.168.1.10），浏览器 HTTPS://192.168.1.1 登录（类比家用路由器）。V200R003~V300R019 默认账号 Admin；V300R021 及以后无默认账号（查说明书/官网"企业网"入口）。
- **Console（大门）**：设备自带 console 口，独占式（一人用后他人不能再用），不需网络通——机房现场"破门而入"的最后救命通道。标准参数：**波特率 9600**（华为默认，错设则命令乱码）、数据位 8、校验无、停止位 1、流控无。
- **VTY（窗户）**：Telnet/SSH 网络远程登录，可多人同时。默认 **VTY 0-4 共 5 条线路**，最多 5 人并发（第 6 人进不来）；前提是网络先通。

**用户级别与命令级别（★重点）**：

| 体系 | 范围 | 说明 |
|---|---|---|
| 用户级别 | 0~15（16 个） | 用户登录后拥有的级别 |
| 命令级别 | 0~3（4 个） | 0 参观（ping/traceroute/telnet 客户端）、1 监控（display）、2 配置（路由协议等）、3 管理（文件/FTP/debug） |

用户级别 N 可执行 0~N 级命令；≥3 即全部可用（3~15 等价）。

★**勿改 console 口级别**（默认 3）：调成 0 后一旦断网，console 只剩参观级、无法配置排障，只能重启。【工程类比】"这相当于你自己把你家的门都锁死了，你进不去了。"

★**实验结论：用户级别优先于线路级别**——console 口设 0，但用 3 级账号登录仍是 3 级。

### 2.4 命令行体系：结构、视图、帮助与报错

**命令结构**：命令字 + 关键字 + 参数名 + 参数值。例：`display ip interface G0/0/0` 中 display=命令字、ip=关键字、interface=参数名、G0/0/0=参数值。

**接口编号 G0/0/0（新手卡点）**：格式=槽位/子卡/接口号（类比电影票"区/排/座"）。高端框式设备（如 12708）：0-4、5-8 是接口板，中间 4 块服务板（提升交换性能），上方 9、10 是主控板（大脑）。华为交换机几乎无"卡中卡"，中间位大概率 0（如 G1/0/1）；AR2220 背面固定 3 口 G0/0/0~G0/0/2（背板不可拆→槽 0 子卡 0）。

**视图体系（★）**：
- 用户视图 `<>`：只能查看，不能配置；
- `system-view` 进系统视图 `[]`：大部分配置在此，可再进接口/协议子视图；
- `quit` 回上级、`return` 回用户视图。
- ★视图错=命令报错，新手高频问题。

**编辑与帮助**：缩写=能唯一识别的最短长度（不确定用 `?` 逐级确认）；TAB 补全（多候选时循环切换）；视图下 `?` 给完整帮助、命令中 `?` 给部分帮助；退格删字符、方向键移光标。

**四类常见报错**：

| 报错 | 原因 |
|---|---|
| Incomplete command | 缺参数 |
| 未注册命令 | ①单词错 ②单词对但**视图错**（如 system-name 须在系统视图） |
| 无法解析 | 命令太短不唯一（只敲一个 A） |
| 参数错误 | 超出范围（OSPF 开销最大 65535，输 70000 报错） |

**undo 两用途**：①开关功能（`undo telnet server enable` 关服务）；②删除命令（`undo ip address`、`undo network 10.0.0.0`、`undo ospf 1`）。改错参数可直接覆盖重配，不必先 undo——【实战口诀】"从哪里拿的就放回哪里"。

### 2.5 文件系统管理

命令均在**用户视图**执行，默认位于 flash 根目录（类比 Windows C 盘）：

```
pwd                        # 查看当前目录（指南针）
dir                        # 列目录（d=目录、-=文件）
cd / cd ..                 # 进目录/回上级，支持绝对路径
more <文件>                # 查看文本内容（Ctrl+C 中断）
mkdir <目录>               # 建目录
rmdir <目录>               # 删目录（只能删空目录，非空报错）
copy <源> <目标>           # 复制/备份/拷贝到目录
move <源> <目标>           # 移动（剪切粘贴，原位置消失）
rename <旧> <新>           # 重命名
```

**删除与回收站（★）**：

```
delete flash:/文件              # 删除→进回收站，可恢复
delete /force flash:/文件       # 强制无提示删，仍进回收站
delete /unreserved flash:/文件  # 彻底删除不进回收站，不可恢复（类比 Shift+Delete）
undelete flash:/文件            # 从回收站恢复（需原路径+文件名）
reset recycle-bin               # 清空回收站（逐个提示确认）
```

★回收站不可直接查看内容——用 `reset recycle-bin` 让设备逐个提示文件、答 No 来确认里面有什么。【设计本源与技术哲学】："他已经做得非常的谨慎了，只要你们自己不做妖问题就不大。""非必要不删除。不清楚文件、不知道作用的就放那儿。"

### 2.6 系统参数与配置管理

**主机名与时间**：
- `sysname R1`（系统视图）——★必须与拓扑命名一致，方便排错沟通；
- `clock timezone BJ add 08:00:00` + `clock datetime HH:MM:SS YYYY-MM-DD`（用户视图），`display clock` 查看。

**用户超时**：`idle-timeout 分 秒`（console/VTY 视图），`0 0`=永不退出。console 可设长，VTY 建议短（远程会话安全性要求高）。

**配置生效机制（★核心心智模型）**——【类比"打开记事本"】：开机加载配置到内存（打开文件）→ 敲命令立即在内存生效（敲字上屏）→ 不保存直接重启=内存清空配置丢失（关掉不保存）；`save` 把内存配置写入 flash 的 vrpcfg.zip（保存文件）。

```
display current-configuration   # 看内存中的运行配置
display saved-configuration     # 看 flash 保存的配置
save                            # 内存→flash 保存
compare configuration           # 对比内存与保存配置差异
```

**恢复出厂值（★新手高频陷阱，两步缺一不可）**：
1. `reset saved-configuration`（清除 flash 配置，不进回收站）
2. `reboot` → **必须答 N（不保存内存配置）**
   若答 Y，内存配置会重新写回 flash，等于白清除。

**启动文件查看与切换**：`display startup` 显示本次/下次启动的系统软件与配置文件。升级割接流程：上传新 VRP → `startup system-software <文件>` → reboot。★割接前必须先调走业务；重大保障期（国庆/双十一）**封网**——冻结变更。`startup saved-configuration <文件>` 可切换不同配置文件启动（类比奥运期间特殊配置、结束后切回日常）。

### 2.7 远程管理实战：综合实验（Console + VTY + FTP + SSH）

**实验拓扑**：R1(10.1.1.1) — R2/R3 — User1/User2。

**需求**：console 密码 Huawei@123 级 3；VTY 0-1 走 AAA（User1 级 3 / User2 级 0 仅 Telnet）；FTP 账号级 3；SSH 账号 ruanwei/123456 级 3。

**配置要点**：

```
# console 密码登录
user-interface console 0
 authentication-mode password
 set authentication password cipher Huawei@123
 user privilege level 3

# VTY 走 AAA
user-interface vty 0 4
 authentication-mode aaa

# AAA 本地用户
local-user user1 password cipher <密码>
 local-user user1 privilege level 3
 local-user ftp password cipher <密码>
 local-user ftp privilege level 3
 local-user ftp ftp-directory flash:     # FTP 根目录，限制不可向上
 local-user ftp service-type ftp

# FTP
ftp server enable

# SSH（步骤链，缺一不可）
rsa local-key-pair create                # ①创建本机密钥对
stelnet server enable                    # ②启用 SSH 服务
ssh user ruanwei authentication-type password   # ③用户认证方式
user-interface vty 0 4
 protocol inbound all                    # ④VTY 放行（all=SSH+Telnet；只写 ssh 会阻断 Telnet）
```

**客户端验证**：User1 telnet 进得系统视图；User2 级 0 被拒；User2 首次 SSH 需先 `ssh client first-time enable` → stelnet 登录 → 保存公钥 yes → 下次直登。FTP 登录后 `get` 下载 / `put` 上传。

**生产环境经典两次排错实录（★宝贵）**：①缺 `protocol inbound all` → SSH 被拒；②缺 `ssh client first-time enable` → 客户端无公钥无法完成首次握手。排错过程比成功配置更有学习价值。

## 三、总结

**核心重点**：
1. 分层判定看转发动作不看设备名；路由器接口隔离广播域，交换机/Hub 不隔离。
2. VRP=华为数通设备的操作系统（VRP5 主流），文件四类：.cc 系统软件 / .pat 补丁 / .cfg|.zip 配置 / .bin PAK——非必要不删除。
3. 用户级别 0~15 对应命令级别 0~3；≥3 全能力；**用户级别优先于线路级别**；console 口级别默认 3 勿动。
4. 视图体系：`<>` 只读 → `system-view` 进 `[]` 配置；新手报错第一大来源是视图错。
5. 配置生效模型"记事本"：命令先在内存生效，`save` 才落 flash；`display current` vs `display saved` 分清运行配置与保存配置。
6. 恢复出厂=reset saved-configuration + reboot 答 **N**（答 Y 前功尽弃）。
7. 文件删除三级：delete（回收站）/ delete /force（无提示仍可恢复）/ delete /unreserved（不可恢复）；回收站内容用 reset recycle-bin 答 No 探明。
8. SSH 五步链：密钥对→启用服务→用户认证→VTY 放行→客户端 first-time enable。
9. 升级/切配置走 startup 体系；割接先调业务，重大保障期封网。
10. 接口编号=槽位/子卡/接口，华为交换机中间位大概率 0。

**落地注意事项**：console 波特率 9600 错设则乱码；vrpcfg.zip 不能删（删=出厂配置，密码也丢）；VTY 只有 5 条线路，第 6 人进不来；Telnet 明文、SSH 加密，生产网用 SSH；FTP 账号级别需 ≥3 并用 ftp-directory 限定根目录；割接窗口选业务低峰，变更前先备份配置（copy vrpcfg.zip）。

**学习建议**：本章是全集实验地基，检验标准是不看笔记独立完成综合实验四件套（console 密码+AAA、VTY、FTP、SSH），并故意制造一次"答 Y"的恢复出厂失败复盘。模拟器保存三步：每台 save → 停止前点软件"保存" → 导出配置文本备份。
