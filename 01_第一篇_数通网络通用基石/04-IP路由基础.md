## 一、总起

上一卷解决了"一个 IP 属于哪个网段"的计算问题，本章回答路由器最核心的问题：**收到一个报文，往哪转？**——先建立路由表的数据结构认知（四要素、来源、优先级/开销），再学第一代人类干预手段：静态路由。随后打通两次"全流程"：同网段通信（ARP）与跨网段通信（查表转发+逐跳重封装），最后掌握网工三大工具（ping/tracert/黑洞路由）与路由汇总思维。

## 二、分述

### 2.1 IP 地址收尾：私网、特殊地址与规划原则

**私网地址三段**（可任意使用，公网不传播，无冲突风险）：
- A 类：10.0.0.0/8；B 类：172.16.0.0~172.31.255.255（记住 16 和 31）；C 类：192.168.0.0~192.168.255.255。
- 企业上网结构：内网私网 → 出口路由器 NAT 转公网。家庭宽带常做**两次 NAT**（光猫一次+家用路由器一次），延时差异如体检指标略高——数字有别、体验无异。

**特殊地址四类**：

| 地址 | 名称 | 要点 |
|---|---|---|
| 主机位全 1 | 子网广播 | 代表本网段所有设备 |
| 255.255.255.255 | 全网（有限）广播 | 代表全网设备；**路由器默认不转发任何广播**——程序多用它发广播：不用改配置就能全网段通用（"有限"即受限于路由器隔离） |
| 0.0.0.0 | 任意/未知地址 | 只可作**源 IP**（典型：DHCP 客户端还没地址时发请求）、不可作目标 |
| 127.0.0.0/8 | 回环地址 | 不出物理接口，本机自测 |
| 169.254.0.0/16 | 本地链路地址 | 自动获取地址失败后的临时地址，实际极少用 |

**IP 规划五原则**：唯一性（★放第一位，内网冲突极难修复）、连续性（便于运维汇总）、结构化（与网络层次对应）、扩展性（留余量）、业务相关性（"望址识义"，如服务器以 10 结尾、一层 1.0 二层 2.0；但有规律可能泄密）。地址改造遵循**最小变动原则**：业务地址尽量不动，优先只改设备互联地址。【设计本源与技术哲学】："IP 地址的规划是根据具体项目具体分析的，没有一成不变的方式。"

### 2.2 路由表结构与路由来源

- **一句话总纲**：路由器通过路由表中的路由信息指导 IP 报文的转发。路由 = 指导报文转发的路径信息。
- **路由信息四要素**：目标网络号 + 子网掩码 + 本地出接口 + 下一跳 IP。类比路标——指完路之后，报文能不能到已与指路的路由器无关，"我的工作已经完成了"。
- **路由只有两种**（类比：世界上只有"自己生的"和"别人家的"两种小孩）：
  - **直连路由**：接口配好 IP/掩码**自动生成**，接口 down 自动删除、up 自动恢复；
  - **非直连路由**：静态（管理员手配）或动态协议（OSPF/IS-IS/BGP/RIP）学习。
- **`display ip routing-table` 字段解读**：

| 字段 | 含义 |
|---|---|
| Destination/Mask | 目标网络号/掩码；/32 为主机路由 |
| Protocol | Direct 直连 / Static 静态 / OSPF / IS-IS / BGP |
| Preference 优先级 | 0~255 **越小越可信**：直连 0（不可改）、OSPF 内部 10、IS-IS 15、静态 60、RIP 100、BGP 255 |
| Cost 开销 | 直连/静态恒 0；同协议不同路径间比较，越小越优 |
| Flag | D=已下发 FIB（一般不关注） |

### 2.3 路由优选与报文转发规则

**路由进表规则（三步）**：
1. 去往同一目的（**网络号和掩码都相同**才算同网段）多来源并存 → **比优先级**，小者进表；
2. 同优先级（通常同协议）→ **比开销**，小者进表；
3. 同协议同开销 → **负载分担**（默认最多 8 条）；★不同协议的路由不能负载分担。
- ★管理员把不同来源的优先级**改成相同值**时，按默认优先级判优——改了等于没改（华为有内部/外部优先级之分）。
- 开销不可跨协议比较：RIP 按跳数（值 2）、OSPF 按带宽累加（值 30），"价值观不同无法比好坏"。

**报文转发规则——最长匹配原则**：报文同时匹配多条路由时，选**掩码最长**的那条执行转发。例：表中同时有 1.1.1.0/24、/27、/29——目标 1.1.1.1 用 /29，1.1.1.14 用 /27，1.1.1.53 只匹配 /24。无匹配路由即丢弃。★IP 报文头**不携带掩码字段**，匹配只看路由表里存的掩码。

**RIB/FIB 分离（转控分离架构）**：RIB（路由信息库）在主控板，由协议计算生成；FIB（转发信息库）是 RIB 下发到各线卡的转发表，报文在线卡直接查 FIB 转发、不经过主控。类比：大脑思考（路由计算），手脚执行（报文转发）——"脑子有病治脑子，不要砍手；路由表有问题转发表自然有问题，修路由表即可"。中高端设备皆用此架构提升转发性能。

### 2.4 静态路由：配置与下一跳规则

**特性**：不占设备资源（无协议交互）、可控性强（想通哪些配哪些）、适合拓扑简单稳定的小网；缺点是失效需人工恢复、有备用路径也无法自动切换。类比：火车只能在铁轨上跑，轨断了就停。

**配置命令**：
```shell
# 1. 标准静态路由配置（以太网等广播链路必须指定下一跳 IP）
[R1] ip route-static 192.168.2.0 255.255.255.0 10.1.12.2 # 或简写掩码：ip route-static 192.168.2.0 24 10.1.12.2

# 2. 点到点链路（PPP/HDLC）可指定出接口（但强烈建议依然指定下一跳以保持规范）
[R1] ip route-static 192.168.3.0 24 Serial 1/0/0

# 3. 缺省静态路由（默认网关，兜底全网未知流量）
[R1] ip route-static 0.0.0.0 0 10.1.12.2

# 4. 浮动静态路由（修改优先级实现主备备份链路）
[R1] ip route-static 192.168.2.0 24 10.1.21.2 preference 100 # 主链路优先级默认 60，备链路设为 100

# 5. 查看路由表与排错
<R1> display ip routing-table                            # 查看全局单播路由表
<R1> display ip routing-table 192.168.2.1 verbose        # 查看某具体目的 IP 的最长匹配与详细迭代参数
```

**下一跳 vs 出接口（★★考点）**：
- **任何时候都可以用下一跳**；
- 出接口为 **PPP/HDLC**（点到点）时可用出接口——链路上只有一个对端，写谁无所谓；
- 出接口为**以太网时必须用下一跳**——MA 多路访问链路一个接口多个下一跳，只写出接口（如 G0）路由器无法确定发 1.1 还是 1.2。
- 写了下一跳后**出接口由路由器自动迭代**（把下一跳当地址查直连路由找出口），管理员不必操心。

**全网通配置原则**：**"所有路由器都要拥有所有的非直连路由信息"**——对着拓扑逐台分析，把每个非直连网段配齐即可。

### 2.5 ARP 与同/跨网段通信全流程

**同网段判定**：自身 IP 与掩码相与得网络号，目标 IP 与自身掩码相与，两者相同即同网段。

**ARP（类型 0x0806，无传输层/应用层封装，纯链路层之上）**：
- Request=广播帧（目标 MAC 全 1），核心字段：发送者 MAC/IP + 目标 MAC（全 1 填充）/目标 IP；Reply=单播。
- ★接收方会把 Request 里**发送者的 MAC/IP 直接记入自己的 ARP 缓存**——设计理念"存在即真实"（收到请求就信任其真实存在，回报时免二次解析）；这也解释了 ARP 攻击的根源：**无条件信任**。
- 类比（点名）：点名喊到"张三同学"，全班听到但知道不是叫自己就忽略，郭德纲本人应答。
- 缓存：华为设备 ARP 老化 20 分钟，自身接口的 ARP 不超时；**每个接口独立维护** ARP 缓存。

**同网段通信三步**：判定同网段 → 查 ARP 缓存找目标 MAC → 无则广播 Request，收到 Reply 后封装发送。

**跨网段通信流程（★★必背）**：
1. PC 判定跨网段 → 查 ARP 解析**网关** MAC → 帧封装（目标 MAC=网关）发出；
2. 路由器收到帧，目标 MAC 是自己 → 二层解封装 → 发现目标 IP 非本机接口 → 查路由表；
3. 匹配路由 → 找出口和下一跳 → **重新二层封装**（新链路新 MAC）转发；
4. 逐跳重复，直至末跳匹配直连路由 → 解析目标主机 MAC →送达。

【设计本源与技术哲学】："当路由器二层解封装后发现目标 IP 非自身接口 IP 时，对该报文执行三层转发——查路由表。" **关键认知**：每跳换链路就换二层帧头，IP 头端到端不变——IP 定义端到端，链路层负责逐跳。**网关的本质就是下一跳**：给电脑配网关 = 在其路由表里加一条缺省路由指向网关。

### 2.6 缺省路由、ICMP 与 Traceroute

**缺省路由（0.0.0.0/0）**：匹配表中找不到的任何目标。典型场景：企业出口——互联网路由几十万条，一条缺省指向运营商即可。★风险：**双向互指成环**（R2 缺省→R3、R3 缺省→R2，未知目标在两机间无限循环），故只在出口单向使用。

**ICMP（协议号 1）与 Ping**：Ping = Echo Request（Type=8）+ Echo Reply（Type=0），收到 Reply 即证明三层来回可达。

**ICMP 不可达消息排错表（★★实用）**：

| Type/Code | 含义 | 原因 |
|---|---|---|
| 3/0 | 网络不可达 | 路由器缺目标网段路由 |
| 3/1 | 主机不可达 | 有直连路由但 ARP 解析不到主机（地址不存在） |
| 3/2 | 协议不可达 | ACL 封了协议 |
| 3/3 | 端口不可达 | ACL 封了端口 |

- ★**单向 Ping 通 = 路由健全**：去程通说明 Request 到达、Reply 发出，问题在反向 ACL 过滤。排错口诀：先查去程路由，再查回程路由，最后怀疑 ACL。
- 能 Ping 通网关 ≠ 能上外网——只证明 PC 到网关二层 OK，需查网关路由表。

**Traceroute**：ICMP 提供的功能（非独立协议），报文用 **UDP** 封装。原理：TTL=1 发出 → 第一跳减到 0 丢包并回 **TTL 超时**报文（以收包接口为源）→ 记录第一跳；TTL=2 再测第二跳……每跳默认测**三次**（三个时间值）。企业内网正常可用；互联网大概率探测不出（中间路由器可禁用响应），VPN 等复杂场景也不一定全通。

**重定向（简提）**：ICMP 路径优化——告诉主机"去某地址请直接找另一台路由器"。仅为本网段主机服务、目标须同网段；因可被伪造有安全风险，主流设备默认关闭。

### 2.7 路由递归、等价与浮动路由

**下一跳可达性铁律**（★【设计本源与技术哲学】："路由必须有直连的下一跳才能够指导报文转发"）：非直连下一跳若无路由可达 → 该路由 **inactive**（出接口 unknown、不下发 FIB、不进路由表）。用 `display ip routing-table protocol static` 可查 inactive 路由。

**路由递归（迭代）**：下一跳非直连时，路由器自动"用下一跳当地址再查表"，逐层迭代到直连下一跳为止。类比：【设计本源与技术哲学】："爸爸的爸爸叫什么？妈妈的妈妈叫什么？——这就是路由递归。"
- 手动递归链示例：`ip route-static 3.3.3.0 24 10.1.34.4` + `ip route-static 10.1.34.0 24 10.1.23.3` + `ip route-static 10.1.23.0 24 10.1.1.2`（层层迭代到直连）；
- **指定出接口递归**：`ip route-static x mask 接口 下一跳`——只按指定接口迭代，递归结果与指定不符则路由无效；
- 多次递归技术上可行但无必要——"没有必要为了递归而去递归……脱裤子放屁。"

**等价路由与负载分担**：同一目的地两条不同下一跳的静态路由自动**负载分担且互为备份**。机制（★）：默认**基于流（per-flow）且不可关闭**——有端口信息按**五元组**哈希、无端口（如 ICMP）按**二元组**，同流走同出口。★负载分担 ≠ 负载均衡：流大小不同，实际带宽占用不均衡。

**浮动路由（主备）**：两条路带宽差距大时不适用分担——主路径默认优先级 60，备路径 `preference 70` 待命；主失效备自动接管，主恢复自动切回。"值越小优先级越高。"

### 2.8 CIDR、路由汇总与环路防护

**CIDR**：不再按 A/B/C 类，只看网络号+掩码长度（192.168.0.0/16 合法）。

**路由汇总**：多个网段用一个网络号代表——省内存、查表快、**增强稳定性**（一条明细失效不影响汇总路由）。

**汇总方法（二进制法）**：各网段网络号写二进制 → 找前面相同的比特位 → 相同位保留、后面全 0 = 汇总网络号；相同位数 = 掩码长度。

**精确汇总条件**（★）：必须**连续且 2ⁿ 个**网段（2、4、8…按 0-1、2-3、0-3、4-7 规律排列）；**奇数个网段绝不可能精确汇总**。不精确汇总 = 汇总范围包含网中不存在的地址。

**地址规划配合**（【设计本源与技术哲学】："少数民族聚居"）：同主类网段集中分配在一个区域，不要被别的主类网段隔开；互联网段一个主类、业务网段一个主类。

**汇总两大风险与规避**：
1. 不精确汇总+不当地址分配 → 报文**跑偏**（匹配到别家更精确的路由走错路）；
2. 不精确汇总+缺省路由 → **环路**（两路由器互指，不存在的网段来回转发）。
3. 破环方法：写一条**更精确的路由**指向正确路径；或指向**空接口 NULL0**（黑洞路由），示例：
```
ip route-static 10.1.100.0 24 NULL0    # 问题网段明细丢黑洞
ip route-static 10.1.0.0 16 NULL0      # 不精确汇总丢黑洞，防缺省环路
```

## 三、总结

**核心重点**：
1. 路由四要素（网络号/掩码/出接口/下一跳）；来源就两种——直连（自动）与非直连（静态/动态）。
2. 优先级表必背：直连 0 / OSPF 10 / IS-IS 15 / 静态 60 / RIP 100 / BGP 255，越小越可信；先比优先级再比开销，同开销负载分担。
3. 最长匹配原则选路；IP 头不带掩码，掩码只存于路由表。
4. 以太网接口配静态路由**必须用下一跳**（MA 链路）；PPP/HDLC 可用出接口；下一跳由路由器自动迭代找出接口。
5. 跨网段通信 = 逐跳"解封装→查表→重封装"，IP 端到端不变、MAC 每跳都换；网关本质就是下一跳。
6. ARP"存在即真实"的缓存学习机制既高效也是攻击面；每接口独立维护缓存。
7. ICMP 不可达表（网络 0/主机 1/协议 2/端口 3）是排错第一工具；单向 Ping 通即证明路由健全。
8. 非直连下一跳必须可递归到直连，否则路由 inactive 不进表。
9. 负载分担基于流（五元组/二元组）不可关、≠均衡；浮动路由用 preference 差实现主备。
10. 精确汇总要连续 2ⁿ 个网段；不精确汇总+缺省=环路，用 NULL0 黑洞路由破环。

**落地注意事项**：企业出口单向配缺省，禁止双向互指；静态路由掩码必须精确按规划配；现网改造遵循最小变动原则（业务地址不动、只改互联地址）；互联网 Traceroute 探不全属正常（中间设备可禁响应），排错以内网为准。

**学习建议**：本章检验标准有三个：① 给一张四五台路由器的拓扑，能逐台写出全网通的静态路由并说明哪些必须用下一跳；② 能白板画出 PC1 ping PC2 的完整跨网段流程（含每跳的帧重封装）；③ 能解释"路由表里有这条路由但 ping 不通"的三种可能（下一跳不可达 inactive / 回程缺路由 / ACL 过滤）。达标后进入第 05 章《OSPF路由协议》。

| 术语缩写 | 英文全称 | 中文含义 | 关键作用 |
|---|---|---|---|
| **RIB** | Routing Information Base | 路由信息库 | 路由器主控板维护的全局软件路由表，汇总所有协议计算出的最优路由 |
| **FIB** | Forwarding Information Base | 转发信息库 | 接口板硬件芯片维护的转发表，直接由硬件线速查表转发业务数据包 |
| **ARP** | Address Resolution Protocol | 地址解析协议 | 实现 IPv4 逻辑地址到二层物理 MAC 地址的动态映射与解析 |
| **CIDR** | Classless Inter-Domain Routing | 无类域间路由 | 消除传统 A/B/C 类地址边界，采用可变长掩码前缀进行灵活路由聚合 |
| **ICMP** | Internet Control Message Protocol | 互联网控制报文协议 | 负责传递网络连通性差错报告与探测信息（Ping 与 Tracert 的底层协议） |
| **TTL** | Time to Live | 生存时间 | IP 头字段，防止报文在网络拓扑环路中无限循环转发，每过一跳减 1 |
