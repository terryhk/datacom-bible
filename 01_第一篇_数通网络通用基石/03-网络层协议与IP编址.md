## 二、分述

### 2.1 交换机工作原理：MAC 地址表

- **表结构与学习**：开机后在内存构建空白 MAC 地址表（关机清空），记录"MAC 地址 + 端口号"。收到帧→读**源 MAC**→与接收接口绑定记入表中。每收一帧都学习：新 MAC 新增表项；已存在则**刷新老化时间回 300 秒**。
- **老化机制（★）**：默认 **300 秒**（可调）未刷新自动清除——保证表项"最新最真最全"（类比人的新陈代谢）。但接口物理层感知对端失效（关机/拔线/shutdown）时**立即删除**表项，不等 300 秒。
- **MAC 地址漂移**：同一 MAC 从不同接口学到→**后学到的覆盖替换**旧表项，保证转发路径跟随真实拓扑。

### 2.2 交换机三种转发行为（★必背）

| 行为 | 触发条件 | 动作 |
|---|---|---|
| **泛洪 Flooding** | ①广播帧（目标 MAC 全 1）②组播帧（默认）③未知单播（MAC 表查不到） | 从其他所有接口各复制一份 |
| **转发 Forwarding** | 目标 MAC 已知的单播 | 仅从对应端口发出 |
| **丢弃 Discarding** | 接收接口恰为该帧应发接口 | 直接丢弃（收到帧不会再从原口发回） |

- 丢弃行为的设计目的：防 Hub-交换机混合组网时的**重复帧**——Hub 泛洪回交换机，若无此机制交换机会把帧再从原口发回，目标主机收到重复帧→应用程序出现"无可预知的结果"。
- 【设计本源与技术哲学】："逆向思维：寻求这件事的价值就可反问，如果没有这个东西会怎么样。"
- ★辨析：这里的"丢弃"仅指同接口收发场景的防重复帧保护，不是所有丢包原因；多路访问是**组网形态**，泛洪是**转发行为**，勿混淆。

### 2.3 以太网帧格式再认识：Ethernet II vs 802.3

| 封装 | 用途 | 结构特点 |
|---|---|---|
| **Ethernet II** | 一般用户应用数据（FTP/HTTP/Telnet） | 类型字段标识上层（0800=IP、0806=ARP） |
| **802.3** | 网络协议数据（生成树/IS-IS/CDP） | 长度字段 + LLC（3 字节 DSAP/SSAP/Control，公有协议靠 DSAP/SSAP 标识上层，如 IP→0x06）+ 可选 SNAP（5 字节，厂家私有协议用；思科 CDP→OUI=Cisco、PID=0x2000） |

华为 MSTP 用 802.3 无 SNAP（业界标准）。经验规律不绝对，**以抓包为准**。

### 2.4 IP 头部逐字段解析

IP 头固定 20 字节 + 可选项（最长 40），总长 20~60 字节。

- **Version**：4=IPv4。
- **Header Length**：头部长度。
- **TOS（8 比特，用前 6 位，0~63 共 64 个值）**：给流量打标的 QoS 字段。
  - 默认转发=FIFO 先进先出、尽力而为——问题：不同业务价值不同却被同等对待。
  - 三类流量的需求画像（★QoS 铺垫）：语音 64kbps/路给够即可、延时丢包要极低（类比重秤最大 500 斤，压 600 斤仍显示 500）；视频 4~10Mbps 给够即可、延时丢包要求低；数据（FTP/迅雷）无天花板、给多少吃多少、TCP 重传容忍丢包、延时不敏感。
  - TOS 打标→设备分不同队列→优先级队列先转发=差异化服务。【设计本源与技术哲学】："QoS 要用在报文所经过的每台设备上"（类比领导视察全程封路）。★QoS 是优化资源配置，不是解决带宽不够。
- **Total Length**：IP 包总长。与 Header Length 配合逐层解封装：帧去 14 头 4 尾→IP 包（按 Total Length）→去包头→段→去 TCP/UDP 头→载荷交应用。
- **TTL（8 比特，0~255，常见默认 64/128/255 由操作系统决定）**：每经一台路由器**先减 1**，减到 0 丢弃。
  - ★★★考点：**TTL ≠ 防环，是环路产生后的兜底**。【设计本源与技术哲学】："TTL 值防环？防个屁环。它是在环路产生之后避免极端故障，防止报文无休止转发导致带宽和设备性能消耗。"
  - 环路危害：A↔B 环路→报文无限转发→带宽耗尽→正常业务也被拖垮。
- **Protocol**：6=TCP、17=UDP（★必记，类似二层类型字段的作用）。
- **Source/Destination IP**：
  - **IP 地址：全局有效、全局唯一**——既能定义同链路通信，也能定义跨链路通信。
  - **MAC 地址：全局有效、本地唯一**——只能定义同链路通信，跨广播域 MAC 可重复（路由器重写二层信息）。
  - 【设计本源与技术哲学】："网络层最牛逼的地方——链路上的通信可通过 IP 定义，跨链路的通信也可通过 IP 定义。"

### 2.5 IP 分片与重组

- **为何分片**：IP 包封装成帧后若大于链路 MTU（以太网 1500），网络层分片、目标主机重组。
- **MTU=1500 的设计权衡**：太小编码开销占比高，太大其他帧等待久（延时高），1500 是"最高性价比值"。
- **三个关键字段**：

| 字段 | 作用 |
|---|---|
| **Identification** | 同一原始包的分片共用相同 ID，据此归类重组 |
| **Flags（3 比特）** | DF=1 不能分片（MTU 不够直接丢包）；DF=0 可分片。MF=1 还有后续分片，MF=0 是最后一片 |
| **Fragment Offset** | 该分片数据距原始包数据起始的偏移，**偏移值 ×8 = 前序分片数据总字节数**（第二片偏移=第一片数据量÷8，第三片=前两片之和÷8） |

- ★**仅第一个分片携带传输层头**（TCP/UDP 头），后续分片直接跟应用数据——重组时只需一个传输层头。
- **重组**：按偏移从小到大排列拼接（目标设备自动完成）。
- IPv6 把分片移入扩展头，不分片的包不携带分片信息（更高效）。

### 2.6 二/十进制快速转换（全集计算地基）

背熟 2⁰~2⁷：**128、64、32、16、8、4、2、1**。

- 十→二：大到小逐位扣减。192=128+64→11000000；99=64+32+2+1→01100011。
- 二→十：为 1 的位幂值相加。01110101→64+32+16+4+1=117。

### 2.7 IP 地址结构与子网掩码

- **32 比特 = 前连续网络位 + 后连续主机位**（★强调三次"连续"，不可穿插）。网络位判定同网段，主机位区分网内设备。类比：网络位=小区名，主机位=楼栋号。
- **子网掩码**：32 比特、连续 1+连续 0，**1 对应网络位、0 对应主机位**，与 IP 一一对应。两种写法：掩码表示法（255.255.255.0）/ 前缀表示法（/24，数字=网络位数量）。
- **默认掩码**（人为定义）：A 类 /8，B 类 /16，C 类 /24。

### 2.8 五类分类与特殊地址

| 类 | 首比特 | 范围 | 默认掩码 | 结构 |
|---|---|---|---|---|
| A | 0 | 1.0.0.0 ~ 126.255.255.255 | /8 | 8 网 + 24 主 |
| B | 10 | 128.0.0.0 ~ 191.255.255.255 | /16 | 16 网 + 16 主 |
| C | 110 | 192.0.0.0 ~ 223.255.255.255 | /24 | 24 网 + 8 主 |
| D | 1110 | 224.0.0.0 ~ 239.255.255.255 | 无 | 组播，不分网络位/主机位 |
| E | 1111 | 240.0.0.0 ~ 255.255.255.255 | 无 | 研究保留 |

- 数学逻辑：0 打头占地址空间一半→A 类最多；10 打头占剩下一半→B 类 1/4，以此类推。
- A/B/C=单播地址，可分配给主机接口；分类是"默认"起点，实际可配非默认掩码（子网划分）。
- **保留段**：0.x 不分配；**127.x=本地环回**——ping 不通 127 是网卡驱动问题，不是网线问题（★排错常识）。

**三个特殊地址**：
- **网络号**：主机位全 0，代表"这个网络本身"，不可分配。类比：雷锋是人，但"雷锋精神"是抽象形象，不再指某个人。
- **广播地址**：主机位全 1，代表网段内所有设备。⚠️ 误区：**见 255 就判广播**——必须按掩码确认主机位是否全 1。反例：192.168.0.255/16 的主机位并非全 1，不是广播地址。
- **可用地址**：网络号与广播地址之间（掐头去尾）。

### 2.9 地址数量与范围计算（★考试重点）

**数量公式**：
- 网段地址总数 = 2ⁿ（n=主机位位数=32−掩码长度）
- 可用地址数 = 2ⁿ − 2（减网络号与广播地址）
- 【设计本源与技术哲学】："什么时候该减 2、什么时候不该减 2，你心中要有数。"

**范围快速算法（★核心技能，两种）**：

方法一（万能但慢）：IP 与掩码转二进制对齐，网络位照抄、主机位全 0 得网络号、全 1 得广播地址。

方法二（快算）——**掩码 ≥24**（以 C 类为单位）：步长=2^(32−掩码)，从该 C 类块起点按步长分组。例：192.168.1.53/28 → 步长 2⁴=16 → 53 落在 48~63 组 → 网络号 .48、广播 .63。

**16 < 掩码 < 24**（以 B 类为单位）：2^(24−掩码) = 块大小（几个 /24 捆成一块）。例：192.168.10.100/22 → 2²=4 个 /24 一块 → 10 落在 8~11 块 → 网络号 .8.0、广播 .11.255。

**掩码快速反推**：/27 → 2⁵=32 → 256−32=224 → 255.255.255.224；/22 → 2²=4 → 256−4=252 → 255.255.252.0。

### 2.10 等长子网划分入门

**需求场景**：192.168.1.0/24 分给 5 个部门，各部门需 20 个可用地址。

**双向满足法（★解题范式）**：
1. 主机位方向：2ⁿ−2 ≥ 20 → n=5（每段 32 地址）✓
2. 子网位方向：/24 借 3 位主机位做子网位 → 2³=8 个子网 ≥ 5 部门 ✓
3. 验证另一方案：若 n=6（每段 64），子网只剩 2 位 → 4 个子网 < 5 部门 ✗

类比：【设计本源与技术哲学】："分蛋糕，每一块大小一样，叫等长子网划分。""资源够用时随便分没人说你不对，不够时就要精打细算。"

**变长子网（引出）**：四部门各需 40/27/10/60 地址——等长 /26（每段 64）都够用但小部门浪费大；需求档位差异大时等长方案脆弱（再增一个部门就崩溃），变长方案下讲展开。

### 2.11 华为设备接口 IP 配置与排错验证（VRP 实战）

#### 配置与命令

理论计算出的 IP 地址必须配置到设备接口才能生效。华为 VRP 支持物理接口（以太口、串口）、逻辑接口（Loopback 环回口、VLANIF 接口）等多种形态的 IP 编址：

```shell
# 1. 物理以太网接口配置 IPv4 地址（支持前缀长度或点分十进制掩码）
[Huawei] interface GigabitEthernet 0/0/1
[Huawei-GigabitEthernet0/0/1] description Link_to_LAN_Switch
[Huawei-GigabitEthernet0/0/1] ip address 192.168.1.1 255.255.255.0  # 或直接写简写：ip address 192.168.1.1 24
[Huawei-GigabitEthernet0/0/1] undo shutdown                          # 华为路由器物理接口默认通常是开启的，若处于 Down 状态则需 undo shutdown
[Huawei-GigabitEthernet0/0/1] quit

# 2. Loopback 环回接口配置（常用于设备管理、Router-ID 与测试，永远处于 UP 状态）
[Huawei] interface LoopBack 0
[Huawei-LoopBack0] ip address 1.1.1.1 32                              # 环回接口通常配置 /32 掩码，节省 IP 资源
[Huawei-LoopBack0] quit

# 3. 三层交换机 VLANIF 接口配置（SVI 虚接口，充当局域网网关）
[Huawei] vlan 10
[Huawei-vlan10] quit
[Huawei] interface Vlanif 10
[Huawei-Vlanif10] ip address 192.168.10.254 24
[Huawei-Vlanif10] quit
```

#### 状态检查与排错命令

```shell
# 查看所有接口的 IP 地址与双 UP 状态（排错第一步）
<Huawei> display ip interface brief
*down: administratively down
^down: standby
(l): loopback
(s): spoofing
(E): E-Trunk down
Interface                         IP Address/Mask      Physical   Protocol  
GigabitEthernet0/0/1              192.168.1.1/24       up         up        
LoopBack0                         1.1.1.1/32           up         up(s)     
Vlanif10                          192.168.10.254/24    up         up        

# 检查接口详细参数（包含 MTU、广播类型、收发包计数）
<Huawei> display ip interface GigabitEthernet 0/0/1

# 连通性测试：Ping 命令核心参数
<Huawei> ping -a 192.168.1.1 192.168.1.2      # -a 指定源 IP 发送 ICMP 报文（测试回程路由与指定接口）
<Huawei> ping -c 5 -s 1500 192.168.1.2        # -c 指定报文数量，-s 指定 ICMP 数据包载荷大小（用于测试大包与分片）

# 路径追踪：Tracert 逐跳探测
<Huawei> tracert 192.168.2.1                  # 利用 TTL 逐跳加 1 探测沿途路由器，判定丢包或环路节点
```

> **★ 双 UP 状态排错口诀**：
> - `Physical UP, Protocol UP`：物理链路连通，二层及网络层协议协商正常，可正常转发数据；
> - `Physical DOWN, Protocol DOWN`：物理层故障（网线没插、光模块损坏、对端未上电或本端 `shutdown`）；
> - `Physical UP, Protocol DOWN`：二层协议不匹配或无载荷（如串口封装协议两端不一致，或以太网 Trunk 口未放行任何活跃 VLAN）。

## 三、总结

**核心重点**：
1. 交换机 MAC 表"源学习、老 300 秒、漂移覆盖"；三行为=泛洪（广播/组播/未知单播）+ 转发（已知单播）+ 丢弃（防重复帧）。
2. TTL 是环路兜底不是防环；协议号 6=TCP、17=UDP 必记。
3. IP 全局唯一 vs MAC 本地唯一；网络层价值=同链路与跨链路通信都用 IP 定义。
4. 分片三字段：ID 归组、DF/MF 标志、偏移×8 位置；仅第一片带传输层头。
5. IP=连续网络位+连续主机位；掩码 1/0 一一对应；127.x 环回排错口诀。
6. A/B/C/D/E 五类按首比特数学划分，默认掩码 /8、/16、/24。
7. 见 255 不一定是广播——按掩码验主机位；0.x 不分配。
8. 数量公式 2ⁿ 与 2ⁿ−2，是否减 2 心中有数。
9. 快算法：≥24 按步长分组（2^(32−掩码)）、16~24 按 /24 捆块（2^(24−掩码)）；掩码反推 256−2^n。
10. 子网划分双向约束：主机位够借取（2ⁿ−2≥需求）且子网数够分（2^借位≥部门数），取最小满足值。

**落地注意事项**：客户网络 IP 规划先数部门/终端量再选掩码，等长方案预留扩展位；现网排错先 ping 127 验网卡驱动，再逐段排查；DF=1 应用遇到 MTU 瓶颈时调大链路 MTU 适配；/31 掩码老设备不支持，点到点链路新设备可用。工程实践准则：数通协议原理必须结合真机或模拟器反复实验验证，方能彻底掌握。

**学习建议**：本章计算题必须动手练到条件反射：任意给"IP/掩码"10 秒内报出网络号、广播地址、可用范围、可用数量；等长子网划分能独立完成"5 部门×20 地址"级需求并说明为何另一档位不行，再进入第 04 章《IP路由基础》。

| **TOS** | Type of Service | 服务类型 | IP 头部 8 位字段，前 6 位用于 DSCP/DiffServ 服务质量标记 |
| **DF** | Don't Fragment | 不分片标志 | IP Flags 字段位，为 1 时禁止分片，超 MTU 则丢弃报文 |
| **MF** | More Fragments | 更多分片标志 | IP Flags 字段位，为 1 表示后续还有分片，为 0 表示最后一片 |
| **VLSM** | Variable Length Subnet Mask | 可变长子网掩码 | 突破传统有类网络限制，实现更精细的 IP 空间按需切分 |
| **CIDR** | Classless Inter-Domain Routing | 无类域间路由 | 将多个小网络前缀汇聚为一个大网络，减少路由表规模 |
