## 一、总起

MPLS 的学习关键在于区分**控制平面**与**转发平面**：控制平面（路由协议+LDP）负责产生和维护路由信息及标签信息——"大脑"；转发平面根据标签转发表执行——"四肢"。MPLS 在二者之间插入了一层"2.5 层"标签转发机制：报文进入 MPLS 域时打标签（PUSH），中间节点查标签表交换（SWAP），出域时弹标签（POP）回到 IP 转发。标签转发表的形成是核心——静态 LSP 需要逐台手工配置（"让你把如花取回家你愿不愿意"），LDP 协议则自动为路由分配标签并分发给邻居，形成动态 LSP。本章三讲递进：第一讲用帧中继实验类比标签交换行为（"在 IP 网络上玩电路转发"），第二讲系统梳理概念（域/角色/FEC/标签结构/LSP）+ 静态 LSP 全链路手搓实验 + 三张表转发机制，第三讲深入 LDP 协议（会话建立/消息类型/标签发布三层机制/触发策略）。

**适用人群**：
- **初学 / 转行人员（HCIP 进阶）**：理解传统 IP 逐跳转发最长匹配瓶颈，掌握 2.5 层标签交换（PUSH/SWAP/POP）与动态隧道基本理念；
- **备考工程师（HCIP / HCIE 核心）**：攻克 MPLS 报文结构（20位标签/EXP/S/TTL）、倒数第二跳弹出 PHP（Label 3）、三张转发表（FIB/NHLFE/ILM）、以及 LDP 标签分发机制（DU/Ordered/Liberal）；
- **一线工程实践者**：掌握运营商骨干与大中型企业网动态 LSP 隧道规划、LSR-ID 与 /32 主机路由绑定、以及 LDP 会话排错。

## 二、分述

### 2.1 MPLS 诞生背景：从帧中继到 IP 网络的标签交换

**90 年代痛点**：IP 转发"最长匹配原则"——一个报文匹配多条路由需反复查表找最精确那条——成为硬件性能瓶颈。

**灵感来源**：帧中继（Frame Relay）的虚电路转发——在一条物理线路上通过 DLCI（0~1024，运营商分配）虚拟出多条逻辑电路。帧中继交换机转发完全基于标签转发表（入接口+入标签→出接口+出标签），不查 IP 路由表。中间做的是**标签交换（swap）**，DLCI 号会变化。

【类比】"就像以前玩街机投币，后来有模拟器了，在电脑上就能玩街机——MPLS 就是在 IP 网络上玩电路转发。"

**MPLS 的本质**：在三层网络上模拟出二层的电路转发行为。标签位于链路层和网络层之间——"2.5 层协议"。

**今天的价值**：转发性能优势被硬件发展抵消（"肌肉练得再强壮也挡不过花生米"），但标签转发天然形成**动态隧道**——VPN 业务的核心优势。静态隧道（IPSec/GRE）需人工指定下一跳配置繁琐，MPLS VPN 是动态隧道"超级简单超级方便"。

### 2.2 控制平面与转发平面

| 平面 | 职责 | 硬件对应 |
|---|---|---|
| 控制平面 | 路由协议产生路由信息 + LDP 生成标签信息 | MPU（主控处理单元） |
| 转发平面 | 根据路由表/标签转发表执行转发 | LPU（线卡）、SPU（服务板） |

【类比】"控制平面就相当于人的大脑，转发平面就相当于人的四肢——大脑下达指令，手脚去执行动作。"

【设计本源与技术哲学】：★"转发平面上不再依赖于路由表，但不代表控制平面不需要路由表。你一定要有这种区别能力。"

### 2.3 MPLS 基本概念

**MPLS 域（Domain）**：连续运行标签转发的设备组成的网络。

**路由角色（相对概念）**：
| 角色 | 职责 |
|---|---|
| LSR | 域内所有标签交换路由器 |
| LER（边缘） | 打标签/剥标签 |
| Ingress（入节点） | 给 IP 报文打标签（PUSH） |
| Transit（中间节点） | 标签交换（SWAP） |
| Egress（出节点） | 弹标签（POP）→IP 转发 |

★角色是**相对的**——"是一个相对的概念，不是一个绝对的"。同一台路由器对不同报文可能是不同角色。类比："海水入大海——4.4.4.4 是大海/目的地，水可从任意地方流入。"

**FEC（转发等价类）**：具有某种共性的数据流集合，最常见定义=匹配同一条路由的报文。标签通常与 FEC 对应。标签在每台路由器上**本地有效、本地唯一**。

**LSP（标签交换路径）**：标签报文穿越 Domain 到达目的地的路径。默认跟路由协议最短路径走（BE），也可通过 TE 按业务需求算路径。**LSP 是单向的**（去和回 FEC 不同）。

### 2.4 标签结构与特殊值

**标签结构（4 字节=32bit）**：
| 字段 | 位数 | 含义 |
|---|---|---|
| 标签值 | 20 | 0~2²⁰-1 |
| EXP | 3 | QoS 优先级 |
| S | 1 | 栈底位（1=最后标签） |
| TTL | 8 | 防环 |

- 理论上标签栈不限个数，实际最多 3 个
- **每台路由器只根据顶部标签做转发决策**——"不关心第二第三标签是什么"
- 标签 TTL 减 1 时 IP 报文 TTL 不减（省校验和重算）
- 二层帧头类型字段：8847（Ethernet）/8281（PPP）标识标签报文

**特殊标签值**：
| 值 | 名称 | 含义 |
|---|---|---|
| 0 | 显式空标签 | 报文中可见，让下一跳根据 EXP 做 QoS |
| 3 | 隐式空标签 | 不在报文中出现，动作=弹出顶部标签（倒数第二跳弹出） |
| 0~15 | — | 保留特殊用途 |
| 16~1023 | — | 静态 LSP 用（华为限制） |
| 1024~1048575 | — | 动态协议用（LDP/TE/BGP 各占一段） |

### 2.5 标签转发动作与三张表

**四种动作**：PUSH（压入）、SWAP（交换顶部）、POP（弹出顶部）、空 POP（整栈弹出）。

**LSP 建立原则（★铁律）**：上游出标签 = 下游入标签。

**三张表**：
| 表 | 存在位置 | 作用 |
|---|---|---|
| FIB（含 FTN） | 仅入节点 | 查 FIB→Tunnel ID≠0→走标签转发（=0 走 IP） |
| NHLFE | 入节点+中间节点 | 含 Tunnel ID/出接口/下一跳/出标签/操作类型 |
| ILM | 中间节点+出节点 | 收到标签报文查 ILM→得 Tunnel ID→查 NHLFE |

**转发流程**：
- 入节点：IP 报文→查 FIB→得 Tunnel ID→查 NHLFE→Push 标签
- 中间节点：标签报文→查 ILM→得 Tunnel ID→查 NHLFE→Swap 标签
- 出节点：标签报文→查 ILM→Tunnel ID 为空→POP→再查 IP 路由表（查两次表，负担稍大）

### 2.6 静态 LSP 手搓实验

**配置命令**：
```bash
mpls lsr-id X.X.X.X                     # 必须先配
mpls                                    # 全局启用
interface GigabitEthernet0/0/0
 mpls                                   # 接口启用

# 入节点：目标/下一跳/出接口必须跟路由表一致，否则 DOWN
static-lsp ingress <名称> destination <目标网络> <掩码> nexthop <下一跳> out-label <出标签>
# 中间节点：入标签=上游出标签；可指定路径不跟路由
static-lsp transit <名称> incoming-interface <入接口> in-label <入标签> nexthop <下一跳> out-label <出标签>
# 出节点
static-lsp egress <名称> incoming-interface <入接口> in-label <入标签>
```

**实验验证**：R1→R2→R3→R5 为 FEC 5.5.5.0 建 LSP（标签 102→203→305）。入节点目标/下一跳必须跟路由表一致否则 DOWN；中间节点可不跟路由指定路径（但路由必须先到位）；同一入标签不能配两条 Transit。

**静态 vs 动态**：静态手工配、配置量巨大不能适应拓扑变化——"让你把如花取回家你愿不愿意"；动态 LDP 自动建、跟路由表走。

### 2.7 LDP 协议全貌

**LDP 定位**：动态标签分发协议，传递路由对应的标签信息。路由协议传递路由信息，LDP 传递标签信息。

**会话类型**（★看 Hello 包形式判断）：
| 类型 | Hello 形式 | 建立方式 | 用途 |
|---|---|---|---|
| 本地 | 组播（224.0.0.2） | 自动 | 公网 LSP 逐跳建立 |
| 远程 | 单播 | 人工指定 | VPLS 场景 |

**LDP ID**：48bit = LSR ID（32bit）+ 标签空间标识符（16bit），如 `1.1.1.1:0`。标签空间 0=基于设备（全局唯一，当前使用）；非 0=基于接口（已淘汰）。

**消息类型**：
| 类型 | 子类 | 端口 | 关键参数 |
|---|---|---|---|
| Discovery | Hello | UDP 646 | 5 秒发送，15 秒失效 |
| Session | Initialization | TCP 646 | 参数协商（类似 BGP Open） |
| Session | Keepalive | TCP 646 | 15 秒发送，45 秒失效（3 倍） |
| Advertisement | Address | — | 宣告接口 IP |
| Advertisement | Label Mapping | — | FEC↔标签映射（类似 BGP Update） |
| Advertisement | Label Withdraw/Release | — | 撤销/释放标签 |
| Notification | — | — | 错误通知 |

**会话建立过程**：
1. 接口启用 LDP→组播 Hello（UDP 646，5 秒一次）
2. Hello 携带传输地址（默认=LSR ID）
3. **传输地址大的一方**向小的一方发起 TCP 三次握手（端口 646）
4. Initialization 参数协商→Keepalive→Operational
5. 之后互发 Address + Label Mapping 消息

### 2.8 标签发布三层机制（★核心）

**发布方式**：
| 方式 | 行为 | 默认 |
|---|---|---|
| **DU（下游自主）** | 无需请求，主动向**所有邻居**通告标签 | ★默认 |
| DOD（下游按需） | 上游先请求，下游才回应 | ATM 环境（已淘汰） |

★DU 实际行为：向所有邻居发（不区分上下游），但**只用下一跳发来的标签**构建 LSP，其他保留以备路径切换——提高收敛速度。

**分配控制方式**：
| 方式 | 行为 | 默认 |
|---|---|---|
| **有序（Ordered）** | 收到下游标签后才向上游分配——要么完整要么不建 | ★默认 |
| 独立（Independent） | 不管下游，有标签就通告——可能 LSP 不完整 |

【设计本源与技术哲学】："咱们要就不干，要干就要干完整。"

**保持方式**：
| 方式 | 行为 | 默认 |
|---|---|---|
| **自由（Liberal）** | 保留所有邻居的标签，只用下一跳的 | ★默认 |
| 保守（Conservative） | 只保留下一跳的 | 节省资源但收敛慢 |

**华为默认组合**：DU + Ordered + Liberal。

### 2.9 LSP 触发策略

| 策略 | 行为 |
|---|---|
| **host**（默认） | 仅为 32 位主机路由建 LSP——★这就是 IA/IP 阶段强调环回口配 32 位主机路由的深层原因 |
| all | 为所有路由建 LSP（含代理出节点=域外路由在域内提供标签转发） |
| none | 直连路由不作为出节点，但非直连仍作为中间节点 |
| 前缀列表 | 精细化控制 |

★**VPN 场景禁止汇总环回口路由**——汇总后 FEC 变化导致 LSP 断裂，VPN 业务失效。

### 2.10 帧中继实验类比（MPLS 入门钥匙）

帧中继交换机转发完全基于标签转发表（入接口+入标签→出接口+出标签），不查 IP 路由表——这就是 MPLS 的行为模型。

**帧中继 OSPF NBMA 考点**：NBMA 接口 Hello 默认单播，需 `peer` 指定或改 `network-type broadcast`——帧中继虽已淘汰但概念出现在考试中。

`fr map ip 10.1.1.2 dlci 102 broadcast`——`broadcast` 参数让虚电路支持广播/组播封装，否则无法跑路由协议。

### 2.11 华为设备 MPLS/LDP 基础使能与状态验证模板（VRP 实战）

#### 1. 全局与接口启用 LDP 动态标签分发

```shell
# ═══ 1. 全局配置 LSR-ID 并开启 MPLS 与 LDP ═══
[R1] mpls lsr-id 1.1.1.1                                # ★必须首先配置 LSR-ID（通常使用 LoopBack0 地址）
[R1] mpls                                               # 全局启用 MPLS 功能
[R1-mpls] quit
[R1] mpls ldp                                           # 全局使能 LDP 协议
[R1-mpls-ldp] quit

# ═══ 2. 互联物理接口启用 MPLS 转发与 LDP 协商 ═══
[R1] interface GigabitEthernet 0/0/1
[R1-GigabitEthernet0/0/1] mpls                          # 接口启用 MPLS 报文转发
[R1-GigabitEthernet0/0/1] mpls ldp                      # 接口启用 LDP 动态分发标签（自动发送 UDP 646 Hello 组播发现邻居）
[R1-GigabitEthernet0/0/1] quit
```

## 三、总结

**核心重点十带走**：
1. MPLS 本质="在 IP 网络上模拟电路转发行为"——2.5 层协议，标签在链路层与网络层之间。
2. 控制平面≠转发平面：转发不依赖路由表，但控制平面必须靠路由协议+LDP 生成标签信息——"大脑下达指令手脚执行"。
3. 路由角色是相对概念（Ingress/Transit/Egress 对不同报文不同）；FEC=匹配同一条路由的报文；标签本地唯一；LSP 单向。
4. 标签 4 字节（20+3+1+8），只看顶部标签；特殊值 0=显式空（QoS）、3=隐式空（弹出）；16~1023 静态、1024+ 动态。
5. 三张表：FIB（入节点，Tunnel ID≠0 走标签）/NHLFE（入+中，出接口+出标签）/ILM（中+出，入标签→Tunnel ID）。
6. LSP 建立铁律：上游出标签=下游入标签；静态 LSP 入节点必须跟路由表配否则 DOWN，中间可指定路径但路由必须先到位。
7. LDP 会话：本地=组播 Hello 自动建（公网 LSP）/远程=单播人工建（VPLS）；Hello 5s/15s，Keepalive 15s/45s；UDP 646+TCP 646。
8. 标签发布三层默认：DU（向所有邻居发只用下一跳的）+有序（要么完整要么不建）+自由（保留所有只用一个）——"要就不干要干就要干完整"。
9. LSP 触发默认 host（仅 32 位主机路由）——这就是环回口必须配 /32 的深层原因；VPN 禁止汇总环回口路由（FEC 变化 LSP 断裂）。
10. MPLS VPN 价值=动态隧道：公网不维护私网路由却提供私网转发服务——"这就是 VPN 最牛的地方"。

**落地注意事项**：`mpls lsr-id` 必须先配否则 mpls 及接口 mpls 都起不来；LSR ID 用环回口地址且 32 位主机路由必须可达（否则 TCP 建不起来）；UDP 646 和 TCP 646 都不能被防火墙/ACL 封禁；静态 LSP 同一入标签不能配两条 Transit；出节点查两次表（ILM→POP→IP 路由表）负担稍大；诊断命令 `display mpls nhlfe/ilm` 仅模拟器 Router 支持（AR 不支持）；`display mpls ldp session` 只有 Operational 才正常——"跟 BGP 一样"。

**学习建议**：MPLS 入门的关键是帧中继实验——虽然帧中继已淘汰，但"标签转发表（入接口+入标签→出接口+出标签）不查 IP"的行为模型就是 MPLS 的核心，理解了帧中继就理解了 MPLS 一半。静态 LSP 手搓实验必做：R1→R2→R3→R5 为 FEC 5.5.5.0 逐台配标签（102→203→305），配完后 `display mpls lsp` 看到完整 LSP 链路，再改中间节点路径体会"可指定不跟路由"的灵活性。LDP 部分重点在三层机制（DU/有序/自由）的排列组合——在纸上画出"向所有邻居发标签但只用下一跳的"和"收到下游标签后才向上游分配"的时序图，画通即理解触发策略 host vs all 的差异。学完本章即可进第 23 章（MPLS L3VPN——VRF+LDP+BGP VPNv4 的组合拳）。
